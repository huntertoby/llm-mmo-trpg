# WL-1 b 段：前端退回圖示（美術 PM 裁定）

美術 PM，2026-11-22。回開發 PM 的三個問題，出處是 `docs/phases/內容擴充評估.md` 第 1 項。

## 結論

1. **同意。** 其實前端已經有退回畫法，而且狀態那一種驗收過了。這一段不用畫新圖，只要確認每條路都會走到退回畫法、不會壞，再補測試。
2. **退回成什麼樣子：沿用現行的畫法**，不改成照類別給通用圖示。理由在下面的表格。
3. **不用出樣張。** 交件時在開發頁拍截圖就好，清單在最後一節。

## 退回畫法（照現行）

| 東西 | 現行的退回畫法 | 裁定 |
|---|---|---|
| 狀態圖示 | `qIcon/status.ts` 的 `paintUnknown`：框照增益、減益、中性的規則畫，有控制類別就染類別底色，中間是狀態名稱的第一個字，字色米白 `#f2e6c8`；沒有名稱就畫「?」。QI-3a 第 5 項已驗收（`QI-2c-2d-3a-3b驗收.md`） | **照舊。** 框和底色已經告訴玩家這是增益、減益還是控制；第一個字可以分出兩個不同的新狀態，通用圖示做不到。11 px 頭頂那一級讀不出字，只剩一塊色塊，可以接受：框色有分類，滑過看得到全名 |
| 骨架徽章 | `qIcon/parts.ts` 的 `entry()` 找不到時，畫 Q 版扁平問號；圓底和稀有度色環照舊 | **照舊。** 骨架只有 16 個，新骨架很少見，問號就夠了 |
| 其他部件圓片（效果、條件、觸發等） | 同上，畫 Q 版問號 | **照舊** |
| 骨架名稱 | `skillIcon.ts` 的 `SKELETON_NAME[skeleton] ?? skeleton`：找不到就直接顯示英文 id | **要改。** 玩家畫面不能出現英文 id。名稱改成從資料讀；前端的表只用來覆寫。資料裡也沒有名稱時要顯示什麼字，由玩法 PM 定 |

## 要加的

- **測試**：列出所有走到退回畫法的 id，存成快照。這份清單就是美術的待畫清單，新內容進來時快照會變，美術就知道要補哪幾個圖。
- **不能壞**：沒有名稱、空字串、`null` 都要畫得出來，不能丟錯誤，也不能整格空白。
