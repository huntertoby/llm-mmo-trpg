# 雲嶺實地地圖：地磚與地物圖庫（樣張與移植需求草案）

美術 PM，2026-11-04。延後的美術項目第 4 項。

- 用途：給 6C 的 18 張雲嶺實地地圖用。這份也是 6B-ART1「探索地磚與建築外觀」的雲嶺部分。
- 樣張：`cloud-tiles.png`；畫法在 `sample/cloud-tiles.html`、`sample/cloudTiles.js`。畫風同 `explore.png`，全部程式繪製。
- 樣張最下面用這套圖庫拼了一張示範地圖「青霧觀山門」（20×12）。
- **等使用者看過再定**；細節照美術 PM 的推薦先做，列在交接文件第 6 節的代決 #32～35。

## 1. 原則

1. **實地地圖照戰鬥規則畫**（21.3）：所有會擋路、擋視線、可燃、可推倒的東西，都要對到 `content/objects.yaml` 的物件功能。
   - 新外觀優先做成現有 ID 的雲嶺外觀（3-37b 的區域換皮）；
   - 只有功能確實不同時，才提新物件 ID，而且要玩法 PM 同意。
2. **純裝飾放在新的裝飾層** `decor`：花草、飄霧、渡船這類，不影響任何規則；就地開打切出戰場時一起帶過去，但只畫，不參與判定。
3. **自動接邊**：石階、水岸、崖壁由相鄰格自動判斷要畫哪種，地圖檔不用另外標。
4. **高低差**照遊戲規格：每級抬高 6（52 單位裡是 6.5），只畫南側立面。
   - 差 1 級：石板格畫成石階；
   - 差 2 級以上：畫岩壁，走不上去。

## 4. 移植需求（使用者定案後，排進 6B-ART1／6C）

1. **畫法**：新增 `render/cloudRidgeField.ts`，照 `cloudTiles.js` 移植；格子 52 虛擬單位，畫到 48。
2. **自動接邊**：在畫地面時讀相鄰格的高度與地形，決定畫石階、水岸還是崖壁；結果放進快取鍵。
3. **資料**（6B-1 的 `FieldMapDef` 加欄位，玩法 PM 和開發 PM 同意後）：
   - `decor: [{at, kind}]`：純裝飾。
   - `buildings: [{at, size, kind, door?}]`：多格建築。佔的格子在規則上照 `kind` 換成牆、柱或可走格，由載入時展開，不改引擎。
4. **新物件 ID**（玩法 PM 同意後加進 `content/objects.yaml`）：`bamboo_grove`、`boulder`、`fence`、`stone_lantern`，以及新地面 `path_stones`。功能都照現有物件複製，見第 2 節。
5. **迷霧三段**：畫在最上層，濃霧不透；淡霧 45%，看得到地形，但敵人、事件標記不畫。
6. **工作量**：約 1.5 段。
   - 地面與自動接邊：0.5；
   - 自然、地物：0.5；
   - 建築與 `buildings` 展開：0.5（和 6B-4 的霧渡鎮屋舍共用）。
