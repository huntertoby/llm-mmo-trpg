## 1. 灰燼之心（熔心坑，區域頭目）

設定（`content/units/ashen_heart.yaml`）：一塊會呼吸的源晶核心殘片，嵌在熔岩甲蟲堆成的殼裡，不移動。

| 部位 | 畫法 |
|---|---|
| 底座 | 熔岩甲蟲堆成的岩堆，4 隻甲蟲的背殼看得到；不會掉落 |
| 核心 | 多面的源晶，橘黃色，一明一暗地呼吸（週期約 2.6 秒，大小 ±6%），外圍有光暈 |
| 熔殼 | 10 塊玄武岩甲蟲殼片圍住核心；殼縫透出熔岩光，隨呼吸變亮，殼片也跟著微微張開 |

各階段（由引擎的階段事件與狀態觸發）：

| 階段 | 外觀 | 觸發 |
|---|---|---|
| 1 殼 | 殼片全部貼著；「熔岩噴發」預告時殼頂冒出熔岩柱 | 開場狀態 `molten_shell` |
| 進入 2 | 殼裂開：10 塊殼片往外飛、旋轉、落到地上變暗（約 1.2 秒） | `molten_shell` 被移除（`status_traits`） |
| 2 呼吸 | 核心整個露出、呼吸；「熔心吸氣」時火星往核心收 | 階段 `breath` |
| 3 熔毀 | 核心龜裂、裂紋發白閃爍；熔岩從底座滴落；坑底發紅 | 階段 `meltdown` |

- 殼片脫落的方向、旋轉和落點，由殼片名稱的雜湊決定（FNV-1a，同 `inkStyle.seedOf`），每次都一樣。
- 熔殼在冰攻擊下碎掉時（`molten_shell` 被冰移除）也播同一段脫落。

## 2. 碎晶之主（裂界門，賽季頭目）

設定（`content/units/rift_shard_lord.yaml`）：浮在浮台上的源晶君主。

| 部位 | 畫法 |
|---|---|
| 軀幹 | 倒三角的晶塊，淡紫水晶色，有晶面線 |
| 核心 | 胸口的菱形核心，青白色，有光暈 |
| 頭 | 小晶面的頭、兩個發光的眼；頭上 5 根晶冠，中間那根最高、青白色 |
| 手 | 兩片浮空的手晶，不連著身體；施法時往前伸，手心有裂界光 |
| 下半身 | 一串往下漸小的碎晶，浮空、慢慢擺動 |

各階段：

| 階段 | 外觀 | 觸發 |
|---|---|---|
| 1 三柱 | 三道灌注光束從源晶柱打進核心：火柱橘、霧柱青、雷柱紫，和柱子同色 | 開場狀態 `rift_channel` |
| 2 碎界脈動 | 6 片碎晶繞著身體旋轉 | 階段 `rift_pulse` |
| 3 核心過載 | 核心裂開、發白閃爍，眼睛變白；瞬步時有 3 層殘影 | 階段 `core_overload`；技能 `skill_blink` |
| 4 界崩 | 下半身的碎晶散得更開，整體偏紫紅 | 階段 `rift_collapse` |

## 3. 和骨架動畫的銜接

兩位頭目都是「部件＋掛點」：
- 每塊殼片、每片浮晶都是一個部件，有自己的位置、旋轉、縮放；
- 動畫只改這三個值，和 `../archive/art/動畫移植需求.md` 的骨架同一套做法。

需要的片段：

| 片段 | 灰燼之心 | 碎晶之主 |
|---|---|---|
| 待機 | 核心呼吸、殼縫透光 | 浮動（上下 3）、手晶擺動、尾部碎晶擺動 |
| 出招（單體） | 核心一亮，從核心射出火球（`skill_fire_bolt`） | 手晶往前伸、手心放出（`skill_cluster_bolt`） |
| 蓄力大招 | 殼頂熔岩柱（第 1 階段）、核心脹大（第 3 階段「熔心爆」） | 晶冠全亮、碎晶往核心收（「界碎」） |
| 吸、吐 | 吸氣：火星往內收；吐息：核心一縮、熱浪往外 | — |
| 召喚 | 殼縫爬出餘燼蜥（第 2 階段） | 地面裂開，晶傀儡浮上來（第 2 階段） |
| 受擊 | 核心白閃、殼片抖一下 | 全身白閃、往後飄一點 |
| 階段轉換 | 殼脫落（上表） | 光束斷掉、碎晶開始繞行／核心裂開／崩解 |
| 倒下 | 核心熄滅、碎裂成幾塊 | 全身碎成晶片落下 |

## 4. 移植需求（給開發 PM，使用者定案後再排）

1. **資料**：在 `doll` 加一個選填欄位 `boss_art`（值：`ashen_heart`、`rift_shard_lord`）。
   - 有這個欄位的單位，改用專屬畫法；沒有的照現在的 `creature`。
   - 前端不認得的值，退回 `creature`，不出錯。
2. **階段**：畫法讀 `UnitView` 已有的階段 ID 和狀態，不新增伺服器欄位。
   - 灰燼之心：`molten_shell` 在不在、階段 `breath`／`meltdown`；
   - 碎晶之主：`rift_channel` 在不在、階段 `rift_pulse`／`core_overload`／`rift_collapse`。
3. **大小**：
   - 兩位頭目仍然只佔 1 格；
   - 畫面寬約 2 格（96），高約 2 格；
   - 頭目在戰場上維持 ×0.9 的規則（5A-ART），不能壓到隔一格以外的單位。
4. **外光與記號**：
   - 「外光只代表頭目」的規則照舊，頭目的外光和金環照現有的畫；
   - 灰燼之心的外光改成核心光暈（同一個顏色），不另外疊一圈。
5. **確定性**：殼片、碎晶的相位和脫落方向，由部件名稱的雜湊決定，不用 `Math.random()`。
6. **工作量**：約 1.25 段。兩位頭目的畫法、階段外觀約 0.75 段；片段（第 3 節）約 0.5 段，可以併進動畫的「技能片段」那一批。

## 5. 檢查清單

- [ ] 裂界門：三柱階段看得到三道光束，顏色和柱子對應；柱子全倒後光束消失、碎晶開始繞行。
- [ ] 核心過載有發白和瞬步殘影；界崩偏紫紅。
- [ ] 兩位頭目不會壓到隔一格以外的單位；同一場重播畫面一樣。
