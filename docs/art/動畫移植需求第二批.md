## 0. 共同原則

1. **動畫只讀結果，不影響結果**：只讀引擎回傳的事件，不改任何數值和規則。LLM 不選動畫，也不新增技能欄位。
2. **純函式、確定性**：
   - 照 `motionClips.ts`、`doorClips.ts` 的寫法：時間 → 姿勢，不用 `Math.random()`，不讀時鐘；
   - 姿勢量化後才放進貼圖快取鍵（沿用 `poseKey`）。
3. **挑變體的雜湊**：
   - 用 `inkStyle.ts` 的 `seedOf`（FNV-1a）；
   - 戰鬥中的鍵是「戰鬥鍵:事件 `seq`:施放者 ID:片段名」，技能變體再加技能 ID；
   - 「戰鬥鍵」先用戰鬥畫面資料裡現有、同一場戰鬥不變的值；真的沒有，才加一個只畫的欄位，並在報告說明；
   - 探索中沒有戰鬥鍵，改用「地圖 ID:單位 ID:動作序號」；
   - 重播、觀戰、重新整理後，都要看到同一個變體。
4. **時間**：
   - 每個片段有基本長度（200～520 毫秒），乘上 `playback.ts` 的速度；
   - 「跳過」直接顯示結果；
   - **按住空白鍵**時暫時 2 倍速，放開恢復（第一段 6N-1 加）；
   - 一般速度下，一招（不含連鎖、反擊）從起手到最後一個結果最長 **1.8 秒**；超過時等比壓縮起手和收尾，命中點不壓。
5. **命中點對齊**：每個片段標 `hitAt`。傷害數字、受擊、特效爆發都在 `hitAt` 那一刻開始；同一片段的所有變體 `hitAt` 都一樣。
6. **異形**：沿用 6M-2 的 4 個通用片段（`creaturePose.ts`）。這批的片段都要有異形版或退回通用片段；召喚物、形態也一樣。
7. **測試頁**：每段都在 dev 頁（`walkGallery` 或新開 `#skills`）列出這段的所有片段和變體，可用 `?anim=0.1` 慢動作。我驗收時看這頁加實戰截圖。
8. **檔案不重疊**（可平行）：
   - 6N-1～6N-3 都會改串接器，**要依序做**；
   - 6N-9、6N-10 和前面不碰同一批檔案，可以平行。

## 2. 6N-1：串接器與起手

### 2.1 串接器（新檔，例如 `battle/skillSequence.ts`）

- **輸入**：一步的事件（`skill_used` 起，到下一個 `skill_used`、回合事件或步驟結束為止）＋技能卡上部件的順序（client 已有）。
- **輸出**：時間軸，每列是 {單位、片段、開始、長度、`hitAt`、特效起點}。
- **規則**（方案 2.3 (2)）：
  1. 照技能卡部件的順序播。「砍＋跳」和「跳＋砍」用同一套片段，只差順序。
  2. 方向和距離讀事件的落點，不寫在片段裡。
  3. 同一個時間點的結果並排播：一次打 3 人，3 人同時受擊；傷害和燃燒一起疊。施放者身上一次只播一個片段。
  4. 連鎖、反應、反擊接在後面，前面加 0.15 秒停頓。
  5. 多段技能只有第一段播起手；後面同類的出招省略蓄力。
  6. 沒有身體動作的原語不佔時間，和前一個片段同時播。
- **事件與原語的對照**：照事件種類對到方案 2.3 (1) 的原語表（例如 `damage_dealt`→`damage`、`healed`→`heal`、`shield_gained`→`shield`、`unit_dashed`→`dash`、`unit_charged`→`charge_through`）。
  - 對不到的事件照現在的特效播，不加身體動作；
  - 報告列出完整對照表。
- **特效起點**：改成武器作用端（杖頭、劍尖、槍口、弓弦）的實際位置，由當下姿勢算（`inkWeaponFrame.ts`）。沒有武器時用手掌。

### 2.2 起手對照表

- 照方案 2.3 (1-1) 的「武器種類 × 施放方式」表，13 列 × 4 欄。
- **施放方式**照技能形狀和射程自動判斷，不新增欄位：

| 施放方式 | 判斷 |
|---|---|
| 近身接觸 | 單體、錐形、十字等，射程 1 |
| 飛行物、遠程 | 單體、直線、連鎖，射程 2 以上 |
| 自身、範圍 | 自身、周圍、環、己方範圍 |
| 地面 | 指定地格、方陣 |

- 起手不看物理或法術；元素只換特效顏色；表上沒有的組合退回「空手」那一列。
- 技能有蓄力、延遲（`timing`、`activation`）時，詠唱或蓄力加長；延遲技能先播目標頭上的標記，到時候再播效果。

## 4. 6N-4：受擊與結果

| 片段 | 觸發（事件） | 做法 |
|---|---|---|
| 受擊 | `damage_dealt` | 白閃 0.1 秒（6M-4 已有剪影閃），後仰、退半步再回來；扣血 ≥ 最大 HP 的 25% 時多一點震動 |
| 閃避 | `attack_rolled` 的 `hit: false` | 側身一跳、殘影 |
| 格擋 | `damage_dealt` 的 `block_permille < 1000` | 舉盾或橫劍、火花、退一小步。沒有盾、沒有武器時用手臂擋 |
| 倒下 | `unit_downed` | 膝蓋一軟、側倒，接到現有的倒地圖示 |
| 復活 | 倒地者被 `revive` | 從倒地站起，一圈綠光 |
| 勝利 | `battle_ended`（我方勝） | 全隊舉手或收刀，浮出「勝利」 |
| 冰面滑倒 | `unit_slid`、滑倒的檢定失敗 | 照設計 #123（使用者決定「滑倒並滑行」）：第一格冰上踉蹌，連續滑行到停點倒下；腳下冰花。一格都沒滑時就地倒下。沿用 `walkAnim.ts` 現有的滑倒判斷（11-04 更正） |
| 陷阱夾住 | 踩到陷阱的事件 | 夾子合起來、停頓 0.4 秒、傷害數字、定身圖示（戰鬥 D 版第 5 張的動畫版） |

- 異形用通用片段的受擊和倒下（6M-2 已有），閃避、格擋退回受擊的輕版。
- **檢查清單**：
  - [ ] 8 種片段在實戰都觸發得到，觸發條件照上表；
  - [ ] 倒下後接上現有倒地圖示，沒有跳一下；
  - [ ] 冰面滑倒照事件的滑行路徑滑到停點再倒下（倒在友軍格時才滑回最近空格）。

## 5. 6N-5：特殊結果（選項 B：特效加停頓）

| 結果 | 觸發 | 做法 |
|---|---|---|
| 暴擊 | `crit: true` | 命中時停頓約 0.1 秒，畫面震動，弧光加粗變金色，傷害數字放大、寫「暴擊」，畫面閃白一下 |

| Boss 大招 | Boss 的預告技能施放時 | 畫面四周變暗 0.3 秒 |

- 「跳過」時不停頓。
- 「暴擊」「格擋」「閃避」三個字樣照去文字化原則：之後有圖示時可換掉，現在先寫字。
- **檢查清單**：
  - [ ] 五種強化都觸發得到；
  - [ ] 一場戰鬥裡多次暴擊，每次停頓不超過 0.1 秒，總時間不明顯拖長。
