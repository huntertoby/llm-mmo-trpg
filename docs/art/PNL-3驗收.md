## 開發 PM 要美術判斷的五件事

### (1) 800×600 任務日誌要捲：**可以接受**（`review-6`）

- 實際捲的距離是 **94px**，不是 126px。126 是捲動前量的（內容 496、可視 370）；捲到底時彈窗下緣 32px 的漸隱不佔排版，內容變 464。原因和 PNL-2 驗收第 5 件事相同。
- 兩個進行中的任務各約 190px，800 的可視高 370 只放得下一張半。要擠進一屏，就得砍步驟或摘要。這兩樣都是這個面板最主要的資訊，不值得為了 800 砍。
- 外框和分頁列不動，切到線頭頁捲動會歸零，和公告板世界事件（捲 74px）同一個做法。
- 要注意的是**已完成的任務**：再加兩個已完成時，800 要捲 320px，1600（面板 720×632）也要捲 102px（`review-7`）。這就是第 2 件事。

### (2) 已完成的任務：**收成「已完成（N）」摺疊**（`review-7`）

- 看圖：已完成的卡整張淡 0.7、綠細框「已完成」，排在進行中的後面。單看一張可以，但已完成的任務會一直累積：雲嶺有 7 個任務，`quest_log` 進行中和完成的都列。累積之後，進行中的卡會被推到要捲的長頁裡。1600 才兩個已完成就要捲了。
- 建議做法：
  - 照 3.2 第 4 條「次要區塊用摺疊」，在任務日誌最後放一個摺疊「已完成（N）」，預設摺起來。展開後卡片照現在的樣子（淡 0.7）。
  - 摺疊標頭已經寫了「已完成」，卡上的綠框「已完成」標籤可以拿掉。和「分頁上已經掛的數字，頁內不再寫」是同一個道理。
  - 0 個已完成時不顯示摺疊。
- 展開後也要量進「最高那一頁」（3.2 第 8 條）。鎖高有 `cappedLock` 上限，打開時在頁內捲，外框不跳。
- 這只是排法，已完成的任務一樣看得到，不牽涉玩法規則，不用問玩法 PM。

### (3) HUD 右側追蹤列：**建議也改「剩 …」**；**要問玩法 PM**（只確認改字，不牽涉規則）（`review-8`）

- 看圖：同一條「商人欠你人情」，追蹤列寫「2 天 23 小時後到期」，面板寫鐘＋「剩 2 天 23 小時」。同一件事在兩個地方用兩種說法，玩家要對一下才知道是同一條。
- 開發擔心追蹤列沒有鐘圖示，但追蹤列的這行就排在線頭名字下面，「剩 2 天 23 小時」單獨看也是剩下的時間，不會讀成別的。字少了兩個，對寬度有限的追蹤列也比較好。
- 「剩 N 天 M 小時」是改字表 #26 已經確認的字面，這次是換一個地方用。照改字的慣例，請玩法 PM 補確認一次。追蹤列的說明卡（`trackHint`）也會跟著改。設計文件只寫「約 3 天到期」，沒有規定顯示字，所以不牽涉已寫入的規則。

### (4) 公告板其他說明字要不要套 KeepNum：**要，PNL-4 順手**（`review-9`）

- 看圖：800 實機的懸賞、時程（完整日程打開）、頭目（規則打開）、成長重閃說明，目前**沒有一處**數字被斷到行首。
- 但說明字都是內容檔的句子，改內容或換更窄的面板就會出現同樣的問題。KeepNum 只把「前一個詞＋數字」包成不斷行，看不出差別，也不佔空間。
- 建議套用到公告板與成長所有 L2／L3 的說明段落：階段說明、頭目解鎖句、挑戰規則、重閃說明。標籤、籌碼、表格欄本來就不斷行，不用套。
- 不另排段。

### (5) 任務類別一律實心標籤：**不建議；改成細框中性**（`review-10`）

- 看圖：
  - 「新手」「主線」「支線」三個都是實心金，字以外完全一樣，顏色本身分不出類別。
  - 已完成的卡淡掉之後，實心金的「支線」仍然是卡上最搶眼的東西，比綠框「已完成」還亮。
- 這套語言的規則是「狀態用實心，天數與類別用細框」：實心金表示懸賞中、可以做；類別用細框（提案 2.4，需求 2.2 `Tag` 一列）。
- 樣張把「新手」畫成實心是**樣張自己的錯**，和規則不一致，開發照樣張做沒有錯。
- 改成細框中性之後，和同一個面板裡線頭列的「個人／世界」標籤同一類。卡上唯一的金色就留給「目前步驟」，一眼找得到現在要做什麼。
- 這只是標籤樣式，類別名稱不變，不牽涉玩法，不用問玩法 PM。
