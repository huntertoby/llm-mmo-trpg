# 戰鬥畫面：現行格子版 vs D 版（樣張說明）

美術 PM，2026-11-04。

> 使用者原話（專案 PM 轉達）：「D 樣張」。
> 依據：共用筆記 `玩法PM-戰鬥拿掉格子評估.md` 的方案 D：規則照舊用格子，畫面藏起格線。

- 樣張：`battle-d.png`，畫法在 `sample/battle.html` 和 `sample/battle.js`。全部程式繪製。
- 這是示意，**不代決**。

## 畫了什麼

同一場戰鬥：
- 地點是渡口石階，和 `explore.png` 是同一個畫面；
- 我方 3 人，對上斷崖幫兩人和一隻霧狼；
- 戰鬥區是畫面中的 12×12，規則照舊用格子。

| 格 | 內容 |
|---|---|
| 1. 現行格子版 | 每格都有格線，頭上有字母標記，右側是一長條文字欄（狀態、技能、敵人、紀錄） |
| 2. D 版：待機 | 不畫格線。戰鬥區外柔和變暗，表示「這裡開打了」，探索畫面直接變成戰場，不切換場景。HUD 用版面 A 的戰鬥版：左上主角卡、上方中央行動順序、右上回合天氣、底部技能列、左下紀錄浮動提示。滑到敵人時出現去文字化的小卡 |
| 3. D 版：選移動 | 可走的格子淡淡浮出（藍色圓角、只有外緣亮）。路徑畫成曲線，殘影表示角色沿路徑平滑走過去，不是一格一格跳 |
| 4. D 版：選範圍技能 | 整個戰鬥區的格線以 10% 的亮度浮出；施放距離內更亮一點；十字命中的格子亮橘；預估傷害浮在目標頭上；技能卡是去文字化的版本 |
| 5. 加碼：2.5D 斜視角 | 同樣是 D 版待機，畫面轉 45° 斜著看，台地有厚度 |

## 斜視角要不要做（利弊）

**好處**：
- 最能擺脫「棋盤」感，看起來像真的場景；
- 高低差可以畫成真的高度（現在是每階抬高 6px 加陰影），懸崖、台地、推落一看就懂；
- 和 D 版的「格子只在需要時浮出」搭配起來，感覺最像動作 RPG。

**壞處**：
1. **全部的美術要重做或改造**：
   - 地形、物件、表面：現在是正上方加一點立面的畫法，要改成斜視角；
   - 紙娃娃的四個朝向：要改成斜向的四個方向；
   - 技能範圍圖示、組裝算式的形狀圖示也要跟著改。
   - 約 6～10 段美術加前端。
2. **遮擋**：
   - 前排的人、樹、柱子會擋到後排，要加透明或剪影（3-18 已有剪影規則，要延伸）；
   - 點選格子也比較難，要加滑鼠吸附。
3. **探索畫面也要一起斜**，否則「探索切進戰鬥」就不連續了：
   - #120 的可走動畫面、城鎮建築都要用斜視角重畫；
   - 樣張第 5 張只把戰鬥區轉過去，周圍的探索畫面沒有，所以看起來像「另一個場景」，這就是不連續的例子。
4. 小地圖、HUD 不受影響。

**我的建議**（只是意見）：
- 先做 D 的俯視版，也就是第 2～4 張。它只動前端的繪圖和演出，美術全部沿用，和 #120 的探索畫面天生連續，約 4～6 段。
- 斜視角當成之後的獨立方向，等 D 和 #120 上線、使用者實際玩過再決定。如果要做，探索和戰鬥要一起轉。

## D 俯視版要做的事（給之後排段參考）

1. 平常不畫格線；選移動、選技能時，格子用淡色圓角浮出，範圍外緣加亮線。
2. 角色沿路徑平滑移動，有轉身和走路動作；敵方回合可以快轉。
3. 戰鬥區外柔和變暗，不另外切場景（配合 #120 的就地開打）。
4. HUD 用版面 A 的戰鬥版；技能卡、單位資訊用去文字化版本（`HUD版面.md` 第二部分）。
5. 字母標記改成：滑到單位才顯示，或者只在行動順序列上顯示。
