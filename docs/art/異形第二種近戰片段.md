## 蜥蜴為什麼換做法

- 量出來的尺寸：尾巴從尾根（臀部後緣內 2 單位）到尾尖長約 25 單位；鼻尖在尾根前方約 39 單位。
- **首選（前腳撐地、後半身掀起、尾巴砸在身前地面）在 1.1 倍內構不到**：前腳撐地時臀部越抬高，尾巴越構不到地面。臀部抬到肩膀上方（身體 65～75 度）時臀高約 24～25 單位，尾巴 1.1 倍（27.4）只能往前伸 10～11 單位，落點在自己頭的位置；鼻尖還在更前面 16 單位。要讓尾根越過鼻尖，身體得翻過 90 度，這時前腳撐不住、肩膀會插進地面。
- **備案（往前躍起、身體前傾）同一個問題**：前傾不到 90 度，尾巴都在頭的後上方。
- **採用：前翻**。首選的前半（前腳撐地、後半身掀起）保留當起手，接著前腳離地、整隻往前翻到背朝下，臀部到了身體前方，尾巴順著翻轉從上方掄下來，尾尖砸在身前地面；砸完往回翻、前腳先落地、後半身落回原位。尾巴組只繞自己的支點轉、沒有位移、沒有拉長。
- 不是第 1 版的原地轉身：身體是在側面平面內翻轉（看得到背刺、肚子、四肢跟著轉），沒有紙片翻面。

## 限制與疑慮

1. **蜥蜴是前翻，不是首選的倒立**（理由見上）；動作幅度比其他四款大，整隻最高到約 69 單位（尾尖），命中時身體中心在原位前方約 15 單位。
2. 蜥蜴命中姿勢在空中停 2 格（500、583）；沒有看實際播放，停格會不會顯得懸空要看動態。
3. 蜥蜴 333 那格頭朝下、鼻尖離地約 8，四肢縮在肚子側，單看這格像倒栽；它是翻轉的過場。
4. 熊的爪、石板處理仍只在正常模式（同第 2 版）；開發移植要帶 `kfN`、`plant`、`ptOf`、`sweep`、`TAILOVER`。
5. 樣張頁的 `frameOf` 在 t 剛好等於格邊界（例如 583.33）時會因浮點誤差取到前一格；這次拍圖都用格內的時間（每格起點＋0.5 ms），檔名仍用整數毫秒。既有的 `?atlas=` 與舊 gif 有這個重複格，這次沒有改 `frameOf`。
6. 其他四款的 `q-creature-<身形>.gif` 還沒有加第二種近戰片段（這次只重出山豹）。

## 實際可用的指令（Windows，Git Bash）

```bash
"/c/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --disable-gpu --mute-audio --no-first-run \
  --allow-file-access-from-files --user-data-dir=<scratchpad>/chrome-profile --virtual-time-budget=20000 \
  --enable-logging=stderr --v=0 --dump-dom "file:///<scratchpad>/shoot.html?mode=close&b=lizard" > dump.html 2> chrome.err
grep -a CONSOLE chrome.err
uv run --no-project python -I docs/art/sample/tools/closeups_save.py dump.html docs/art/closeup/melee2
```

暫存頁 `shoot.html`（不進 repo）載入 `sample/qCreature.js`、`qCreatureAnim.js`，把每張畫布轉成 `<pre data-file="檔名">data:image/png…</pre>`（`pre` 不能有其他屬性，否則 `closeups_save.py` 對不到）。模式：`close` 特寫、`strip` 並排、`all` 一款全部片段、`atlas` gif 用的格、`hash` 逐格像素雜湊、`num` 量部件座標。gif 用 `ffmpeg -framerate 25/7 -i gif-%03d.png`（加 `palettegen`／`paletteuse`）。
