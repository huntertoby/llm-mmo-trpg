## 和現有片段差在哪（看連拍）

- **hound**：現有雙咬是原地前探、快咬兩下。新的先蹲、騰空撲一大段（衝到目標前），咬住後頭一上一下甩，再退回。
- **feline**：現有爪擊身體幾乎水平、爪從上往下。新的先壓到肚子貼地，再人立斜起，爪由下往上。
- **bear**：現有熊掌拍上身只抬一點。新的上身立起約 50 度、一掌舉過頭，停兩格後重拍到地面，節奏慢→快。

## 自查

| 項目 | 結果 |
|---|---|
| 關節方向 | 腿只繞肩、髖轉；前腳往前上舉、後腳往後撐；沒有反折。 |
| 腳穿地 | 踩地的腳用 `plant` 由髖的位置反推，腳底落在地面（各圖都沒穿地）；出手的前腳離地。 |
| 身體斷開 | 沒有。熊、豹舉手時手臂根部被頭蓋住，看起來是連在肩上。 |
| 部件跑位 | 第一輪發現：山豹的 `spots` 斑點掛在頭部組（`qCreature.js` 的 `LAST` 機制），頭轉太大時斑點會飛出身體。改成豹的頭只小幅轉（0.16 以內），靠身體人立把頭抬開；最終圖沒有斑點跑位。 |
| 命中朝向 | 每格命中都朝目標方向。蜥蜴是尾巴朝目標、頭背對，符合轉身甩尾。 |
| 特效出發點 | 咬合在鼻尖並跟著頭甩，爪痕在爪前方，星爆在獠牙／鼻吻／尾尖。 |
| 收尾 | 首格與末格像素完全相同（5 款都 0 差異）；犬、熊、豬、蜥的首格等於靜態姿勢。 |
| 確定性 | 只用 `u` 的純函式；同格畫兩次像素相同。 |
| 減少動態 | 沿用既有路徑（身體不動、只前推 2 單位、特效照放），5 款每格都符合。 |
| console | 片段頁 `?t=0`（自測 6/6）、`?view=strip`、5 款 `?atlas=`、單格 `?b=…&reduce=1` 都沒有 console 訊息或錯誤。 |

## 限制與疑慮

1. **犬狼的甩頭在畫面上是上下擺**：異形只有側面，真正的左右甩看不到，所以畫成頭上下擺＋身體反向小晃。12 格／秒下一格一個方向，共 2 個半來回，想再慢就得加長片段。
2. **蜥蜴轉身**是身體左右壓成一半再翻面，沒有正面圖，轉到一半的兩格（t=250、333）身體是壓窄的側面。
3. **前腳畫在頭後面**（`qCreature.js` 的繪製順序），所以熊舉掌只露出前臂上半和掌，手臂拉長 1.4 倍、加粗 1.35 倍才看得到；山豹的爪只撩到下巴高度，再高就被頭蓋住。
4. **山豹首格**和靜態差 72 個像素，現有爪擊的首格也一樣（只要有姿勢就會出現），不是這次造成的。
5. **`spots` 掛頭部組**是 `qCreature.js` 既有的問題，這次沒動；之後如果頭要大幅轉動，要先修。
6. 碎石（豬）與星爆（蜥）淡出時外框會變黑色，所以提早結束，不會有黑塊殘留。
7. 開發移植時要帶上 `kfN`、`plant` 兩個輔助函式。
