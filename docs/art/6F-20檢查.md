## 2. 開發 PM 問的 4 題：決定

1. **決定 X 只做到 1600 寬**：選 **(a) 維持現狀**。1040、800 寬照舊只留「+2」。
   - 理由：窄畫面上一個狀態圖示只剩 7～8px，留一個圖示本來就難辨認；點一下單位會開精簡小卡，狀態都列在上面，觸控也看得到。不放寬「超出格子 ≤ 6」和「隔 3px」，那兩條是防重疊的底線。
   - (b) 疊成角標會壓到圖示本身，不採用。
   - 這條算 X 的補充：「1 個圖示＋『+1』」只在放得下的寬度用，放不下就「+2」。
2. **800 寬的「+」貼近金框**：照收。讀得出是「+2」，總寬不變比較重要。
3. **預覽框自動捲動**：照收。動作名稱被捲出去沒關係：底部列和右下按鈕都標著目前的動作（「普攻」高亮）。不縮短說明文字。
4. **其他地方的英文「Boss」**：同意一起改成「**頭目**」，包含佈告欄「賽季 Boss」、預覽文字、開發選單「5 場戰鬥加 Boss」、開發標題列的「Boss 戰（開發）」。介面文字一律繁體中文。下一段順手做，不用再拍圖。程式識別字（`boss`、`rank` 等）不動。
