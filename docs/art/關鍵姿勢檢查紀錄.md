### 第 2 項：手臂張開的開關（只給比較圖用）

- `qDoll.js` 新增一個集中的開關 `ARM_SPREAD_SET`，每一組有五個參數：
  - `a`：手臂往外的角度；
  - `dx`：肩膀往外移多少；
  - `tilt`：法杖、長柄往外傾多少；
  - `robe`：穿長袍時手臂多往外的角度（跟著長袍邊平行）；
  - `hold`：持單手武器的手多往外一點。
- 三組的值：
  - A＝第 16 版：`a 0.7`，其他都是 0；
  - B：`a 0.375, dx 3.93, tilt 0.27, robe 0.11, hold 0`；
  - C：`a 0.05, dx 3.93, tilt 0.33, robe 0.11, hold 0.18`。
- 只有在 `qDoll.js` 載入前設了 `window.QDOLL_ARM_SPREAD`，才會用 B 或 C；其他頁都沒設，一律是 A。A 的每個算式都退回第 16 版的數值，所以其他特寫逐位元組不變。
- 肩膀外移（`dx`）時，在 `arm()` 裡畫一塊同色的斜肩，把肩頭接回軀幹，所以縫從腋下才開始。只有往外張的手臂會跟著外移；拳套、兩手握的武器照舊。
- 杖、柄往外傾（`tilt`）時，握點照傾角補回，杖尾仍在地面線；桿子在拳頭以上往外離開手臂，光暈也離開頭。
- 法杖正面、背面的握點照手高差補回（`OH16`）。用 A 時差值是 0。
- 第 3 項預覽：`window.QDOLL_SHIELD_CENTER` 設了，背面的盾心才會對準左拳；沒設時照第 16 版。只有比較圖會設。
- 比較圖產生頁 `sample/tools/arm-spread-compare.html`：
  - `qDoll.js` 載入三次，得到 A、B、C 三份。
  - 每格先畫在和 `closeups.html` 同大小的畫布上（K 3.4、放大 3 倍、720×700），再貼到大圖上。
  - 存檔方式和特寫一樣（`--dump-dom` 加 `closeups_save.py`）。

  - 肩膀比 A 寬，斜肩接回軀幹。手臂從腋下往外下方斜伸，和軀幹之間從腋下就有背景色，往下越來越寬，手臂中段量到 24px。

  - 肩膀和 B 一樣寬，兩隻手臂幾乎直垂、和軀幹平行。從腋下到拳頭，手臂和軀幹的外框之間一路有一條細背景色縫，手臂中段量到 2～3px。

## 七、要美術 PM 決定

1. **B 欄是 A 和 C 的中間，不是角度減半。** 肩膀和 C 一樣外移，角度取 A 和 C 的中間（0.375）。角度減半、肩膀不動時，手臂幾乎貼身，和 C 分不出來。
2. **C 欄的肩膀比第 16 版寬。**
   - 要讓縫從腋下一路到拳頭，肩膀得往外移 3.93 單位，再用斜肩接回軀幹。
   - 從正面、背面看，人變得比較寬肩。這是全程留縫的代價，要不要接受請決定。
3. **縫寬不是每一列都在 2～4px。**
   - C 欄大部分在 2～4px：腋下第一列只有 1px，腋下稍下和腰的一兩列 5～6px。原因是軀幹的圓角和長袍斜邊。
   - 持劍手為了不讓護手壓進軀幹，多往外一點（`hold`），縫在拳頭附近比較寬。
4. **B 批套用時，還要一起處理這幾件事（這批照規定沒動）：**
   - 法杖、長槍往外傾以後，桿尾會斜到腳邊；
   - 杖＋書背面的書會碰到長袍；
   - 劍盾正面、背面的盾會碰到或蓋到軀幹。
5. **其他文件裡還有這個詞。** `武器待機移植需求.md`、`Q版回歸評估.md` 和舊版修正清單裡還有第二種雙手劍姿勢的字樣，這批沒碰（不在 A 批要改的清單裡）。其中 `武器待機移植需求.md` 寫的是「使用者定案：不做」，意思和這批一致。
