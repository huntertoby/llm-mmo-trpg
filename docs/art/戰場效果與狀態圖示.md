## 1. 現況的問題

| # | 問題 |

## 2. 提案

### 2.1 狀態圖示規則（③）

| 看哪裡 | 由哪個欄位決定 | 規則 |
|---|---|---|
| 外框形狀＋框色 | `polarity` | buff＝綠色圓形、debuff＝紅色圓角方形、neutral（含姿態）＝金色六角形。不認得或沒填 → neutral。 |
| 圖樣顏色 | `control_group` → `on_turn_start_damage.element` → `polarity` | 硬控黃 `#ffd84a`、移動控制藍 `#6ac8ff`、心智控制紫 `#c890ff`；持續傷害用元素色；其餘依 polarity（守護、護盾、再生、不死等保留原本的專屬色）。 |
| 圖樣 | 狀態 ID 查表 | 一個狀態一個圖樣。四組重複改為：監視＝狙擊鏡、被揭露＝睜眼加放射線；守護＝盾、護衛＝盾＋↓、護盾＝泡泡；強化＝雙箭頭↑、戰意＝戰旗；狂怒姿態＝爪痕、堅壁姿態＝城垛。不認得 → 外框照 polarity，中間畫名稱第一個字。 |
| 戰場：頭頂狀態列 | 排序 | 格子上緣一排 14px，最多 3 個；超過時顯示 2 個＋「+N」。順序：硬控 → 移動／心智控制 → 持續傷害 → 其他減益 → 增益 → 中性，同一級依 ID 排（確定性）。 |
| 戰場：身上特效 | 欄位，不寫死 ID | 只有 5 類：`skip_turn`＋`removed_by_element` 含 fire＝冰塊罩全身；其他 `skip_turn`＝頭上轉圈星星；`absorbs_damage`＝淡藍泡泡；`prevents_move`＝腳下藤蔓；`on_turn_start_damage`＝腳邊元素粒子（最多 2 種）。另外 `concealed` 的單位畫成半透明。 |

### 2.2 戰場效果（②）

| 項目 | 由哪個欄位決定 | 規則 |
|---|---|---|
| 煙霧、黑暗 | 表面的 `blocks_sight` | 除了地面那層，**在單位之上**多畫一層半透明霧（黑暗是紫黑色＋紫色光點），蓋住單位下半身。新的擋視線表面自動套用（顏色預設灰）。 |
| 冰牆 | 物件 `expiresIn`、`hpRatio` | 有高度的冰晶塊（擋視線）；剩 1 回合時變矮、變透明、底下出現水窪與水滴。 |
| 荊棘叢 | `expiresIn` | 暗色底＋交纏藤蔓＋白刺＋小紅花；剩 1 回合時枯成褐色、刺變少。 |
| 倒塌物 | — | 一堆有外框的大石塊（看得出「擋路、可躲」），不再像地面碎石。 |
| 薄冰 | `hpRatio` | 冰板下看得到冰窟的暗影；裂痕隨 HP 增加，≤ 33% 時露出黑水破洞。 |
| 物件受損（通用） | `hpRatio` | 所有可破壞物件：≤ 66% 一道細裂、≤ 33% 三道粗裂。 |
| 剩餘回合徽章（通用） | `expiresIn`／區域與陷阱的剩餘回合 | 黑底圓形白字；**最後 1 回合改橘色**。取代現在右上角的白字。 |
| 陷阱 | 陣營、技能的 `trap.trigger`、技能元素、`remaining` | 地上一個圓形踏板。外圈＝陣營色（我方藍實線、被揭露的敵方紅虛線＋「!」）；中間＝元素色的捕獸夾（`enter` 踩到觸發）或沙漏（`delay` 倒數，加剩餘回合徽章）。沒被揭露的敵方陷阱不畫（同現況）。不認得的元素 → 灰色。 |
| 持續區域 | 區域格子、`affects`、元素（或 `surface`）、`anchor`、剩餘回合 | 整塊只描**外框**（鄰格同區域的邊不畫）。**對看的人有害**（會打到我方）＝實線＋斜紋；**有益**＝虛線＋光點。`moving`＝前進方向那側外框上畫三角箭頭；`caster`＝施放者腳下一圈虛線環。剩餘回合徽章在最左上那格。不認得的元素 → 灰色。 |

## 4. 移植需求（使用者選定後交開發 PM；以下依全部選 A 撰寫）

畫法以 `docs/art/sample/fx.js` 為準（Canvas 2D，52px 虛擬格，可直接移植成 TS，比照 3-16a 的 `terrainArt`／`objectArt` 做法）。建議拆兩段：

### 段 1：狀態圖示（③）

1. `render/skillParts.ts` 的 `STATUS` 表：圖樣與顏色改用 `fx.js` 的 `GLYPH`、`glyphColor()`；外框改由 `polarity` 決定（`framePath()`）。**外框只用在狀態圖示本身**（狀態列、頭頂列、資訊欄）；技能圖示的組裝部件維持原本的圓形部件框。
2. `polarity`、`control_group`、`on_turn_start_damage.element`、`skip_turn`、`removed_by_element`、`absorbs_damage`、`prevents_move` 需要前端拿得到：若 glossary API 的 statuses 沒有這些欄位，請補（只讀內容資料，不影響引擎）。**不要在前端寫死狀態 ID 清單**（圖樣查表除外；不認得的走預設）。
3. 頭頂狀態列：`unitSprite` 在格子上緣（圖示中心約在格子頂端 +1px）畫 14px 圖示列，規則見 2.1；和現有的定時炸彈、蓄力、灌注徽章不衝突（那些在左右兩側，仍保留）。倒下的單位不畫。
4. 身上特效 5 類：見 `fx.js` 的 `bodyUnder()`（腳下，畫在單位前）與 `bodyOver()`（畫在單位後）；暈眩的星星可以慢慢轉（有動畫時），沒有動畫時靜止也可以。`concealed` 的單位 alpha 0.55。
5. 測試：32 個狀態＋不認得的 ID／polarity／空字串都畫得出來、不丟例外；排序與輸入順序無關；0 個、33 個狀態不出錯（比照樣張頁的自測）。

### 段 2：戰場效果（②）

1. `objectArt.ts`：`ice_wall`、`thorn_wall`、`rubble`、`thin_ice` 換成 `fx.js` 的畫法；繪圖規格（`ObjectArtSpec`）加入 `turnsLeft`（取自 `expiresIn`）與 `hpStage`（0：> 66%、1：≤ 66%、2：≤ 33%，**用級距進快取鍵，不要用原始比例**）。
2. 通用受損裂痕：所有 `hpRatio !== null` 的物件依 `hpStage` 疊 `cracks()`。
3. 剩餘回合徽章：`BattleRenderer.objectSprite` 的白字改成 `turnsBadge()`（最後 1 回合橘色）；區域、陷阱共用。
4. 擋視線表面的上層霧：`blocks_sight` 表面在該列的單位層之後畫 `sightVeil()`（建議放在 `rowLayers` 新增的一層，跟著格子抬高）。表面的 `blocks_sight` 前端若拿不到，請補進 glossary。
5. 陷阱：`TrapDraw` 需要 `team`、`trigger`（`enter`／`delay`）、`element`、`remaining`。API 的 `TrapView` 目前只有 `skill_id`、`remaining`、`team`：trigger 與元素可由前端技能表查 `skill_id`，查不到就退回 `enter`＋灰色。畫在 `traps` 層（單位之下）。
6. 持續區域：`drawZones` 改為整個區域一起畫（同一 zone id 的格子一組），外框只描外緣；有害／有益依「`affects` 對**目前玩家陣營**是否有害」判斷（enemies 且施放者是敵方、或 all 且有傷害效果＝有害；allies 且施放者是我方＝有益）；元素取區域效果的元素，沒有時用 `surface` 的顏色，再沒有用灰。`caster` 的虛線環畫在施放者腳下。
7. 測試：所有物件、表面、陷阱、區域的未知值（新物件、新表面、未知元素、未知 trigger）都不出錯，退回灰色預設。
