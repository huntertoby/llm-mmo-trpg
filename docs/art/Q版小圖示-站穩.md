## 0. 資料與框

- `content/statuses.yaml`：`polarity: neutral`、沒有 `control_group` → **中性金色六角框、深底、不染類別底色**；圖樣在狀態卡 20 與頭頂 11 都是 tiny（≤14px：一個主體、不包外框）。`beneficial: true`、`mechanic_only: true`（技能不會施加，只有站起來時給）。
- 說明：剛站起來，任何來源都不會讓你倒地；冰面照樣會滑、滑完不倒地；到自己下一個回合結束。→ 題材是「站得穩、不會被撂倒」，**照常可以移動**，所以不能像定身（被釘住）或緩速、纏繞（移動受限）。

## 2. 推薦：方案 B（張腳站穩的人形）

1. **和倒地是一對**：倒地＝米白人形趴平、站穩＝米白人形站直張腳，都踩在地面線上；玩家剛從倒地站起來就拿到站穩，兩個圖示前後出現，一看就懂「從躺著變成站穩」。框也不同（倒地紅圓角方、站穩金六角）。
2. **不碰「移動」的語言**：A、C 的靴子在 HUD「移動」、條件「移動過」、觸發「移動時」、纏繞都出現過；站穩不是移動加成也不是移動限制，用靴子會被讀成移動相關。C 的錨還會讀成「被釘住」（定身），和說明相反。
3. **剪影獨一無二**：剪影排（`steady-3-near.png` 第 4 排）裡只有 B 是全身直立人形；石膚、應變是半身。
4. 亮度最高（v2：223、亮面 100%），在深底六角框裡最醒目。

**仍不好認**（照 v2 最終圖）：頭頂 11 真 1 倍只看得出「站著的一個小人」，叉腰的手肘洞變成兩個暗點、腳不分開；和應變在頭頂 11 都是金六角裡一團米白，靠應變的紅點與站穩底下的沙色橫線分。v2 的沙色地面線和米白的腳色相近、沒有外框（tiny 不包），20 真 1 倍腳和地面線黏成一條淺色下緣。地面線變寬變粗後 `fitK` 從 0.80／0.74 降到 0.74／0.70，人形比第 1 版小一點。`!o.tiny` 的亮面細節（頭上白點、身體右側暗面）在 20、11 都不會畫，只在開發頁 52px 這類大尺寸出現。

## 3. 移植需求（給開發 PM）

照 `Q版小圖示-狀態移植需求.md` 的做法（新條目排在表最後、同一套 `paint()`／`fitK`／`blit`）。來源：`docs/art/sample/qIconsSteady.js` 的 `standWide`（`PICK = "steady_b"`；`install()` 掛成 `QIconsStatus.NEW.steady`）。

1. **`client/src/render/qIcon/status.ts` 的 `NEW` 最後加一筆**（`kind` 由 `entry()` 自動判成 `"new"`、`src` 為 `"new"`；用到的 `rr`、`ln`、`ci`、`el`、`f`、`CREAM` 檔裡都已經有）：

   ```ts
   // KD-1：站穩（docs/art/Q版小圖示-站穩.md 方案 B v2；樣張 qIconsSteady.js 的 standWide 原樣）
   steady: { zh: "站穩", topic: "米白人形兩腳張開成「人」字、雙手叉腰，腳踩一道寬沙色地面線（倒地的反面：站直）", d: (c, o) => {
     rr(c, "#e0c088", -9.8, 8.2, 19.6, 3, 1.5);
     for (const s of [-1, 1]) { ln(c, CREAM, 3.6, [[s * 1.8, 1.6], [s * 5.6, 7.6]]); rr(c, CREAM, s > 0 ? 4.2 : -8.8, 6.6, 4.6, 2.6, 1.3); }
     for (const s of [-1, 1]) ln(c, CREAM, 2.6, [[s * 3.2, -2.6], [s * 7, -0.2], [s * 3.6, 2.2]]);
     rr(c, CREAM, -4.2, -3.8, 8.4, 6.8, 2.8);
     ci(c, CREAM, 0, -7.2, 3.6);
     if (!o.tiny) { el(c, "#ffffff", -1.2, -8.4, 1.4, 0.9, -0.6); f(c, "rgba(0,0,0,0.12)", () => c.rect(1.6, -3.4, 2.4, 6.2)); } } },
   ```

   - topic：「米白人形兩腳張開成「人」字、雙手叉腰，腳踩一道寬沙色地面線（倒地的反面：站直）」。
   - 配色：人形 `CREAM #f2e6c8`（同倒地、應變的米白人形）、地面線沙色 `#e0c088`（v2；同方案 A 的地面線、HUD「移動」靴子的靴口色）、亮面白、暗面黑 12%。
2. **`AWAITING_ART_STATUSES` 拿掉 `"steady"`**（變成空陣列；之後新狀態等圖時再用）。這幾個測試靠它過濾，拿掉後 steady 會進各自的基準／計數，照各測試的做法更新：`render/qi2cStatusUnchanged.test.ts`、`render/qi3bWiring.test.ts`、`render/qi4aStatusTile.test.ts`、`render/qIcon/qIconStatus.test.ts`、`render/skillIcon.test.ts`（100 行）。
3. **`statusFit.json` 重產**（開發頁 `?set=fitgen`，不手改）。樣張量到的值（`--audit`，軟體繪製）：`steady|16.80|0.00` → **0.74**、`steady|9.00|0.00` → **0.70**（v2；第 1 版是 0.80／0.74）；沒有類別底色，不會有 inset ＞0 的鍵。遊戲端量出來應該相同，不同請列原因。
4. **`skillIcon.test.ts` 的部件庫檢查**（`KNOWN_PARTS.statuses`，技能組裝列的狀態部件圓片）：steady 是 `mechanic_only`、技能不會施加，部件圓片要不要也收這一筆：**待開發查證**。若要收，照第 5 批移植需求 3.3 第 13 點「同一個題材在部件圓片與狀態框呼叫同一份畫法」，部件圓片直接呼叫上面這一份，不另畫。
5. **驗收截圖**（照狀態移植需求第 5 節）：steady 的狀態卡 20、頭頂 11，真 1 倍與 DPR 2 各 ×6 最近鄰，和本文 `steady-2-true1x.png` 的 B 欄逐像素對照（`cardCanvas`／`headCanvas`，同 `res`）；實機一張剛站起來的主角（HUD 狀態列＋頭頂），1600 寬。
6. 後端不用動；玩法 PM 不用決定。

## 5. 自查紀錄

- `steady_shots.py --audit`：A、B、C 三個都過（佔框 ≥70%、出框 ≤1%、平均亮度 ≥100、亮面 ≥5%、最粗處 ≥12%；量法同 `q-icons-status.html?part=audit`）。B 第 1 稿地面線寬 21.2 單位，撞到六角框的斜下緣，`fitK` 只到 0.74／0.70（頭頂碰到下限）；第 2 稿地面線縮成 18、兩腳收進一點，`fitK` 升到 0.80／0.74（第 1 版交件）。v2 地面線照美術 PM 改成沙色、寬 19.6、粗 3，下緣到 11.2 單位，`fitK` 回到 0.74／0.70（頭頂碰到下限 0.70，出框 0.5% 仍 ≤1%）；亮度 213 → 223、亮面 84% → 100%，其他項照樣過。
- 沒有改任何既有檔（`qIconsStatus.js`、第 5 批樣張頁、`qicons_shots.py` 都沒動），所以既有指紋不受影響。
- 三張截圖都用 Read 看過最終版；真 1 倍與最近鄰放大都在 canvas 裡用 `imageSmoothingEnabled = false` 放大、直接輸出 PNG（真最近鄰，不經過瀏覽器縮放）。
