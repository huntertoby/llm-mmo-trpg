## 2. 共用規矩

### 2.1 Q 版的畫法語言

- **剪影外框**：整個圖樣外面包一圈，色 `#16121a`（人物同色）。做法是「先畫色塊，再把剪影往外長一圈墊在底下」（`QIcons.render`、`QDoll.stamp` 都是），不是逐筆描邊。不描內線、不排線。
- **平塗三階**：每個零件最多本色、一階亮面（白 45%～80% 的細條或小橢圓，放左上）、一階暗面（黑 22% 或材質暗色，放右下）。
- **光暈**只給會發光的東西（元素球、火、魔導），畫在外框底下（`def.pre`），不包外框。閃光、深色弦線這類要壓在最上面的畫在 `def.post`。
- **前後重疊的兩件**（交叉的兩把劍、壓在盾上的星）：後畫的那件用 `halo()` 自己再包一圈。
- **粗短、圓角**；直角用 `poly(…, round)` 磨圓。

### 2.2 配色來源（不要自己調色）

- 材質色照人物：`paperdoll.js` 的 `MATERIAL`／`qIcons.js` 的 `M`。人物沒有的材質（銅、銀、晶石）用現行裝備圖示的色（`gearArt.js` 的 `MATERIAL`）。
- 元素色照 `client/src/render/palette.ts`（`qIcons.js` 的 `EL`）。
- 人物手上那件有什麼零件、什麼顏色，圖示就有同樣的零件與顏色，只加粗。和人物不同的地方寫在畫法檔的註解，也寫進紀錄檔。

### 2.3 圖示畫法規則 14 條（精簡版；全文在 `Q版小圖示樣張.md` 第 2 節）

1. 外框粗細＝顯示邊長的 5%，最細 1px、最粗 1.6px。
2. 平塗、每個零件最多三階；光暈在外框底下。
3. 加粗上限：劍、匕首刃寬 ≤ 全長 1/4；短柄 ≤ 1/8；長柄 ≤ 1/12 且 20px 時不細於 1.2px（48 格裡約 2.9 單位）。頭可以放大，柄不跟著粗。
4. 配色、零件和人物一致。
5. 元素用「主色＋亮色＋白芯」三層。
6. 深底上（裝備格、技能底、狀態框、事件卡圓）圖樣平均亮度 ≥100，亮度 ≥150 的亮面 ≥5%；暗色零件換亮一階的同類色。
7. 佔框：塊狀或直立 ≥70%，45° 斜放的長條 ≥60%；留白先讓給外框，不縮主形。武器在米色圓章裡，分母用圓章框線以內的直徑（44/48）。
8. ≤24px 省小零件；≤14px 只留一個主體、不包外框。大小兩種是同一個題材。
9. ≤24px 的人形畫成單色剪影（米白），不畫五官。
10. 抽象概念可以用符號，但要粗外形（線寬 ≥12%）加亮面。
11. 同類之間先改剪影、再改顏色，不能只換色。
12. 方向照現行慣例；斜放的武器不超過圓章。
13. 框不動（稀有度框、米色圓章、裝備格、狀態框、事件卡圓環、功能列圓底），只換框裡的圖。
14. 技能主圖＝道具＋動作。

### 2.4 武器的方向

- **人物手上**：握把在手（原點）、作用端朝 −y，再由手決定角度。
- **圖示**：長條武器握把在左下、作用端在右上（45°）。畫在「握把 +y、作用端 −y」的直立座標，用 `QIcons.W.diag()` 轉 45°。
- 長槍、霰彈槍：畫在「槍口 +x、上方 −y」，轉 −45°（槍口朝右上）。手槍只斜 −0.42 弧度。
- 拳套、盾、書、法器珠直立。成對武器兩把交叉成 X、握把在下。
- 斧刃、鐮刃在直立座標的 +x 側（轉完在右下），和人物側面同一邊。

### 2.6 防具飾品（第 2 批學到的）

- **先讀人物身上那一件怎麼畫**（`qDoll.js` 的 `body()`、`Q_headgear()`、`leg()`、`handFormOver()`），零件與配色照抄再加粗；人物不分的形制靠「誇大一個零件」分開（護肩、毛尾巴、翻口、刺輪），並寫進紀錄的「和人物不一致」。
- **皮色 `#8a5a32` 的亮度剛好 100**，整件皮製品只要有深色背帶、腰帶就不到規則 6。做法：加淺皮色的翻口、滾邊（主色混 42% `#ffe6b8`）與金扣，本色不動。太暗的染色（亮度 < 105）**照顏色判斷怎麼換亮、不照染色名稱**（`qIconsArmor.js` 的 `tone()`）：近黑（亮度 < 70 且彩度 < 40）保留深色，是規則 6 的例外，靠原有的淺色滾邊、翻口、金扣；彩度高的深色（紅、藍、紫，彩度 ≥ 90）三個色版同乘 1.09、只提高明度、不混白；彩度低的深色（褐）混 15% 白。改完用 `--audit armor` 把全部材質、染色、元素變體一起量，不要只量預設（黑染在自查表另列例外欄，不套平均亮度，其餘各項照常）。
- **有一個大洞的東西（兜帽的臉洞）**：洞不要塗全黑（用暗色的亮一階），洞口不要畫一圈粗的淺色邊（像甜甜圈、馬蹄鐵），用細的同色亮邊；洞開到下襬變成拱門形比閉合的橢圓像兜帽。
- **中空的環（戒指、臂環）**：用 `destination-out` 真的挖洞，看得到格底；斜著看、畫出內壁與朝前的緣才不是一個幾何圓圈。戒指立著、臂環橫躺，兩個才分得開。
- **容易畫成別的東西的組合**：圓頂＋波浪白邊＋頂上一顆球＝杯子蛋糕；看得到筒口的錐形筒＝水桶；圓＋一個尖＋一個點＝鳥頭；圓上兩個點加一條直線＝臉；盾形＋十字＝盾（全罩盔撞鳶盾）。畫完每款問一次「不看名稱像什麼」。
- **撞圖要和別批排在一起**：樣張頁 B 的最下面放「圓的、長方的、手形的、尖的」四組，把第 1 批同樣大結構的拿來並排（含剪影）。
- **樣張頁太高時加 `&sub=`／`&group=` 分段**：Read 看 1100px 以上的圖會縮小；總表、變體表各切成幾段拍到暫存資料夾看，正式截圖仍拍整張。
- **變體表一列放不下**（9 個染色 × 兩種尺寸）會被頁面右邊切掉而且不報錯：整頁圖縮小後看不出來，要分段看；超過 6 個變體的列只放一種尺寸。

### 2.7 技能主圖（第 3 批學到的）

- **先寫推導規則與統計腳本，再畫**：技能有四百招，圖是「內容欄位 → 道具、出手、記號」算出來的。先用腳本看每個道具、記號各有幾招、最大的同圖群是誰，再決定要畫哪些；樣張頁讀腳本匯出的資料檔，不在頁面裡另寫一份規則。
- **一張圖三層**：道具（包外框）、出手線（畫在 `pre`、不包外框、用元素底的亮色）、效果記號（實心粗外形，自己用 `halo()` 再包一圈壓在道具上）。對目標的記號放右上（武器的作用端），對自己的放左下，道具往對角讓開。
- **道具一律量外接框再擺**（`qIconsSkills.js` 的 `boxOf()`）：把外接框長邊縮放到指定單位、外接框中心放到指定位置。不要用「以 24,24 為中心乘一個倍率」——每個道具原本的大小、重心都不同，會貼格邊或佔框不到 70%。
- **記號要是實心的粗外形**：箭頭、十字、鎖、骷髏、星。線條畫的（兩道斜線、圓環加十字）在 24px 會糊。自查量「最粗處內切圓直徑 ≥ 顯示邊長 12%」。
- **容易讀成別的東西**：紅色粗叉＝「不能用」；兩顆並排的圓頭長條＝藥丸，兩片兩頭尖的＝葉子；一灘加兩顆圓泡＝老鼠頭、青蛙；圓環加四芒星會和紅準星撞；鋸齒圈＝齒輪、鋸片；捕獸夾中間加一顆紅點＝怪獸的眼睛；殘影沿著道具自己的長軸退會整個被道具蓋住（要往旁邊退）。
- **不要畫兩次同一件事**：火焰道具＋燃燒記號是兩團火（改成只畫大一號的道具）；道具已經是召喚物就不再畫召喚記號。沒有武器也沒有元素的法術不要硬塞一顆「通用晶石」，把記號放大當主圖。
- **頁尾量高度時字型可能還沒載入**：格子很多的版面（實例總表）把標題列的高度寫死，不然截圖會少最後一排。
- **截圖檔名太長會存不出來而且不報錯**：`--query` 很長時（`only=` 列十幾個）拆成幾次拍。
- **套用現行 client CSS 的情境圖**：`.battle-screen` 會撐滿視窗，照 `q-icons.html` 在 `.qi-scene` 底下蓋掉高度。

### 2.8 徽章、小圓片、卡片小圖（第 4 批學到的）

- **現行那一欄用遊戲端原始程式打包**：樣張端的舊版（`parts.js`、`assembled.js`）會落後遊戲端。寫一個進入點 import 要的函式掛到 `window`，用主資料夾 `client/node_modules` 的 vite 以 lib 模式打包成 IIFE（`minify: false`；沒用到卻被牽進來的套件如 `pixi.js` 設成 external），產物放 `tools/`、檔頭註明自動產生。資料（名詞表、每招的圖示資料）用後端自己的函式匯出，不要手抄。只存在 React 元件裡的 SVG 才原樣抄進頁面。
- **先算圖樣本身有幾 px**：圓片裡的圖只佔直徑的 78%，18px 的小圓片裡圖樣是 12px、56px 圖示角落的圓片裡是 10px，都在「≤14px 只留一個主體、不包外框」那一級。簡化程度照圖樣本身的大小給（`def(cat, id, 圖樣px)`），不要照圓片的大小。
- **沿用上一批的記號，直接呼叫**：這批的座標和第 3 批的效果記號一樣（原點為中心、半徑約 10），`QS.ACT[x].d` 直接當圖樣；畫在 48 格的（風格樣張的狀態、HUD、元素道具）包一層 `from48()` 縮進來。同一個題材在徽章、圓片、卡片、HUD 用同一個形，寫在清單的 `src`。
- **深色圓片上的「主圖＋右上小圖」**（修正內容、帶問號的條件）：小圖在 18px 只有 4px，只能當「有一個東西」；要靠它分的幾個（召喚物數值五種）等於分不開，照實寫。
- **容易讀成別的東西**：金環中間插一面小旗＝高爾夫球洞；金環上一道梯形光柱＝禮帽；地平線上半圓加三道粗光芒＝警報燈（改成五道短光芒、細的藍色地平線）；上下左右四個朝內的三角＝輻射標誌、風車；箭頭穿過直條＝十字架。
- **自查的亮度不算外框色的像素**：沿用的記號在洞裡墊了外框色（準星），放在深色圓片上那一塊等於底色。
- **九宮格放進圓片要縮到 0.8**，四角才不會頂到色環。
- **（第 2 版）圓片裡的圖樣要收在色環內**：圖樣格 ±10 單位只是圖樣本身的方框，圓片色環內緣在半徑約 12 單位；方的、寬的、四角有東西的（磚牆、鋼牙、盾、吊牌、骷髏、對話框、爆炸、翅膀）四角會頂出去。用 `fit(d, 0.8～0.9)` 整個縮，斜放的長條（劍）放大到兩端剛好半徑 11.5 左右。看 30px 的 2 倍圖找頂到環的，不要只看 18px。
- **（第 2 版）示意圖的亮度以亮格為準**：九宮格這類「亮的是重點、暗的是背景」的圖，自查不要把暗格算進平均亮度（樣張頁 audit 對形狀排除 `UNLIT` 色）；把暗格提亮過關會讓亮格不跳出來。亮格放大、暗格縮小再暗一階，單位畫成圓、格子畫成方，比換顏色好分。
- **（第 2 版）同一家族用同一個外框、換底色與紋章**（六個姿態狀態都是「姿態」徽章的六角臂章）：剪影排會一樣，撞圖紀錄要寫「刻意同形、靠底色分」，並把和徽章本身最像的那一個（同色的）點出來。
- **（第 2 版）讀成別的東西**：金邊白盤金心＝荷包蛋；圓盾加放射鋼條＝車輪；淺色素面圓盤＝鏡頭、按鈕（圓盾要有木板紋或盾心才像盾）；圓頂長方木板＝門（塔盾改鳶形，下緣尖）；壓扁的一灘加鼓包＝麵包、熱狗；兩個 V 沒拉開＝紙飛機；等長的牆與箭頭交叉＝加號、十字架；四個斜角的橘色塊圍一個中心＝和嘲諷的青筋記號很近（要靠中心有沒有亮芯分）。
- **（第 2 版）會增加的清單先用腳本盤點**：「技能會施加哪些狀態」要連 `shield` 效果帶的 `status` 一起算（`帶電護盾` 只掛在護盾上），只搜 `apply_status` 會少一種。
- **`cat > 檔 <<'EOF'` 的 heredoc 可以用**（帶引號的 `'EOF'`）；`python - <<EOF` 與結尾留一個沒有輸入的 `cat` 會卡住。批次改檔用 node 腳本做「找不到就丟錯」的字串取代，比 `sed` 安全。

### 2.9 狀態圖示（第 5 批學到的）

- **清單以名詞表為準**：遊戲端不寫死狀態清單，靠後端名詞表的 `status_look`（`polarity`、`control_group`、`dot_element`）上色、`GLYPH` 查圖樣；樣張頁讀 `qPartsData.js` 的 `QPARTS_GLOSSARY.statuses`（118 個），頁面自己檢查每個都排進總表（沒排到的印在頁首與 console）。
- **尺寸照遊戲端算，不照名目**：狀態卡 20px 是 `tileCanvas`（100 單位、裁成半徑 49 的圓）裡 `paintStatusIcon(50, 50, 84)` → 框 16.8px；頭頂 11px 是 `statusIconCanvas(id, 11)` → 框 9px（px−2）。框線寬 `max(1.5, size×0.09)`，頭頂的框線佔了框邊長的 17%。
- **圖樣要收進框線內緣**：同一個圖樣在圓框、圓角方框、六角框裡能用的面積不同，固定比例會蓋到框線（第一次量 29 個出框）。照圓章自動縮放的做法寫 `fitK(id, 框邊長)`：畫到框內緣以外的像素 ≤0.5% 為止，兩種框邊長各算。自查的「佔框」分母是框內緣的寬度（圓＝直徑、圓角方＝邊長、六角＝對邊距離）。
- **類別色畫在底色**：控制類（`control_group`）的框填不透明的類別底色（硬控 `#d4ac20`、移動 `#2f78c8`、心智 `#8a4ccc`）；45% 透明疊在深底上會變成褐色、1 倍下幾乎看不出（第 1 版樣張對照 (b)）。染底後圖樣和底色同色系的（黃星在黃底、紫對話框在紫底）會黏住：**狀態卡 20** 染底的框裡圖樣包 1 個裝置像素的外框，自查加量「圖樣和底色的亮度差 ≥30」。**頭頂 11 不能包外框**（第 1 版被退：9px 的框裡外框加圖樣把底色吃光，嘲諷的紫只剩角縫、暈眩成一團芥末色）：改成圖樣四周留 1 裝置像素的底色圈（`fitK(id, 框邊長, inset)`，`innerPath` 再內縮 1/res CSS px，這一級最小縮放放寬到 0.4），同色系或塞滿框的另給頭頂用的形（`HEAD_TINT`：暈眩一顆米白大星、沉默淡紫白對話框、嘲諷青筋往外推）。「類別色看得到」優先於「圖樣認得出」：真 1 倍圖樣只剩 4～5px。
- **同一家族的一級一圖**：元素架勢 5 級在 20px 畫不出級數（5 顆點每顆不到 1px），各級同一個圖，級數交給狀態卡角落的數字（美術 PM 定；角落現在是「回合數 → 數值 → 空」，要不要顯示級數由開發 PM 定）；第 4 批已畫的壹級直接沿用到貳～伍級。
- **同一個六角臂章的家族在頭頂 11 靠底色分**：兩個暖色底（紅、紅橘）加同一團黃火在 11px 會黏（第 1 版狂怒對烈焰姿態被退）。新增一個成員時先把同色系的全部在頭頂 11 真 1 倍排一排（`v2-near-hex`）：底色色相要拉開（紅 vs 酒紅），紋章的主形要不同（火 vs 白斜條），不要只靠多一個小零件（白刃在 11px 只剩一兩個亮點）。
- **（第 2 版）讀成別的東西**：圓頂直立的灰石立在一條地面上＝墓碑（頂在頭上的增益讀成「快死了」，改成寬大於高的平頂多面岩塊、拿掉地面）；白色方塊中間一道裂縫＝撕開的紙箱（改成 T 字形：寬肩甲、袖洞挖進去、V 領挖深，本體亮鋼灰不接近純白；但剪影會像 T 恤）。
- **借用要先看在新框裡讀不讀得出**：第 4 批效果「分擔傷害」（Y 形分岔箭頭）是唯一施加「靈魂連結」的效果，但放進狀態框讀不出「連結」、比現行的雙環難認，另畫成雙環並列為待決（同題材不同形要寫明）。
- **讀成別的東西**：半球殼加一條橫底座＝安全帽（改成龜殼：中間六角殼片、下緣一排圓邊片）；兩片對稱往下歪的石板＝翅膀、飛蛾（改成左半不動、右半掉下去）；直線接一段圓弧的風＝U 形迴轉箭頭（改成一圈半的螺旋）；盾面三根刺＝遠山、天際線（刺改長在盾緣）；白色胸甲加粗裂縫＝撕開的紙（加圓肩、腰線，裂縫變細）。
- **腳本的名字衝突**：`qicons_shots.py status` 現在是第 5 批；風格樣張的狀態特寫改叫 `style-status`。頁面用到 `getImageData` 多次時 Chrome 會印 `willReadFrequently` 的提示，腳本已不把它當錯誤。

### 2.10 疊在別的圖上的小記號（第⑤b 批關鍵字學到的）

- **先盤點遊戲端畫在哪、多大、幾個**：現行 `motif()` ≤36px 不畫、一個關鍵字畫兩處；樣張端第 1、2 批只示意元素、縮 0.75。兩邊不一樣時以遊戲端為準，樣張的示意寫成「和遊戲端不同」。
- **不要疊在主圖身上**：Q 版的記號要 ≥9px 才認得出，疊在器物上一定蓋到最好認的部分、和器物同色時分不開。放在角落、自己帶一個深色圓底與 1 個裝置像素外框，就和主圖分開了。
- **小圓章不要畫色環**：13px 的圓章，1px 外框＋1px 環吃掉 4px，圖樣只剩 8px。把關鍵字色混進圓底（深色混 28%）一樣看得出顏色，圖樣多 2px。做法比較排一張（`q-icons-keywords.html?part=lab`：環／沒有環 × 兩種大小），在真 1 倍最小尺寸挑。
- **角落：固定一個角為主，例外寫成一張表，不要「量了挑最少」**（第⑤b 批第 1 版被退）：量出來的角在一格背包裡右下、左上、左下亂跳，掃一排不好找；量法還有「差 2% 算不算平手」這種開發照文字重寫就會不一樣的門檻。第 2 版：第一個一律右下，只有右下會蓋到主圖**最好認的那一頭**時才換角，寫在 `KEY_CORNER`（斧刃、連枷錘頭、月牙刃、弓弩臂、鞋尖、墜子、骨符牙尖在右下 → 換角；X 交叉的成對武器左上是後面那把 → 寫明固定右下）。量測函式（`coverOf`）留著只給自查印數字、幫你挑例外，不決定位置。挑例外要**看圖**，不只看數字（骨符右下 22% 看起來普通，看圖才知道蓋的是牙尖）。
- **幾個記號照類別定，不照百分比**：最小尺寸（32）只畫一個；大的「斜放的單把長條兩個（右下、左上兩個空角）、其他一個」。開發好移植、使用者好理解；代價是圓章數不等於關鍵字數，要交使用者決定（會消失的資訊）。
- **X 交叉的成對武器，兩個上端都是作用端**：量「作用端」只算右上半會漏掉後面那把的上端（左上），第一個圓章就蓋掉一整把、讀不出「雙」。
- **最小尺寸的記號只留一個主體**（規則 8）：撞擊「三角＋星＋牆」在 13px 圓章裡糊成一團，簡化成「牆＋大星」；第 4 批的小工具沒匯出、檔不能改時，在自己的檔照抄色與形並註明出處，大的尺寸照舊直接呼叫。換題材前先在最小尺寸試（倒地換成趴地人形，13px 只剩米白一塊加鼓包＝麵包），不行就留著、寫進紀錄。
- **改版的對照**：把上一版的結果（角的表、被換掉的圖樣）抄進樣張頁、畫一排「上一版｜這一版」（`?part=bag`、`?part=v2`），比文字清楚；指紋頁（`?part=hash`）要在**改之前**先加好、先存。
- **改共用畫法前先查誰在呼叫**：第 1 批的 `def()` 也被第 3 批技能主圖直接呼叫，只改圖示的東西（錘柄亮一階）會讓 `--hash skills` 跟著變。用旗標分開（`def(look, icon)`），改完六份指紋全比。
- **頁面的自查門檻自己訂的時候，寫清楚理由**；不過就改圖（圖樣在圓章裡的縮放 `k`），不改門檻。
- **heredoc 的 `cat > 檔 <<'EOF'` 可以寫 node 腳本**；`node -e "…"` 裡的雙引號會被 shell 吃掉，替換內容有反引號、`${}` 時改用 Edit 工具。

### 2.5 同一個題材、兩種框（第 1 批第 2 版學到的）

- 畫法收到的 `o`：`small`（≤24px）、`tiny`（≤14px）、`owPx`（外框幾個裝置像素）、`badge`（畫在米色圓章裡）、`u`（1 CSS px 是幾個單位，畫 1px 細線用）、`flat`（量剪影那一遍）；成對武器另外有 `pair`、`rear`（後面那把）。
- **軟的、沒有固定剪影的東西（鞭、繩、鍊）在 20px 圓章不要畫成一條曲線**，加上外框就是一條蟲。圓章裡換成盤起來的構圖，用 `o.badge` 分；裝備格 32px 以上才用 S 形。量圓章縮放（`Q.badgeScale`）與自查都要用圓章的構圖量。**盤起來不要畫成「圓環＋大洞＋沿半徑伸出的直柄」**（就是放大鏡）：洞拿掉，實心圓上畫一條螺旋暗線（≤24px 線寬 2 單位、繞不到兩圈才看得到）；握柄、繩捲、甩出去的梢三件各留自己的剪影（握柄壓在繩捲上，20px 會黏成一團），握柄的延長線不要過圓心。
- **要看得到「空隙」的東西（弓與弦之間）**：外框一圈就吃掉 1px，20px 時兩條線中間要留 3px 以上的底色才看得到。做法：主形變細、弧加深；細線（弦、箭桿）畫在 `def.post`，自己不包外框，線寬用 `o.u`（1px）；細線用深褐色，不用外框色（不然和外框黏成一塊）。深底（裝備格）上同一條線換成亮色、畫在圖樣裡。改完用小頁面量空隙有幾 px，不要只憑眼睛。
- **成對武器交叉成 X**：≤24px 把後面那把的小零件省掉（`o.rear`），交叉處才不會擠成一團。有弧度的刃交叉後怎麼調角度都會黏（張開像牛角、收窄像兔耳），改成兩把並排斜放、不交叉。
- **圓的東西放進圓章**（圓盾）縮到約 80%，外面留一圈底色，不然是圓套圓、貼到金框。
- **圖樣貼進框裡不要縮放、要對齊整數裝置像素**（前三批真 1 倍修正學到的）：`Q.render(def, a, res)` 的 canvas 邊長是 `round(a × res)`；`drawImage(cv, x, y, a, a)` 只要 `a × res` 或 `x × res` 不是整數，瀏覽器就重新取樣，1px 外框被抹成半透明、整塊糊掉（鞭三款、雙左輪、化身 24px 都是這樣，看起來像「沒有外框、被平滑縮小」）。用 `QIconsWeapons.blit(ctx, cv, x, y, a, res)`：照 canvas 原尺寸貼、左上角四捨五入到整數裝置像素。圓章自動縮放（`meta.badge < 1`）、各種框的留白比例幾乎都會讓 `a` 落在小數，新寫的 `paint()` 一律用它。看到某幾款真 1 倍特別糊、同一張其他款清楚時，先查這一步，不要先改構圖。目前第 1 批圓章、第 3 批技能主圖、第 4 批（`paint()`、`cardCanvas()`、`paintIcon()` 的主圖，第 2 版）已改；第 1 批裝備格、第 2 批、風格樣張的 `art()` 仍是舊的縮放貼法（真 1 倍還認得出，沒改以免動到過審的指紋）。**縮放後的 ctx 也能用**：`blit` 的最後一個參數是「ctx 每單位幾個裝置像素」（圓片裡是 `unitPx × res`），沒縮放的 ctx 傳 1；不只 `drawImage(cv, x, y, a, a)`，**沒給寬高、只貼在小數位置的 `drawImage(cv, x, y)` 也會重新取樣**（第 4 批卡片小圖貼在 −1.9 裝置像素）。
- 20、24px 圓捲的螺旋暗線在真 1 倍繞不出來（半徑只有 4px）：換成一道粗的淺色外弧＋一小段深色內弧；同膚色相連的零件（巨人的手臂與肩膀）在 ≤24px 用 `halo()` 分開；淺色小零件（光環）在 ≤24px 加粗、換飽和色，**頂緣維持原本的高度**，不然 `boxOf()` 兩種尺寸一起量的外接框會變、連大尺寸都一起縮。
- 圓章裡的自動縮放與裝備格留白（6%）定義在 `qIcons.js`（`Q.badgeScale`、`Q.GEAR_PAD`），風格樣張與第 1 批共用；不要在各自的檔裡另寫一份。

## 4. 出圖與截圖

### 4.1 樣張頁的寫法

- 頁面用 `<script src>` 依序載入現行畫法檔與新畫法檔，最後一段 inline script 用 `OB.h` 組版面。照抄 `q-icons-weapons.html` 的 `<script>` 清單最省事。
- 用 `?part=…` 分段（整頁、每類特寫、情境圖、`audit`、`inspect`／`review`），腳本才能一段一張拍。
- 頁尾一定要寫 `document.documentElement.dataset.h = 頁面高度`，腳本靠它決定視窗高度。
- 「現行」那一欄直接呼叫現行畫法（`OBLive.weaponIcon`、`GearArt.draw`、`AssembledIcon.draw`、`ItemIcons.draw`、`FX.statusIcon`）。現行畫法只存在遊戲端、樣張端沒有時，把那幾行程式原樣抄進頁面並註明出處。
- 每個圖示要有：實際尺寸（放在現行的框上）、4 倍放大（直接用向量畫到 4 倍，簡化程度照 1 倍）、最近鄰放大（`image-rendering: pixelated`，把 canvas 的 CSS 尺寸拉大 4～6 倍）。最近鄰放大有兩種：
  - **2 倍內部解析度**：`canvas(…, 1)` 預設的 canvas 是 CSS px ×2（和遊戲的 DPR 2 一樣），是 200% 縮放螢幕上的像素。各頁 `a`／`b`／`close`／`review`／`inspect` 標「2 倍內部解析度」的都是這種；前三批過審時看的就是這種。
  - **真 1 倍**：傳 `{ res: 1 }`，canvas 寬高＝CSS px，是 100% 縮放螢幕上的像素（比 2 倍糊、細線會斷）。各頁 `?part=true1x` 一格三張：現行（真 1 倍）｜Q 版真 1 倍｜Q 版 2 倍（對照），放在實際的框上。`review`（weapons、armor、skills、parts）與 `q-icons.html?part=inspect` 也多一列真 1 倍。
  - **審查最小尺寸一律看真 1 倍**（圓章 20、裝備格 32、技能 28／24、圓片 18、狀態 11…）；2 倍只當對照。現行那一欄的真 1 倍：`OBLive.weaponIcon`、`AssembledIcon.draw`、`QPartsLive.skillIconCanvas` 內部固定 ×2，頁面給它 px/2 換到真 1 倍（線寬照 px 算），SVG 則畫進 1 倍 canvas。注意遊戲端目前固定 DPR 2，100% 螢幕上實際是 2 倍圖被瀏覽器縮小，會比真 1 倍柔一點；真 1 倍是最壞情況。

### 4.4 自查與看圖

- `?part=audit`：每個圖樣在最小尺寸的佔框比（規則 7）、有沒有超出圓章、平均亮度與亮面面積（規則 6）、有沒有貼到 48 格邊。全部要過；不過就改圖，不改門檻。
- `q-icons.html?part=inspect`、`q-icons-weapons.html?part=review`：全部最近鄰放大（2 倍內部解析度一列、真 1 倍一列），一張看一批（`&from=0&n=16` 分段）。畫的過程用這個看，比整頁快；交件前最小尺寸再用 `?part=true1x` 看一次。
- 確認截圖是裝置像素比 1：真 1 倍放大 6 倍的一個像素在截圖裡要是 6×6 的純色方塊（腳本拍 `true1x` 用 `--force-device-scale-factor=1`）。
- **Read 工具看大圖會縮小**：寬 1280、高 1100 以內的圖大致是原尺寸；更高的整頁圖會被縮到看不清細節。細節以特寫（每種一張）與 review 分段圖為準；整頁圖只確認版面沒有溢出、沒有缺格。要放大某一塊，可以用一個只放 `<img>` 的小網頁加 `transform: scale()`，再用無頭 Chrome 拍那一塊。
- 細線（弦、亮線）在縮小的圖裡會看不到，要放大確認真的有畫出來。
- **改版時先存一份「改之前」的指紋**（`--hash`）再動手。交件要列「實際有改變的圖」，不能用 `git status` 判斷：整張截圖只要版面差 1px 就整檔不同（第 1 批第 2 版遇到：commit 裡的舊特寫比樣張頁原始檔的版面寬幾 px，重拍後 21 張全部顯示有變，其實只有 14 張的圖示有變）。
- 樣張頁會用到別批的共用資料（`obSamples.js` 的 `OB.SKILL` 等）。別人改了共用資料，你的頁面可能整頁中斷（腳本印 `page did not finish (no data-h)`）。先用 `--dump-dom` 加 `--enable-logging=stderr --v=0` 看 console 的錯誤；共用檔不要改，把缺的資料抄進自己的頁面並註明出處。
- **Bash 的 heredoc 在這個環境會失敗**（內容有引號時報 `unexpected EOF`）。要跑的腳本用 Write 工具寫到暫存資料夾再執行；一行改一處的小修改可以用 `sed -i`。

## 5. 品質底線

1. **不能有幾何占位**：圓、方塊、一條斜線代替東西都不行。真的要占位就在樣張上寫「占位」並在回報說明。
2. **不低於現行**：每個圖示和現行並排，1 倍下認得出是什麼，而且不比現行難認。
3. **和人物同一把**：圖示旁邊放 `QDoll.stamp` 拿著同一件的人物對照；零件、配色對得上，只加粗。
4. **同類分得開**：把同一類全部的最小尺寸排成一張（含只留剪影的一排），自己找撞圖。
5. **已有素材一定要用**：人物用 `QDoll.stamp`，現行圖示用現行畫法，不另畫簡化版。
6. **每張最終檔都要 Read 看過**；1 倍圖用最近鄰放大逐個看。只靠自查表過關不算完成。
7. **「我看到」照圖寫**：照最終特寫與 1 倍放大圖親眼看到的寫，不照程式的意圖寫；看不清、認不出的照實寫進「仍不好認」清單。
8. 一次整理交件：全部做完才 commit、才回報；紀錄檔要有完整清單、每個的「我看到」、撞圖結果、和人物不一致之處與理由、給開發移植的重點、要美術 PM 決定的事。

改擺位或共用的出手線時，連帶變到的招會比點名的多（例如把直線突刺的楔形調暗，元素道具的直線技也會一起變、在有色的底上直接看不到）：改完用 `--hash skills` 比對，沒打算動的長相有變就把條件收窄，通過審查的圖（淬毒箭、召喚配弓）要確認指紋沒變。

## 7. 環境規則

- Windows 11、Git Bash。Python 用 `uv run python`；Chrome 在 `C:\Program Files\Google\Chrome\Application\chrome.exe`。
- **不開伺服器**，樣張頁用 `file:///` 開。不用 8000（使用者）、8001（本機 LLM）、8010 埠。
- **不結束不是自己啟動的程序**：禁止 `taskkill /IM`、`pkill`。無頭 Chrome 用前景執行，拍完自己結束；等待不寫 until 輪詢迴圈。
- 瀏覽器一律靜音（`--mute-audio`）。
- **不下載外部素材**，全部程式繪製。
- **不 push**。只 commit 在自己的分支；`git add` 指定路徑，commit 前 `git status` 確認只有派工單允許的檔。commit 訊息第一行英文。
- **獨立 worktree**：所有指令在自己的 worktree 裡跑，不 `cd` 到別的 repo 或 worktree。worktree 從 main 切出來時可能沒有要用的樣張，開工第一步照派工單 `git merge --no-edit <指定的 commit>`（用 commit hash，不用分支名），有衝突才停下回報。
- 中途不要停下來回報（worktree 可能被清掉），全部做完 commit 後才回報。
- 暫存檔放派工單指定的暫存資料夾，不放進 repo。
- 改註解不要在一行中間插 `//`（後半行會被註解掉）；用 `/* … */`。
- 回報與文件用繁體中文；程式碼、識別字、commit 第一行用英文。
