## 2. 共用規矩

### 2.1 Q 版的畫法語言

- **剪影外框**：整個圖樣外面包一圈，色 `#16121a`（人物同色）。做法是「先畫色塊，再把剪影往外長一圈墊在底下」（`QIcons.render`、`QDoll.stamp` 都是），不是逐筆描邊。不描內線、不排線。
- **平塗三階**：每個零件最多本色、一階亮面（白 45%～80% 的細條或小橢圓，放左上）、一階暗面（黑 22% 或材質暗色，放右下）。
- **光暈**只給會發光的東西（元素球、火、魔導），畫在外框底下（`def.pre`），不包外框。閃光、深色弦線這類要壓在最上面的畫在 `def.post`。
- **前後重疊的兩件**（交叉的兩把劍、壓在盾上的星）：後畫的那件用 `halo()` 自己再包一圈。
- **粗短、圓角**；直角用 `poly(…, round)` 磨圓。

### 2.2 配色來源（不要自己調色）

- 材質色照人物：`paperdoll.js` 的 `MATERIAL`／`qIcons.js` 的 `M`。人物沒有的材質（銅、銀、晶石）用現行裝備圖示的色（`gearArt.js` 的 `MATERIAL`）。
- 元素色照 `client/src/render/palette.ts`（`qIcons.js` 的 `EL`）。
- 人物手上那件有什麼零件、什麼顏色，圖示就有同樣的零件與顏色，只加粗。和人物不同的地方寫在畫法檔的註解，也寫進紀錄檔。

### 2.3 圖示畫法規則 14 條（精簡版；全文在 `Q版小圖示樣張.md` 第 2 節）

1. 外框粗細＝顯示邊長的 5%，最細 1px、最粗 1.6px。
2. 平塗、每個零件最多三階；光暈在外框底下。
3. 加粗上限：劍、匕首刃寬 ≤ 全長 1/4；短柄 ≤ 1/8；長柄 ≤ 1/12 且 20px 時不細於 1.2px（48 格裡約 2.9 單位）。頭可以放大，柄不跟著粗。
4. 配色、零件和人物一致。
5. 元素用「主色＋亮色＋白芯」三層。
6. 深底上（裝備格、技能底、狀態框、事件卡圓）圖樣平均亮度 ≥100，亮度 ≥150 的亮面 ≥5%；暗色零件換亮一階的同類色。
7. 佔框：塊狀或直立 ≥70%，45° 斜放的長條 ≥60%；留白先讓給外框，不縮主形。武器在米色圓章裡，分母用圓章框線以內的直徑（44/48）。
8. ≤24px 省小零件；≤14px 只留一個主體、不包外框。大小兩種是同一個題材。
9. ≤24px 的人形畫成單色剪影（米白），不畫五官。
10. 抽象概念可以用符號，但要粗外形（線寬 ≥12%）加亮面。
11. 同類之間先改剪影、再改顏色，不能只換色。
12. 方向照現行慣例；斜放的武器不超過圓章。
13. 框不動（稀有度框、米色圓章、裝備格、狀態框、事件卡圓環、功能列圓底），只換框裡的圖。
14. 技能主圖＝道具＋動作。

### 2.4 武器的方向

- **人物手上**：握把在手（原點）、作用端朝 −y，再由手決定角度。
- **圖示**：長條武器握把在左下、作用端在右上（45°）。畫在「握把 +y、作用端 −y」的直立座標，用 `QIcons.W.diag()` 轉 45°。
- 長槍、霰彈槍：畫在「槍口 +x、上方 −y」，轉 −45°（槍口朝右上）。手槍只斜 −0.42 弧度。
- 拳套、盾、書、法器珠直立。成對武器兩把交叉成 X、握把在下。
- 斧刃、鐮刃在直立座標的 +x 側（轉完在右下），和人物側面同一邊。

### 2.6 防具飾品（第 2 批學到的）

- **先讀人物身上那一件怎麼畫**（`qDoll.js` 的 `body()`、`Q_headgear()`、`leg()`、`handFormOver()`），零件與配色照抄再加粗；人物不分的形制靠「誇大一個零件」分開（護肩、毛尾巴、翻口、刺輪），並寫進紀錄的「和人物不一致」。
- **皮色 `#8a5a32` 的亮度剛好 100**，整件皮製品只要有深色背帶、腰帶就不到規則 6。做法：加淺皮色的翻口、滾邊（主色混 42% `#ffe6b8`）與金扣，本色不動。太暗的染色（亮度 < 105）**照顏色判斷怎麼換亮、不照染色名稱**（`qIconsArmor.js` 的 `tone()`）：近黑（亮度 < 70 且彩度 < 40）保留深色，是規則 6 的例外，靠原有的淺色滾邊、翻口、金扣；彩度高的深色（紅、藍、紫，彩度 ≥ 90）三個色版同乘 1.09、只提高明度、不混白；彩度低的深色（褐）混 15% 白。改完用 `--audit armor` 把全部材質、染色、元素變體一起量，不要只量預設（黑染在自查表另列例外欄，不套平均亮度，其餘各項照常）。
- **有一個大洞的東西（兜帽的臉洞）**：洞不要塗全黑（用暗色的亮一階），洞口不要畫一圈粗的淺色邊（像甜甜圈、馬蹄鐵），用細的同色亮邊；洞開到下襬變成拱門形比閉合的橢圓像兜帽。
- **中空的環（戒指、臂環）**：用 `destination-out` 真的挖洞，看得到格底；斜著看、畫出內壁與朝前的緣才不是一個幾何圓圈。戒指立著、臂環橫躺，兩個才分得開。
- **容易畫成別的東西的組合**：圓頂＋波浪白邊＋頂上一顆球＝杯子蛋糕；看得到筒口的錐形筒＝水桶；圓＋一個尖＋一個點＝鳥頭；圓上兩個點加一條直線＝臉；盾形＋十字＝盾（全罩盔撞鳶盾）。畫完每款問一次「不看名稱像什麼」。
- **撞圖要和別批排在一起**：樣張頁 B 的最下面放「圓的、長方的、手形的、尖的」四組，把第 1 批同樣大結構的拿來並排（含剪影）。
- **樣張頁太高時加 `&sub=`／`&group=` 分段**：Read 看 1100px 以上的圖會縮小；總表、變體表各切成幾段拍到暫存資料夾看，正式截圖仍拍整張。
- **變體表一列放不下**（9 個染色 × 兩種尺寸）會被頁面右邊切掉而且不報錯：整頁圖縮小後看不出來，要分段看；超過 6 個變體的列只放一種尺寸。

### 2.7 技能主圖（第 3 批學到的）

- **先寫推導規則與統計腳本，再畫**：技能有四百招，圖是「內容欄位 → 道具、出手、記號」算出來的。先用腳本看每個道具、記號各有幾招、最大的同圖群是誰，再決定要畫哪些；樣張頁讀腳本匯出的資料檔，不在頁面裡另寫一份規則。
- **一張圖三層**：道具（包外框）、出手線（畫在 `pre`、不包外框、用元素底的亮色）、效果記號（實心粗外形，自己用 `halo()` 再包一圈壓在道具上）。對目標的記號放右上（武器的作用端），對自己的放左下，道具往對角讓開。
- **道具一律量外接框再擺**（`qIconsSkills.js` 的 `boxOf()`）：把外接框長邊縮放到指定單位、外接框中心放到指定位置。不要用「以 24,24 為中心乘一個倍率」——每個道具原本的大小、重心都不同，會貼格邊或佔框不到 70%。
- **記號要是實心的粗外形**：箭頭、十字、鎖、骷髏、星。線條畫的（兩道斜線、圓環加十字）在 24px 會糊。自查量「最粗處內切圓直徑 ≥ 顯示邊長 12%」。
- **容易讀成別的東西**：紅色粗叉＝「不能用」；兩顆並排的圓頭長條＝藥丸，兩片兩頭尖的＝葉子；一灘加兩顆圓泡＝老鼠頭、青蛙；圓環加四芒星會和紅準星撞；鋸齒圈＝齒輪、鋸片；捕獸夾中間加一顆紅點＝怪獸的眼睛；殘影沿著道具自己的長軸退會整個被道具蓋住（要往旁邊退）。
- **不要畫兩次同一件事**：火焰道具＋燃燒記號是兩團火（改成只畫大一號的道具）；道具已經是召喚物就不再畫召喚記號。沒有武器也沒有元素的法術不要硬塞一顆「通用晶石」，把記號放大當主圖。
- **頁尾量高度時字型可能還沒載入**：格子很多的版面（實例總表）把標題列的高度寫死，不然截圖會少最後一排。
- **截圖檔名太長會存不出來而且不報錯**：`--query` 很長時（`only=` 列十幾個）拆成幾次拍。
- **套用現行 client CSS 的情境圖**：`.battle-screen` 會撐滿視窗，照 `q-icons.html` 在 `.qi-scene` 底下蓋掉高度。

### 2.5 同一個題材、兩種框（第 1 批第 2 版學到的）

- 畫法收到的 `o`：`small`（≤24px）、`tiny`（≤14px）、`owPx`（外框幾個裝置像素）、`badge`（畫在米色圓章裡）、`u`（1 CSS px 是幾個單位，畫 1px 細線用）、`flat`（量剪影那一遍）；成對武器另外有 `pair`、`rear`（後面那把）。
- **軟的、沒有固定剪影的東西（鞭、繩、鍊）在 20px 圓章不要畫成一條曲線**，加上外框就是一條蟲。圓章裡換成盤起來的構圖，用 `o.badge` 分；裝備格 32px 以上才用 S 形。量圓章縮放（`Q.badgeScale`）與自查都要用圓章的構圖量。**盤起來不要畫成「圓環＋大洞＋沿半徑伸出的直柄」**（就是放大鏡）：洞拿掉，實心圓上畫一條螺旋暗線（≤24px 線寬 2 單位、繞不到兩圈才看得到）；握柄、繩捲、甩出去的梢三件各留自己的剪影（握柄壓在繩捲上，20px 會黏成一團），握柄的延長線不要過圓心。
- **要看得到「空隙」的東西（弓與弦之間）**：外框一圈就吃掉 1px，20px 時兩條線中間要留 3px 以上的底色才看得到。做法：主形變細、弧加深；細線（弦、箭桿）畫在 `def.post`，自己不包外框，線寬用 `o.u`（1px）；細線用深褐色，不用外框色（不然和外框黏成一塊）。深底（裝備格）上同一條線換成亮色、畫在圖樣裡。改完用小頁面量空隙有幾 px，不要只憑眼睛。
- **成對武器交叉成 X**：≤24px 把後面那把的小零件省掉（`o.rear`），交叉處才不會擠成一團。有弧度的刃交叉後怎麼調角度都會黏（張開像牛角、收窄像兔耳），改成兩把並排斜放、不交叉。
- **圓的東西放進圓章**（圓盾）縮到約 80%，外面留一圈底色，不然是圓套圓、貼到金框。
- 圓章裡的自動縮放與裝備格留白（6%）定義在 `qIcons.js`（`Q.badgeScale`、`Q.GEAR_PAD`），風格樣張與第 1 批共用；不要在各自的檔裡另寫一份。

## 3. 尺寸與色票速查

### 3.1 尺寸（CSS px；canvas 內部解析度 ×2）

| 東西 | 尺寸 | 最小 |
|---|---|---|
| 武器小圖示（米色圓章） | 20、24、28 | 20 |

## 4. 出圖與截圖

### 4.1 樣張頁的寫法

- 頁面用 `<script src>` 依序載入現行畫法檔與新畫法檔，最後一段 inline script 用 `OB.h` 組版面。照抄 `q-icons-weapons.html` 的 `<script>` 清單最省事。
- 用 `?part=…` 分段（整頁、每類特寫、情境圖、`audit`、`inspect`／`review`），腳本才能一段一張拍。
- 頁尾一定要寫 `document.documentElement.dataset.h = 頁面高度`，腳本靠它決定視窗高度。
- 「現行」那一欄直接呼叫現行畫法（`OBLive.weaponIcon`、`GearArt.draw`、`AssembledIcon.draw`、`ItemIcons.draw`、`FX.statusIcon`）。現行畫法只存在遊戲端、樣張端沒有時，把那幾行程式原樣抄進頁面並註明出處。
- 每個圖示要有：實際尺寸（放在現行的框上）、4 倍放大（直接用向量畫到 4 倍，簡化程度照 1 倍）、**1 倍圖最近鄰放大**（`image-rendering: pixelated`，把 1 倍 canvas 的 CSS 尺寸拉大 4～6 倍）。只有最後這個才是 1 倍下實際看到的像素。

### 4.3 無頭 Chrome（腳本裡實際用的參數；手動拍也照這組）

```bash
"/c/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --disable-gpu --mute-audio --no-first-run \
  --allow-file-access-from-files "--user-data-dir=<暫存資料夾>\chrome-prof" --hide-scrollbars \
```

- **一律 `--mute-audio`**；`--user-data-dir` 放暫存資料夾；用 `file:///` 開，不開伺服器。
- 讀頁面高度：同一組參數把 `--screenshot` 換成 `--dump-dom`，找 `data-h="…"`。
- 在獨立 worktree 裡，Bash 指令要簡單：一次一個指令、不要 `cd` 到 worktree 外、不要用 heredoc 寫檔（會被擋）。暫存檔用 Write 工具寫，再用 `node <檔>`／`uv run python <檔>` 跑。
- Python 用 `uv run python`（沒有 Pillow）；JS 語法檢查：`node -e "new Function(require('fs').readFileSync('<檔>','utf8'))"`。

### 4.4 自查與看圖

- `?part=audit`：每個圖樣在最小尺寸的佔框比（規則 7）、有沒有超出圓章、平均亮度與亮面面積（規則 6）、有沒有貼到 48 格邊。全部要過；不過就改圖，不改門檻。
- `q-icons.html?part=inspect`、`q-icons-weapons.html?part=review`：全部 1 倍圖最近鄰放大，一張看一批（`&from=0&n=16` 分段）。畫的過程用這個看，比整頁快。
- **Read 工具看大圖會縮小**：寬 1280、高 1100 以內的圖大致是原尺寸；更高的整頁圖會被縮到看不清細節。細節以特寫（每種一張）與 review 分段圖為準；整頁圖只確認版面沒有溢出、沒有缺格。要放大某一塊，可以用一個只放 `<img>` 的小網頁加 `transform: scale()`，再用無頭 Chrome 拍那一塊。
- 細線（弦、亮線）在縮小的圖裡會看不到，要放大確認真的有畫出來。
- **改版時先存一份「改之前」的指紋**（`--hash`）再動手。交件要列「實際有改變的圖」，不能用 `git status` 判斷：整張截圖只要版面差 1px 就整檔不同（第 1 批第 2 版遇到：commit 裡的舊特寫比樣張頁原始檔的版面寬幾 px，重拍後 21 張全部顯示有變，其實只有 14 張的圖示有變）。
- 樣張頁會用到別批的共用資料（`obSamples.js` 的 `OB.SKILL` 等）。別人改了共用資料，你的頁面可能整頁中斷（腳本印 `page did not finish (no data-h)`）。先用 `--dump-dom` 加 `--enable-logging=stderr --v=0` 看 console 的錯誤；共用檔不要改，把缺的資料抄進自己的頁面並註明出處。
- **Bash 的 heredoc 在這個環境會失敗**（內容有引號時報 `unexpected EOF`）。要跑的腳本用 Write 工具寫到暫存資料夾再執行；一行改一處的小修改可以用 `sed -i`。

## 5. 品質底線

1. **不能有幾何占位**：圓、方塊、一條斜線代替東西都不行。真的要占位就在樣張上寫「占位」並在回報說明。
2. **不低於現行**：每個圖示和現行並排，1 倍下認得出是什麼，而且不比現行難認。
3. **和人物同一把**：圖示旁邊放 `QDoll.stamp` 拿著同一件的人物對照；零件、配色對得上，只加粗。
4. **同類分得開**：把同一類全部的最小尺寸排成一張（含只留剪影的一排），自己找撞圖。
5. **已有素材一定要用**：人物用 `QDoll.stamp`，現行圖示用現行畫法，不另畫簡化版。
6. **每張最終檔都要 Read 看過**；1 倍圖用最近鄰放大逐個看。只靠自查表過關不算完成。
7. **「我看到」照圖寫**：照最終特寫與 1 倍放大圖親眼看到的寫，不照程式的意圖寫；看不清、認不出的照實寫進「仍不好認」清單。
8. 一次整理交件：全部做完才 commit、才回報；紀錄檔要有完整清單、每個的「我看到」、撞圖結果、和人物不一致之處與理由、給開發移植的重點、要美術 PM 決定的事。

## 6. 常被審查退的點（整理自 `Q版小圖示樣張-審查.md` 三版與各批的審查）

| 被退的原因 | 做法 |
|---|---|
| 圖示和人物手上不是同一件（塔盾畫成鋼邊鐵箍，人物是木盾加白直紋） | 先讀 `qDoll.js`／`paperdoll.js` 那一件怎麼畫，照它的零件與顏色 |
| 換了題材反而比現行難認（背包像掛鎖） | 和現行並排看 1 倍；不確定就保留現行的構圖只換畫法 |
| 圖太小太暗，外框吃掉面積（兩把劍只剩暗暗的 X） | 放大撐滿框（規則 7）；深底上暗色零件換亮一階（規則 6）；前後兩件用亮邊或 `halo` 分開 |
| 含人形的小圖示有臉有衣服，讀成別的意思（倒地像睡著） | ≤24px 人形用單色剪影加一個記號 |
| ≤14px 塞兩個以上主體、兩個箭頭黏在一起 | 只留一個主體；成對的符號中間留 2 個裝置像素 |
| 加粗過頭（長杖變棍棒） | 柄照規則 3 的上限，頭可以大 |
| 拿掉箭之後弓像三角形、彎月；弦是淺色壓在米色圓章上看不到 | 圓弧弓臂；≤24px 的弦用深色線、畫在外框之上 |
| 圖樣超出框（靴口壓格框、盾與拳套四角頂出圓章） | 直立塊狀放進圓章要縮；用 audit 的「超出圓章」與 1 倍放大圖檢查 |
| 小尺寸比大尺寸暗一階、底色吃掉圖樣 | 小尺寸加粗、底色壓暗 |
| 改 Q 版後原本靠顏色傳達的資訊不見了（狀態的控制類別色、技能的核心效果圓片） | 先盤點現行靠什麼區分；會消失的資訊做一組對照讓使用者決定，不要默默拿掉 |
| 「我看到」和圖不符、圖有問題沒寫到 | 照最終圖重寫；溢出、蓋住、認不出都要寫 |
| 範圍外的東西混進來（防具飾品、六類以外的小圖示） | 只畫派工單列的；會造成兩種畫風並排的，做對照、列為待問 |

第 2 批防具飾品第 2 版被退的（同檔「第 2 版複審」）：

## 7. 環境規則

- Windows 11、Git Bash。Python 用 `uv run python`；Chrome 在 `C:\Program Files\Google\Chrome\Application\chrome.exe`。
- **不開伺服器**，樣張頁用 `file:///` 開。不用 8000（使用者）、8001（本機 LLM）、8010 埠。
- **不結束不是自己啟動的程序**：禁止 `taskkill /IM`、`pkill`。無頭 Chrome 用前景執行，拍完自己結束；等待不寫 until 輪詢迴圈。
- 瀏覽器一律靜音（`--mute-audio`）。
- **不下載外部素材**，全部程式繪製。
- **不 push**。只 commit 在自己的分支；`git add` 指定路徑，commit 前 `git status` 確認只有派工單允許的檔。commit 訊息第一行英文。
- **獨立 worktree**：所有指令在自己的 worktree 裡跑，不 `cd` 到別的 repo 或 worktree。worktree 從 main 切出來時可能沒有要用的樣張，開工第一步照派工單 `git merge --no-edit <指定的 commit>`（用 commit hash，不用分支名），有衝突才停下回報。
- 中途不要停下來回報（worktree 可能被清掉），全部做完 commit 後才回報。
- 暫存檔放派工單指定的暫存資料夾，不放進 repo。
- 改註解不要在一行中間插 `//`（後半行會被註解掉）；用 `/* … */`。
- 回報與文件用繁體中文；程式碼、識別字、commit 第一行用英文。
