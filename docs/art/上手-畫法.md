## 2. 共用規矩

### 2.1 Q 版的畫法語言

- **剪影外框**：整個圖樣外面包一圈，色 `#16121a`（人物同色）。做法是「先畫色塊，再把剪影往外長一圈墊在底下」（`QIcons.render`、`QDoll.stamp` 都是），不是逐筆描邊。不描內線、不排線。
- **平塗三階**：每個零件最多本色、一階亮面（白 45%～80% 的細條或小橢圓，放左上）、一階暗面（黑 22% 或材質暗色，放右下）。
- **光暈**只給會發光的東西（元素球、火、魔導），畫在外框底下（`def.pre`），不包外框。閃光、深色弦線這類要壓在最上面的畫在 `def.post`。
- **前後重疊的兩件**（交叉的兩把劍、壓在盾上的星）：後畫的那件用 `halo()` 自己再包一圈。
- **粗短、圓角**；直角用 `poly(…, round)` 磨圓。

### 2.2 配色來源（不要自己調色）

- 材質色照人物：`paperdoll.js` 的 `MATERIAL`／`qIcons.js` 的 `M`。人物沒有的材質（銅、銀、晶石）用現行裝備圖示的色（`gearArt.js` 的 `MATERIAL`）。
- 元素色照 `client/src/render/palette.ts`（`qIcons.js` 的 `EL`）。
- 人物手上那件有什麼零件、什麼顏色，圖示就有同樣的零件與顏色，只加粗。和人物不同的地方寫在畫法檔的註解，也寫進紀錄檔。

### 2.3 圖示畫法規則 14 條（精簡版；全文在 `Q版小圖示樣張.md` 第 2 節）

1. 外框粗細＝顯示邊長的 5%，最細 1px、最粗 1.6px。
2. 平塗、每個零件最多三階；光暈在外框底下。
3. 加粗上限：劍、匕首刃寬 ≤ 全長 1/4；短柄 ≤ 1/8；長柄 ≤ 1/12 且 20px 時不細於 1.2px（48 格裡約 2.9 單位）。頭可以放大，柄不跟著粗。
4. 配色、零件和人物一致。
5. 元素用「主色＋亮色＋白芯」三層。
6. 深底上（裝備格、技能底、狀態框、事件卡圓）圖樣平均亮度 ≥100，亮度 ≥150 的亮面 ≥5%；暗色零件換亮一階的同類色。例外：近黑的染色、黑色材料（黑曜等）保留深色本體，靠亮線與亮面 ≥5% 撐，自查表另列實際亮度。
7. 佔框：塊狀或直立 ≥70%，45° 斜放的長條 ≥60%；留白先讓給外框，不縮主形。武器在米色圓章裡，分母用圓章框線以內的直徑（44/48）。
8. ≤24px 省小零件；≤14px 只留一個主體、不包外框。大小兩種是同一個題材。
9. ≤24px 的人形畫成單色剪影（米白），不畫五官。
10. 抽象概念可以用符號，但要粗外形（線寬 ≥12%）加亮面。
11. 同類之間先改剪影、再改顏色，不能只換色。
12. 方向照現行慣例；斜放的武器不超過圓章。
13. 框不動（稀有度框、米色圓章、裝備格、狀態框、事件卡圓環、功能列圓底），只換框裡的圖。
14. 技能主圖＝道具＋動作。

### 2.4 武器的方向

- **人物手上**：握把在手（原點）、作用端朝 −y，再由手決定角度。
- **圖示**：長條武器握把在左下、作用端在右上（45°）。畫在「握把 +y、作用端 −y」的直立座標，用 `QIcons.W.diag()` 轉 45°。
- 長槍、霰彈槍：畫在「槍口 +x、上方 −y」，轉 −45°（槍口朝右上）。手槍只斜 −0.42 弧度。
- 拳套、盾、書、法器珠直立。成對武器兩把交叉成 X、握把在下。
- 斧刃、鐮刃在直立座標的 +x 側（轉完在右下），和人物側面同一邊。

### 2.5 同一個題材、兩種框（第 1 批第 2 版學到的）
- 畫法收到的 `o`：`small`（≤24px）、`tiny`（≤14px）、`owPx`（外框幾個裝置像素）、`badge`（畫在米色圓章裡）、`u`（1 CSS px 是幾個單位，畫 1px 細線用）、`flat`（量剪影那一遍）；成對武器另外有 `pair`、`rear`（後面那把）。
- 軟的、沒有固定剪影的東西（鞭、繩、鍊）在 20px 圓章改成盤起來的構圖（`o.badge` 分），不要畫成放大鏡（圓環＋大洞＋直柄）；量縮放與自查都用圓章的構圖。
- 要看得到空隙的東西（弓與弦）：20px 時中間留 ≥3px 底色；細線畫在 `def.post`、不包外框、1px（`o.u`）深褐。改完量空隙，不憑眼睛。
- 成對武器交叉成 X：≤24px 省掉後面那把的小零件（`o.rear`）；有弧度的刃交叉會黏，改並排斜放。圓的東西放進圓章縮到約 80%。
- **圖樣貼進框裡要對齊整數裝置像素、不縮放**：用 `QIconsWeapons.blit(ctx, cv, x, y, a, res)`（最後一個參數＝ctx 每單位幾個裝置像素）；`drawImage` 貼到小數位置（含沒給寬高的）會重新取樣、1px 外框被抹糊。某幾款真 1 倍特別糊時先查這一步，再改構圖。細節（螺旋暗線、哪幾批已改 `blit`）見歸檔 2.5。
- 圓章裡的自動縮放與裝備格留白（6%）定義在 `qIcons.js`（`Q.badgeScale`、`Q.GEAR_PAD`），風格樣張與第 1 批共用；不要在各自的檔裡另寫一份。

### 2.6 防具飾品（第 2 批學到的）
- 先讀人物身上那一件怎麼畫（`qDoll.js` 的 `body()`、`Q_headgear()`、`leg()`、`handFormOver()`），零件與配色照抄再加粗；人物不分的形制靠誇大一個零件分開，寫進紀錄的「和人物不一致」。
- 太暗的染色**照顏色判斷、不照染色名稱**（`qIconsArmor.js` 的 `tone()`）：近黑保留深色（規則 6 例外）；彩度高的深色三個色版同乘一個倍率、不混白；彩度低的混一點白。改完 `--audit armor` 量全部變體。
- 中空的環用 `destination-out` 真的挖洞；每款畫完問一次「不看名稱像什麼」，撞圖要和別批同樣大結構的並排（含剪影）。
- 頁面太高時用 `&sub=`／`&group=` 分段看；一列放不下會被右邊切掉而且不報錯（超過 6 個變體的列只放一種尺寸）。細節見歸檔 2.6。

### 2.7 技能主圖（第 3 批學到的）
- 先寫推導規則與統計腳本再畫；樣張頁讀腳本匯出的資料檔，不在頁面另寫一份規則。
- 一張圖三層：道具（包外框）、出手線（`pre`、不包外框、元素底的亮色）、效果記號（實心粗外形、自己 `halo()`）；對目標放右上、對自己放左下。道具一律量外接框再擺（`boxOf()`）。
- 記號要實心粗外形（最粗處內切圓 ≥ 顯示邊長 12%）；不要畫兩次同一件事（火焰道具＋燃燒記號）。細節與「讀成別的東西」清單見歸檔 2.7。

### 2.8 徽章、小圓片、卡片小圖（第 4 批學到的）
- **現行那一欄用遊戲端原始程式打包**（vite lib 模式 IIFE、`minify: false`、用不到的套件 external，產物放 `tools/` 註明自動產生）；資料用後端自己的函式匯出，不手抄。
- **先算圖樣本身有幾 px**，簡化程度照圖樣大小（18px 圓片的圖樣只有 12px，已是 tiny）；圓片裡的圖樣收在色環內（`fit(d, 0.8～0.9)`）。
- 沿用上一批的記號直接呼叫，同一個題材在徽章、圓片、卡片、HUD 用同一個形（寫在清單的 `src`）。自查亮度不算外框色像素；示意圖以亮格為準。「自身」＝右下米白小人形、「沒有」＝紅斜槓（左下到右上）、「目標帶狀態」＝右上問號：照用。
- **新條目一律排在各表最後**，前面的行序、指紋、真 1 倍分段才不動。替暫代補正式圖：先查遊戲端借的是誰，和被借的並排；還沒合進 main 的用 `git log --all` 找分支再 `git show <分支>:<路徑>`。
- 腳本字串取代前先數出現次數（不是剛好 1 次就丟錯），改完重拍前一段、`git status` 沒變才算沒碰到。細節見歸檔 2.8。

### 2.9 狀態圖示（第 5 批學到的）
- 清單以後端名詞表為準（`qPartsData.js` 的 `QPARTS_GLOSSARY.statuses`）；尺寸照遊戲端算（狀態卡 20 → 框 16.8px；頭頂 11 → 框 9px）。
- 圖樣收進框線內緣（`fitK(id, 框邊長)`）；控制類的類別色畫成不透明底色：狀態卡 20 的圖樣包 1 裝置像素外框，頭頂 11 不包外框、留 1 裝置像素底色圈。「類別色看得到」優先於「圖樣認得出」。
- 同家族一級一圖；同一個六角臂章的家族在頭頂 11 靠底色色相＋主形分。`qicons_shots.py status` 是第 5 批，風格樣張的叫 `style-status`。細節見歸檔 2.9。

### 2.10 疊在別的圖上的小記號（第⑤b 批關鍵字學到的）
- 先盤點遊戲端畫在哪、多大、幾個，以遊戲端為準。記號不疊在主圖身上：放角落、自帶深色圓底＋1 裝置像素外框；小圓章不畫色環（關鍵字色混進圓底）。
- 角落固定右下，例外寫成表（`KEY_CORNER`），看圖挑，不用「量了挑最少」。多個關鍵字＝一個圓章＋深底米白「＋」小圓牌（奇數邊長），方向照角定、例外寫表。最小尺寸只留一個主體。
- 改版前先存指紋（`?part=hash`）；改共用畫法前先查誰在呼叫，用旗標分開；改版時把舊版對照固定住（傳舊版旗標）。兩個畫圖 agent 同時拍圖時 Chrome 設定檔會打架：寫小包裝 `import qicons_shots as q`，換掉 `q.BASE` 的 `--user-data-dir`。細節見歸檔 2.10。

### 2.11 補道具、補圖（11-12 學到的）
- 新長相一律加在各表最後；借別批的形但載入順序相反時，照抄並註明出處、別批的檔不動。共用的 worktree 可能有別人的未提交改動：`git add` 只加自己的路徑，交件前 `git status` 看一次。細節見歸檔 2.11。

### 2.12 HUD（第⑦批學到的）
- 現行只存在 React 元件時：vite lib 打包成 IIFE、`renderToStaticMarkup` 出 SVG 字串、載成 `Image` 再畫；頁面一定要 `<meta charset="utf-8">`。
- 同題材先找前幾批；借用前問「同一個畫面會不會同時出現、意思一不一樣」。只有圖示沒有字的位置、並排出現的兩個圖，同類用剪影分（規則 11）。
- 給已過審的一批補圖放在另一張表（例 `WISH`），不進原表與 `list()`，原本的指紋一行都不動。情境照規格的數字畫在 canvas，先畫真 1 倍再最近鄰放大。細節見歸檔 2.12。

### 2.13 事件卡（第⑧批學到的）
- 圓環裡看圖樣本身幾 px（同 2.8），另量「出環」（≤1%）。要在別人的整張圖裡只換一個小圖：呼叫期間包一層、`finally` 換回。
- 借前批的圖到 ≤14px 前先用真 1 倍問「單看這一個認得出嗎」，不行就另給 `o.tiny` 的形、原用途不動。規則 2 的例外只限多面體骰子的分面（最多四階）。
- 淺色底：符號用近黑 `#16121a`、彩色的圖包 1px 外框；規則 6 改量邊緣對比。派工單的數量照實核對；加新段不動前一批的清單。細節見歸檔 2.13。

### 2.14 物品（第⑥批學到的）
- 遊戲端沒有這類圖示時照 CSS 把現行畫在 canvas；盤點時把會用到圖示的位置一起列，最小尺寸照實際用到的定。
- 同一類照內容的敘述找不同的容器（規則 11）；框線色不要和裝備稀有度撞；自查量主形不含光暈；沿用的圖貼邊時外面包一層縮放，原檔不動。
- 真 1 倍分段的放大倍率照最大尺寸算寬度（超過 1280 會被切掉而且不報錯）。寫移植需求前查遊戲端的資料接得到嗎、誰真的在畫（追到最上層呼叫者）；清單列的小畫布要對齊整數裝置像素。細節見歸檔 2.14。

## 4. 出圖與截圖

### 4.1 樣張頁的寫法

- 頁面用 `<script src>` 依序載入現行畫法檔與新畫法檔，最後一段 inline script 用 `OB.h` 組版面。照抄 `q-icons-weapons.html` 的 `<script>` 清單最省事。
- 用 `?part=…` 分段（整頁、每類特寫、情境圖、`audit`、`inspect`／`review`），腳本才能一段一張拍。
- 頁尾一定要寫 `document.documentElement.dataset.h = 頁面高度`，腳本靠它決定視窗高度。
- 「現行」那一欄直接呼叫現行畫法（`OBLive.weaponIcon`、`GearArt.draw`、`AssembledIcon.draw`、`ItemIcons.draw`、`FX.statusIcon`）。現行畫法只存在遊戲端、樣張端沒有時，把那幾行程式原樣抄進頁面並註明出處。
- 每個圖示要有：實際尺寸（放在現行的框上）、4 倍放大（直接用向量畫到 4 倍，簡化程度照 1 倍）、最近鄰放大（`image-rendering: pixelated`，把 canvas 的 CSS 尺寸拉大 4～6 倍）。最近鄰放大有兩種：
  - **2 倍內部解析度**：`canvas(…, 1)` 預設的 canvas 是 CSS px ×2（和遊戲的 DPR 2 一樣），是 200% 縮放螢幕上的像素。各頁 `a`／`b`／`close`／`review`／`inspect` 標「2 倍內部解析度」的都是這種；前三批過審時看的就是這種。
  - **真 1 倍**：傳 `{ res: 1 }`，canvas 寬高＝CSS px，是 100% 縮放螢幕上的像素（比 2 倍糊、細線會斷）。各頁 `?part=true1x` 一格三張：現行（真 1 倍）｜Q 版真 1 倍｜Q 版 2 倍（對照），放在實際的框上。`review`（weapons、armor、skills、parts）與 `q-icons.html?part=inspect` 也多一列真 1 倍。
  - **審查最小尺寸一律看真 1 倍**（圓章 20、裝備格 32、技能 28／24、圓片 18、狀態 11…）；2 倍只當對照。現行那一欄的真 1 倍：`OBLive.weaponIcon`、`AssembledIcon.draw`、`QPartsLive.skillIconCanvas` 內部固定 ×2，頁面給它 px/2 換到真 1 倍（線寬照 px 算），SVG 則畫進 1 倍 canvas。注意遊戲端目前固定 DPR 2，100% 螢幕上實際是 2 倍圖被瀏覽器縮小，會比真 1 倍柔一點；真 1 倍是最壞情況。

### 4.2 腳本

```bash
uv run python docs/art/sample/tools/qicons_shots.py                # 兩頁全部重拍
uv run python docs/art/sample/tools/qicons_shots.py <組名…>                # 只拍指名的組（weapons、armor、skills、parts、status、keywords、hud、event、items、style-status…；組名見腳本）
uv run python docs/art/sample/tools/qicons_shots.py --audit [批]           # 自查表（weapons｜armor｜skills｜parts｜status｜keywords｜hud｜event｜items｜wish；不給＝風格樣張）
uv run python docs/art/sample/tools/qicons_shots.py --hash [批]            # 像素指紋（改之前、之後各存一份；--hash armor var＝全部變體）
uv run python docs/art/sample/tools/qicons_shots.py true1x [頁…]           # 真 1 倍（shots/qicons/true1x/，每張寬 1280、高 ≤1100）
uv run python docs/art/sample/tools/qicons_shots.py --page <頁> --query "part=review&only=…" --out <暫存資料夾>   # 指名幾款的 1 倍圖放大
uv run python docs/art/sample/tools/qskills_derive.py --export       # 改了推導規則或技能內容後：重算統計、重匯 qSkillsData.js
```

- 各組的名稱、輸出路徑、`true1x` 檔名清單見歸檔 4.2（與腳本的 `*_SHOTS`）。

**`--out` 只給 `true1x`、`--zoom`、`--query` 用**：指名特寫組（`items`、`event-b`、`hud-b`…）重拍一律寫回 repo 的 `closeup/`、`shots/`，`--out` 對它們沒有作用；要拍到別處只能用 `true1x`、`--zoom` 或 `--query`。`--query` 的輸出檔名照網址參數長出來，太長（Windows 路徑超過 260）時無頭 Chrome 不報錯、檔案也不會出現：一次少列幾個 `only=`。

**`--audit` 印表的編碼**：自查表有「≥」，這台主控台是 cp950；`-I` 會忽略 `PYTHONIOENCODING`。`audit()` 已先 `sys.stdout.reconfigure(encoding="utf-8")`（第⑧批第 2 版），上面的指令照抄就能印；其他會印中文的旗標（`--hash`）若遇到 `UnicodeEncodeError`，加 `-X utf8`（`uv run python -X utf8 -I …`）。

新增一批時在腳本的 `WEAPON_SHOTS`、`ARMOR_SHOTS` 旁邊加一組 `(名稱, 頁面, 網址參數, 輸出路徑, 倍率)`。改完跑 `uv run ruff check` 與 `uv run ruff format --check`。

### 4.3 無頭 Chrome（腳本裡實際用的參數；手動拍也照這組）

```bash
"/c/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --disable-gpu --mute-audio --no-first-run \
  --allow-file-access-from-files "--user-data-dir=<暫存資料夾>\chrome-prof" --hide-scrollbars \
  --virtual-time-budget=20000 --window-size=1280,<高> "--screenshot=<輸出.png>" "file:///<樣張頁絕對路徑>?part=b&mute=1"
```

- **一律 `--mute-audio`**；`--user-data-dir` 放暫存資料夾；用 `file:///` 開，不開伺服器。
- 讀頁面高度：同一組參數把 `--screenshot` 換成 `--dump-dom`，找 `data-h="…"`。
- Bash 指令要簡單：一次一個指令、不要 `cd` 到 worktree 外。暫存腳本用 Write 工具寫到暫存資料夾，再用 `node <檔>`／`uv run python <檔>` 跑；`cat > 檔 <<'EOF'` 只在內容沒有反引號、`${…}` 時可以用，`python - <<EOF` 與沒有輸入的 `cat` 會卡住。**shell 字串裡不放反引號**（`node -e "…"`、`python -c "…"` 裡的反引號會被當成指令替換），要用就改 Edit 工具或先寫成檔。
- Python 一律 `uv run python`（這台的 `python` 是商店空殼）；要 PIL 用 `uv run --with pillow python …`。JS 語法檢查：`node -e "new Function(require('fs').readFileSync('<檔>','utf8'))"`。Python 改檔用 `read_bytes`／`write_bytes`（`write_text` 在 Windows 會整檔換成 CRLF）。
- 真的要開埠（除錯埠等）時只綁 127.0.0.1，開之前先 `netstat` 查有沒有人在用；不用 8000、8001 埠。
- **截圖格式**：真 1 倍與最近鄰放大用 PNG，而且必須是真最近鄰（PIL `Image.NEAREST` 或 `image-rendering: pixelated`）；其他截圖 jpg 品質 80。

### 4.4 自查與看圖

- `?part=audit`：每個圖樣在最小尺寸的佔框比（規則 7）、有沒有超出圓章、平均亮度與亮面面積（規則 6）、有沒有貼到 48 格邊。全部要過；不過就改圖，不改門檻。
- `q-icons.html?part=inspect`、`q-icons-weapons.html?part=review`：全部最近鄰放大（2 倍內部解析度一列、真 1 倍一列），一張看一批（`&from=0&n=16` 分段）。畫的過程用這個看，比整頁快；交件前最小尺寸再用 `?part=true1x` 看一次。
- 確認截圖是裝置像素比 1：真 1 倍放大 6 倍的一個像素在截圖裡要是 6×6 的純色方塊（腳本拍 `true1x` 用 `--force-device-scale-factor=1`）。
- **Read 工具看大圖會縮小**：寬 1280、高 1100 以內的圖大致是原尺寸；更高的整頁圖會被縮到看不清細節。細節以特寫（每種一張）與 review 分段圖為準；整頁圖只確認版面沒有溢出、沒有缺格。要放大某一塊，可以用一個只放 `<img>` 的小網頁加 `transform: scale()`，再用無頭 Chrome 拍那一塊。
- 細線（弦、亮線）在縮小的圖裡會看不到，要放大確認真的有畫出來。
- **改版時先存一份「改之前」的指紋**（`--hash`）再動手。交件要列「實際有改變的圖」，不能用 `git status` 判斷：整張截圖只要版面差 1px 就整檔不同（第 1 批第 2 版遇到：commit 裡的舊特寫比樣張頁原始檔的版面寬幾 px，重拍後 21 張全部顯示有變，其實只有 14 張的圖示有變）。
- 樣張頁會用到別批的共用資料（`obSamples.js` 的 `OB.SKILL` 等）。別人改了共用資料，你的頁面可能整頁中斷（腳本印 `page did not finish (no data-h)`）。先用 `--dump-dom` 加 `--enable-logging=stderr --v=0` 看 console 的錯誤；共用檔不要改，把缺的資料抄進自己的頁面並註明出處。

## 5. 品質底線

1. **不能有幾何占位**：圓、方塊、一條斜線代替東西都不行。真的要占位就在樣張上寫「占位」並在回報說明。
2. **不低於現行**：每個圖示和現行並排，1 倍下認得出是什麼，而且不比現行難認。
3. **和人物同一把**：圖示旁邊放 `QDoll.stamp` 拿著同一件的人物對照；零件、配色對得上，只加粗。
4. **同類分得開**：把同一類全部的最小尺寸排成一張（含只留剪影的一排），自己找撞圖。
5. **已有素材一定要用**：人物用 `QDoll.stamp`，現行圖示用現行畫法，不另畫簡化版。
6. **每張最終檔都要 Read 看過**；1 倍圖用最近鄰放大逐個看。只靠自查表過關不算完成。
7. **「我看到」照圖寫**：照最終特寫與 1 倍放大圖親眼看到的寫，不照程式的意圖寫；看不清、認不出的照實寫進「仍不好認」清單。
8. 一次整理交件：全部做完才 commit、才回報；紀錄檔要有完整清單、每個的「我看到」、撞圖結果、和人物不一致之處與理由、給開發移植的重點、要美術 PM 決定的事。
9. **字的畫面下限 ≥10 px**（見 3.3）。

## 6. 常被審查退的點（要點；整理自各批審查，逐條原文與表格見歸檔第 6 節）

- 圖示和人物手上不是同一件 → 先讀 `qDoll.js`／`paperdoll.js` 那一件。換題材反而比現行難認 → 和現行並排看 1 倍。圖太小太暗、外框吃掉面積 → 撐滿框（規則 7）、暗零件換亮一階（規則 6）。小尺寸比大尺寸暗、底色吃掉圖樣 → 小尺寸加粗、底色壓暗。
- 含人形的小圖示有臉有衣服 → ≤24px 單色剪影加一個記號。≤14px 塞兩個主體 → 只留一個，成對符號中間留 2 個裝置像素。加粗過頭 → 柄照規則 3 上限。圖樣超出框 → 縮，用 audit 與 1 倍放大檢查。
- 改 Q 版後靠顏色傳達的資訊不見 → 先盤點現行靠什麼區分，做對照讓使用者決定。「我看到」和圖不符、寫了程式的意圖 → 照最終圖、每個尺寸看 1 倍放大再寫，看不到就寫看不到，不用「都」帶過。
- 範圍外的東西混進來 → 只畫派工單列的。某幾款真 1 倍沒外框、像被平滑縮小 → 先查貼法（2.5）。

## 7. 環境規則

- Windows 11、Git Bash。Python 用 `uv run python`（`python` 是商店空殼；要 PIL 用 `uv run --with pillow python`）；Chrome 在 `C:\Program Files\Google\Chrome\Application\chrome.exe`。
- **不開伺服器**，樣張頁用 `file:///` 開。不用 8000（使用者）、8001（本機 LLM）、8010 埠；真要開埠只綁 127.0.0.1，開之前 `netstat` 查。
- **不結束不是自己啟動的程序**：禁止 `taskkill /IM`、`pkill`。無頭 Chrome 用前景執行，拍完自己結束；等待不寫 until 輪詢迴圈。
- 瀏覽器一律靜音（`--mute-audio`，網址加 `?mute=1`）。
- **模型**：畫圖、審查一律 Opus 5.5。
- **不下載外部素材**，全部程式繪製。
- **不 push**。只 commit 在自己的分支；`git add` 指定路徑，commit 前 `git status` 確認只有派工單允許的檔。commit 訊息第一行英文。
- **獨立 worktree**：所有指令在自己的 worktree 裡跑，不 `cd` 到別的 repo 或 worktree。worktree 從 main 切出來時可能沒有要用的樣張，開工第一步照派工單 `git merge --no-edit <指定的 commit>`（用 commit hash，不用分支名），有衝突才停下回報。
- 中途不要停下來回報（worktree 可能被清掉），全部做完 commit 後才回報。
- 暫存檔放派工單指定的暫存資料夾，不放進 repo。
- 改註解不要在一行中間插 `//`（後半行會被註解掉）；用 `/* … */`。
- 回報與文件用繁體中文；程式碼、識別字、commit 第一行用英文。
