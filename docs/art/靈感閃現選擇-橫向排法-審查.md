# 靈感閃現「選變體」橫向排法：審查

> 獨立審查 agent，2026-11-13。只讀，不改樣張。審查對象：commit `31c66c85e`（`sample/flash-choice.html?layout=row｜grid`、`flashChoice.js`、`flashChoice.css`、`tools/flash_choice_shots.py`、`靈感閃現選擇-改版提案.md` 第 11 節、`上手-畫法.md` 4.8）。
> 使用者原話：「閃現選擇畫面的新排法 可以是橫向嗎 畫張樣張」。要求：內容與改字照提案不變；1600、800 各一張；可附直向對照。
> 自己重拍與量測用 `flash_choice_shots.py` 的函式，輸出與 Chrome 設定檔都放在自己的暫存資料夾（無頭 Chrome、`file:///`、網址帶 `mute=1`，沒開伺服器）；審查用的圖存成 `shots/flash-choice/review-row-*`。

## 結論

**有 1 條必修（文件與做法要更正，畫面本身不用重做），其餘通過。** 1600 四張並排、800 四張並排、800 的 2×2 建議版都畫了；字、圖示、字級、四種「後」的記號都和直向版一樣；直向版逐像素沒變；量測數字和截圖、和我重量的結果一致；選中不跳位置。必修的是大標斷行：11.1 與 4.8 寫「已用切詞解決任意斷行」，但做法本身會把單字詞往後黏成長串，壓力情況與 2×2 仍斷在詞中間（「敵／人」「縮小／版」「點燃／斬」），而 4.8 把這個做法當成教給下一個 agent 的方法。

## 必修

1. **大標斷行的做法與文件說法不符**（`review-row-transform-800-x4.png`、`review-row-grid-rows-800-x4.png`、`row-stress-1600.jpg` 第 3 組第 3、4 張、`row-stress-800.jpg` 第 3 組）。
   - 畫面：「打中時把敵／人往外推 1 格，」（800 四張並排）、「打中時把敵人往外／推 1 格」（1600）、「自動補上縮小／版的點燃斬」（800、1600 都有）；2×2 第 4 張「敵人剛被／撞過，／這招多傷一截」右邊空一大塊、「撞過，」單獨一行。
   - 原因：`flashChoice.js` 的 `headBreaks` 把單字詞（時、把、推、版、斬…）一律併進**下一個**詞，切出來的塊太長（用同一段邏輯在 node 跑：「打中時把敵人｜往外｜推 ｜1 ｜格，｜可以｜接撞擊」「補上縮小｜版的點燃｜斬」「敵人｜剛被｜撞過，｜這招多傷一截」）。塊比一行寬時 `overflow-wrap: anywhere` 只能在塊裡任意斷，等於回到原本的問題；「縮小版」「點燃斬」則是被切開後黏錯邊。
   - 要做：(a) 11.1 那句「字不變，只加斷點」後面照實寫「使用者那一組沒問題；壓力情況仍有詞中斷行」，或改好做法再重拍 `row-stress-*`；(b) `上手-畫法.md` 4.8「窄卡的大標斷行」一條同步更正（目前是教下一個 agent 照這個做法做）。改做法的方向（給參考，不限定）：單字詞併進**前一個**詞、塊長超過一行字數時在塊內再插斷點，或直接列一張「不可拆詞」表（技能名、狀態名）。使用者看的 `row-1600`、`row-800`、`compare-row-*` 這一組大標斷得都正常，不必重拍。

## 可修

1. **2×2「前 → 後回到一行」說得太滿**（`row-800-alt.jpg`、`review-row-grid-orphan-x3.png`）：新加的兩列（積水、額外傷害）「後」仍折到下一行，第 4 張還剩「有）」兩個字單獨一行。11.5 第 1 點改成「沒有『新』的列回到一行」，孤字可以在括號說明前插斷點或把括號字縮短處理。
2. **2×2 在 800 是零餘量**：選項區可視 238、內容 238（我重量一樣），面板要的高度 422～425 已超過上限 414、被夾住；直向版是 238／232，還有 6px。字型或任何一列多 1px 就會開始捲。11.5 已寫「剛好」，建議移植需求另外註明這點。
3. **11.5「壓力情況和直向差不多（transform 好一點）」說得太保守**：2×2 是 1.11／1.33／1.19 屏，直向是 1.33／1.39／1.69 屏，rows 與 transform 都明顯比直向少捲。改成照數字說，結論對 2×2 更有利、不影響建議。
4. **11.2 直向卡寬寫「約 696」「約 469」，實量 692、465**（頁面 `data-results` 的 `cards`）。不影響結論，順手改成實數。
5. **對照圖沒寫上下兩排是什麼**（`compare-row-1600.jpg`、`compare-row-800.jpg`、`compare-row-800-alt.jpg`）：頁面只標「直向」「橫向（四張並排）」，使用者要自己猜上排是都沒選、下排是選中第 4 個。在欄標題下加一行小字（例如「上：還沒選／下：選了第 4 個」；這是樣張頁的說明，不是遊戲字），或在給使用者的訊息裡講。
6. **捲動區下緣漏出一條內容**（`review-row-rows-800-x4.png`、`review-row-grid-rows-800-x4.png`、`row-stress-800.jpg`）：漸隱帶下面、分隔線上面還露出約 10px 的卡片（選中卡的金框、「3 回合」「燃燒」的上半）。直向版 `stress-800.jpg` 也一樣，是原本就有的，不是這次造成的；但四張並排時四張在同一條線被切，看起來像一排梳齒，比直向明顯。可以和直向一起交給移植時處理（漸隱貼齊捲動區底）。
7. **800 四張並排在 transform 選中時，選中卡的後半（不用花 AP、燃燒變 ▼2 回合）完全看不到**（`review-row-transform-800-x4.png`）：11.4 第 2 條已寫明「選中的那張沒辦法整張露出來」，判斷正確；建議補一句「看不到的剛好是轉型最重要的代價」，讓使用者選排法時知道分量。

## 通過的項目

1. **品質底線**：沒有幾何占位；圖示全部沿用前批（`diffStack` 用同一個 `r.icon`、`nowChip`，警告三角是第⑦批 HUD 的 `IP.ICON.warn`）；字級和直向窄版一樣（大標 14、前 → 後 12.5、欄位名 12.5，`flashChoice.css` 第 150、153、199 行），1600 是 15／13；邊框、金框、類別細框標籤、單選圈都是直向版那一套，不低於已定案的面板。（`row-1600.jpg`、`row-800.jpg`）
2. **字沒有改**：`optCard` 的 row／grid 分支用同一個 `o.head`、`o.cat`、`o.diff()`，`diffStack` 的「沒有」「→」「新」和 `diffRows` 同字；`headBreaks` 只插 `<wbr>` 與把「數字＋空格」換成不斷行空格。上下固定區（標頭、原技能列、說明、確定、卸下選單）沒動。新出現的只有對照頁的欄標題「直向」「橫向（四張並排）」「橫向 2×2」，是樣張頁的標籤，不是遊戲字。
3. **四種前 → 後的記號在窄卡分得開，含真 1 倍**（`true1x-row-800-x4.png`、`review-row-rows-800-x4.png`、`review-row-transform-800-x4.png`、`review-row-grid-rows-800-x4.png`）：變好＝實心金底（「5 格」「1 回合」「3×3，9 格」）、代價＝細框＋警告三角（「⚠ 4 回合」「⚠ 3 回合」）、變弱＝無底無框＋▼（「▼ 3 格」「▼ 3 回合」）、新＝綠色「新」小圓牌＋底色塊、待資料＝虛線框＋斜紋小標。四張並排時「後」常常換到下一行行首，但「前」是灰字並以「→」結尾、「後」各有底／框／▼，換行後仍分得出哪塊是前、哪塊是後。原 commit 的真 1 倍只有基本那組（沒有變弱），變弱我補拍了 rows 與 transform 兩組。
4. **第 11 節數字和截圖一致**：我重量（`data-results`）的面板高、可視／內容、大標行數、卡寬、卡高，全部和 11.2 兩張表一樣（四張並排 1600：720×425、184／172、1／2／2／2、卡寬 169；800：493×395、219／208、2／3／2／3、卡寬 113；2×2：493×414、238／238、1／2／2／3、卡寬 231；壓力 800 四張並排 262、304、276 對 238／238／212，大標 2／3／2／3、5／6／5／3、1／3／3／5；2×2 263、317、252，transform 捲 50；1600 四張並排面板 456、501、492）。重拍的 `row-1600`、`row-800`、`row-800-pick`、`row-800-alt`、`row-800-alt-pick` 和 commit 裡的檔逐像素相同。
5. **直向版沒變**：重拍 `new-1600.jpg`、`new-800.jpg`，和 `31c66c85e~1`（改動前）的檔做 `ImageChops.difference`，`getbbox()` 都是 `None`。程式上直向分支 `optCard` 的最後一段與 `diffRows` 一行沒改，`.fc-lay-*` 只在 `layout` 不是 `col` 時加上。
6. **選中、都沒選不跳位置**（`review-row-pickdiff-800.jpg`：紅色＝都沒選與選中第 4 個之間有變的像素）：四張並排只有第 4 張的框與字色、下固定區的說明與確定鈕變了，前三張、原技能列、分隔線一個像素都沒動；2×2 也一樣（前三張、上排區域 diff 為空）。面板高取五種狀態最高、下固定區 `min-height` 固定，`need` 數列和截圖相符。

9. **1600、800 各一張、附直向對照**：`row-1600.jpg`、`row-800.jpg`（照要求的四張並排）、`row-800-alt.jpg`（建議版）、`compare-row-1600.jpg`、`compare-row-800.jpg`、`compare-row-800-alt.jpg`，要求都有交到。
