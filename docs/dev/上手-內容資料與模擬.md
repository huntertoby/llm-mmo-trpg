## 二、資料怎麼流

**載入**

1. `load_library()` 依序：第一批表（`KNOWN_CONTENT_FILES` 的單檔）→ 種族與出身 → 規則包 `Ruleset` → 詞條與物品 → 技能與單位 → 地圖 → 大世界 → 一輪與其他。
2. 資料夾型的內容（`skills/`、`units/`、`maps/`、`world/fields/<區>/`…）是**掃 `*.yaml`、依檔名排序**載入，檔名必須等於 `id`。新增一個檔就會被讀到，不必登記。
3. 每個檔用對應的 pydantic model 驗證（拼錯欄位直接報錯），再做跨檔檢查：技能的預算與結構、單位引用的武器／技能／狀態存在、地圖地形與連通性、AI 表引用的狀態存在、大世界的遭遇與任務引用存在。任何問題都拋 `ContentError`。
4. `uv run trpg content check` 就是跑這一整套並印摘要。
5. `ContentLibrary.for_season(season_id)` 會套上 `world/season.yaml` 的當季覆寫；大世界一律用套過的版本。

**加一個技能（不改引擎）**

1. 找一招最像的抄：`content/skills/skill_<id>.yaml`。必填的骨幹：`id`、`schema_version`、`name_zh`、`tier`、`rank`、`rarity`、`kind`、`skeleton`、`category`、`ap_cost`、`shape`、`effects`、`cost`、`tags`、`narrative`、`provenance`；敵人專用加 `enemy_only: true`。
2. `effects[].type` 只能用 `skill_primitives.yaml` 已有的原語；需要新原語就不是內容工作，要動引擎（`src/trpg/engine/skills/primitives/`）並另排段。
3. `uv run trpg skills budget <id>` 看預算比例，要落在合格區間（70%～100%）；`uv run trpg skills show <id>` 看效果摘要。
4. `uv run trpg content check`。
5. 跟著要更新的登記處（CB-2e 加「收霧斬」時實際動到的）：
   - 技能圖示快照 `client/src/render/fixtures/skill_icons.json` 會多一筆：`uv run python -m tests.narrative.icon_fixture` 重產（IP-1 查證：`scripts/export_client_fixtures.py` 寫的是 `unitDolls.json`、`raceLooks.json`、`skillCards.json`，不含它）；
   - `tests/content/test_skill_scaling.py` 的內建招數（目前 402）；
   - 敵人專用招：`tests/skillgen/test_enemy_only.py` 的名單；
   - CLI 快照的 `skills_list`、`skills_show_all` 鍵（見第四節第 2 點）。
6. 要讓某個單位會放：加進該單位的 `skills:`（頭目是 `phases[].skills`）。
7. 行為一致測試：實際跑引擎放一次，驗效果（範例 `tests/engine/test_enemy_skills_149.py`）；要驗 AI 會選到它用 `tests/world/test_enemy_ai_moves_149.py` 的寫法。
8. **圖示道具 `icon_prop`（選填，IP-1，06 6.36）**：寫在 `weapon_req` 下一行（例 `icon_prop: "w:hammer"`），指定技能主圖畫哪個道具；沒填照推導（QI-2a 起推導在後端：`icon_of()` 算出 `SkillIcon.art`＝`prop`／`motion`／`act`／`tint`／`spark`，表在 `content/skill_icon_art.yaml`；`icon_prop` 插在道具第 2、3 列之間，出手照最後的道具重算，所以填了可能改出手，例 `w:dagger` 的單體近戰變 `thrust`）。**化身招（效果有 `enter_form`）與效果帶 `wielding_weapon` 條件的招（含複合第二段）不能填**——圖示固定畫化身／那把武器（QI-2a D4，`skill_checks.py::icon_prop_fixed_problem`）。**只影響圖示**：不進引擎、預算、重播與出題。值只能是 `content/skill_icon_props.yaml` 的道具，而且要和 `weapon_req` 對得上（道具有 `weapon_class` 時技能要同大類或 `any`；中性、元素、召喚、化身、`none` 不限）——由 `load_library` 擋（`skill_checks.py::icon_prop_problems`）。只有 `content/skills/` 能填：劇情技能填了會擋；LLM 提議、白板、工坊草稿的輸入一律先丟掉（`trpg.content.skills.drop_icon_prop`），不算錯。新增道具值要先有美術圖並進美術清單，再加進 YAML。改了要重產技能圖示快照（`uv run python -m tests.narrative.icon_fixture`）與 `scripts/export_client_fixtures.py`（`skillCards.json`）。正式呼叫 `icon_of`／`skill_icon` 要傳內容庫上的表（`icon_art_rules(library)`）；不傳時讀預設內容資料夾（只給測試與快照腳本）。

**加一個單位**

1. `content/units/<id>.yaml`：`id`、`name_zh`、`attributes`、`max_hp`、`speed`、`armor_bonus`、`weapon`、`ai_profile`、`tags`、`skills`、`reactions`、外觀 `doll`；頭目另有 `phases`（第 1 項是開場階段，之後每項帶 `trigger`，例 `{kind: hp_below, permille: 600}`，可換 `skills`、`ai_profile`、加減狀態、改天氣、召喚）。
2. 要在大世界出現：放進 `content/world/encounters/<區>.yaml` 的陣容，或 `content/world/fields/<區>/<地圖>.yaml` 的 `spawns`；元素變體與精英詞綴寫在 `content/world/enemies.yaml`（`variants`，以既有單位為 `base`）。
3. `uv run python scripts/export_client_fixtures.py`（`unitDolls.json` 會多一筆）；外觀的檢查在 `tests/content/test_enemy_looks.py`、`test_ordinary_enemy_looks.py`。
4. 異形（非人形）的畫法與動畫片段在前端，新身形要美術樣張與移植，不是加 YAML 就有。

**加一張戰鬥地圖**

1. `content/maps/<id>.yaml`：`size`、`heights`（每格一個數字）、`terrain`（每格一個圖例字元）＋`legend`、`objects`、`start_zones`（`ally`、`enemy`）、必填 `archetype`；可選 `surfaces`、`weather`、`objective`、`alt_objectives`、`encounter`、`events`。
2. `uv run trpg map show <id>` 用文字網格看一眼；`uv run trpg map list` 看類型與是否有預設遭遇。
3. 連通性與起始區由載入時的跨檔檢查擋；另有 `tests/content/test_map_reachability.py`、`test_map_archetypes.py`。
4. 實地地圖（走路探索用）是另一套：`content/world/fields/<區>/*.yaml`，schema `fields.py`。

**內容 digest 與雜湊（誰用來判斷「內容變了」）**

| 名稱 | 在哪 | 涵蓋 | 用途 |
|---|---|---|---|
| `hash_ruleset(ruleset)` | `src/trpg/engine/ruleset_hash.py` | 內嵌的規則包 | 戰鬥紀錄的 `ruleset_hash`；重播前比對 |
| `ruleset_hash(library)` | `src/trpg/roguelite/save.py` | 全部內容檔（依相對路徑排序的排序鍵 JSON） | 一輪存檔判斷「內容檔已更新，這場從頭開始」 |
| `content_digest(library)` | `src/trpg/world/save.py` | 上一項＋實地地圖＋大世界規則 | 世界日誌的規則鍵 `log_rules_key`（`LOG_FORMAT｜w<WORLD_RULES_VERSION>｜規則包雜湊｜digest 前 16 碼`） |

所以**只改 `content/` 不用加任何版號**：digest 會變，舊的世界日誌自動標成「規則已變、不能重播」，舊戰鬥紀錄因為內嵌了當時的規則包仍可重播。只有規則包的資料結構變了，舊戰鬥紀錄才會因雜湊不符被拒絕（`docs/phases/戰鬥紀錄格式變更.md` 1.2）。

規則包內嵌技能全文，所以**只影響顯示的技能欄位（例 `icon_prop`）也會改變三個雜湊**；新欄位用 `exclude_if=lambda v: v is None` 讓沒填的技能序列化不變（IP-1：36 招填值後三個都變了，重播照樣通過，`tests/content/test_icon_prop_battle_ip1.py`）。

**只給顯示用、沒進規則包的內容檔（例 `skill_icon_art.yaml`）**：`hash_ruleset` 不變（舊戰鬥紀錄照樣重播），但它在 `library.files` 裡，所以**改了 `ruleset_hash` 與 `content_digest` 照樣會變**——使用者重開伺服器後進行中的一輪從頭開始、世界日誌標成不能重播（QI-2a 新增這個檔時一次，之後每改一次表再一次；`tests/content/test_icon_art_battle_qi2a.py`）。證明某個雜湊變動只來自某個檔：`dataclasses.replace(lib, files=[f for f in lib.files if f[0].name != "<檔名>"])` 重算，要回到改前的值（`PhaseQI-2a報告.md` 第 4 節）。

**`trpg sim` 與 `trpg battle`**

| 指令 | 做什麼 | 規模 |
|---|---|---|
| `trpg battle --map <id> --seed <n> [--ally-build …] [--log-json <檔>]` | 一場自動對戰 | 小 |
| `trpg battle replay <檔>` | 重播並驗證一致 | 小 |
| `trpg sim maps [--maps a,b] [--seeds N] [--jobs J] [--ally-build …]` | 每張地圖預設陣容跑 N 場（預設 20）：勝率、輪數、DPR、技能使用、異常 | 指定 1～2 張圖、少量種子時小 |
| `trpg sim skills`、`trpg sim keywords`、`trpg sim flash` | 技能報表、關鍵字抽樣、閃現整輪 | 中～大 |
| `trpg sim matrix [--builds …] [--maps …] [--seeds N]` | build × 地圖，每格預設 30 場 | **大**（不限縮時是全部 build × 全部地圖 × 30） |
| `trpg sim completion [--maps …] [--seeds N]` | 9 種指揮官設定 × 地圖 × 種子（預設 20） | **大** |

`--jobs` 預設 0＝用滿全部邏輯核心；和別的 agent 共用機器時明確給 `--jobs 8` 以下。報表不含時間、結果先依種子排序才彙總，所以輸出與 `--jobs` 無關，可以逐字比對。

**量頭目施放率的做法（`scripts/cb2e_sim.py`）**

1. **走大世界的真實路徑**：`new_character` 建角 → 把 `content/sim/builds.yaml` 的 build 底稿拉到地點建議等級、帶系統傭兵（`default_party`）→ 組一個 `EncounterResult` → `prepare_battle(library, char)` 拿到 `setup` 與 `seed`。不要自己手拼 `BattleSetup`，否則等級、難度倍率、陣容和玩家實際遇到的不同。
2. `run_battle(prepared.setup, prepared.seed, UtilityAI(library.ai_profiles), on_step=watch)`，雙方都由效用 AI 操作。
3. `on_step` 回呼（`_BossWatch`）只看頭目本體的事件：`TurnStarted`（分母：頭目在該階段的行動回合數）、`SkillUsed`（分子，技能 ID 去掉 `_t<階>` 尾碼）、`BossPhaseChanged`（階段）、`ReactionTriggered`、`RoundStarted`。
4. 歸屬規則：只認 `template_id` 等於頭目的單位；頭目回合中途轉階段而那回合還沒放招時，回合改歸新階段。
5. 規模：預設 3 個頭目 × 8 個 build × 10 個種子＝240 場，程序池 `JOBS = 8`。用 `--only mist|ashen|rift` 與 `--seeds` 縮小；結果寫 JSON（`--out`），`report` 子命令可重印成表不必重跑。
6. 門檻（腳本常數）：每回合施放率 < 10%（`LOW_PERMILLE`）標為要處理、< 20%（`OK_PERMILLE`）標為餘裕小；分 build 勝率下限 40%。
7. **前後對照要同種子逐場配對**：`conceal --content <改前的 content 目錄> --out before.json`、改後再跑一次、`compare before.json after.json`；報表列出淨變動與勝負翻轉場數。淨變動 0 不代表沒影響（CB-2e 有一組 64 場淨 0 但 10 場互換）。
8. 寫新的量測腳本時照這個結構：子命令分「跑」與「重印」、結果存 JSON、平行用 `ProcessPoolExecutor`（或 `sim/parallel.py::run_tasks`）、輸出只印摘要表。

**量新手任務一路打過去的做法（`scripts/ob6_newbie_sim.py`，OB-6b）**

1. **直接呼叫純函式 `world_step`，不用 `WorldStore`**：`WorldStore.create` 的角色 ID 與世界種子用 `secrets`，每次不同（CB-2d 同一份內容量到 32% 與 52% 就是這個原因）。腳本自己組 `WorldState(season_seed=…)`、`new_character(…, pending_hero(library), region="cloud_ridge")` 加 `opening=new_opening(seed)`，種子＝`SEED_BASE + 格 × 1000 + i`。
2. 流程：`opening_class` → 接 `starter_ferry` → BFS 一次走一格（盡量避開目標以外的視野，碰到就打）→ 第 1、2 步 → 沿出口走回霧渡鎮 → `opening_confirm` → 延後的三選一一律選第 1 張 → 第 3 步一路走到 `terrace_clash`，路上每一場都打。輸了就停。時間固定（`NOW`），清空的隊伍不重生。
3. 打一場：`prepare_battle` → `begin_battle` → `advance`（`CommandedAI(UtilityAI)`），`on_step` 收步驟並看主角的 `SkillUsed`、`UnitDowned`；再把步驟送 `FightAction`。比 `auto_steps` 再 `_run` 少算一次。
4. **配對**：第 1、2 步與正式選定只跑一次，第 3 步對每個候選內容各跑一次（候選在記憶體裡換：`dataclasses.replace(library, units=…, world_encounters=…)`；內容庫的快取欄位是 `init=False`，replace 後是新的）。對照表列每格的淨變動與「倒下與否」翻轉的人數。
5. `--per-cell` 是「走到第 3 步的人數」：第 1、2 步輸掉的人另列，腳本依序補第 80、81… 個人直到每格分母夠（驗收要求分母 ≥ 80）。
6. 4 格 × 80 人（實際 325 人）`--jobs 4` 約 2 分鐘（OB-6b 實測 126 秒）；冒煙用 `--per-cell 2`，同參數跑兩次 JSON 逐字相同（除了耗時）。
7. **和 CB-2d 的 42% 不能直接比**：舊量測從竹林直接走去梯田（帶著第 2 場剩的 HP、三選一全跳過）；新流程第 3 步前回霧渡鎮正式選定（HP 回滿、屬性重配、兩組三選一選第 1 張），所以第 3 步倒下率掉到 ≤ 8%（`docs/phases/PhaseOB-6b報告.md`）。第 1→2 步之間仍不休息，竹林是帶著渡口剩的 HP 打。

**AI 估值表（`content/ai_profiles.yaml` 的 `status_values` 一類）**

1. 對敵人施加狀態的收益：列在 `status_values` 的狀態＝行為模式的 `damage` 權重 × 等值傷害點數 × 命中率（× 抵抗失敗率）；**沒列的狀態用 `status` 權重，而莽夫 `brute`、側擊 `flanker`、刺客 `assassin` 的 `status` 是 0**（`src/trpg/engine/ai/utility/gains.py`）。持續傷害發生在下一回合、不在預覽事件裡，所以沒列就等於 0 分。
2. 技能代價只扣不補（`scoring.py::skill_cost`，耐力 × `stamina_permille` ＋ 冷卻 × `cooldown`）：和普攻同傷害、只多一個狀態的招，狀態沒估值時永遠輸普攻（BAL-20：T1 餘燼啃咬比同目標普攻少 6 分，幼蜥 0/435 回合）。補上 `burning: 3` 後幼蜥 59%（`docs/phases/PhaseBAL-20報告.md`）。
3. 這是**全域表**：每個帶該狀態的招（`content/skills/` 提到燃燒的約 20 招）與我方由 AI 操作的主角、傭兵都一起變。改一筆要量 ① 施放率、② 我方相關 build 與傭兵勝率（同種子配對）、③ 三頭目每招施放率，並掃 AI 固定種子測試（第四節第 3 點）。
4. 召喚物的技能不跟施放者升階（永遠 T1，`engine/summons`），量召喚物的招時要記得這點；施放者把招「灌注」給召喚物時事件是 `SkillInfused`／`InfusedSkillCast`，只數 `SkillUsed` 會漏掉。
5. 行為一致測試的寫法：`tests/engine/test_ai_burning_value_bal20.py`——用 `score_action` 比同目標的招與普攻，估值從內容檔讀、不寫死，另附「拿掉這筆就輸代價分」的對照組。

## 三、必守的規矩

1. **內容即資料**（守則 4）：新增內容不改引擎；非改引擎不可的（新原語、新觸發條件、新階段觸發種類）要在報告寫明並另排段。
2. **內容該是什麼不是實作者決定**：數值、招式組、台詞照規格或玩法 PM 的定稿；規格沒給的原型數值照最保守的預設做完，寫進報告「待 PM 決定」（守則 11）。**不要反覆手動試數值**：寫腳本輸出摘要表，把建議值交給 PM。
3. **`extra="forbid"`、`frozen=True`**：schema 加欄位要給預設值（否則每個既有檔都要補），並想清楚會不會改到規則包的序列化（見第二節 digest 表）。
4. **`*_zh` 是繁體中文**；識別字、欄位名用英文；檔案 UTF-8、LF 行尾。
5. **載入順序與排序是確定性的一部分**：資料夾依檔名排序；程式裡要順序就 `sorted`，不依賴 `dict` 以外的容器順序。
6. **技能預算**：內建技能的比例要在合格區間；例外只能登記在 `tests/known_budget_exceptions.py`（要有玩法決定的出處）。
7. **玩家技能池一律經過 `player_pool`**：敵人專用招（`enemy_only`）不能進玩家的池；`tests/test_architecture.py::test_player_skill_pools_go_through_player_skills` 會掃直接迭代 `library.skills` 的寫法。改到技能池的段要跑 `tests/test_architecture.py`。
8. **模擬的節制**（守則 11、`docs/開發PM交接.md` 6.6）：
   - `trpg sim completion`、`trpg sim matrix` 全量、`scripts/balance_baseline.py` 除非規格要求否則不跑；規格要求時「只在最後跑一次」。
   - PM 跑全量 `check.py` 期間不跑模擬（互搶 CPU）；不確定就先問。
   - 輸出用安靜模式，只把摘要表寫進報告；完整 JSON 放暫存區，不進 repo。
9. **改了 AI 表或技能數值就是平衡變更**：要附模擬摘要（守則 8），並列出因此改動的固定種子與快照。
10. **量測腳本放 `scripts/`**，受 `scripts/ruff.toml` 檢查；一次性的在結案後搬 `scripts/archive/`。
