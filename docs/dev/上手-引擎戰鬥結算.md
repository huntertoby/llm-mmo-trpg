## 二、資料怎麼流

**一個動作的結算**

1. 呼叫端拿 `legal_actions(state)` 列出的 `Action`（或自己組一個）送 `resolve(state, action)`。
2. `resolve` 先 `acting_unit(state, action)` 驗行動者，再進 `resolve_with(base, action, decisions=())`。
3. `resolve_with` 建 `Ctx(base.clone(), …)`——**傳入的 `state` 不會被改**；用 `ACTION_HANDLERS[action.type]` 找到 `_do_*`。
4. `_do_*` 檢查合法性（不合法拋 `IllegalActionError`）、扣 AP，組出效果丟進 `effects.queue.execute(ctx, effects)`。
5. `execute` 逐一取出效果，`handler_for(kind)` 找處理函式（`effects/handlers.py` 的 `_damage`、`_heal`、`apply_status`…），處理函式改 `ctx.state` 並回傳事件；每個事件再經 `triggers.effects_for(ctx, event, depth)` 換成後續效果入列（連鎖深度有上限，數值在 `content/rules/core.yaml`）。
6. 技能走 `_do_use_skill` → `skills/interpreter.py::use_skill` → `Cast`（`skills/cast.py`）：選取 → `_pay_costs` → 每個效果用 `primitive_handler(kind)` 轉成效果模型 → 同一個佇列。
7. 結束時 `finish_resolution(ctx)`（`turns.py`）：檢查頭目階段、勝負、把亂數狀態寫回 `state.rng_state`，回傳 `ResolveResult(state, events, pending=None)`。

**暫停點（pending）**

- 結算途中需要玩家回答（`prompt` 反應、複製技能、複合技能第二段）時拋 `PauseForDecision`；`resolve_with` 接住，把「原始狀態 JSON＋動作 JSON＋已回答的決定」存進 `state.pending`（`PendingResolution`），回傳帶 `pending` 的 `ResolveResult`。
- `resume(state, decision)` 從 `pending.base_state_json` 還原，**把整個動作連同累積的 `decisions` 重跑一次**，只回傳暫停點之後的事件。所以處理函式裡暫停點之前的程式會被執行不只一次，必須每次結果相同。
- `Pending.kind` 有 `reaction`、`copy_skill`、`followup` 三種。

**部位分流**（PB-1a，05 5.12.2；`parts.py`、`part_breaks.py`）

1. 動作 `Attack`／`UseSkill` 帶 `target_part`（沒選不輸出）。`resolve` 在既有檢查之後呼叫 `check_target_part`：能不能選由 `part_targets` 判（宣告時判一次，R5）——召喚物、蓄力武器普攻、非單體或對目標沒傷害的技能、複製施放整個不行；部位已破、`exposed_in` 不含目前階段、`behind`（近戰且站在 `back_xy`）、`high_or_far`（高 ≥ 1 層或曼哈頓距離 > 3）、`disabled`（倒地、暈眩、冰凍）逐個判。
2. 普攻：`perform_unit_attack(..., part_id=)` → `_attack_once`：命中用 `defense_view`（部位有 `armor_bonus` 才換），`DamageEffect.part_id` 帶上；連擊武器每一下、詞條連擊都帶；穿透後方、守護者攔下的打本體。技能：只有 `interpreter._resolve_cast` 把 `cast.part_id` 設成動作的 `target_part`（第二段、延遲段、複製、灌注、被動都不帶），`Cast.part_for(unit)` 只對主要目標回部位 ID（`roll_one` 換護甲、`attack_damage` 帶 `part_id`）。
3. `_damage`：沒有 `part_id` 走原路徑；有的話元素修正用 `element_view`，扣完 HP 發 `damage_dealt` 後**緊接著** `part_damaged`（扣頭目實際扣掉的 HP，扣 0 不發）、降到 0 發 `part_broken`（那一下頭目倒下時 `applied: false`）。
4. `part_broken` 觸發 `BreakPartEffect`，處理函式直接呼叫既有的 `apply_status`／`remove_status`／`cancel_charge` 處理函式（事件照常回到佇列觸發）。封招進 `sealed_skills`（`skill_problem` 擋）、能力下降進 `part_mods`（讀點：`rules/statuses.py::move_points_for_turn`、`damage_dealt_permille`，`rules/combat.py::defense_value_permille`、`roll_attack` 的命中、`element_modifier_ppm`）、停機制進 `suppressed_statuses`（`apply_status` 入口跳過、不發事件，所以換階段的 `add_statuses` 也加不上）。
5. 沒有部位的單位這些欄位全是空值、序列化不輸出；PB-1a 比對 46 場 `different=0`、狀態 JSON 逐字相同。

**連擊武器的單體武器技**（DD-1，#153，08 8.11；`skills/cast.py`）

1. `skills/targeting.py::skill_strikes(caster, skill)`：`category: weapon`、形狀 `single` 時回手上武器（`held_weapon`）的 `strikes`（雙匕首 2），其他 1。`Cast.strikes` 只在 `modified` 的施放（主動、姿態、反應技、複製、第二段）用它，被動與陷阱觸發一律 1。
2. `Cast.run`：第一下照舊（`roll_hits` → 全部效果）之後 `extra_strikes()`：目標還活著就 `roll_one(target, extra=True)` 再擲命中（預覽時同普攻的後續幾下：最少後果失手、最多後果暴擊；`backstab_first_only` 的武器不算背刺；形態進入獎勵在 `form_bonus` 暫存後再吃一次），命中就重打每個 `damage`（`affects` 是 enemies／all）效果——`resolve_effect(effect, extra=True)` 不再做元素觸及格子與風的擴散。
3. 附加效果只一次：前面某一下已命中就不再結算；前面都沒中、這一下才中，就在這一下結算對敵人的非傷害效果、`consume_target_stacks()` 與賭注。賭注分支的 `self_damage_of_hit`（DD-1b，08 8.11 細節 6）在會多打時（`repeated_damage()` 非空）先記進 `deferred_hit_backlash`，`extra_strikes()` 之後由 `settle_deferred_hit_backlash()` 以賭注擲骰後全部幾下的傷害總和結算；不多打時 `deferred_hit_backlash` 是 `None`，照原位置結算。結算完把 `hits` 合併成「任一下命中」，再算冷卻修正；`backlash_on_miss`、`react_to_hits`（每個目標仍只反應一次）、第二段的「命中」判斷都看合併後的結果。
4. 預覽 `_damage_expectation` 的期望值 × `skill_strikes`（每下命中率、暴擊率相同）；效用 AI 的傷害收益吃這個期望值，所以不必另改 `ai/`。

**近戰轉向的例外**（BS-1，#157；`quiet_strikes.py`）

1. 一般規則：`after_attack(..., turns=...)` 在一次攻擊或施放結算完讓被近戰打到的單位轉向攻擊者。`turns` 來自普攻的 `perform_unit_attack`（第一下的 `victim`）與技能的 `Cast.melee_victims`（`roll_one` 記，連擊的後幾下不記）。
2. 例外在**記的時候**擋：`no_turn_reason` 有值就不記（隱蔽是命中判定之前判斷，因為 `after_attack` 才移除隱蔽）。守護者攔下時原本「把最後一筆換成守護者」也只在沒有例外時做（守護者也不轉）。
3. 無聲＝修正規則 `silent_strike`：`modifiers.silent_strike(state, unit, use)` 查 `_applicable(..., "silent_strike")`＋`unit.weapon.id in SILENT_WEAPONS`（`dagger`、`dual_dagger`；形態中的天生武器不算）。`unit_rules` 改讀 `unit.all_skills`，所以 `grant_skill` 暫時給的「只有無聲」的修正技能（`is_silent_grant`，影纏給無聲步）也生效。
4. 紀錄與預覽：`attack_rolled.no_turn`（`exclude_if` None，沒例外時 JSON 不變）；`Preview.no_turn`／`no_turn_reason` 與 `notes`「背刺・無聲（不會轉身）：X」；戰鬥紀錄文字尾巴加「［背刺・無聲（不會轉身）］」（`narrative/events.py::_no_turn_note`）；API `PreviewOut.no_turn`、`no_turn_reason`（`| None = None`，前端型別不變成必填）。
5. AI：`ai/parts.py::silent_behind_extra` 在 `position._facing_terms` 加分（`facing:` 表的 `silent_behind`，持有無聲、站在相鄰敵人背後格時每名加一次）。

**連擊武器「每一下都命中」**（DD-3，#158；`skills/cast.py`）

1. 效果條件 `all_strikes_hit`：帶它的效果在第一輪 `resolve_effect` 與 `_strike_effects` 都跳過（`after_all_strikes`），`extra_strikes()` 打完、每一下都命中原本的目標（`self.redirected` 沒被守護者攔、`enemies[0] is original`、打滿 `strikes − 1` 下）才 `settle_all_strikes()`：設 `all_strikes_landed`、結算那些效果一次。`Cast.holds` 對這個條件回 `all_strikes_landed`；`condition_met` 在施放以外一律 `False`（預算、AI 估計看不到）。

**回合與環境**：`_do_end_turn` → `end_turn` → `advance_turn`；全員行動完走 `_end_round`（環境回合、勝利條件、輪數上限）→ 下一輪。這些事件都在同一次 `resolve` 的 `events` 裡。

**自動對戰與重播**

- `run_battle(setup, seed, policy, decide=…, on_step=…, controllers=…)`：`begin_battle` 開場，之後交給 `advance` 迴圈；`policy` 是 `(state) -> Action`（`choose_action` 或 `UtilityAI(library.ai_profiles)`），只剩 `EndTurn` 時自動結束回合（`has_only_end_turn`）。
- `BattleRun.to_log()` → `BattleLog`（`format`、`ruleset_hash`、`seed`、`setup`、`actions`、`events`、`final_state`）。
- `replay(setup, seed, steps)` 用同一個引擎把步驟再跑一遍；CLI 的 `trpg battle replay <檔>` 會比對事件與最終狀態。

**AI 怎麼選招（施放率的來源）**

1. `UtilityAI.__call__(state)` → `rank(state)`：列 `legal_actions`，每個技能先用 `skill_estimate`（不跑引擎）排序，只留前 `skill_candidates` 個；移動只留 `move_candidates` 個。
2. 留下的候選跑 `preview` 再 `score_action`：分數＝預覽收益＋命中率 × Σ 權重 ×（動作後位置價值 − 動作前位置價值），全部用 `Fraction`。
3. 取分數最高且為正的；沒有正分就結束回合；平手照 `legal_actions` 的順序。
4. 行為模式取 `UnitState.ai_profile`（頭目換階段時由 `boss_phases._enter` 換掉）。
5. **部位變體**（PB-1b，`ai/parts.py`）：`rank` 的最後由 `_with_parts` 展開——行動者是玩家方、不是召喚物（R9），而且場上有帶部位的單位時，已評分的普攻與單體技能候選後面緊接著放每個 `part_targets(...).ok` 的部位變體（依部位 ID；在 `skill_candidates` 截斷之後才展開，不擠掉本體候選）。變體分數＝自己的預覽分數＋`part_score`（`on_break` 各項在 `ai_profiles.yaml` `parts:` 的價值 ×（最少後果的 `part_damaged` ÷ 部位剩餘血量，上限 1）；最多後果能破、而且能封頭目下一招或打斷蓄力時加 `priority_bonus`）。排在本體後面，所以同分打本體。沒有部位的戰鬥 `_with_parts` 原樣回傳。頭目那邊：`position._facing_terms` 的 `back_exposed` 在 `reach: behind` 的部位快破（≤ `near_break_permille`）時多扣 `guard_back_bonus`（這兩個值由表格的 `parts:` 填入每個行為模式的 `weights`）。**繞背**（PB-1b2）：`_facing_terms` 另加 `ai/parts.py::circle_back_extra`——玩家方、近戰（`weapon.is_melee`，同背刺）、不是召喚物的單位站在頭目背後格，而且頭目有 `reach: behind`、目前階段已露出、還沒破的部位時加 `circle_back_bonus`（每名頭目一次；同樣由 `parts:` 填入 `weights`）。它是位置價值的一項，所以移動候選的排序（`virtual_move_score`）也吃得到；藉機攻擊、危險表面等照常扣，不另做安全判斷。
6. 某招幾乎不放，通常是：便宜估計把它排到候選外、收益表沒有它施加的狀態（`status_values`／`ally_status_values` 沒那一筆就當 0 分）、或條件要等人走進範圍。量法見 `docs/dev/上手-內容資料與模擬.md` 的 `scripts/cb2e_sim.py`。

## 三、必守的規矩

1. **確定性**（守則 1、2）：引擎內亂數只從 `ctx` 上的 `Rng` 取；`tests/test_architecture.py::test_no_nondeterministic_apis_in_deterministic_packages` 會掃 `random`、`uuid4`、讀時間。要順序就排序，不迭代 `set`、不用內建 `hash()`；百分比用整數千分比或 `Fraction`，不用浮點。
2. **依賴方向**（守則 5）：`trpg.engine` 目前只匯入 `trpg.shared` 與 `trpg.content`；`pyproject.toml` 的 import-linter 合約另外禁止它匯入 `trpg.world`（守則 5 的清單之外多這一個）。`lint-imports` 與 `test_dependency_direction` 都會擋。
3. **不改傳入的狀態**：處理函式只動 `ctx.state`；要試算用 `simulate_preview`／`simulate_branch`，不要自己 `clone` 後呼叫 `resolve`。
4. **`state.py` 加欄位要同步三處**：dataclass 欄位、該類別的 `clone()`（手寫逐欄）、序列化（`state_to_json` 走 pydantic adapter，新欄位要有預設值）。`tests/engine/test_state_clone.py` 檢查 `clone` 有沒有漏。
5. **`LOG_FORMAT` 何時加一**（`runner.py`；全文在 `docs/phases/戰鬥紀錄格式變更.md` 第 1 節）：
   - 要加：事件、動作、決定、`BattleState`、`BattleLog` 的欄位增減或改型別；同樣的規則包與步驟新舊引擎算出不同結果（結算規則、事件順序、**亂數取用次數**）。
   - 不加：只改 `content/` 的內容或數值、`Ruleset` 加有預設值的欄位、只改文字與介面。
   - 加的時候：改 `LOG_FORMAT` 與它下面那行說明、在 `戰鬥紀錄格式變更.md` 加一條、更新測試裡寫死的版號字串（PR-1 當時有 12 處，用 Grep 找 `trpg-battle-log/`）。另有 3 個重播測試寫死 `LOG_FORMAT.endswith("/1xx")`（`tests/engine/` 的 `test_collided_sacrifice_firearm.py`、`test_self_costs.py`、`test_wind.py`，用 `grep -rn 'endswith("/1' tests` 找），要確認重播仍一致後一起改成新版號；它們不在一般會跑的直接相關測試裡，漏改常到全量才發現。
6. **新事件型別**要加進 `events/union.py` 的 `Event`，並決定對各陣營是否可見（`event_filter.py`）；前端的事件是任意 JSON，要顯示得另外在 `client/src/api/types.ts` 手寫窄化。
7. **預覽不能有副作用**：`Ctx.preview` 不為 `None` 時不擲真骰（`FixedRng` 回最小或最大值）、不暫停、不檢查頭目階段、不做測試模式的過輪。加新的分歧點（擲骰、檢定）要走 `ctx.check_d20`／`ctx.mark_branch()`，否則 `simulate_preview` 會以為「最少」「最多」相同而少跑一次。
8. **只在特定戰鬥生效的規則不放 `Ruleset`**：測試模式的旗標放 `BattleSetup.practice` → `BattleState.practice`，`None` 時每個分支都不走，規則包雜湊不變（`practice.py` 檔頭）。
9. **複雜度**（守則 12）：`ruff` `C901` 上限 15；新增複雜度類 `# noqa` 要在報告逐一說明。
10. **行為一致測試**：規則句（看什麼屬性、花什麼資源、誰能抵抗）要有「實際跑引擎」的表格測試，不只測資料（`docs/開發PM交接.md` 6.2 第 1 點）。

## 四、常踩的坑

1. **暫停點之後才做的事要放在 `resolve_with` 的 `try` 裡**。PR-1 的規格原本要在 `finish_resolution` 做測試模式的自動過輪，但換手時的 `start_turn` 可能再拋 `PauseForDecision`，而 `finish_resolution` 在 `try` 外，會變成沒人接的例外；實際改成 `practice_pass_round`、放在 handler 之後的 `try` 內。（`docs/phases/PhasePR-1報告.md` 第 2 節）
2. **讓單位倒下只有一條路**：`unit.downed = True` 只在 `lifecycle.down_unit` 裡；呼叫點全在 `effects/handlers.py`（`_damage`、`_share`、`_redirect`）。要擋倒下（免死、測試模式的 `hold_standing`）得三處都處理，順序是免死先、`hold_standing` 後。其他改 HP 的路徑（`gear/core.py`、`skills/targeting.py::pay_skill_cost`、`forms.py`）不會倒下。（同上第 4 節）
3. **「最近的空格」要用既有的 `rules/landing.py::nearest_free`**（曼哈頓距離，同距離依 `y` 再依 `x`），不要自己寫一個用 `set` 或亂數的版本。（`docs/phases/PhasePR-1b報告.md` 第 2 節）
4. **資源補滿不發事件**：測試模式的補 HP、法力、裝備充能是直接寫狀態，沒有 `Healed`、`stacks_changed`，也不觸發超載；畫面要讀結算後的狀態，不能等事件。只有冷卻歸零會發 `skill_cooldown_changed`。（PR-1 報告第 7 節、PR-1b 報告第 5 節）
5. **引擎自己過輪時步驟列表不會多一個 `EndTurn`**：結果事件裡直接有 `turn_ended` 與下一位的 `turn_started`，重播照樣對得上；不要在 API 層再補送 `EndTurn`。（PR-1 報告第 7 節）
6. **動到 AI 估值表會改掉別的測試的固定種子**。CB-2e 只在 `ally_status_values` 加 `concealed: 2`，就讓 `tests/engine/test_displace_ai.py` 與 `test_hurl_object.py` 兩場「某個種子會放出某招」的測試不再成立，也讓 `test_support_ai.py` 的全表比對失敗。處理方式是掃種子換一個仍會發生的（斷言與重播比對不放寬），並在報告列出。（`docs/phases/PhaseCB-2e報告.md`「快照與改動的測試」）
7. **錐形、要等人走進身前的招，在空地圖的 AI 測試量不到**：`skill_thunder_clap` 在兩名英雄、40 個種子的空地圖一次都不放，改用正式地圖的測試驗。寫「AI 會選到某招」的測試前先想清楚場地。（同上「行為一致測試」）
8. **頭目階段的回合歸屬**：頭目在自己的回合中途轉階段、那回合還沒放招時，回合要歸新階段；源晶柱這類同陣營單位也會發 `BossPhaseChanged`，統計時只認頭目本體（`template_id` 比對）。`scripts/cb2a_sim.py` 就算錯過。（同上「模擬腳本」）
