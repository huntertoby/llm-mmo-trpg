## 一、這一塊在哪些檔

路徑都在 `client/src/` 底下（另註的除外）。原則：**`battle/` 是純函式（算要畫什麼、什麼時候畫），`render/` 是 PixiJS（照著畫），`ui/`、`screens/` 是 React。**

## 二、資料怎麼流

**從點擊到畫面**

1. 玩家點格子 → `BattleCanvas` 把 client 座標用 `clientToTile` 換成格子 → `battle/tileClick.ts` 的規則決定是選取、行動還是釘資訊卡。
2. 要行動 → `useBattleActions` → `usePlayback` 鎖住操作、呼叫 `api`（`POST /api/battles/{battle_id}/actions`，回答暫停點用 `/decision`）→ 拿到 `BattleResponse`（`initial_view`、`steps[]`、`view`）。每個 step 帶這一步的事件與該步之後的 `view`。
3. `playbackPlan(res, …)` 把 `steps` 排成 `Frame[]`。每一步固定的順序：標示行動者 → 移動動畫 → 技能特效（蓄力、飛行，等到命中）→ 畫該步的 `view` → 地形升降 → 地圖回饋 → 加紀錄 → 停頓。
4. `usePlayback` 逐格 `frameOps(frame)` 取 `PlayOp`，交給 `BattleRenderer`（`motionLayer`、`skillLayer`、`vfxLayer`…）播放。
5. **播完一定以 `res.view` 重畫**。動畫只是過場，任何「看起來的狀態」都不能留到下一步。
6. 畫靜態畫面：`buildDrawModel(view, …)` → `DrawModel` → `BattleRenderer.draw(model)`。
7. **測試模式（`view.practice`，#147）的戰場畫法**（PR-2c）：`buildDrawModel` 只在 `view.practice` 為真時多一個 `DrawModel.practice`（`practiceSceneOf(view.map_id)`：滑軌、水池範圍），`BattleRenderer.draw` 畫完地形格後呼叫 `drawPracticeScene`——水面每格一塊方角的水（地形層，蓋掉原本圓角的水面）、外圈石條與滑軌（表面裝飾層，**石條放在它壓到的那一排**，那一排的人站在它上面）。實戰、技能工坊（3F）沒有這個鍵，畫法不變。木樁的新外觀不看旗標（3F 也換，PR-2 第 8 點）；木樁在 `unitDrawOf` 帶 `noBar: true`。HUD 的測試模式分支是 PR-2b 的事。
8. **點有部位的頭目**（PB-1c；R1 普攻也算、R6）：伺服器 `BattleResponse.part_options`（`legal_actions` 裡目標有部位的普攻與單體技能，各帶 `options`：`part_id`、`ok`、`reason_zh`）。`battle/tileClick.ts` 要送出的普攻或瞄準單體技能對到 `part_options`（`partOptionsFor`：種類＋技能＋目標）時回 `part_menu`，`useTileInteraction` 開 `PartMenu`；選了部位就在原動作加 `target_part` 照原本的 act／submit 送出。**選單開著時按下滑鼠就關了**，所以 `.battle-board` 的 `onPointerDownCapture`（`onBoardPointerDown`）先記下開著的選單目標，點擊規則看它：再點同一個頭目＝本體，點別處只關選單。選單開著時格子資訊卡不顯示（會蓋住選單）；`BattleCanvas` 標 `aria-expanded`。選取（滑過列、方向鍵）時 `sel.setPanelPreview` 預覽帶部位的動作，`previewText.partPreviewLines` 多一行「拂塵還剩 12」。破壞的占位演出：`specials.ts` 的 `part_break`（那一下頭目的受擊升級成重擊片段＝重擊白閃，停頓 `PART_BREAK_STOP_MS` 70）＋`impact.ts` 一次重擊微震＋`feedback.ts` 浮動字「{部位} 破！」；紀錄 `part_broken` 的 tone 是 `break`（紅叉＋粗體）。頭目資訊被隱藏時伺服器就把部位 `hp`／`max_hp` 與 `part_damaged` 的剩餘血量改成 null（`api/hidden_info.py`），前端一律畫「未露出」、不寫數字。
9. **測試模式的 HUD**（PR-2b）：分支點一律是 `view.practice`（`BattleScreen` 的 `shown.practice`、`BattleBottomBar`／`ModePanel` 的 `view.practice`），**實戰分支的輸出和改前逐字相同**（`battle/pr2bPractice.test.ts` B 組鎖住）。上方中央 `PracticeBar`（`TestModeBadge`＋定稿句）取代 `TurnBar`；右上勝利條件換成「沙盒・不算勝負」，輪數照舊；回合操作沒有「結束回合」（自然收合、靠底）；技能鈕不寫冷卻；預覽總覽行拆成各自不換行的段、多一行必中句；前端自寫的操作提示句過 `practiceWording`（伺服器給的技能說明不過）；紀錄在 `BattleScreen` 先過 `practiceRoundLines` 再交給 `BattleLogDock`（浮動提示與完整清單都看得到）。版面量測的「上方中央」選擇器是 `ORDER_SELECTOR`（`.turn-bar` 或 `.practice-bar`）。PR-2d 補：提示條上的徽章說明卡傳 `PRACTICE_BADGE_HINT_ZH`（`TestModeBadge` 的 `hint`；一輪測試模式的三處不傳、原字不動）；開場橫幅（`BattleBanner`）只有 `PRACTICE_BANNER_ZH` 一行＋開場訊息；召喚物面板前端自寫的字過 `practiceWording`；高亮格與紅框貼水池往內縮一個石條寬（`practiceRange.poolInsets`，實戰沒有 `model.practice` 時不縮）。D 組測試 `battle/pr2dPractice.test.ts`。
10. **靶場的兩種戰鬥**（PR-2b，`WorldScreen` 的 `rangeFight`）：`trial`＝選大類／正式選定／重選畫面的「拿起試打」「看示範」（離開鈕「回到靶場」、開場訊息「靶場試打：{武器}＋{招 1}、{招 2}」）；`practice`＝工坊師傅的「靶場試玩」（「離開靶場」、只寫標題、地名讀 `WorkshopView.capital_zh`、回主城時面板關著）。兩種離開時都先 `DELETE …/range/trial`（`api.worldRangeTrialClose`）。

**單位動畫片段怎麼挑**

- 人形：`viewGrip.weaponClassInView`（從這一步開始前的 `view` 的裝備算）→ `skillClips` 依武器類別給起手／出招片段；普攻另依 `attackFamilyInView` → `skillSequence.variantFor(family, battleKey, seq, casterId)` 用 `variantHash` 挑變體。技能卡上的原語決定出招前後要不要插原語片段（`primitivesOf`）。
- 異形：`creatureActionOf({basic, skillId, primitives, shape, strikeClip, dist, range, weaponRange})` 依序判斷——召喚 → 位移 → 衝鋒原語 → 錐形＝吐息 → 指定招 → 其餘照現行。普攻一律 `melee`。走到「其餘」時看**技能本身的射程**（CB-3c，`isMeleeSkill`）：射程 1、跟武器（施放者拿近戰武器）、或等於施放者近戰武器的射程才算近戰技能，形狀 `single` → `melee2`（不看施放當下的距離）；射程比近戰長的法術貼身放 → `cast`（和隔著距離放同一個施法片段）；射程不知道（卡上沒有）時照 CB-3 的舊判定（`single`＋相鄰 → `melee2`）。射程來自技能卡（`icon.segments[i].range`，跟武器時 `stats.range_weapon`）；近戰武器射程來自 `/api/glossary` 的 `weapon_ranges`（`battle/glossary.ts` 的 `meleeWeaponRange(unit.weapon_id)`）。再由 `attackClipFor(身形, 類型)` 找片段；身形沒有第二種、或是頭目時退回第一種。
- 挑法**只看這一步的事件與畫面資料，不用亂數、不讀繪製器狀態**，所以重播、觀戰、重新整理都挑到同一個片段。
- 片段的時間：`skillTimeline` 排出 `SkillRow`（起手 → 出招前原語 → 出招 → 出招後原語 → 收勢），近身以「出招命中那一刻＝特效命中」對齊，遠程以「放出那一刻＝飛行物離手」對齊；整招上限 `SKILL_CAP_MS`，連鎖與換人前停 `CHAIN_GAP_MS`。
- 異形第二種近戰的 5 個片段照自己的格數播（12 格／秒，`creatureOwnFrames`、`ownFrameU`）；其餘片段是 12 格量化（`quantizeClipU`）。

**特效落點怎麼算**

- 一律用「世界座標」（未抬高的格子座標）加 `tileLift`：格子中心取 `liftedCenter(pos, height)`；畫布座標＝世界座標往下移 `topReserve(grid)`。不要自己乘 `RAISE`。
- `vfx.ts` 的特效描述帶的是格子（施放者、目標、範圍格）；`vfxLayer` 畫的時候才換成像素。地上的特效（`clip: "map"`）裁在地圖矩形內，跟著人的（蓄力、刀光、飛行物、受擊、浮動字）不裁。
- **異形片段自帶的特效**（白弧、星爆、掃尾 `sweep`、塵土）是 `qCreaturePartPose` 給的「異形自己的側面座標」（朝東、腳底為原點，相鄰目標在 x ＝ 52，`CREATURE_FX_TARGET_X`），在 `inkCreature.drawCreature` 裡**和身體一起畫進身體貼圖**，貼圖跟著 `creatureSide` 左右鏡射。異形只有東、西兩面；出招時用 `creatureFacingTo`（只看目標偏東或偏西，同一欄維持原朝向）。所以 CB-3c 以前，目標在正南、正北時特效畫到側邊的空格，站最右欄（或最左欄）又朝外時畫到地圖外被裁（身體貼圖 176×136 也放不下往南北一格的特效）。
- CB-3c 起同一欄、**CB-4 起正南北與四個斜向（含頭目）**：目標不在同一排時（`creatureFxTurnOf` 回方向 `FxTurn` ＝ {x: sign(dx), y: sign(dy)}，同一排回 `null`），姿勢帶 `fxTurn`，身體貼圖不畫特效（頭目是 `drawBossFrame` → `bossAct` 的 `noFx`）；`skillLayer.placeTurnedFx` 另放一張特效貼圖（`ArtTextures.creatureFx` → `inkCreature.renderCreatureFxCanvas`，畫布 `CREATURE_FX_BOX` 240×300、腳底 200），放在這一列的效果節點（效果圖層，蓋在目標之上、這一列結束跟著移除），原點在**目標方向的相鄰格中心**（斜向＝斜對角那一格，跟著那一格抬高）。轉法在 `render/creatureFxTurn.ts`（「剪切」）：以「相鄰目標」那一點為原點，u ＝ x − 52 → (|方向 x| × u, y ＋ 方向 y × u × `fxTurnScale`)：同一欄時橫向收到中線（＝CB-3c 的公式，`cb4FxAnchor.test.ts` 逐筆比對）、斜向橫向距離照舊；異形自己（u ＝ −52）往回一格、高度不變；貼圖照 `creatureSide` 鏡射；形狀不轉、只搬位置。頭目的特效取自 `qBoss.bossPoseFx`（不含 `ranged`），大小用 1（`inkCreature.fxSizeOf`）、戰場縮放 1.6。東西向照舊畫進身體貼圖（鍵與畫法都沒變）；**CB-4b 起頭目東西向**：`drawBossFrame` 沒有轉向時傳 `sameRow`，`bossAct` 先過 `qBoss.bossSameRowFx`——只有灰燼之心 `ram` 改：星爆水平放在目標格中心（`BOSS_EW_TARGET_X` ＝ 52 ／（`DOLL_SCALE` × 1.6）≈ 30.66 單位＝48 px，高度照片段）、塵土照剪切跟著目標格（往施放者側 8 單位≈12.5 px）；其他片段、碎晶之主原樣（`bossPlan`、命中對齊、轉向的 `bossPoseFx` 都沒改）。姿勢鍵只在有轉向時多 `fxturn<x>:<y>`。

**被遮擋外框（OCL-1a）**

- **什麼時候算**：`BattleRenderer.draw` 畫完全部單位後呼叫 `drawOcclusion`（擺位改變才算；待機換貼圖不重算）。照畫的順序（由北到南、同一排照 `units` 子節點，頭目先畫）收集擺位 → 被擋者先過濾（倒下、`hiddenInfo`、`concealed`，不呼叫任何遮罩）→ 前排＝畫在它之後、南邊 0～3 排、外接矩形相交、身體面積 ≥ 4000 模型 px²、沒倒下 → 模型像素算比例 → 遲滯（沒畫時 ≥ 55%、畫著時 < 45% 才拿掉；`outlineWas` 跨 `draw` 保留）。要畫的才做貼圖：被擋者身體（畫面解析度）上算色帶，裁切照畫的順序疊（大型前排加、之後的小兵挖掉），Sprite 放 `silhouettes`、`tint`＝`RING[team].stroke`、`alpha` 0.8。
- **快取鍵**：身體 alpha `om|<res>|<身體鍵>`（模型像素用，res＝k，1 畫布 px ＝ 1 模型 px）、`oa|<res>|<身體鍵>`（畫面解析度，res 同身體貼圖）——`ArtTextures.alphaMask`，同一鍵只 `getImageData` 一次；模型像素遮罩照「小數位置」快取、整數部分只平移；外框貼圖 `ol|<res>|<身體鍵>|w:<線寬>|i:<襯邊>|c:<裁切雜湊>`（線寬、襯邊是貼圖 px、量化 0.25）。`setScale` 只重建外框貼圖（`rebuildOutlines`），比例與遲滯不重算。
- **舊剪影規則**（6F-22，D5）：`legacySilhouetteWanted(被地形擋, 有新外框)`——同一單位這一格有新外框就不畫舊剪影；`drawUnit` 不再自己畫，改在 `drawOcclusion` 最後決定。
- **大型前排的預篩**（OCL-1b，PM 裁定 1a 待決 1）：`BareBody.fill`（紙娃娃、人形召喚物 `DOLL_MAX_FILL` 0.45；實測最大 0.298）× 畫布不到 4000 的不畫遮罩（基本大小、精英的紙娃娃都不會）；大型前排有像素的範圍（`tightBox`）碰不到被擋者整張畫布時，被擋者的遮罩也不畫。判定結果和不預篩相同（ocl-gallery 6 個場面逐筆比過）；只有紙娃娃的場面 `getImageData` 0 次。
- **播放（OCL-1b）**：片段播放中**沿用片段開始前的結果**；`refreshOcclusion` 只在移動結束（`endMove`）、出招前轉向（`playSkill`）、出招列結束（`rowEffect` 的 `end`）時重算，擺位一律用 `draw` 時記下的「站好」身體位置（`restOf`），所以片段中途重算等於片段開始前；擺位簽名沒變就沿用、不重建 Sprite。移動（走路、位移、進出門）時 `beginMove`：移動者自己的外框藏起來，有人在移動時不重算（別人沿用到移動結束）。每格 `tickOutlines`（ticker 優先度 `LOW + 1`，在所有動畫之後、算繪之前）把外框對齊身體節點的平移；外框和身體同一個錨點（腳底），**OCL-1c 起跟著身體節點一起轉**（`rotation` 照抄），轉角超過 `OUTLINE_MAX_ROTATION`（0.35 rad，約 20°：空翻、倒下）才藏；受擊側彎（約 10°）看得到外框與閃白。倒下片段（`hideOutline`）照舊藏。
- **受擊閃白 k**：每個白閃呼叫點把（當下白閃, 這個效果自己的峰值）交給 `flashOutline`（`ReactHost.outline`）；k ＝ `outlineFlashK(flash, peak)`，`tint` ＝ mix(陣營色, 白, k)、`alpha` ＝ 0.8 + 0.2k，結束送 (0, 1)。峰值常數在片段旁邊：`HUMAN_HIT_FLASH` 0.85、`HEAVY_HIT_FLASH` 0.95、`BLOCK_FLASH` 0.35（`reactFlashPeak`）、`CREATURE_HIT_FLASH` 0.9、異形重擊 `CREATURE_HEAVY_FLASH` 1.0（`creatureReactFlashPeak`；OCL-1c 起照實際片段量化後的值，由 `quantizeCreaturePose` 算出，不是名義 0.99）、減少動態 `REDUCED_FLASH_PEAK` 0.85、疊層 0.85 × strength、木樁 `DUMMY_FLASH_ALPHA`。**峰值一律等於那個片段實際送出的白閃最大值**（`ocl1Playback.test.ts` 第 11 項逐列鎖住）。

## 三、必守的規矩

1. **浮動卡規則**（`docs/開發PM交接.md` 6.5.1，重點）：
   - 所有彈出卡片、說明框、資訊卡都用共用元件（`useFloatCard`＋`<FloatCard>`、`<Hint>`、格子用 `TileCardController`、部件說明 `PartTip`）；不准自製彈出層、不准用原生 `title=`。`floatCardRule.test.ts` 會掃 `position: fixed／absolute` 的彈出層與 `title=`，例外要進白名單並寫理由。
   - 行為：滑過約 150 ms 才開（`OPEN_DELAY_MS`）、離開後 250 ms 寬限＋橋接區（`CLOSE_GRACE_MS`、`BRIDGE_PX`）、可滑進卡片、點一下釘住、Esc 或點外面關、同時只開一張、貼齊觸發元素（預設上方，超出才翻轉或內推）、太高時卡內捲動、portal 到 `body`。
   - **格子資訊卡是例外**：不能滑進，只能點擊釘住（沒釘住時 `pointer-events: none`、換格立刻換卡）。
   - **彈出選單的觸發按鈕要標 `aria-expanded`**：選單開著時 `<Hint>` 不顯示說明卡，否則會蓋住選單。
   - `<Hint>` 不產生外層元素，子元素必須是**單一 DOM 元素**（事件與 ref 用 `cloneElement` 掛上去）。
   - 明文例外：技能面板的技能卡、雇用面板技能圖示的說明牌優先開在下方。
   - 改到前端的段都要在瀏覽器實測「從觸發元素滑進卡片 → 卡內捲到底 → 釘住 → 關閉」（1600×900 與 800×600），結果寫進報告。
2. **`battle/` 保持純函式**：不讀時鐘、不用 `Math.random`、不讀繪製器狀態、不跨步驟記憶。要變化就用 `variantHash(key)`（鍵由戰鬥、序號、單位組成）。這樣 vitest 才測得到，重播也才一致。
3. **前端不裁決規則**：只讀事件與 `view`，不自己判斷命中、傷害、能不能走。缺資料就請後端加欄位（然後重產型別）。
4. **不為了動畫加技能資料欄位**：挑片段靠原語、形狀、距離；非加不可的指定招放前端名單（例 `CREATURE_CHARGE_SKILLS`），LLM 與 YAML 都碰不到。
5. **位移一律從 `elevation.ts` 來**；座標換算用 `stageLayout.ts`，滑鼠事件不經過 Pixi。
