# 上手：前端戰鬥畫面與動畫（`client/src/`）

> 給實作 agent：派工 prompt 指到這份時，讀完就能動手改戰鬥畫面（PixiJS 戰場、HUD、浮動卡）、單位動畫與特效、開發頁。
> 2026-11-12 整理，依據當時的 main（React 18、PixiJS 8、vite 8、vitest 5；版本寫在 `client/package.json`）。
> 美術的樣張與驗收項目在 `docs/art/`（移植需求、`<段>檢查.md`）；畫法本身（Q 版人物、圖示）看 `docs/art/上手-畫法.md`。這份只寫遊戲端的程式。
> 改到這一塊時順手更新這份。

## 二、資料怎麼流

**從點擊到畫面**

1. 玩家點格子 → `BattleCanvas` 把 client 座標用 `clientToTile` 換成格子 → `battle/tileClick.ts` 的規則決定是選取、行動還是釘資訊卡。
2. 要行動 → `useBattleActions` → `usePlayback` 鎖住操作、呼叫 `api`（`POST /api/battles/{battle_id}/actions`，回答暫停點用 `/decision`）→ 拿到 `BattleResponse`（`initial_view`、`steps[]`、`view`）。每個 step 帶這一步的事件與該步之後的 `view`。
3. `playbackPlan(res, …)` 把 `steps` 排成 `Frame[]`。每一步固定的順序：標示行動者 → 移動動畫 → 技能特效（蓄力、飛行，等到命中）→ 畫該步的 `view` → 地形升降 → 地圖回饋 → 加紀錄 → 停頓。
4. `usePlayback` 逐格 `frameOps(frame)` 取 `PlayOp`，交給 `BattleRenderer`（`motionLayer`、`skillLayer`、`vfxLayer`…）播放。
5. **播完一定以 `res.view` 重畫**。動畫只是過場，任何「看起來的狀態」都不能留到下一步。
6. 畫靜態畫面：`buildDrawModel(view, …)` → `DrawModel` → `BattleRenderer.draw(model)`。
7. **測試模式（`view.practice`，#147）的戰場畫法**（PR-2c）：`buildDrawModel` 只在 `view.practice` 為真時多一個 `DrawModel.practice`（`practiceSceneOf(view.map_id)`：滑軌、水池範圍），`BattleRenderer.draw` 畫完地形格後呼叫 `drawPracticeScene`——水面每格一塊方角的水（地形層，蓋掉原本圓角的水面）、外圈石條與滑軌（表面裝飾層，**石條放在它壓到的那一排**，那一排的人站在它上面）。實戰、技能工坊（3F）沒有這個鍵，畫法不變。木樁的新外觀不看旗標（3F 也換，PR-2 第 8 點）；木樁在 `unitDrawOf` 帶 `noBar: true`。HUD 的測試模式分支是 PR-2b 的事。
8. **測試模式的 HUD**（PR-2b）：分支點一律是 `view.practice`（`BattleScreen` 的 `shown.practice`、`BattleBottomBar`／`ModePanel` 的 `view.practice`），**實戰分支的輸出和改前逐字相同**（`battle/pr2bPractice.test.ts` B 組鎖住）。上方中央 `PracticeBar`（`TestModeBadge`＋定稿句）取代 `TurnBar`；右上勝利條件換成「沙盒・不算勝負」，輪數照舊；回合操作沒有「結束回合」（自然收合、靠底）；技能鈕不寫冷卻；預覽總覽行拆成各自不換行的段、多一行必中句；前端自寫的操作提示句過 `practiceWording`（伺服器給的技能說明不過）；紀錄在 `BattleScreen` 先過 `practiceRoundLines` 再交給 `BattleLogDock`（浮動提示與完整清單都看得到）。版面量測的「上方中央」選擇器是 `ORDER_SELECTOR`（`.turn-bar` 或 `.practice-bar`）。PR-2d 補：提示條上的徽章說明卡傳 `PRACTICE_BADGE_HINT_ZH`（`TestModeBadge` 的 `hint`；一輪測試模式的三處不傳、原字不動）；開場橫幅（`BattleBanner`）只有 `PRACTICE_BANNER_ZH` 一行＋開場訊息；召喚物面板前端自寫的字過 `practiceWording`；高亮格與紅框貼水池往內縮一個石條寬（`practiceRange.poolInsets`，實戰沒有 `model.practice` 時不縮）。D 組測試 `battle/pr2dPractice.test.ts`。
9. **靶場的兩種戰鬥**（PR-2b，`WorldScreen` 的 `rangeFight`）：`trial`＝選大類／正式選定／重選畫面的「拿起試打」「看示範」（離開鈕「回到靶場」、開場訊息「靶場試打：{武器}＋{招 1}、{招 2}」）；`practice`＝工坊師傅的「靶場試玩」（「離開靶場」、只寫標題、地名讀 `WorkshopView.capital_zh`、回主城時面板關著）。兩種離開時都先 `DELETE …/range/trial`（`api.worldRangeTrialClose`）。

**單位動畫片段怎麼挑**

- 人形：`viewGrip.weaponClassInView`（從這一步開始前的 `view` 的裝備算）→ `skillClips` 依武器類別給起手／出招片段；普攻另依 `attackFamilyInView` → `skillSequence.variantFor(family, battleKey, seq, casterId)` 用 `variantHash` 挑變體。技能卡上的原語決定出招前後要不要插原語片段（`primitivesOf`）。
- 異形：`creatureActionOf({basic, skillId, primitives, shape, strikeClip, dist, range, weaponRange})` 依序判斷——召喚 → 位移 → 衝鋒原語 → 錐形＝吐息 → 指定招 → 其餘照現行。普攻一律 `melee`。走到「其餘」時看**技能本身的射程**（CB-3c，`isMeleeSkill`）：射程 1、跟武器（施放者拿近戰武器）、或等於施放者近戰武器的射程才算近戰技能，形狀 `single` → `melee2`（不看施放當下的距離）；射程比近戰長的法術貼身放 → `cast`（和隔著距離放同一個施法片段）；射程不知道（卡上沒有）時照 CB-3 的舊判定（`single`＋相鄰 → `melee2`）。射程來自技能卡（`icon.segments[i].range`，跟武器時 `stats.range_weapon`）；近戰武器射程來自 `/api/glossary` 的 `weapon_ranges`（`battle/glossary.ts` 的 `meleeWeaponRange(unit.weapon_id)`）。再由 `attackClipFor(身形, 類型)` 找片段；身形沒有第二種、或是頭目時退回第一種。
- 挑法**只看這一步的事件與畫面資料，不用亂數、不讀繪製器狀態**，所以重播、觀戰、重新整理都挑到同一個片段。
- 片段的時間：`skillTimeline` 排出 `SkillRow`（起手 → 出招前原語 → 出招 → 出招後原語 → 收勢），近身以「出招命中那一刻＝特效命中」對齊，遠程以「放出那一刻＝飛行物離手」對齊；整招上限 `SKILL_CAP_MS`，連鎖與換人前停 `CHAIN_GAP_MS`。
- 異形第二種近戰的 5 個片段照自己的格數播（12 格／秒，`creatureOwnFrames`、`ownFrameU`）；其餘片段是 12 格量化（`quantizeClipU`）。

**特效落點怎麼算**

- 一律用「世界座標」（未抬高的格子座標）加 `tileLift`：格子中心取 `liftedCenter(pos, height)`；畫布座標＝世界座標往下移 `topReserve(grid)`。不要自己乘 `RAISE`。
- `vfx.ts` 的特效描述帶的是格子（施放者、目標、範圍格）；`vfxLayer` 畫的時候才換成像素。地上的特效（`clip: "map"`）裁在地圖矩形內，跟著人的（蓄力、刀光、飛行物、受擊、浮動字）不裁。
- **異形片段自帶的特效**（白弧、星爆、掃尾 `sweep`、塵土）是 `qCreaturePartPose` 給的「異形自己的側面座標」（朝東、腳底為原點，相鄰目標在 x ＝ 52，`CREATURE_FX_TARGET_X`），在 `inkCreature.drawCreature` 裡**和身體一起畫進身體貼圖**，貼圖跟著 `creatureSide` 左右鏡射。異形只有東、西兩面；出招時用 `creatureFacingTo`（只看目標偏東或偏西，同一欄維持原朝向）。所以 CB-3c 以前，目標在正南、正北時特效畫到側邊的空格，站最右欄（或最左欄）又朝外時畫到地圖外被裁（身體貼圖 176×136 也放不下往南北一格的特效）。
- CB-3c 起，**只有同一欄**（`creatureFxTurnOf` 回 1／-1）時：姿勢帶 `fxTurn`，身體貼圖不畫特效；`skillLayer.placeTurnedFx` 另放一張特效貼圖（`ArtTextures.creatureFx` → `inkCreature.renderCreatureFxCanvas`，畫布 `CREATURE_FX_BOX`），放在這一列的效果節點（效果圖層，蓋在目標之上、這一列結束跟著移除）。轉法在 `render/creatureFxTurn.ts`：腳底座標 (x, y) → (0, y ＋ 轉向 ×（x − 52）× `fxTurnScale`)，「相鄰目標」那一點剛好落在相鄰那一格中心（跟著那一格抬高）、異形自己（x ＝ 0）留在原地、高度不變。東西向與斜向照舊畫進身體貼圖（鍵與畫法都沒變）；頭目照舊（見第四節第 3 點）。

**畫布留邊**

- `STAGE_MARGIN = { top: TILE_SIZE / 2 + 2, right: TILE_SIZE / 4 }`（上 26、右 12 模型像素；一格 48）。它是 `DrawModel.margin` 選填欄位，只有 `BATTLE_DRAW` 會給。
- 上緣併進 `topReserve`、右緣加進 `stagePixels` 的寬度，所以格子的世界座標不變；用 `topReserve`／`stagePixels` 換算的地方（`clientToTile`、`fitScale`、畫布大小）自動跟上。只有浮動卡靠右時的 `right` 要另外加右緣留邊（`stageLayout.cardPlacement`）。
- 實地地圖（`client/src/world/`）與開發頁預設不帶留邊。
- 單位頭頂預留 `UNIT_HEADROOM`（28）；高大的頭目另列 `BOSS_HEADROOM`。

**`window.__layoutSmoke`**（`dev/layoutSmoke.ts`；步驟全文在 `docs/開發PM交接.md` 6.2 第 5 點）

1. `corepack pnpm -C client build`，背景啟動 `uv run trpg serve --port <指定的埠>`。
2. 每個尺寸：調視窗大小 → `localStorage.clear()`（有舊存檔時頁面會接回去、全部量不到）→ 開 `/?dev=1&anim=0.1&mute=1` → 執行 `await window.__layoutSmoke.runCase("標題")`。
3. 三個尺寸：1600×900、1040×624、800×600；全 PASS 才算過。
4. 其他入口：`runScreens`、`runEntry`、`runPostBattle`、`runTown`、`scan()`（文字溢出）、`corners()`。純函式 `evaluate(snapshot)` 有 vitest。
5. 新增版面元件時把它的量測加進 `layoutSmoke.ts`（`HUD_SELECTORS`、`MAP_COVER_SELECTORS`）。

**API 型別**

- 後端改了 API：`uv run python scripts/export_openapi.py`（寫 `client/openapi.json`）→ `corepack pnpm -C client gen:api`（寫 `src/api/schema.d.ts`），兩個檔一起 commit；`tests/api/test_openapi_snapshot.py` 會擋沒重產的。
- 元件裡用 `api/types.ts` 的別名（`BattleView`、`UnitView`、`SkillCard`…），不要直接寫 `components["schemas"][…]`。事件在 OpenAPI 是任意 JSON，用 `asEvent` 與 `types.ts` 的手寫型別窄化。
- 前端測試用的內容快照（`battle/fixtures/glossary.json`、`render/fixtures/unitDolls.json`、`skill_icons.json`、`ui/fixtures/skillCards.json`）由 `uv run python scripts/export_client_fixtures.py` 從 `content/` 產生，不要手改。

## 三、必守的規矩

1. **浮動卡規則**（`docs/開發PM交接.md` 6.5.1，重點）：
   - 所有彈出卡片、說明框、資訊卡都用共用元件（`useFloatCard`＋`<FloatCard>`、`<Hint>`、格子用 `TileCardController`、部件說明 `PartTip`）；不准自製彈出層、不准用原生 `title=`。`floatCardRule.test.ts` 會掃 `position: fixed／absolute` 的彈出層與 `title=`，例外要進白名單並寫理由。
   - 行為：滑過約 150 ms 才開（`OPEN_DELAY_MS`）、離開後 250 ms 寬限＋橋接區（`CLOSE_GRACE_MS`、`BRIDGE_PX`）、可滑進卡片、點一下釘住、Esc 或點外面關、同時只開一張、貼齊觸發元素（預設上方，超出才翻轉或內推）、太高時卡內捲動、portal 到 `body`。
   - **格子資訊卡是例外**：不能滑進，只能點擊釘住（沒釘住時 `pointer-events: none`、換格立刻換卡）。
   - **彈出選單的觸發按鈕要標 `aria-expanded`**：選單開著時 `<Hint>` 不顯示說明卡，否則會蓋住選單。
   - `<Hint>` 不產生外層元素，子元素必須是**單一 DOM 元素**（事件與 ref 用 `cloneElement` 掛上去）。
   - 明文例外：技能面板的技能卡、雇用面板技能圖示的說明牌優先開在下方。
   - 改到前端的段都要在瀏覽器實測「從觸發元素滑進卡片 → 卡內捲到底 → 釘住 → 關閉」（1600×900 與 800×600），結果寫進報告。
2. **`battle/` 保持純函式**：不讀時鐘、不用 `Math.random`、不讀繪製器狀態、不跨步驟記憶。要變化就用 `variantHash(key)`（鍵由戰鬥、序號、單位組成）。這樣 vitest 才測得到，重播也才一致。
3. **前端不裁決規則**：只讀事件與 `view`，不自己判斷命中、傷害、能不能走。缺資料就請後端加欄位（然後重產型別）。
4. **不為了動畫加技能資料欄位**：挑片段靠原語、形狀、距離；非加不可的指定招放前端名單（例 `CREATURE_CHARGE_SKILLS`），LLM 與 YAML 都碰不到。
5. **位移一律從 `elevation.ts` 來**；座標換算用 `stageLayout.ts`，滑鼠事件不經過 Pixi。
6. **截圖規則**（`docs/開發PM交接.md` 6.5.2）：存 `docs/art/shots/<段名小寫>/`；每段 ≤ 10 張、jpg 品質 80、單張 ≤ 300 KB（GIF 只用在動畫段，一樣算張數）；報告與派工都寫完整路徑。**美術驗收的每一項都要有截圖**，只有 vitest 的不算通過；實機到不了的情況用開發頁畫出來，並在報告的「實機未看」逐項列出。
7. **測試與巡檢一律靜音**：無頭 Chrome 加 `--mute-audio`、網址帶 `?mute=1`、vitest 用 mock 的 AudioContext、不用系統指令播音檔。
8. **減少動態**：有 `prefers-reduced-motion` 的分支（`render/reducedMotion.ts`、`world/frameLoop.ts` 的 `prefersReducedMotion`）；新動畫要想好減少動態時顯示什麼（現行出招列直接跳最後一格）。
9. **文字用繁體中文**；地名、台詞、技能名讀伺服器資料，不寫死在元件裡。

## 四、常踩的坑

1. **`<Hint>` 外包一層元素出過三次事**（拖曳線跑位、「結束回合」變直條、說明卡蓋住選單）：`父 > 子` 的 CSS 因多一層而失效。現在 `<Hint>` 不包元素、由 `__layoutSmoke` 的 `hintWrappers` 檢查擋住。同類錯誤第一次出現就全專案掃同樣寫法。（`docs/開發PM交接.md` 6.5.1、6.2 第 5 點）
2. **畫布不留邊時，貼邊的大型異形會被裁**：精英＋大型蜥蜴站最上排，尾尖超出格頂 52.5（原預留 28），所以上緣留邊是 26 而不是剛好半格 24；右緣 12 只蓋得住「目標在最右欄」。（`docs/phases/PhaseCB-3報告.md` 待決 4、`PhaseCB-3b報告.md` 待決 1、2）
3. **異形片段自帶的特效畫在身體貼圖裡、跟著左右鏡射**：目標在正南／正北時曾落在側邊空格、站邊欄時超出畫布。CB-3c 改成同一欄時另畫一張轉向的特效（第二節「特效落點」）。還沒涵蓋的：**頭目**（`drawBossFrame` 照舊畫進貼圖）；**斜向**的目標（特效仍在施放者那一排、目標那一欄）；**精英＋大型東西向**的「相鄰目標」點在 73.1 px，比目標格邊多約 1 px（既有）。改片段特效時記得 `turnCreatureFx` 只換位置（x 收到中線），弧、星爆的形狀不轉。（`PhaseCB-3c報告.md`）
4. **異形出招會翻面**：`SkillLayer.playSkill` 開頭把施放者轉向目標，目標在正南北時朝向變 `south`／`north`，`creatureSide` 把敵方畫成朝西，原本朝東的就翻了。CB-3 改成異形用 `creatureFacingTo`；人形不動。新加會轉向的地方要分人形與異形。（`PhaseCB-3報告.md`「蜥蜴朝向確認結果」）
5. **取格的浮點邊界**：`Math.floor(t / (1000/12))` 在 t 剛好是格邊界時會取到前一格（商是 6.999…）。取格一律先加 `EPS`（`1e-6`）再取整，並用測試逐格鎖住。（`PhaseCB-3報告.md`「`frameOf` 確認結果」）
6. **「單體近戰技能」看技能本身的射程，不看施放距離**（CB-3c）：以前非普攻＋`single`＋相鄰就播 `melee2`，碎晶之主貼身放晶蝕會播近戰揮擊。現在射程比近戰長的法術貼身放播施法片段。測試的假技能卡若不給射程，會走「射程不知道」的舊判定；要測新判定就照 API 給 `icon.segments[i].range`／`stats.range_weapon`，施放者給 `weapon_id`（`battle/cb3cMeleeRange.test.ts`）。（`PhaseCB-3c報告.md`）
7. **同一隻同回合連續出手時，前一招的結尾被下一步截掉**（下一步在前一招結束前約 200～260 ms 就開始）；是既有的播放排程，不是片段壞掉。查「少格」先分清楚是片段中間還是結尾，用 `window.__battleTrace` 看格號。（`PhaseCB-3b報告.md` 結論、問題 1）
8. **互相匯入會變循環**：`inkCreature` 匯入 `qCreatureAnim`，後者要讀支點時不能反過來匯入，所以把 `RIG` 搬到 `creatureRig.ts`。`test/importCycles.test.ts` 會擋循環。（`PhaseCB-3報告.md`「改了什麼」）
9. **快照不一定反映畫面改動**：`render/__snapshots__/` 的兩個檔只含靜態異形與人形；有姿勢才看得出的差異（例如斑點改組）快照不會變，只能看圖。反過來，快照變了要在報告逐項說明。（`PhaseCB-3報告.md`「快照變動說明」）
10. **兩個雜湊快照測試跨平台要重跑**：`creaturePose.test.ts`、`inkDollSnapshot.test.ts` 的數字固定 6 位小數，換機器（Mac ↔ Windows x64）後要確認仍然通過。（`docs/開發PM交接.md` 6.1）
11. **vitest 掃原始碼不要用 `import.meta.glob`**：檔案清單會被快取，新加的檔掃不到；用 `test/sourceScan.ts` 的 `readSources`。（`ui/floatCardRule.test.ts` 檔頭）
12. **`__layoutSmoke` 量不到東西**：通常是沒先 `localStorage.clear()`（頁面接回舊的一輪），或沒帶 `?dev=1`（會回 `NEED_DEV_ZH` 那句）。（`docs/開發PM交接.md` 6.2 第 5 點）
13. **vite 開發伺服器的 `/api` 寫死轉到 `127.0.0.1:8000`**（`client/vite.config.ts`），那是使用者的埠。要接自己開的 `trpg serve`，另寫一份暫存的 vite 設定檔把 `/api` 轉到自己的埠，用完刪掉；不要改 `vite.config.ts`。（`PhaseCB-3b報告.md`「其他」）
14. **熱更新會讓本機草稿被清空**，看起來像 bug；重新載入後重現不出來的先不要當成正式問題。（`docs/phases/PhaseOB-5報告.md` 第 7 節）
15. **交件前沒關的無頭 Chrome 拖垮整台機器**（7 組各吃約 60% CPU，全量測試從 15 分拖到 45 分以上）。自己啟動的 vite、`trpg serve`、無頭 Chrome 都記 PID，交件前逐一關掉並確認沒有殘留；不用 `taskkill /IM`。（`docs/開發PM交接.md` 6.6 第 1 點、守則 13）
16. **截圖容易超量**：CB-3 交了 52 張 11.6 MB、CB-3b 19 張最大 789 KB，都超過 6.5.2。連拍用合圖（一張多格）並壓到 300 KB 內。（`PhaseCB-3報告.md` 待決 8、`PhaseCB-3b報告.md` 待決 4）
17. **`check.py --full` 不含 `vite build`**：build 要另外跑，結束碼也要是 0 才能交。（`docs/開發PM交接.md` 3.000 第 2 點）
18. **專案沒有 Playwright／puppeteer**：要自己驅動無頭 Chrome 時，用 Node 24 內建的 `WebSocket` 直接走 DevTools Protocol（`Runtime.evaluate`、`Input.dispatchMouseEvent`、`Page.captureScreenshot` 的 `format: "jpeg", quality: 80`；要 3 倍特寫改 `Emulation.setDeviceMetricsOverride` 的 `deviceScaleFactor: 3`，不要用 clip 的 `scale` 放大）。Chrome 啟動器的 PID 會先結束，殘留要用 `--user-data-dir` 認。世界畫面會記住上次的角色（`localStorage` 的 `trpg.world.character`），換角色直接寫這個鍵再進。`?anim=0.1` 時點地圖走路很慢，點完要等。（`PhaseOB-6a報告.md` 第 2 節）
