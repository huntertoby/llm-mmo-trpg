## 七、數值工坊（NW-1a 後端；前端 NW-1b；技能 NW-2a 後端、NW-2b 前端）

使用者在瀏覽器改 `content/` 的數值、當場驗證、跑小模擬改前改後並排、寫回並自動 commit。規格 `docs/phases/PhaseNW計畫.md`。

**在哪**

| 檔案 | 職責 |
|---|---|
| `content/tuning_fields.yaml`、`src/trpg/content/tuning_fields.py` | 白名單與載入檢查（每個路徑都對得到 schema 的整數欄位、禁止表、不開 ID／`*_zh`／外觀）；路徑工具 `parse_path`／`format_path`／`path_matches`（`phases[*].trigger.permille` ↔ `phases[1].trigger.permille`） |

| `api/tuning/drafts.py` | 改動單 `Change{file, path, old, new}`、草稿檔 `<save_dir>/tuning/drafts/<名稱>.json`、`normalize`／`merge`／`reverse` |

| `api/tuning/sim_jobs.py` | 模擬工作：一次一個、可取消、程序池保留、改前結果以樹雜湊＋情境快取在 `<save_dir>/tuning/sims/` |
| `api/tuning/service.py`、`routes.py`、`schemas.py` | 服務層與端點（`/api/tuning/*`）、回應型別 |
| `src/trpg/skillgen/library_check.py` | `library_violations`（NW-1a 從 `trpg.cli.budget` 搬來；`api` 不能匯入 `cli`） |
| `api/tuning/objects.py` 的 `concrete_fields` | 白名單 `phases[*].*` 展開成具體路徑：**開場階段（沒有 `trigger`）一律不展開**（schema 規定開場階段不能有改動；NW-1b 起 `phases[*].mana_restore` 也照這條）；`phases[*].trigger.*` 另外只展開 `hp_below` |
| 前端 `client/src/screens/TuningScreen.tsx`、`client/src/tuning/` | NW-1b 畫面（入口 `tuning/TuningEntry.tsx` 在開發選單；純函式 `model.ts`、流程 `flow.ts`、元件 `FieldForm.tsx`／`SimPanel.tsx`／`DraftPanel.tsx`、樣式 `styles/tuning.css`）；細節見 `docs/dev/上手-前端戰鬥畫面與動畫.md` 第一節 |

**三道門**：`dev_mode` 為真、環境變數 `TRPG_TUNING=1`（`create_app(tuning=...)` 可覆寫）才掛路由；請求帶 `CF-Connecting-IP`／`X-Forwarded-For`／`Forwarded` 任一個就 403。OpenAPI 匯出與快照測試用 `create_app(tuning=True)`，所以 `client/openapi.json` 含這些端點。

**加一類可改的欄位**：只改 `content/tuning_fields.yaml`（守則 4）；要新的對象種類（技能、裝備…）才動 `TARGET_MODELS` 與 `check.py` 的單檔 schema（NW-2 起）。會被 `bundled_content_dir()`／`default_content_dir()` 在 schema 匯入時讀的檔（`skill_primitives.yaml`、`skill_shapes.yaml`、`modifier_changes.yaml`、`llm/*.yaml`）不能開：草稿複本看不到。

**坑**

1. **測試絕不對真的 `content/` 寫回**：寫回測試一律用 `tests/api/tuning/conftest.py` 的 `repo`／`repo_service`（`tmp_path` 的假 repo）；讀專案 content 的服務把 `git` 設 `None`。PM 在主資料夾（`main`）跑測試時，`git` 沒設 `None` 的服務**真的會**寫回。
2. **寫回後固定答案的測試會變紅**（parity 夾具、CLI 快照、AI 固定種子）：走 NW 0.0／第 0 節第 6 點的「收編」小段，只更新測試，不改使用者的數值。
3. 單位範本不在規則包裡：改單位欄位 `content_digest`、`ruleset_hash` 會變、`hash_ruleset` 不變（`tests/api/tuning/test_check.py`）。
4. 頭目實戰護甲另有遭遇的 `armor_mods`、血量另有等級成長：工坊表單的 `notes_zh` 會提示（NW-3b 起寫「數值工坊還沒開放遭遇的護甲調整」）；遭遇的 `armor_mods` 還沒開。
5. **寫回要在 `main` 分支的 repo**：agent 的 worktree 分支寫不回（前置檢查擋）。實機試寫回的做法（NW-1b）：在 worktree 裡 `git clone --local --no-hardlinks <worktree> <worktree>/.scratch_x/repo`、clone 裡 `checkout -b main`，`trpg serve` 設 `TRPG_CONTENT_DIR=<clone>/content`——commit 只落在那個 clone，用完刪資料夾即可。
6. `git log --grep '^tune'` 也會撈到早期手寫的 `tune(ai): …` commit（例 BAL-5 `dcd94d4a`）；對那種非工坊產生的 commit 按「還原」，後端照樣產反向改動單，只會收白名單內欄位。
7. 模擬結果的「每回合施放率」可以超過 100%（一回合放好幾次，例如「火焰箭」）：分子是施放次數、分母是頭目行動回合數。
