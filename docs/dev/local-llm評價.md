## 總結

**好用**
- 長（數百行以上）、結構規律、只要「整體重點」的文件：例如 PK-2 比較這種有固定表格和指標的報告，摘要準、行號大致可用，省下讀全文的量最多。
- 規律欄位的抽取（`local_ask`）準確度高，但前提是答案在原文裡有固定寫法；這種情況 grep 通常更快更準，local-llm 只在欄位寫法不一、grep 抓不到時才划算。

**不好用**
- 短檔（約 100 行以下）或短輸出：直接讀或 `tail` 更省，交給它反而多一次呼叫。
- 要「完整列出 N 項」的清單：會漏項、編號錯位，看起來完整其實不完整，最危險。
- 交接文件這類**按時間往下累積**、同一件事新舊狀態並存的文件：模型不會判斷哪條是最新，會把已結案的事當待辦。
- 它不一定照指示附行號；附了也可能差 1 行。

**建議怎麼用**
1. 只用在約 300 行以上、結構規律、只需要重點的文字（測試失敗很多的 log、長比較報告、長模擬輸出）；能 grep 的先 grep。
2. 問清單時，拿回結果後先數項數、對一下原文的標題或編號（例如 grep 該節標題），再相信。
3. 不要拿它摘要交接文件或決定紀錄來判斷「現在要做什麼」；這類一律讀「現況」那節原文。
4. 它給的行號只當起點，改東西前照行號讀原文確認（同守則第 5 節）。
