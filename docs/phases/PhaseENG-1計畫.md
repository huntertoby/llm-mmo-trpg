# Phase ENG-1｜傷害公式合一與 `unit_downed` 順序鎖定

> 來源：2026-11-10 結構盤點，使用者同意（「go」）。**實際結算一個數字都不能變**；同種子重播結果必須與改前相同，`LOG_FORMAT`、`WORLD_RULES_VERSION` 不加一。

## 範圍外

- 不解 `engine/effects/__init__.py`、`engine/lifecycle.py` 的延遲匯入環。
- 不改任何數值（#146 等排在之後）。
- 不改觸發器的實際順序，只鎖定。

## 問題

1. 傷害公式手寫 3 份：`src/trpg/engine/effects/handlers.py:242`（實際結算）、`src/trpg/engine/preview.py:708`（普攻預覽）、`:942`（技能預覽）。
2. 實際結算在護陣 ×0（`ward == 0`）時傷害是 0、不套最低傷害（`handlers.py:252`）；兩份預覽沒有這個判斷，會顯示最低傷害。
3. `unit_downed` 有多個觸發函式（`bombs.py:167`、`death_surfaces.py:25`、`delayed.py:272`），依註冊順序串接（`triggers.py:55`、`:65`），註冊順序來自匯入順序，沒有測試鎖定。日後改檔名或調整匯入可能默默改變戰鬥結果。

## 交付項目

1. **S1 傷害計算合一**：抽出一個純函式（整數運算，維持原本先乘後除的順序），三處都呼叫它。護陣 ×0 的判斷也進同一份，預覽顯示要與實際結算一致。注意：`status_ppm == 0` 不等於護陣 ×0，要照實際結算以 ward 判斷，不能用 `status_ppm` 代替。
2. **S2 鎖定觸發順序**：測試明確列出 `unit_downed` 的觸發函式順序，以及其他有 2 個以上觸發函式的事件的順序。要在全新直譯器中從不同入口（至少 `trpg.engine`、API、CLI、sim）匯入後比對，因為順序取決於匯入路徑。發現入口間順序不一致時停下來，寫進報告，不要自行改順序。

## 受影響的既有功能

| 項目 | 影響 | 處理 |
|---|---|---|
| 實際結算 | 純重構 | 重播與快照原樣通過 |
| 預覽 | 只有 ward == 0 的情況改變 | 其餘情況數字不變 |
| 前端顯示的預覽數字 | 同上 | 欄位不變，不需改 client |
| 戰鬥紀錄格式 | 不變 | `LOG_FORMAT` 不加一 |

## 行為一致測試

- 表格測試，**實際跑引擎**：涵蓋一般、爆擊、元素抗性、天氣、倍率、易傷、護盾、最低傷害、護陣 ×0、護陣 ×0 且有易傷，比對預覽的傷害表與引擎 `damage_dealt` 實際數字。普攻與技能各跑一輪。
- 公式函式本身對舊寫法的逐一比對（hypothesis，整數參數範圍取實際可能值）。

## 驗收條件

- `ruff check`、`ruff format --check`、`uv run mypy`、`lint-imports` 通過，沒有新增複雜度 noqa。
- `tests/engine`、`tests/test_architecture.py` 通過，並回報 CLI 快照是否有受影響（應該沒有；有的話不重產，先查原因）。
- 至少 3 張地圖、不同種子各一場 `trpg battle --log-json` ＋ `replay` 通過，且與 main 版本產生的紀錄逐位元相同（附比對方法）。
