# Phase SK-3 計畫：#166 第 3 組（新觸發與流程）

> 來源：`docs/design/06*.md` 6.38 第 10、11、12 點，6.6（觸發深度上限）；玩法交接 4.1.26；決定紀錄 #166（使用者「8 B 其他都照建議」）。
> 設計細節以原文為準。**數字一律是初值，接數值工坊，不試數值、不跑平衡量測。** 接在 SK-2 之後（main 71c69a4d7 已含 SK-2）。

## 範圍

1. **新觸發「你造的關鍵字被利用時」**（6.38-10）：給被動與詞條用。你製造的關鍵字（你造的燃燒、潮濕、標記……）被任何人利用時觸發；每回合最多 1 次；照觸發深度上限。引擎要能追蹤「這個關鍵字是誰造的」，存在戰鬥狀態，重播要一致。
2. **戰前佈置**（6.38-11）：開戰前（雙方都還沒行動），玩家可以在我方起始區內免費放 1 個自己的刻印、陷阱或表面；條件是裝備著會做這件事的技能，放了就算那招用過（照常進冷卻）；每場 1 個。要有 API 和前端操作（可以跳過）；AI 代打或沒有可放的技能時直接跳過。
3. **新原語「重擲」（只限反應）**（6.38-12）：隊友擲骰後讓他重擲取較好的，或敵人命中你時逼他重擲取較差的；每輪 1 次照反應規則；預覽要顯示。

新觸發、新原語要能被出題用到的話，只加 content 資料與 schema；**組合器、挑選打分、閃現檔不要動**（SK-1 在改），接進出題的部分寫進「待 PM 決定」，由後面的小段接。

## 檔案邊界

- 可以改：引擎觸發、反應、擲骰、戰鬥開場流程、狀態、content 原語與觸發資料、API（戰前佈置）、前端（佈置操作、預覽、演出）、工坊欄位。
- SK-1 同時在改組合器、挑選打分、閃現、變奏、條件判定，這些檔不要碰。

## 驗收

- 相關目錄的測試（分目錄、一次一組、最多 `-n 8`）、ruff、format、mypy、lint-imports、前端 tsc 和相關 vitest 都要 0。新觸發和新原語各有引擎單元測試，含重播確定性。
- 戰鬥不變比對（照 PK-4、SK-2 報告的做法）：沒用到新東西的戰鬥 different=0；有差異要逐場說明。戰前佈置預設會不會改到既有戰鬥（例如 AI 代打）要特別說明。
- 快照與夾具：先預測再逐鍵核對，不整批重產。版號有升就列出（`LOG_FORMAT` 目前 /129；SK-1 也可能升，衝突時由開發 PM 處理）。API 有改就重產 OpenAPI。
- 實機截圖：每項至少 1 張（戰前佈置要用真畫面）。DPR 1、靜音，不用 8000、8001 埠。
- 報告 `docs/phases/PhaseSK-3報告.md`：做了什麼、測試、截圖路徑、待 PM 決定。
