## 範圍

分兩段，**同一個 agent 依序做，每段各自 commit**（兩段都會改 `classes.yaml` 和清單文件，不能平行）。

### a. engine、world、剩下的 text

1. **`engine/*` 的 config（約 20 筆）**：
   - 暴擊下限、預設持續回合等規則數字，搬進 content 規則（`core.yaml` 或對應的檔），經 Ruleset 帶進引擎。
   - 戰鬥紀錄照 `docs/phases/戰鬥紀錄格式變更.md` 判斷。新欄位有預設、舊紀錄結算不變的話，`LOG_FORMAT` 就不升。
2. **`world/*` 的 config（約 42 筆）**：好感門檻、時鐘、動作請求上限等，搬進 `world/rules.yaml` 或對應的檔。
   - HC-4d 裁定 2：沒有世界規則時的備用值，照 HC-4d 的做法處理。能改成必填就改必填；真的需要備用值的地方（例如沒有實地地圖的測試內容），備用值只寫一份，放在 content 載入層。
3. **剩下的後端 text（約 30 筆）**：HC-6a 留下的 26 筆，加上 HC-6b 留下的 api 4 筆。
   - 「最多 1 個」、「1 階」、「每輪 1 次」這類引擎或檢查寫死的數字：先把數字搬進 content 規則，檢查和說明都讀它。
   - 搬了反而怪的（真的是結構，例如「恰好 1 個」是定義），照 `classes.yaml` 改判 const，並附理由。
   - 誓約冷卻「1 天內」（HC-6a 裁定 3）：從 `cooldown_seconds` 組字。
     - 能整除 86400 的寫「N 天內」，不能整除的寫「N 小時內」。
     - 目前的值組出來要和現在逐字相同。
   - 工坊「沒寫＝5／4」：schema 已經沒有預設值，所以這句說明已經過時。改成照實際情況說明，例如「必填」，或照內容檔的現值組字。玩家看到的字會變，報告要列出改前、改後。

### b. api、llm、server、前端剩下的 config

1. **`api/*` 的 config（約 60 筆，含 `api/tuning`）**：
   - 工坊的上下限對齊 `api/tuning/schemas.py` 或內容的建議範圍，只留一份。
   - 預生成的上限搬進 content 規則。
2. **`llm/*` 的 config（約 35 筆）**：LLM 呼叫設定，例如重試次數、等待秒數。
   - 屬於部署設定的放 `config/llm.toml`；**這段是寫進 schema 的預設，不改 `config/llm.toml` 的值**。要加鍵的話，鍵的預設要等於現在程式裡的值，並寫進報告。
   - 屬於遊戲規則的（例如許願 10 秒門檻）放 content。
3. **`server/*` 4 筆、前端 config 22 筆**：前端的改由 API 帶，同 HC-3 的做法。
4. **HC-4c 裁定 1**：重播、賽程封存讀到 pydantic 驗證失敗時，改給和「雜湊不符」同一類的中文說明，不要把驗證錯誤原文丟給玩家。要有測試，用一份舊格式的紀錄。
5. **HC-6b 待決**：新欄位的預設值暫時歸 config 的那些（後端 config 162 → 181），這段一起搬或改判。
6. **收尾**：
   - 搬完變成 0 筆的規則刪掉。沒歸類的要是 0，`--unused` 沒有輸出。
   - 重產清單文件。報告附上每一類的前後筆數。

## 驗收

- **結果不變**：
  - 438→442 招的逐招預算、78 場戰鬥，都要 different=0。
  - 閃現出題、組合器 census 小樣本，也要 different=0。
- **字不變**：
  - CLI 快照、parity、前端夾具都不變。只有 API 新欄位造成的夾具變動除外，要逐鍵列出。
  - 說明文字用固定請求比對前後。除了 a.3 指定的兩處和 b.4，其他都要 different=0。
- **新開進工坊的格子**：每格都要有中文名，並寫清楚調高、調低會怎樣，照 `docs/dev/上手-數值工坊.md` 的寫法。
- **靜態檢查**：下面這些結束碼都要是 0：
  - ruff、format、mypy、lint-imports；
  - `trpg content check`、`classify.py --check`；
  - tsc、vitest、build。
- **測試**：
  - 開發中經看門狗只跑相關的測試。
  - **每段全部 commit 之後，先問開發 PM「準備跑 check.py」**。收到回覆後，照指示先 `git merge --no-edit main`，再跑 `uv run python scripts/check.py` 和 `uv run pytest -m slow tests/skillgen/test_refactor_parity.py tests/cli`。
  - 有失敗就修好、commit、重跑，直到全部通過。
  - 沒收到回覆不要交件。
  - a 段通過後先交件，開發 PM 合併、推上去後，再回頭做 b 段。
- **commit 與報告**：每項一個 commit。報告寫在 `docs/phases/PhaseHC-7報告.md`，a、b 分節。
