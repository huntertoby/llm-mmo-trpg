# 閃現 LLM 提議的多樣性量測（4-L12）

> 只量不調：本文只描述數字與可能原因，沒有改任何模板、提示詞或設定。

**結論**
1. **多樣性：模型沒有鎖死少數幾個模板。** 956 題、模型通過驗證的提議共 2077 次，目錄裡出現過的 51 種模板有 48 種被提出過；最高的 `keyword_imbue` 占 15.8%（它在目錄裡的占比也有 10.3%），沒有任何模板的「提出占比 ÷ 套得上占比」超過 2（最高 1.54），也沒有類別超過 1.5。比先前 30 招、18 種模板、最高 11% 的小樣本廣，因為這次涵蓋了所有技能類型與角色階級 1～3。
2. **偏好很輕、冷落集中在少數：** 輕度偏好「元素」「加深」「輔助」類（比值 1.3～1.4），偏少提「範圍」「延長」類（0.57、0.62）；真正近乎 0 的只有 `shield_wet`（套得上 31 場、通過 0 次）與 `shield_charged`（0.22）。這兩個與 `summon_bridge` 等多半是「模型試了但被驗證退回」，不是模型不想選。另外有明顯的**位置偏好**：模型回應裡的第一個提議有 83% 取自選單的前三分之一。
3. **轉型：LLM 一次都沒提過，也不能提**（轉型不在給模型的目錄裡，0 次提出、0 次被退回）；玩家看到的大變化選項有 12.7%（123／966）是轉型，**全部是引擎的保底補上的**。保底只對「角色階級 2 以上的主動技」有效（階級 2～3 的主動技 122／123 題有；階級 1 只有 1／47 題有；被動、反應、姿態、修正型被動本來就沒有轉型），且實際只集中在轉成姿態（44%）與召喚（37%），轉成陷阱 0 次。

## 怎麼量的

- 腳本：`scripts/eval_flash_diversity.py`（`--real` 用 `config/llm.toml` 的本機模型 swift，平行 8 個請求；`--mock` 用 Mock；`--from-csv` 只重新彙整 CSV）。
- 技能：每個技能類型各取 3 招，**依角色階級 1～3 各跑一遍**（招本身階級更高的只跑 ≥ 它的階級）。類型共 13 種：主動（武器、法術、召喚、輔助、接續、陷阱）、被動（一般、輔助向）、反應（一般、輔助向）、修正型被動、姿態（一般姿態、變身姿態）；另外有 6 種「**先轉型再閃**」的技能（把第 3 次大變化強制選成 to_passive_on_hit／to_reaction_melee／to_summon／to_trap／to_stance／to_modifier，再量第 4 次的小變化；元素姿態、召喚物、陷阱等就在這裡出現）。
- 情境：不指定類別（`open`）、指定類別（`focused`，每招 2 個、只挑確實有套得上變化的類別）、第 3 次大變化（`major`）、第 3 次大變化指定加深或橋接（`major_focused`）。
- 兩批獨立的種子（0 與 1000，各抽不同的技能）：共 243 個樣本、**956 題**、每題平均 11.6 秒、合計約 26 分鐘。原始明細：`flash_diversity_4L12.csv`（種子 0，472 題）、`flash_diversity_4L12_b.csv`（種子 1000，484 題）；兩份合併彙整：`uv run python scripts/eval_flash_diversity.py --from-csv docs/phases/4-L9/flash_diversity_4L12.csv docs/phases/4-L9/flash_diversity_4L12_b.csv`。
- 名詞：**套得上** ＝ 該題的目錄（引擎真的套得上、在選單裡）有這個模板的題數；**LLM 提出** ＝ 通過驗證的提議次數；**被退回** ＝ 被驗證擋下的項目次數（含重複）；**玩家看到** ＝ 最後 4（或 3）個選項裡的次數（含資料補位）。**提出÷套得上** ＝ 提出占比 ÷ 套得上占比，1 ＝ 照比例，> 2 標「偏好」，< 1/3 標「冷落」（套得上場次 < 5 標「樣本少」）。「隨機期望」＝ 若每題的提議在目錄裡平均分配，這個模板應被提出的次數。樣本有限，比值在場次少時雜訊很大。

### 可能原因

- **冷落多半是「被退回」，不是「沒被想到」。** `shield_wet` 被嘗試 46 次、通過 0；`shield_charged` 嘗試 73 次（65 退回）、通過 8；`summon_bridge` 124 次（115 退回）、通過 9；`range_plus` 305 次（235 退回）；`stance_potency` 347 次（285 退回）。若把退回也算作「模型想選」，這些模板其實是被選的；真正少被提的是 `area_plus`、`followup_hit` 等。退回原因最可能是引擎套不上或 `note_zh` 敘事與效果不一致（這支腳本沒記到每個模板的代碼，未逐一驗證）。
- **位置偏好：** 目錄至少 6 條時，提出的模板落在目錄前／中／後三段的比例是 47.6%／26.6%／25.8%；回應中的第一個提議 83.3%／9.7%／6.9%。目錄條目依各類別排序後的順序排列（資料順序中 area 排第一，但 area 仍偏低），所以類別偏好與位置偏好不是單純同一件事，兩者無法分開（沒有做打亂目錄順序的對照）。
- **`keyword_imbue` 領先**：它每個關鍵字都是一個選單項，同一題可以被提多次（帶不同關鍵字），本來就容易領先。
- **輔助、護盾類模板**只在輔助向技能的目錄出現，樣本場次少，比值易受影響。
