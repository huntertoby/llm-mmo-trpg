# Phase X10-1 計畫：×10 換算工具（還不改內容）

> 來源：#169 題 10；`docs/design/05-*.md` 5.4.1；盤點 `docs/phases/X10-影響盤點.md`（先讀，裡面的「關鍵做法」照做）。
> 三段：X10-1 工具與清單 → X10-2 套用（內容、引擎、預算一次換） → X10-3 前端與工坊換算紀錄。
> **這段不改任何遊戲數字**，戰鬥結果必須完全不變。

## 範圍
1. **欄位清單**：`scripts/x10/fields.yaml`。
   - 列出 `content/` 每個檔要 ×10 的欄位路徑，以及明確不變的欄位。
   - 盤點標「未核對」的檔要逐筆看完。
   - 每個檔的數字欄位都要歸類：要嘛 ×10，要嘛列為不變，不能有漏網。
   - 寫一個測試：掃 `content/` 所有數字欄位，凡是不在清單裡的就失敗。
   - 判斷不了的列在報告「待 PM 決定」。
2. **換算腳本**：`scripts/x10/rescale.py`。
   - 照清單改 YAML，保留註解和格式（用現有的 YAML 往返工具；沒有就用 ruamel）。
   - 有 `--dry-run`，輸出「檔、路徑、舊值、新值」的 CSV。
   - 跑兩次會檢查出來並拒絕，不會變成 ×100。
   - 這段只跑 dry-run，把 CSV 存到 `docs/phases/X10-換算預覽.csv`。
3. **放寬上限**：把擋住 ×10 的 schema、原語上限放寬到 ×10（盤點第 3 節）。
   - 現在的內容都在舊上限內，放寬後內容和戰鬥都不變。
4. **工坊調過的數字**：從 git log 找出數值工坊寫回的 commit（`api/tuning/writeback.py` 的 `commit_message` 格式），列出使用者調過的欄位，存成 `docs/phases/X10-工坊調過的欄位.md`。
   - 每列寫：檔、路徑、使用者調成的值、換算後的值。
   - 這份給 X10-3 做工坊的換算紀錄用。

## 驗收
- ruff、format、mypy、lint-imports、`trpg content check` 結束碼 0。
- 戰鬥不變比對 different=0（這段不能改到任何戰鬥）。
- 相關測試分目錄跑，最多 `-n 8`。不要用 `-m ""`，不要跑全量。
- 每項一個 commit，每個 commit 單獨跑也要乾淨。
- 報告寫在 `docs/phases/PhaseX10-1報告.md`，裡面要附：
  - 清單的統計：幾個檔、幾個欄位 ×10、幾個不變；
  - dry-run 的總筆數；
  - 預算要改單位的係數清單，給 X10-2 用。
