# Phase PK-4 比較：許願池「現行（自由設計）」vs「願望驅動」、閃現借別類候選

> 2026-11-16，實作者（PK-4）。資料與實機截圖在 `docs/phases/PK-4資料/`；腳本 `scripts/wish_compare.py`（`run`／`run --mock`／`flash`／`report`）。

## 白話摘要（先讀這段）

- **這次沒有接到本機模型**：開工時 `localhost:8001` 沒有服務、LM Studio 沒載入任何模型（`lms ps`：No models are currently loaded）。照上手筆記「loaded 不是只有 Gemma 就停下回報」，**真模型量測沒做**；我試著照第 8 點載入 Gemma，被權限擋下，沒有再試。所以下面的 12 個願望是 **Mock**（Mock 對字：名稱有字出現在願望裡就選；Mock 命名），**秒數只有程式那一段（出題、組候選）可參考，名稱、描述與「回應願望」那一句都不是模型寫的**。LM Studio 載好 Gemma 後，PM 可以直接跑 `uv run python scripts/wish_compare.py run` 再 `report` 補上真模型那一份（同 12 句、同格式）。
- **願望驅動做到了什麼（程式這段是真的）**：
  1. 不再「沒聽懂就退回」：舊流程 12 句裡 4 句被退回（W3 火焰範圍、W4 位移、W8 護盾、W12 做不到——對不上任何關鍵字）；新流程一律照標籤出題，**連一個標籤都沒對到也照一般完整技能出 3 張**，0 句被退回。
  2. 標籤比關鍵字多四類：元素、效果類型、形狀、種類都能許。例：W3「燒起來的火焰」舊流程對不上關鍵字被退回，新流程 3 張都是火焰；W10「越打越強的被動」要的「直線、主動」都中。
  3. 做不到就照實寫：36 張裡 12 張卡上有「最接近你願望的一招：有…；…這次做不到。」（例 W1：有冰凍；火焰這次做不到）。全部命中的卡不寫。
  4. 程式這段的時間：中位 1.7 秒、最長 5.3 秒（W5 高處：組合器很難做出帶「高處」的招）；舊流程最長 11.6 秒（Mock 自由設計的重試）。真模型還要加兩次呼叫（翻標籤、挑 3 張），估計 3～5 秒，**召喚、高處這種難做的關鍵字可能逼近 10 秒門檻**（逾時照舊退回清單點選、不扣錢）。
- **閃現（B）**：PK-3 比較的 10 個情境，可挑的 31 格裡只有 1 個候選的格子 **16 → 11**，候選總數 64 → 75；有借別類候選的格子 7 格（22%），選項裡借來的佔 14%。大變化（加深、橋接）、指定類別、輔助技、被動照舊沒有借（可用類別本來就只有那幾類）。混合至少 2 類由程式守住（挑得太集中時從後面的格子改回第一個）。

## 怎麼比

- 同一個角色（主城、輔助英雄、Lv 1、法器）、同一個世界種子、同 12 句願望。
- 現行：`wish_enabled: false`，生成函式對關鍵字＋自由設計；拿不到 LLM 版時照引擎的退路（照關鍵字用組合器）。
- 願望驅動：開關打開，翻需求標籤＋照標籤做候選＋挑 3 張；拿不到 LLM 版時照標籤排序取前 3 名。
- 表上的 3 張就是玩家會看到的那一份。秒數是生成函式（含出題）的時間。
