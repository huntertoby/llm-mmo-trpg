# Phase TS-2 計畫：試用 testmon（只跑改動有呼叫到的測試，TS-1 的 B 步）

> 來源：
> - 使用者同意分兩步做測試分流（TS-1 計畫開頭有原話）：
>   - 「不能那種有call到的function測試就好？」
>   - 對「先做 A……再試 B 只跑有用到的測試……先試跑對照沒漏才正式用」回答：「好」。
> - 2026-11-22 使用者回覆「開始試」，由專案 PM 轉達。條件如下：
>   1. 只對「只改後端」的情況試，前端照 A 的分流。
>   2. 試用期間，每次只跑選到的測試之後，都要再全跑一次對照；有任何漏抓就記進報告。
>   3. 試到一定次數後交報告，由使用者決定要不要正式用。
> - 套件與版本已經專案 PM 同意，使用者先前也同意安裝：
>   - `pytest-testmon==2.3.0`
>   - `coverage==7.17.1`
>   - 只放開發相依。最新版 2.3.1、7.17.4 發布不滿兩週，所以不用。
> - 分流規則見 `docs/phases/PhaseTS-1報告.md` 第 1、2 節，以及 `docs/dev/上手-測試.md`。

## 範圍

1. **安裝**：
   - 用 `uv add --dev` 鎖定上面兩個版本，`pyproject.toml`、`uv.lock` 一起 commit。
   - testmon 的資料檔（`.testmondata*`）加進 `.gitignore`。
2. **試用模式**：`scripts/check.py` 加一個選用參數，例如 `--testmon`。
   - 不加參數時，行為和現在完全一樣，戳記規則也不變。
   - 只有分流結果是「後端」時才用 testmon 選測試；其他範圍照 A 的規則。
   - testmon 選出來的跑法**不寫任何通過戳記**，hook 也不會因此放行。
   - 先查 testmon 2.3.0 和 pytest-xdist、`scripts/run_pytest.py` 看門狗、`loadgroup` 搭不搭得起來：
     - 搭不起來就照最保守的做，例如選測試時不平行；
     - 做法和耗時都寫進報告。
   - 開頭那一行要寫：這次用 testmon，選了幾個測試、略過幾個。
3. **試跑對照**：至少 8 次，每次都要「選測試的跑法」加「全跑」各一次。
   - 至少 5 次是**故意弄壞**：
     - 在 worktree 裡對後端程式做一個小改動，讓某些測試會失敗。例如改一個常數、讓一個函式回傳錯的值、拿掉一行。
     - 位置要分散：引擎結算、規則、內容載入、skillgen、API。
     - 比對：全跑失敗的測試，有沒有每一個都被選到。沒選到的就是**漏抓**。
     - 對照完把改動還原，不 commit。
   - 至少 3 次是**真實改動**：從 git 歷史挑只改後端的 commit，在它的上一版建好 testmon 資料，再套上那個 commit 跑。比對選到幾個、耗時多少、全跑結果是不是一致。
   - 每次記錄：改動、選到／全部的測試數、兩邊的耗時、兩邊失敗的清單、漏抓清單。
4. **文件**：
   - 在 `docs/dev/上手-測試.md` 補試用模式的用法，並寫明「試用中，不能取代交件前的 `--all`」。

## 不做

- 不改 hook、`.claude/pm-workflow.json`、`CLAUDE.md`。
- 不改其他測試的內容，也不改不加參數時的分流行為。
- 不把 testmon 接進交件流程。

## 驗收

- 試用模式的測試：
  - 後端範圍才啟用；
  - 前端、全跑範圍不啟用；
  - 不寫戳記；
  - 開頭那一行的內容。
- 報告附上試跑對照表，至少 8 列。
- 報告寫結論與建議：
  - 有沒有漏抓、省多少時間；
  - 要不要正式用；
  - 正式用的話，CLAUDE.md 第 11 條與流程**建議改寫的全文**，由 PM 轉使用者決定。
- **靜態檢查**：ruff、format、mypy、lint-imports，結束碼都要是 0。
- **全量檢查**：全部 commit 之後跑 `uv run python scripts/check.py --all`，結束碼要是 0。
- **commit 與報告**：每項一個 commit。報告寫在 `docs/phases/PhaseTS-2報告.md`。
