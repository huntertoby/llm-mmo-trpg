# Phase SK-1 計畫：#166 第 1 組（只加資料或條件）

> 來源：`docs/design/06*.md` 6.38 第 1、2、3、6、7 點；玩法交接 4.1.26；決定紀錄 #166（使用者「8 B 其他都照建議」）。
> 設計細節以 6.38 原文為準，本計畫只列範圍與驗收。**數字一律是初值，接數值工坊，不試數值、不跑平衡量測。**

## 範圍

1. **距離條件**（6.38-1）：新條件「貼身」（距離 1）與「遠距」（距離 ≥ 5，工坊可調）。照一般條件打折預算；組合器、LLM（schema／提示詞）、工坊都能用。和 6.18 G 的連續縮放並存。
2. **「本回合移動過」折扣調小**（6.38-2）：條件定義不變，`harshness` 改成較寬鬆的一級，數值放工坊。
3. **閃現側變與小變化**（6.38-3）：
   - 側變（每次閃現最多 1 張）：換形狀可換骨架（單體 → 直線 3／錐形 2／十字）、換元素（關鍵字跟著換，卡片寫前 → 後）、推 ↔ 拉、換觸發時機、以血支付。
   - 新小變化：收回射程、蓄勢、利用地面、距離加碼、擊殺重置、每場一次、附淨化／附加速。
   - 不做：打帶跑（1 階不出，照複合技門檻）、濺射、拋射、分打。
   - 交件時用 PK-3 的閃現比較腳本（`scripts/pick_compare.py` 或 `wish_compare.py flash`，先查哪個）報 1 階單體白板每類候選數的前後對照（紙面，不呼叫 LLM）。
4. **新方向優先製造卡**（6.38-6）：挑選模式打分時，「新方向」格裡會製造該關鍵字（或同時製造又利用）的卡優先，純利用的排後。只改打分，出題規則（6.27.4）不變。
5. **戰場變奏讀「本回合施放過帶某標籤的技能」**（6.38-7）：6.24 變奏條件多這一種（6.16 C 條件已有）。

- SK-2 同時在做引擎新原語（吸收表面、鉤、推不動算撞擊、疾病擴散）。**不要碰**引擎的位移、推拉、狀態傳播與原語結算檔案；條件判定檔若必須改，只加新條件分支，在報告列出改了哪幾行，合併時由開發 PM 處理衝突。

- 戰鬥不變比對（照 PK-4 報告第 6 節的做法）：既有技能的戰鬥 different=0；有差異要逐項說明是 6.38 造成的。
