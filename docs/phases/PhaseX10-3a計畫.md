# Phase X10-3a 計畫：×10 收尾（後端）

> 來源：#169 題 10；`docs/design/05-*.md` 5.4.1；`docs/phases/PhaseX10-2b報告.md` 待決 1、4 與開發 PM 裁定；專案 PM 轉使用者「清掉重來」（舊存檔已季末重置）。
> 小段，只動後端和內容的文字。前端、骰子顯示另排 X10-3b。

## 範圍
1. **舊單位存檔直接拒絕**：roguelite 存檔、大世界角色存檔讀到舊單位時，回明確的錯誤和提示（例如「這是數值改版前的存檔，已經不能使用」），不要讀成很弱的角色。
   - 判斷方式照最保守的做法：存檔寫入時記下 `quantity_scale`；沒有記或不相符就視為舊存檔。
   - 新存檔一律寫入這個欄位。
   - API 和 CLI 都要顯示提示。
2. **說明文字的量類數字**：掃 `content/` 裡手寫的說明文字（`description`、`name_zh` 以外的中文說明欄位、劇情與情境文字）有沒有寫死舊單位的量。
   - 有就照 ×10 改。
   - 列表放在報告：檔、欄位、舊字、新字。
   - 不確定是量類還是不變類的，不改，列為待決。
3. **測試小工具的舊單位**：`tests/skillgen/helpers.py` 預設耐力 8 改成新單位，連帶的測試照新數字改，不放寬斷言。

## 驗收
- 每項都要有回歸測試；第 1 項要測三種情況：舊存檔被拒、新存檔可以讀、錯誤訊息的文字。
- 戰鬥不變比對 different=0（這段不該改到戰鬥）。
- ruff、format、mypy、lint-imports、`trpg content check` 都要 0。
- **交件前所有目錄的非 slow 測試都要各跑一輪**，最多 `-n 8`；cli 另外跑 `-m slow`。不要用 `-m ""`。
- 每項一個 commit。報告寫在 `docs/phases/PhaseX10-3a報告.md`。
