# Phase HID-1b｜隱蔽單位的圖層與預告洩漏

> 來源：`docs/art/HID-1檢查.md`（美術 PM 2026-11-07 決定）、`docs/開發PM交接.md` 3.1 第 3.1 點（玩法 PM 條件）。使用者 2026-11-10 同意恢復（「go」）。

## 範圍外

- 不改隱蔽規則、感知判定與揭露時機。
- 不改攻擊紅框的大小。
- 不做 #146～#150。

## 交付項目

1. **圖層**（`docs/art/HID-1檢查.md`）：
   - 「？」徽章和所有 HUD（HP 條、狀態列、徽章）畫在霧上面，人物本身留在霧下面。
   - HP 條、「？」徽章畫在攻擊紅框上面；順序是紅框在單位層之下、HUD 之下。
2. **預告不得洩漏隱蔽單位**（玩法 PM 條件）：`TelegraphChangeOut`（`src/trpg/api/schemas.py:286`，由 `src/trpg/api/telegraph.py:49` 產生）的 `before`、`after`、`amount`、`text` 對「隱蔽且對玩家未揭露」的單位，不得帶出 HP、護盾、狀態（目前可能洩漏狀態到期，要先查證，並把查到的洩漏欄位逐一列在報告）。隱蔽判定要沿用 HID-1 既有的資訊過濾函式，不另寫一份。
3. **四角飾件舊 FAIL**：戰鬥主角卡左下「四角飾件」的 `runCase` 依種子出現的 FAIL，查出原因並修掉，固定至少 5 個種子驗證。
4. **補拍**：見驗收條件。

## 受影響的既有功能

| 項目 | 影響 | 處理 |
|---|---|---|
| 引擎 `telegraph` | 不改；過濾只在 API 層，引擎的預告結果要維持完整 | 確定性與重播不受影響 |
| 開發模式或除錯檢視 | 若直接讀未過濾的預告 | 列出，不改 |
| `HID-1` 既有過濾 | 共用 | 既有測試原樣通過 |
| 已揭露、相鄰、我方單位 | 預告內容不變 | 測試比對與改前相同 |
| 繪製圖層 | 其他 HUD 不得被霧或紅框蓋住，也不得蓋住不該蓋的東西 | 跑排版煙霧檢查 |

## 行為一致測試

- API 層表格測試，**實際跑引擎**：隱蔽未揭露、隱蔽已揭露（相鄰）、一般敵人、我方 × 會產生預告的變化種類（狀態到期、環境傷害、護盾變化等）；未揭露單位的 `before`、`after`、`amount`、`text` 不含實際數值或狀態名，其餘情況與改前相同。
- 掃描序列化後的完整預告回應，確認未揭露單位的 HP、護盾數值與狀態 ID 不出現在對應項目中。

- 前端：`typecheck`、相關 vitest、`npx vite build` 結束碼都是 0。
- 排版煙霧檢查（`docs/開發PM交接.md` 6.2 第 5 點）1600×900、1040×624、800×600 全 PASS，四角飾件固定 5 個種子都 PASS。
