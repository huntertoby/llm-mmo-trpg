### 0.2 守則（沿用 CLAUDE.md，本階段特別注意）

1. **走路也是確定性的**：位置、巡邏、遇敵、事件全部由引擎依種子決定，世界日誌可以完整重播（21 共同前提）。巡邏用 `trpg.world.rng` 的新串流，不用 `random`。
2. **實地地圖是內容資料**：放在 `content/world/fields/`，以 pydantic 驗證；新增地圖不改程式（守則 4）。
3. **實地地圖照戰鬥規則畫**：地形 ID、高低差、物件和戰鬥地圖共用 `content/terrain.yaml` 與物件表，因為要就地切出戰場（21.3）。
4. **舊存檔要能讀**：角色現在只有 `region`、`location`，沒有座標。升級時放到該地點的預設入口，不讓舊角色壞掉。`WORLD_FORMAT`、`CHAR_FORMAT`、`WLOG_FORMAT` 有變就遞增，舊格式照現行策略處理（舊世界日誌標成「規則已變、不能重播」，與 `LOG_FORMAT` 遞增時相同）。
5. **戰鬥畫面和 roguelite 不受 HUD 影響**（`HUD移植需求.md` 第 1 節）。
6. 只做本階段規格內的事；多人同場（9.6.7 第 13 條）、即時朋友位置、新物件 ID（法陣地板、冷卻井等）不做，但設計不可擋住它們。

### 0.3 現況接點（2026-11-04 盤點）

- 位置：`world/state.py` 的 `CharacterState.region`、`location`，沒有座標。移動在 `world/step.py` 的 `_check_travel`、`_travel`：扣趕路補給、擲遇敵、`roll_event`、`_perceive`。
- 地點圖：`content/world/maps/{cloud_ridge,ashen_waste}.yaml`，schema 是 `content/world_map.py` 的 `LocationMapDef`。各 18 個地點，連線分別 21 條、17 條；`pos` 只用來顯示。
- 戰鬥：`world/battle.py` 的 `encounter_map()`、`reskin()`、`prepare_battle()`；站位交給地圖的 `start_zones`。沒有「從大地圖切一塊」的函式。驗證工具在 `content/maps.py`：`check_map`、`standable`、`step_allowed`、`_reachable_from`。
- 重播：`world/replay.py`，日誌寫在 `api/world.py` 的 `WorldStore._apply`。
- 前端：`world/WorldMap.tsx` 是 SVG 節點圖，右側一長條面板。`render/BattleRenderer.ts` 吃 `DrawModel`，`dev/regionGallery.ts` 已有「拼假的 BattleView 交給渲染器」的先例。
- 版本：`LOG_FORMAT` 為 `trpg-battle-log/111`、`WORLD_FORMAT` 為 `trpg-world/1`、`CHAR_FORMAT` 為 `trpg-char/1`、`WLOG_FORMAT` 為 `trpg-wlog/1`。

## 2. 6B-1 詳細規格：實地地圖資料格式與驗證

> 給實作 agent。動：`src/trpg/content/`（新 `fields.py`，`library.py` 載入）、`content/world/fields/`（格式範例與霧渡鎮、渡口石階兩張草稿）、`tests/content/`、`trpg content check`。**不改引擎**，也不改 `world/`。世界狀態與走路動作是 6B-2 的事。
> 依據：第 0、1 節；21.2、21.3、21.5、21.6；`content/maps.py` 的 `MapDef`（地形、高低差、物件的寫法照抄，讓 6C-2 可以直接切出戰場）；`content/world_map.py` 的 `LocationMapDef`（連線）。完成報告：`Phase6B-1報告.md`。

### 2.1 目標

每個地點一張實地地圖（`FieldMapDef`），城鎮另有室內圖。載入時驗證：
- 每條地點連線剛好對應一對出口；
- 出口、門、傳送石都站得上去而且互相走得到；
- 地形和物件 ID 合法。

### 2.2 資料格式（`content/world/fields/<region>/<location>.yaml`；室內放 `<region>/interiors/<id>.yaml`）

| 欄位 | 說明 |
|---|---|
| `id`、`region`、`location` | `location` 對到地點圖的地點 ID；室內圖寫 `interior_of: <location>` |
| `size`、`heights`、`terrain`、`legend`、`objects`、`surfaces` | 和 `MapDef` 同寫法（共用驗證工具） |
| `exits` | `[{at: [[x,y],…], to: <相鄰地點>, arrive: <對面出口的 id>, id}]`：邊緣出口，可以佔好幾格（路口寬 2～3 格） |
| `doors` | `[{at: [x,y], to: <室內圖 id 或隱藏地點>, id, hidden_until?: reveal}]`：門與洞口；隱藏地點的入口 `hidden_until: reveal`（21.6） |
| `teleport_stones` | `[{at: [x,y], id}]`：每區 2～3 個，城鎮各 1 個（數量由驗證檢查，第 2.3 節） |
| `entry` | 預設入口格（舊存檔、傳送、全滅回城都放這裡） |
| `npcs`、`facilities` | 城鎮與室內用：`[{at, id}]`；`facilities` 的 `id` 對到現有的設施種類（商店、鐵匠、酒館、導師、公告板、雇用、附魔台） |
| `spawns` | 6C-1 用：`[{at, group, patrol?: [[x,y],…]}]`；這段只定義欄位與驗證，不接遭遇 |
| `campfires`、`event_spots`、`situation_objects` | 6C-5 用：同上，先定義欄位 |

### 2.3 驗證（`field_map_problems()`，`trpg content check` 印出）

1. 地形、物件 ID 都在表裡；網格尺寸與 `size` 一致；出口格在邊緣上（門與傳送石不必）。
2. **一條連線＝一對出口**：地點圖每條連線 (a, b) 在 a 的地圖有 `to: b` 的出口、在 b 的地圖有 `to: a` 的出口，且雙方的 `arrive` 互相指向；隱藏地點的連線改用相鄰地圖上的 `doors`（`hidden_until: reveal`）。沒有連線的出口算錯。
3. 雲頂觀只從源晶裂痕進入；裂界門不畫（Q2 預設）。
4. 從 `entry` 走得到每個出口、門、傳送石、NPC 旁邊、設施旁邊（沿用 `standable`、`step_allowed`、`_reachable_from`）。
5. 尺寸照 21.3 的種類範圍，超出時給**警告**而不是錯誤（屬於數值）。
6. 傳送石：每區 2～3 個、每個城鎮 1 個；不足時給警告（地圖還沒畫完前先放行），6D-R 改成錯誤。
7. 還沒有實地地圖的地點**不算錯**，因為這階段逐段補。`content check` 要印出「雲嶺 x／18、荒原 y／18」。

### 2.4 這段要畫的兩張草稿

## 3. 6B-2 詳細規格：座標與走路動作

> 給實作 agent。動：`src/trpg/world/`（`state.py`、`actions.py`、`step.py`、`town.py`、`save.py`、`replay.py`，新 `field.py`）、`src/trpg/api/`（世界畫面多帶位置；不做前端）、`tests/world/`、`tests/api/`。**不改引擎**（`src/trpg/engine/`）。
> 依據：第 0、1 節；21.2、21.9 第 3、7、8、9 條，21.10（Q3、Q6、Q8）；6B-1 的 `content/fields.py` 與報告 `Phase6B-1報告.md` 第 5 節。完成報告：`Phase6B-2報告.md`。

### 3.1 位置模型

- `CharacterState` 加 `field: FieldPos | None`，內容是 `map`（實地地圖或室內圖 ID）、`x`、`y`、`facing`。原本的 `region`、`location` 保留，仍是「在哪個地點」的真相；`field` 一定屬於那個 location，或它的室內圖。
- 所在 location 沒有實地地圖時，`field` 是 `None`，照舊用 `TravelAction` 移動。這階段地圖逐段補，兩種方式並存。
- **舊存檔**：載入時 `field` 是 `None`。第一次需要座標時（世界畫面、走路），放到所在 location 實地地圖的 `entry`，這一步不寫進日誌，因為重播時算出來的結果一樣。`CHAR_FORMAT`、`WLOG_FORMAT` 遞增，舊日誌照現行策略處理。

### 3.2 動作

| 動作 | 內容 | 規則 |
|---|---|---|
| `WalkAction(path)` | 一串相鄰格（四方向），一次最多 30 格 | 每一步要 `step_allowed`（高低差、不可站、物件）；中途碰到出口、門、傳送石就停在那一格並觸發（3.3）；有未處理的遭遇時拒絕。**走格子不花時間、補給，也不擲遇敵**（Q3）。日誌記整串路徑，重播逐格重算 |
| `UseTeleportStoneAction(to)` | 站在傳送石上，傳到已解鎖的另一顆 | 傳送石要先走到過才解鎖（`CharacterState.teleport_stones`）；跨區照現行 `teleport` 的規則（去過的城鎮）。圖上點選傳送是 6C-6 |
| 現有的 `TravelAction` | 保留 | 目前地點有實地地圖時拒絕，提示「請走到出口」；沒有地圖時照舊 |

### 3.3 觸發

1. **邊緣出口**：踩上出口格就換圖，等於一次 `_travel(to)`。原有的檢查、扣補給（潛行在 6C-5 才做，這段 `hasten` 一律 false）、遇敵擲骰、`roll_event`、機遇提示、`_perceive` 全部沿用，所以「進入一張地圖＝一步」（21.9 第 9 條）自然成立。
   - **抵達位置**：放在對面出口 `arrive` 那一組格子**往地圖內側一格**的可站格上，不是出口格本身，所以不會一到就被送回去（6B-1 待決第 7 點）。對應位置照出口格的順序，寬度不同時取最近的格子。
   - 遇敵時照舊產生 `pending_encounter`。戰鬥怎麼開打照現行做法，就地切地圖是 6C-2。
2. **門**：踩上就換到室內圖或隱藏地點。室內圖**不算進入一張地圖**（Q6）：不擲遇敵、不擲事件、不扣時間。進隱藏地點算 `_travel`。`hidden_until: reveal` 的門，未發現時不可站、不顯示。
3. **離開室內**：室內圖的出口回到門所在的外面那一格，往外一格。
4. **傳送石**：踩上就解鎖，不自動傳送。
5. **城鎮**：城鎮地圖內走路照 1，城鎮本身也不算一步（Q6）；進城、出城的出口照 1。

### 3.4 確定性與重播

- 走路本身不抽亂數；換圖時沿用 `STREAM_TRAVEL` 等既有串流，順序和現在的 `_travel` 一樣。
- `world/replay.py` 能重播 `WalkAction`。測試同一組動作重播兩次結果一致，也和實際玩的結果一致。

### 3.5 API

- `WorldView` 加 `field`：目前地圖的地形、高低差、物件、出口、門（隱藏的不給）、傳送石、NPC、設施，以及自己的位置與朝向。格式要讓 6B-3 能直接組成 `DrawModel`。
- 動作端點收 `walk`、`use_teleport_stone`。
- OpenAPI 重產。

### 3.6 測試

- 表格測試涵蓋：
  - 走路合法與不合法（牆、高低差、超過 30 格、有遭遇）；
  - 出口換圖與抵達位置；
  - 門進出，以及室內不擲骰；
  - 隱藏門；
  - 傳送石解鎖與傳送；
  - 舊存檔放到 `entry`；
  - 有實地地圖時拒絕 `TravelAction`。
- 世界日誌重播：霧渡鎮 → 渡口石階走一圈，含一次遇敵。
- 交件：ruff、format、mypy、lint-imports、相關測試、swamp 種子 7 重播。
