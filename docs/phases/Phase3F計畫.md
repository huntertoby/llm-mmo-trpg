## 1. Phase 3F-1｜工坊後端（opus）

### 1.1 API（路徑可微調，報告列出最終版本）

- `POST /api/workshop/options`：輸入「目前組到一半的技能」（可缺欄位），回傳 **下一步的合法選項**，每個選項附中文名稱與一句說明：
  - 骨架（與它允許的種類 active／passive／reaction／stance／modifier……）→ 形狀（含參數範圍，例如射程、大小）→ 核心效果與附帶效果（依骨架允許的原語、上限個數；每個原語的參數與範圍：骰數、推幾格、哪種元素、哪種狀態……）→ 條件 → 代價（法力、冷卻、每場次數、源力……）→ 稀有度。
  - 「合法」以骨架、互斥規則、原語定義（`skill_primitives.yaml`）、最低稀有度推導；不合法的選項不列，或列出但標示原因（擇一，報告說明）。
- `POST /api/workshop/check`：輸入完整或部分技能，回傳：
  - 是否合法；違反的規則（中文，指出是哪條骨架限制或互斥規則）。
  - 預算：可用預算、技能點數、百分比（合格 70–100%），以及逐項點數明細（同 `trpg skills budget` 的內容）。
  - 最低稀有度與原因。
  - 技能卡片的中文描述（沿用 `trpg.narrative` 的描述模組）。
- `POST /api/workshop/random`：用隨機組合器產生一個技能（可指定階級、稀有度、骨架、種子），回傳完整定義，讓使用者修改。
- `POST /api/workshop/export`：回傳 YAML 文字（格式與 `content/skills/*.yaml` 相同，`provenance.origin` 標示來自工坊）。
- **裝上試玩**：`POST /api/battles` 新增可選欄位：自訂技能定義列表、主角要換掉哪一格（或加在空格）。以 `Ruleset.with_skills` 加入，裝備上限照常檢查（主動 ≤ 6、被動 ≤ 3、反應 ≤ 1）；不合法的技能拒絕並回中文原因。下載的戰鬥紀錄包含自訂技能，`trpg battle replay` 能重播。

### 1.1A 靶場地圖（使用者要求，2026-10-20：「裝上試玩 幫我做個靶場地圖」）

- 新地圖 `content/maps/training_range.yaml`（名稱「靶場」）：**只給工坊試玩用**，不進 roguelite 抽選、`sim matrix` 與一般地圖列表的預設選項（工坊的地圖選單預設選它）。
- 場地分區，讓各種技能都有東西可以試（約 12×10）：
  - 開闊區：放幾個木樁，試傷害、範圍形狀。
  - 牆邊與窄道：試推擊、撞擊、衝鋒、直線衝撞。
  - 物件區：木箱、油桶、可推倒的石柱與枯樹，試投擲、推倒、穿透、撥開。
  - 地形區：水窪、草叢、高台與一處深淵或岩漿邊，試元素互動、隱蔽、高度、傳送他人、墜落。
  - 一個源泉格，讓傳說技能可以多開一次。
- **木樁**：新單位範本 `training_dummy`（敵方，HP 很高、不移動、不攻擊、沒有反應；AI 行為模式設為原地防禦或什麼都不做），讓玩家能安心反覆施放、看每一下的數字。另放 1–2 個會移動、會攻擊的一般盜賊（可在工坊選「木樁」或「會反擊」兩種對手，預設木樁）。
- 勝負：木樁全倒或手動結束都可以；最大輪數設高一點（例如 30），方便慢慢試。
- `scripts/map_push_check.py` 通過；地圖與木樁範本通過內容驗證。

### 1.2 驗收條件（3F-1）

1. `options`：從空技能一步步走到完整技能的測試（至少 3 種骨架：打擊、位移、修正），每一步回傳的選項都能組出合法技能；回傳的參數範圍與 `skill_primitives.yaml` 一致。
2. `check`：合法技能回傳的預算百分比與 `trpg skills budget` 一致；不合法技能回傳中文原因（骨架限制、互斥規則、最低稀有度各一例）。
3. `random`：同種子同參數結果一致；產生的技能 `check` 合法。
4. `export`：匯出的 YAML 重新載入後與原技能相同。
5. 裝上試玩：用自訂技能開戰、施放一次、下載紀錄並 `trpg battle replay` 重播通過；不合法技能與超過裝備上限被拒。
6. 靶場：地圖與木樁通過驗證、不出現在 roguelite 抽選與 `sim matrix`；木樁整場不移動、不攻擊（測試）；裝上試玩可選「木樁」或「會反擊」對手。
7. `check.py` 全過。

## 3. Phase 3F-3｜複合技能：位移後接動作（使用者要求，2026-10-20；拆兩段）

> 使用者原話：「就是應該要有 位移後 做什麼事的雙骨架 但是可能就要加 預算這樣」。起因：想做「瞬移後對錐形範圍打擊」，目前一個技能只能有一種形狀（傳送只配指定格、錐形要從施放者展開），做不到。
> 排程：3-5b 之後、3-5c 之前（開發 PM 建議，使用者可改）。設計文件由玩法 PM 補寫（`docs/design/06-技能.md`），規格與設計衝突時以設計為準。

### 3.1 資料格式（3F-3a）

- 技能新增可選的 **動作段** `followup`：`{skeleton, shape, effects, condition}`。有 `followup` 的技能稱為複合技能：
  - **位移段**＝技能本身：骨架用 `displace`（或新增 `mobility` 骨架，實作者擇一並說明），效果只能是一個 **施放者自身位移原語**（`teleport`、`leap`、`dash`、`charge_through`、`shadowstep`），形狀照該原語的 `allowed_shapes`。
  - **動作段**：有自己的骨架與形狀，照該骨架的規則檢查（核心原語、附帶效果上限、占比、互斥規則）；形狀以 **位移後的落點** 為原點。先開放：`self` 為中心的形狀（`cross`、`square3`、`ring`）、`cone`、`line`、`single`；動作段不能再有位移段（不能套娃）、不能含召喚、區域、陷阱。
  - 6.6「每個技能效果原語 ≤ 4」以兩段合計。
- 最低稀有度：至少 **稀有**，且不低於兩段各自要求的最高稀有度。

### 3.2 結算與選取（3F-3a）

- 結算順序：位移段 → 若施放者實際移動到落點（沒有被擋下、沒倒下）→ 動作段以落點為原點結算；位移被擋下時動作段不結算（同 `dash` 規則）。
- 選取：兩段（位移目標 → 動作目標）。動作段的合法目標以「假設已在落點」推算；`use_skill` 新增 `followup_target`（方向、單位或格子）。`legal_actions` 的組合數要設上限（例如錐形與直線只列 4 個方向；單體只列落點射程內的目標），避免爆量。
- 預覽：同時顯示落點與動作段的影響範圍、命中率、傷害。
- 事件與重播：沿用既有事件；紀錄能看出兩段。

### 3.3 預算（3F-3a）

- 複合技能點數 ＝（位移段點數 ＋ 動作段點數）×（1000 ＋ `composite_tax_permille`）÷ 1000。`composite_tax_permille` 初值 **150**（省下一次行動的代價），放 `content/skill_budget.yaml`，之後以模擬調整。
- 動作段的點數依它自己的骨架與形狀倍率計算（和一般技能相同）；可用預算照技能本身的 AP。
- `trpg skills budget` 與工坊的檢查都要列出兩段明細與加成。

### 3.4 AI、工坊、網頁（3F-3b）

- AI：評估「落點 × 動作目標」組合（候選落點與動作目標都設上限，以預覽評分）。
- 工坊：選項推導與檢查支援動作段（「要不要接動作段」→ 動作段的骨架、形狀、效果）；即時檢查顯示兩段明細。
- 戰鬥網頁：兩段選取（先點落點／目標，再點方向或動作目標），預覽兩段範圍。
- 示範技能：「瞬影旋斬」（傳送 → 錐形傷害）、「躍擊震地」（跳躍 → 以自己為中心的十字或方形傷害並擊倒），裝進 build。

### 3.5 驗收條件

3F-3a：
1. schema：合法的複合技能（三種位移原語 × 兩種動作形狀）與不合法例子（動作段再放位移、召喚、區域；效果合計超過 4；位移段放兩個效果）。
2. 結算：落點為原點的錐形與自身中心形狀正確；位移被擋下時動作段不結算；`charge_through`、`dash` 停下的位置才是原點。
3. 預算：兩段加總 ×（1 ＋ 15%）的測試；`trpg skills budget` 顯示明細。
4. 預覽與實際結算一致；重播一致；`check.py` 全過。

3F-3b：
1. AI 在 `trpg sim maps --seeds 5` 中有使用複合技能的紀錄。
2. 工坊能組出「瞬移 → 錐形打擊」並通過檢查；PM 用瀏覽器在靶場施放一次。
3. vitest；`check.py` 全過。

## 4. Phase 3F-4｜複合技能的其他 5 種（玩法 #15；拆兩段）

> 來源：`docs/玩法PM交接.md` #15、設計 `docs/design/06-技能.md` 6.23（衝突時以設計為準）。使用者原話：「優先 1、2 都加」。接在 3F-3（基本型「位移 → 動作」）之後、**3-5c 之前**（使用者 2026-10-20 決定）；3F-3a 的 `followup` 已設計成可擴充（`when` 欄位）。

### 4.1 3F-4a：四種即時的第二段（opus）

| `when` | 種類 | 第二段原點／對象 | 何時結算 |
|---|---|---|---|
| `after_action` | 動作 → 位移（打帶跑） | 第二段是施放者自身位移，以動作後的位置為起點 | 一定結算（施放者倒下則不做） |
| `after_gather` | 聚集 → 範圍打擊 | 第一段把範圍內敵人拉向一點（`pull` 朝中心），第二段以該點為中心 | 一定結算 |
| `on_kill` | 擊殺 → 接下一段 | 動作或位移；對象依第二段形狀，從第一段目標的位置或施放者位置起算（實作者定並說明） | 第一段擊殺目標才結算 |
| `on_hit` | 命中 → 加碼段 | 動作；預設對同一目標 | 第一段命中才結算 |

- **預算**：`after_action`、`after_gather` 加成同基本型 150‰；`on_kill`、`on_hit` 的第二段點數 × 觸發機率（命中用預估命中率、擊殺用 `on_kill_expected_permille`，沿用既有係數）再加成。
- **元素連鎖規則**（6.23）：兩段之間若形成元素或表面連鎖（第一段造表面／施加狀態、第二段的元素會引爆或與之互動，依 `content/interactions.yaml` 判斷），schema 拒絕或預算加價 `composite_self_combo_permille`（初值 1000‰，即點數翻倍）；實作者擇一並說明（若 3F-3a 已做就沿用）。
- 選取：第二段需要玩家選的（位移的落點、`on_kill` 的下一個目標）在結算時用 `pending` 詢問玩家（同 `copy_skill`），AI 與重播直接帶選擇；不需要選的直接結算。
- 示範技能：回馬斬（錐形斬擊 → 後跳 2 格）、引力爆（拉向中心 → 中心爆炸）、死亡迴旋（擊殺 → 跳到下一個敵人身邊再砍）、破甲連擊（命中 → 錐形震波）。

### 4.2 3F-4b：延遲段、AI、工坊、網頁（sonnet）

- `when: delayed`：第二段在 **施放者下回合開始時**，或 **指定條件成立時**（先做「本輪被攻擊」）結算；等待期間是施放者身上的狀態（可序列化、重播），**施放者倒下、暈眩、冰凍時取消**；網頁與環境預告顯示倒數與預計範圍。延遲段的折扣 `composite_delayed_discount_permille`（初值 800‰）。示範：蓄力斬（下回合開始自動釋放範圍斬）、格擋反擊（本輪被攻擊時觸發範圍反擊）。
- AI：評估 3F-4a 與延遲段（組合數設上限，最簡單近似）。
- 技能工坊：能組出所有種類並在靶場試（選項推導加上 `when` 與第二段）。
- 網頁：第二段的 `pending` 選取、延遲段倒數顯示。

### 4.3 驗收條件

3F-4a：四種 `when` 的結算（含不觸發時第二段不結算）、元素連鎖規則、預算折算、`pending` 選取與重播；每種一個示範技能裝進 build；`check.py` 全過。
3F-4b：延遲段的倒數、條件觸發、取消（倒下、暈眩、冰凍）、環境預告；工坊能組出六種複合技能（PM 用瀏覽器在靶場各試一種以上）；AI 在 `sim maps` 有使用紀錄；`check.py` 全過。
