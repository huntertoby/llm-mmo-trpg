## A. 讀程式的回答

### A1. 沒開 LLM 時，閃現選項怎麼來？

- 來源是 `UsageSource`（`src/trpg/skillgen/flash_offer.py`）：**固定的模板表**（`content/flash_templates.yaml`，小變化約 60 個、大變化 8＋12 個、轉型 6 個），依「這招的用法統計」排序後輪流取，不是 Mock，也不是隨機組合器。
- 每個選項的說明是模板的固定一句話（例：「多打一下：同一個目標多一段命中（每段傷害依預算調整）」）；小變化**不改名**，大變化與轉型是「前綴・原名」（例：「收割・頂撞」）。
- 新技能（升級三選一、機遇）沒開 LLM 時才是**隨機組合器**（`random_composer`），名字像「頂撞（二）」「撞擊加碼」。
- 所以是的：沒開 LLM 時，玩家看到的閃現全是模板句，新技能的名字是組合式的，會覺得無聊。

### A2. 開 LLM 時，LLM 負責什麼、引擎負責什麼？

| 項目 | 誰決定 | 備註 |
|---|---|---|
| 挑哪幾個變化（類別＋模板） | **LLM** | 只能從引擎事先算好的「目錄」挑；目錄＝沒開 LLM 時同一套候選，且只列這招套得上的 |
| 第二關鍵字、第二元素、新形狀 | **LLM**（從目錄的選單挑） | 每個模板的關鍵字選單最多 6 個、橋接最多 3 個，都是引擎先排好的 |
| 一句話說明 `note_zh` | LLM 寫 | **只拿來檢查，然後丟掉，玩家看不到**（`Variation` 沒有這個欄位） |
| 名稱與敘事（命名步驟 `name_offer`） | LLM 寫得出來 | **遊戲沒有呼叫**：只有評估工具 `flash_eval.py` 用；遊戲裡選項名稱照舊 |
| 轉型（轉被動、反應、召喚、陷阱、姿態、修正型） | **引擎（資料＋種子）** | 「轉型不在目錄內（由資料保底）」 |
| 所有數值、預算、強度下限 | **引擎** | LLM 輸出的 schema 沒有任何數值欄位 |
| 不足的選項 | **引擎**用模板補位 | |

### A4. 使用者怎麼開 LLM 試閃現

1. 確認 LM Studio 已載入模型，模型名用 `GET http://100.87.188.89:1234/v1/models` 列出的那個（目前是 `swift-1.5-qwen3.8-27b-uncensored-dynamic-mtp`）。
2. **不要改進版控的 `config/llm.toml`**：在主資料夾建 `config/llm.local.toml`（`.gitignore` 的 `*.local.*` 已排除），內容：
   ```toml
   base_url = "http://100.87.188.89:1234/v1"
   model = "swift-1.5-qwen3.8-27b-uncensored-dynamic-mtp"
   api_key = "local"
   timeout_s = 240.0
   max_retries = 3
   temperature = 0.7
   max_tokens = 1024
   json_schema_mode = "auto"
   generate = true            # 大世界與網頁 LLM 開關的預設＝開
   enable_thinking = false
   reasoning_effort = "none"  # 這個模型在 LM Studio 必填，見 B.1
   oneof_as_anyof = true
   ```
3. 開伺服器前設 `TRPG_LLM_CONFIG=config/llm.local.toml`（PowerShell：`$env:TRPG_LLM_CONFIG="config/llm.local.toml"`），再 `uv run trpg serve`。
4. 先跑 `uv run trpg llm ping`：最後一行要是「schema 寫法：response_format」。
5. 大世界：標頭的 LLM 開關（`generate = true` 時預設開）；角色 4 級後、在城鎮或營火、有靈感點、那招上場用過，按閃現。前端會先等預先生成（最多 10 秒），沒趕上就給模板版。
6. roguelite：開新一輪時勾 LLM（`POST /api/runs` 的 `llm: true`），或命令列 `uv run trpg run auto --seed 11 --llm`。

### A5. 補齊大約要幾段

| 段 | 內容 | 工作量 |
|---|---|---|
| 1 | **把 LLM 的名稱與說明接進遊戲**：大世界預先生成與 roguelite 出題後呼叫 `name_offer`（大變化、轉型），名稱寫進提議紀錄供重播；`note_zh` 存進選項當玩家看得到的說明（小變化也有一句 LLM 說明） | 1～2 段（大世界要動預先生成的紀錄格式與重播） |

最少 2 段（1＋2）就能讓「開 LLM 的閃現」看起來和沒開不一樣；含願望池約 4～6 段。

## B. 實測結果

### B.1 端點

- `GET /v1/models`：HTTP 200，0.01 秒。列出 `swift-1.5-qwen3.8-27b-uncensored-dynamic-mtp`、`gemma-4-12b-it`、`gemma-4-31b-it`、`qwen3.8-27b`、`qwen3.6-35b-a3b`、一個 embedding 模型。
- **模型名**：派工給的是 `…qwen3.6-27b…`，伺服器上的是 `…qwen3.8-27b…`。用 3.6 的名字 LM Studio 也接受，但回應的 `model` 是 3.8；建議設定用列表上的正確名稱。
- **思考模式**：`chat_template_kwargs.enable_thinking=false` 對這個模型**無效**，仍輸出思考內容；60 token 的上限全被思考用光、回答是空的。加 `reasoning_effort = "none"` 後思考 token 歸零、0.8～1.5 秒回答。`docs/部署說明.md` 只寫了 Gemma 要加，這個模型也要。
- `trpg llm ping`：0.40 秒，schema 寫法 `response_format`（約束有生效）。

### B.2 閃現走 LLM（`make_offer` ＋ `LlmFlashSource`，與遊戲同一條路）

7 招 × 3 種題目（第 1 次不指定、指定類別、第 3 次大變化），角色 2 階、地區雲嶺、手上長劍：

| 技能 | 種類 | 不指定 | 指定類別 | 大變化 |
|---|---|---|---|---|
| 火焰箭 | 主動 | 部分（3/4） | 部分（2/3） | 部分（3/4）＋轉型「反擊」 |
| 餘燼烙印 | 被動 | LLM 湊滿 | 部分（1/3） | （測試腳本沒推到第 3 次） |
| 迎頭痛擊 | 反應 | LLM 湊滿 | LLM 湊滿 | 部分（3/4） |
| 暗影突襲 | 主動（隱蔽） | LLM 湊滿 | 部分（1/3） | 部分（2/4）＋轉型「餘波」（被動） |
| 回春 | 主動（治療） | LLM 湊滿 | 部分（1/3） | LLM 湊滿＋轉型「架式」（姿態） |
| 普攻精通 | 修正型被動 | 部分（3/4） | LLM 湊滿 | 目錄是空的 → 全模板 |
| 堅壁姿態 | 姿態 | LLM 湊滿 | LLM 湊滿 | 目錄是空的 → 全模板 |

統計（21 題）：

- LLM 湊滿 9、部分 9、全模板 3（都是目錄空的，修正型與姿態的大變化沒有 LLM 可挑）。
- 選項來源：LLM 挑的 50 個、模板補位 10 個、轉型保底 3 個。
- LLM 呼叫 40 次，**平均 2.9 秒、中位 2.6 秒、最長 8.1 秒；0 次逾時、0 次連線錯誤、0 次 JSON 或 schema 錯誤**。每題（含重試）平均 5.6 秒、最長 12.2 秒（大世界有預先生成，玩家通常不必等）。
- 提議的 94 項中 42 項被擋（45%）：
  - `flash.duplicate` 18：指定類別時目錄只剩 1～2 個模板，題目卻要 3 個，模型只好重複，三次都白試。
  - `flash.note_zh.missing_added` 11：說明沒寫出「加上的效果」的詞。部分是誤擋，例：「山風捲起火焰，霧氣中多一段風屬傷害」被擋，因為詞表的風只收「狂風、疾風、風刃…」。
  - `flash.note_zh.effect_mismatch` 3：說明提到這招沒有的效果。
  - 被擋的理由全是**說明文字**或**重複**；而說明文字最後根本不顯示。

實際選項例子（玩家會看到的樣子；「說明」是模板固定句）：

1. **火焰箭・不指定**（LLM 挑 `keyword_exploit`＋潮濕）：名稱「火焰箭」；說明「加第二個關鍵字：目標帶有該關鍵字時加碼」；製造點燃、利用潮濕；效果 1d4 火焰＋燃燒 1 回合＋「若目標站在水上再 1d10 火焰」；預算 95%。LLM 寫的說明「雲嶺濕氣重，目標帶濕時火焰爆發更猛。」沒有顯示。
2. **迎頭痛擊（反應）・不指定**（LLM 挑 `focus_condition`）：名稱不變；說明「專注：觸發條件收緊一級…換成觸發效果」；新條件「目標血量低於 50%」；武器傷害 ×1.8；預算 91%。
3. **堅壁姿態・不指定**（LLM 挑 `stance_ward`）：說明「姿態附帶護盾」；進入時護盾 2d6＋力量、2 回合；預算 96%。
4. **回春・大變化**（LLM 挑 `support_imbue`＋潮濕）：名稱「潮濕・回春」；說明「橋接潮濕：施放時在目標腳下留下潮濕的場地」；再生 3 回合＋治療 1d8＋造水；預算 88%。
5. **暗影突襲・大變化轉型保底**：名稱「餘波・暗影突襲」，**轉成被動**；說明「你的攻擊命中時，自動對被打中的敵人補上縮小版的這招」；1d8 物理＋1d6 火焰；預算 98%。

對照：同一批大變化如果呼叫命名步驟（遊戲目前沒呼叫），模型給的名稱是「山火燎原、雲火引信、雨焚劍意」「霧隱灼劍、鶴唳焚雲」「寒泉養冰、霧潤生息、磐石凝姿」，每題約 8 秒（最慢一題 24 秒）——這才是使用者期待的「有呈現」。

**roguelite 實跑**（`trpg run auto --seed 11 --llm --flash-policy mixed`，一輪）：閃現 4 題全走 LLM（湊滿 2、部分 2），選項名稱仍是「頂撞」「收割・頂撞」「撞擊加碼」；同一輪的完整技能提議 1 題 3 次都沒過（`keyword.required`、`budget.weak`、`skeleton.secondary_count`），退回組合器。

**願望**：沒辦法測，程式沒有願望池（見 A3）。
**轉成被動或反應**：測得到（火焰箭轉反應「反擊」、暗影突襲轉被動「餘波」、回春轉姿態「架式」），但都是資料保底，不是 LLM 選的。
