# Phase E2 計畫：單位規則表（種族、裝備共用；AI 看免疫）

> 來源：
> - `docs/phases/內容擴充評估.md` E2。
> - 規則：`docs/design/08-裝備.md` 8.29「E2」（#175）。
> - 施工草案：`docs/phases/E2-E5草案.md` 的「E2」節。行號是當時讀的，施工前要再確認。
>
> E1 合併以後才能派，因為兩段都會改 `equipment.py`。這段和 E5 平行，兩邊不改同一批檔案。

## 範圍

1. **共用規則表**：
   - 把種族被動的規則種類和參數檢查抽成共用模組，例如 `content/unit_rules.py`。`races.py` 改成從共用模組匯入，YAML 格式不變。
   - 先純搬移：種族的查詢結果逐條比對，一條都不能變。
2. **裝備的地形規則詞條**：
   - 新增詞條類別 `terrain`，欄位和參數檢查跟共用表同一套。
   - `affixes.yaml` 先不放任何一條，產生器也不產。
3. **引擎查詢改成看所有來源**：
   - `engine/rules/race.py` 的 `passive_of` 等函式改查「單位身上所有規則來源」：先看種族，再依裝備部位的固定順序看裝備。各查詢函式的介面不變。
   - 8.29 E2 第 1 點：同一條規則同時來自種族和裝備，或來自兩件裝備時，**不疊加**。裝備那條標灰，寫「和種族被動〇〇重複，沒有效果」。數值型的規則也一樣。
   - 裝備給的移動加成，計入「裝備的移動加成合計 +2」（8.21.5.3）。
   - 角色面板、裝備卡要顯示裝備的地形規則和標灰原因。API 新欄位要有預設值，並重產 OpenAPI 和前端型別。
4. **AI 看雙方的免疫**（8.29 E2 第 2 點）：
   - `engine/ai/utility/position.py` 的 `_harmful` 加上 `unit` 參數，呼叫端都改成傳入要評估的單位：
     - 自己免疫的格子，AI 敢站；
     - 不會把免疫的對手推進那種格子；
     - 不會在對手腳下放對方免疫的表面。
   - 做成開關，放在 content 規則，**預設開**（使用者已定）。關掉時要和現在的結果逐場相同。
5. **收尾**：`classify.py --check` 要通過，新加的數字照 `classes.yaml` 歸類。

## 不做

- E3 的新規則種類（霜行、攀岩、表面傷害免疫）。
- 招牌效果的定價、「同時 3 個」、產生器（E6）。
- 不改 `docs/design/`，不改 `config/` 既有的值，不改既有的數值。

## 驗收

- **結果不變（開關關閉時）**：442 招逐招預算、a 段那組 78 場（`compare78.py`）、census 小樣本、CLI 快照、parity，都要 different=0。
- **開關打開（預設）時**：
  - 78 場比對要列出有差異的場次，並逐場說明原因。
  - 預期只有帶免疫的單位（例如角魔）參與的場次會變。其他場次要 different=0。
  - CLI 快照、parity 有變時，逐項說明原因再重產。
- **新機制的測試**：
  - 裝備地形規則可以生效；
  - 和種族重複時標灰、不疊加；
  - 移動加成上限；
  - AI 不把免疫的對手推進那種格子；
  - 重播確定性：同種子跑兩次，結果相同。
- **截圖**：裝備卡、角色面板的地形規則與標灰，1600×900、800×600 各一張，存到 `docs/art/shots/e2/`，交美術 PM 看。
- **靜態檢查**，結束碼都要是 0：
  - ruff、format、mypy、lint-imports；
  - `trpg content check`、`classify.py --check`；
  - tsc、vitest、build。
- **全量檢查**：全部 commit 之後，照派工的指示跑 `uv run python scripts/check.py`，加上 slow 的 parity 和 cli。
- **commit 與報告**：每項一個 commit。報告寫在 `docs/phases/PhaseE2報告.md`。
