## 1. 目標

把視線從「看得到／看不到」兩種結果，擴充為 **全掩護、半掩護、隱蔽** 三層，並加入牆壁地形。讓遠程搶高台、位移推出掩護、破壞掩護成為有意義的戰術，給不同 build 更多發揮空間。

**不在範圍內**：技能系統、新元素、新勝利條件、LLM、前端。

## 3. 規則

### 3.1 三層視線阻擋

| 類型 | 來源 | 效果 |
|---|---|---|
| 全掩護 | 物件標籤 `blocks_sight`、地形 `wall`、高度規則（計畫 5.1 視線） | 視線被擋，不能選為目標（沿用現有邏輯） |
| 半掩護 | 物件標籤 `half_cover` | 命中 −2（數值放 `core.yaml` 的 `half_cover_hit_penalty`） |
| 隱蔽 | `concealed` 狀態（草叢、黑暗、濃霧） | 攻擊有劣勢（沿用 1B） |

半掩護與隱蔽可同時生效（−2 且劣勢）。

### 3.2 半掩護判定

對遠程攻擊（含遠程技巧動作），目標受到半掩護，若且唯若存在一個格子 C 同時滿足：

1. C 與目標 **四方向相鄰**；
2. C 上的物件帶 `half_cover` 標籤且未被摧毀；
3. C 位於攻擊者與目標之間：以「攻擊者到目標的方向」判斷——C 相對於目標的方向向量，與目標指向攻擊者的方向向量 **內積 > 0**（即 C 在目標朝向攻擊者的那一側，含斜向）；
4. 攻擊者的高度 **沒有** 高於「C 的地形高度 + 1」。（攻擊者比掩護物高至少 1 層時無視半掩護；物件本身視為 1 層高。）

- **近戰攻擊無視半掩護。**
- 判定必須對稱性無關（半掩護本來就是單向的：目標躲在箱子後面，不代表攻擊者也被掩護），但必須是 **確定性** 的，且 `preview` 要顯示「半掩護 −2」並說明來源物件。
- 單位不提供掩護。

### 3.3 牆壁地形

- 新增地形 `wall`：不可通行、阻擋視線（全掩護）、不可站立、不可被一般攻擊破壞（之後由技能決定）。
- 地圖圖例新增 `#` 對應 `wall`（若 `#` 已被使用，改用其他字元並在報告說明）。
- 地圖連通性檢查需考慮牆壁。

### 3.4 新物件

在 `content/objects.yaml` 新增或調整：

| 物件 | 標籤 |
|---|---|
| `crate`（木箱） | breakable、pushable、blocks_move、**half_cover**、flammable |
| `low_wall`（矮牆） | breakable（高 HP）、blocks_move、**half_cover** |
| `oil_barrel`（油桶） | 原有標籤 ＋ **half_cover**（躲在油桶後面很危險，這是刻意的） |
| `fallen_log`（倒木） | breakable、blocks_move、**half_cover**、flammable |

### 3.5 AI

效用 AI 的評分加入掩護考量：
- 遠程與弓手行為模式：偏好結束回合時站在有半掩護、且能看到敵人的位置。
- 狡猾行為模式：偏好用推擊把敵人推離掩護，或攻擊敵人的掩護物件。
- 權重放在 `content/ai_profiles.yaml`。

### 3.6 地圖

- 3 張示範地圖加入牆壁與半掩護物件，讓掩護在每張圖都有意義。
- 新增 1 張示範地圖 `ruined_fort`（廢墟要塞）：牆壁、矮牆、高台並存，用來展示三層視線。

## 4. 驗收條件

1. `uv run python scripts/check.py` 五項全過；Phase 1A、1B 的驗收條件仍成立。
2. 情境測試：
   - 遠程攻擊箱子後方的目標 → 命中 −2；從側面（箱子不在兩者之間）攻擊 → 無懲罰
   - 攻擊者站在高 1 層以上的位置 → 無視半掩護
   - 近戰攻擊 → 無視半掩護
   - 箱子被摧毀後 → 半掩護消失
   - 半掩護 ＋ 隱蔽同時生效
   - 牆壁阻擋移動與視線
3. `preview` 顯示半掩護懲罰與來源物件，命中率計算包含它。
4. AI 情境測試：弓手在有掩護與沒掩護的兩個等價射擊位置中選擇有掩護者；狡猾模式在可行時會推擊掩護後的敵人或攻擊掩護物件。
5. `trpg battle --map ruined_fort --seed 42` 跑完並分出勝負，戰鬥紀錄中看得到半掩護的影響（例如「命中 −2：木箱掩護」）。
6. 重播與確定性測試仍通過。
7. 第 2.5 節 10 項決定皆已實作並有對應測試；AI 效能達到目標；四張示範地圖的勝率與輪數表格符合範圍。
