1. **遇敵卡頭像（#9、G4）卡在資料，沒做。**
   - 任務說「如果真的需要伺服器多給資料，先停下來問我」，所以這項停下來問。
   - 遇敵卡的資料（`EncounterEnemyView`）只有名字、精英、詞綴、第三方，沒有範本 ID 和紙娃娃外觀，也沒有頭目標記。
   - 實地地圖上的敵群（`FieldEnemyView`）只帶「帶頭那一名」的外觀，同一群裡其他範本（例如盜賊群裡的盜賊盾衛）畫不出來。
   - client 也沒有範本 → 外觀的對照表（`unitDolls.json` 只是測試用的 fixture）。
   - 要做，需要伺服器在 `EncounterEnemyView` 每一名加上 `look`（同 `FieldHeroView`：`template_id`、`doll_look`、`race_look`，頭目的 `rarity` 在 `doll_look` 裡）。這是加欄位，不影響規則。
   - 補上欄位後，前端約 0.25 段：縮圖用 `renderFigureCanvas`，精英、頭目的金環照 `敵人外觀.md`。
   - 請決定：開伺服器小段補欄位，或改用別的做法。
2. **雇用面板的技能圖示**是用現有 API 間接對出來的：主題句相同的 build，加上名字相同的技能卡。
   - 如果之後兩個 build 的主題句相同、同名技能不同，可能對錯。
   - 比較穩的做法是請伺服器在 `MercenaryView` 加 `skill_ids`。現在照最保守的做法：對不上的名字寫字。
   - 影子（其他玩家的影子）的技能不在 build 裡，照舊寫字。
3. **物品格的物品名牌**：消耗品、材料還沒有物品圖示（G10），先畫名字小牌（2 字×2 行）。G10 移植後換成圖示。
4. **一種物品超過疊數時**，伺服器算多格，畫面只畫一格，空格照伺服器的格數少畫。這種情況下，格表上看起來的空格會比實際少一兩格，但總數照伺服器的「N／30 格」。
5. **空槽圖示**是「該欄預設造型的灰階淡化剪影」（頭盔、皮甲、手套……），沒有另畫空槽專用圖。
6. **選取與詳情**：點格子看詳情（預設選第一格有東西的）。原本所有裝備卡一次列出來，現在一次看一張。
7. **路牌位置**：插在出口依 (y, x) 排序的第一格，多格的出口只插一塊。南北向的牌靠格子左側，東西向的放在格子上半。
8. **室內地圖不畫路牌和光圈**（已經有門墊和入口光），滑過照樣有綠框和地名。室內這段沒有另外截圖。
9. **戰鬥的撤離出口格**照舊是「出」綠框，因為那是勝利條件的標記，不在這段範圍。
10. **開發頁的雇用與別大類截圖**：雇用面板的資料來自伺服器的真實角色（霧渡鎮可以雇用），只是沒走到酒館點開；別大類的弓是固定資料。
