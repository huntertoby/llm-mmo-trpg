# Phase FL-1d 報告：增益範圍補定（06 6.34「費用方向」第 6 點）

> 規格：`docs/design/06-技能.md` 6.34「費用方向」第 6 點的 FL-1c 後補範圍（玩法 PM 89a524d1e）；背景 `docs/phases/PhaseFL-1c報告.md`。開工時 `git merge --ff-only main`（`89a524d1e`）。

## 1. 改法

**規則**（`src/trpg/skillgen/flash_cost.py`）

- `_BUFF_DURATION_TYPES` 加 `shield`、`cheat_death`、`redirect_damage`：它們的 `duration` 算「狀態回合」，蓄力 +1（累計原招 +2）、輕巧降（最少 1，再低由驗證器擋：護盾最少 2）。
  - 護盾沒寫回合＝2（原語定義「省略＝2」，`_SHIELD_DEFAULT_DURATION`）；`strength_table` 也把沒寫回合的護盾記成 2，否則「沒寫 → 3」比不到。
  - 不死、轉移傷害沒寫回合（用狀態預設）時不調（現有內容都有寫）。
- 只對友方的區域裡巢狀的狀態：新增 `_walk`（頂層效果＋只對友方的 `zone` 裡巢狀的 `apply_status`），`_Step.sub` 指巢狀的第幾個。`strength_table`（鍵 `effects[i].effects[j]:apply_status:<狀態>.<欄位>`）、退路步驟（回合、數值型狀態的強度）、原招回合表都走它，**算法跟直接施加的狀態一樣**（強度只在回合加不上去時才調）。
- `grant_ap`、`extra_reaction` 的數量不算（本來就不在退路裡，測試鎖住）。
- 調整順序（傷害 → 狀態強度 → 狀態回合）、一次一項、蓄力可一升一降、輕巧不准任何一項變強：都沒動。巢狀的步驟排在它的區域之後。

**差異清單**（`src/trpg/api/flash_changes.py`）：卡片數字沒有這些回合，另外列：

- `effects[i].amount`：「護盾回合」「不死回合」「轉移傷害回合」（護盾沒寫算 2），接在 FL-1c 的「獲得技能回合」「區域回合」同一處。
- `effects[i].effects[j].amount`／`.magnitude_permille`：「<狀態名>回合」「<狀態名>強度」（例：戰歌的「激昂回合 1 → 2」）。

**has_options 與快取**：沒改，照舊（同一套衍生流程自動吃到新規則）。API schema 沒變，`openapi.json` 重產後沒有差異。

## 5. 待 PM 決定

1. **「區域裡面巢狀的狀態」只算只對友方的區域**：規格寫在第 6 點「增益」底下，所以對敵或全體的區域（目前只有火牆，巢狀是傷害）裡的狀態不算。現有內容只有戰歌有巢狀狀態，實際沒有差別。
2. **巢狀只算 `apply_status`**：區域裡巢狀的治療、護盾、傷害骰子不在退路裡（規格只說「狀態」）。
3. **不死、轉移傷害沒寫回合時不調**（用狀態預設的寫法沒有對應的比較基準）；護盾沒寫照原語定義算 2。現有內容都有寫回合。
4. **輕巧降不算預算的回合（不死、轉移傷害）**：預算器不替這兩種的回合計價，降回合不會讓「扣掉代價的分數」變低，所以 `light_adjusted` 一路降到最少 1 回合、取最後一個合格的（魂結 3 → 1）。照 FL-1a 的退路規則，沒有另訂。要不要讓預算器替它們的回合計價屬數值，交使用者在工坊看。
5. 仍沒有選項的 7 招與戰歌輕巧、展翼蓄力、不死之誓的粒度問題同 FL-1c，未變。
