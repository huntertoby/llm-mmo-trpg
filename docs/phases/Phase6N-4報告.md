## 1. 觸發（只讀事件，不改規則）

`vfxFor` 在切段落時順便記下每個受擊者的反應，時間＝那一段的命中點（`cast.impactMs`，串接器再對齊出招的 `hitAt`）。同一段同一人只留一個：倒下 ＞ 格擋 ＞ 重擊 ＞ 受擊 ＞ 閃避。

| 片段 | 事件 |
|---|---|
| 受擊 | `damage_dealt`，`amount > 0` |
| 重擊（多一點震動） | 同上，`hp_before − hp_after ≥ 最大 HP × 250‰`（最大 HP 讀這一步的 `view.units[].max_hp`） |
| 格擋 | `damage_dealt` 的 `block_permille < 1000` |
| 閃避 | `attack_rolled` 的 `hit: false`（技能的命中判定和普攻開段的那一個都算） |
| 倒下 | `unit_downed`（取代同一段的受擊） |
| 冰面滑倒 | 沿用 `walkAnim.ts` 的判斷（`check_rolled` 失敗、`unit_slid`），見第 4 節 |
| 陷阱夾住 | `trap_triggered` 的 `unit_id` 是走路的人（沿用 6A-4d 的停頓） |

- 這一段施放者打的、這一段裡倒下的算這一段；別人打的（反擊、持續傷害、陷阱）放到這一步的最後。
- 被撞倒的人（`knock_prone`）只播 6N-2 的 `knocked_down`，不另播受擊；命中那一刻的白閃改由這個片段帶。
- 變體的雜湊：閃避往左或右跳 ＝ `seedOf("戰鬥鍵:seq:單位:dodge")`。**戰鬥鍵用 `view.map_id`**（畫面資料裡沒有戰鬥 ID；同一場不變，重播、重新整理一樣），見待決 2。

## 2. 片段（`reactClips.ts`，時間 → 量化姿勢，24 格）

| 片段 | 長度 | 做法 |
|---|---|---|
| 受擊 | 360 ms | 6M-4 的 `humanHit`：白閃只閃剪影（開頭 0.85）、仰一下、退 7 再回來 |
| 重擊 | 440 ms | 同上，退 1.3 倍，退的時候抖幾下，白閃久一點 |
| 閃避 | 380 ms | 蹲一下 → 往側邊跳 14、離地 5 → 落回原位；身體往反方向斜；原地留一張淡藍殘影淡掉；**沒有白閃** |
| 格擋 | 340 ms | 很快擋起來：副手是盾＝舉盾（另一隻手往前抬）；主手是表上的武器＝橫劍（主手往前上抬、手肘彎，武器照預設握法）；空手、符紙、拂塵、傀儡線、法球＝雙臂交叉擋臉。身前迸 7 道火花、退 3、淡白閃 |
| 倒下 | 640 ms | 0～0.22 受擊（白閃、往後彈）→ 0.22～0.55 膝蓋一軟往下沉 → 0.55～1 側倒，最後一格＝倒地圖示（見第 3 節） |
| 陷阱夾住 | 400 ms（＝6A-4d 的停頓） | 夾子合上那一刻（0.25）白閃、身體一縮、膝蓋彎，最後站直；腳不動。停頓結束才跳傷害數字與定身圖示（6A-4d 原有） |

- 一招（不含連鎖、反擊）從起手到命中仍照 6N-1 的 1.8 秒上限；反應是在命中點之後播，不影響上限。
- **異形**：受擊、重擊、倒下用 6M-2 的通用片段（`hit`、`fall`）；閃避、格擋退回受擊的輕版（幅度一半、沒有白閃）。陷阱夾住用受擊。
- **形態、召喚物、倒地狀態的人**：沒有骨架，受擊、重擊、倒下疊白色剪影閃白（6C-8），格擋淡一點（0.4），閃避不閃。

## 3. 倒下接上倒地圖示（沒有跳一下）

- 正式播放在命中點那一刻就用結果重畫，倒下的人在重畫後已經是倒地圖示。片段畫的是**站著的紙娃娃**（`uprightTexture`；側倒時換不含影子的 `figureBare`），旋轉、平移照 `paperdoll.drawFigurePose` 的倒地變換（平移 (-27, -11)、轉 90°），透明度從 1 慢慢變成倒地外觀（0.6／0.45），灰階先拿掉、躺平時放回去；最後一格直接換回倒地圖示的貼圖。測試鎖住最後一格的旋轉、平移、姿勢。
- 原本 `unitSprites` 不含倒下的人（重畫後片段找不到人，6C-8 的倒地白閃也是這樣）。新增 `downedSprites`／`downedDrawOf` 只給倒下片段找；待機、狀態、走路照舊不碰倒下的人。
- 倒下的異形原本重畫成站著的灰色貼圖，倒下片段播完會跳回站著。改成重畫時也畫 `fall` 片段的最後一格（塌扁、往後倒，透明度交給倒地外觀）——**這改了倒下異形的靜態樣子**，見待決 3。

## 4. 冰面滑倒、陷阱

- 冰面滑倒（6E-2）原本就有：第一格踉蹌 → 每格滑行 → 停點倒下（`proneBody`，從滑行姿勢倒下）；腳下冰花與擦痕；倒在友軍格才短短滑回空格。這段沒改動畫，只在 `#react` 列出來。
- **規格文字和現行規則不一致**：需求文件 6N-4 節寫「停在那一格（規則沒有多滑 N 格）」，但 `docs/design/05-戰鬥.md` 的 #123（2026-11-04 使用者決定）是「滑倒並滑行」，引擎也照這個出 `unit_slid` 的路徑。動畫只讀事件，所以照引擎：有滑行就滑、停點倒下；一格都沒滑時就地倒下（待決 1）。
- 陷阱：夾子合上、停頓 0.4 秒、傷害數字、定身圖示是 6A-4d 原有的；這段加上被夾住的身體反應（第 2 節）。

## 5. 退還、層數圖示對齊命中點（6N-3 驗收第 3 點）

`still` 的片段（`rewind_still`、`stack_still`）的開始時間從「前一個片段一開始」改成**這一段的命中點**（`cast.impactMs`＋位移；近身＝出招命中、遠程＝飛行物到）。仍然不佔時間、不推後面的片段。測試改成「退還、加層、減層都在命中點出現，晚於出招開始」。

## 6. 貼圖快取：城鎮待機 bug 與「釘住每個小人目前的貼圖」

**原因**（6Q-1 推測正確）：6N-3 的 LRU 只釘「重畫場景那一輪」要的貼圖。兩次重畫之間，待機（`IdleMotion`，含 6N-10 的 NPC 小動作、6Q-1 的轉側面）、走路、技能片段要的姿勢貼圖沒有釘住；超過 600 張時被淘汰並**馬上銷毀**，而畫面上的小人還拿著它，Pixi 下一幀畫到已銷毀的貼圖（`alphaMode`／`uid` 是 null）→ 繪製器重建。

**修法**（兩層）：
1. **每個小人目前的貼圖釘住**：`TextureLru.hold(owner, key)`（一個 owner 一張，換貼圖時換掉；同一張被幾個人用就計幾次）。BattleRenderer 所有換小人貼圖的地方都改走 `setBodyTexture`（`poseBody`、`restBody`、`idlePose`），所以戰場單位、實地地圖的主角、NPC、朋友影子、敵群，經過 `idleMotion`／`npcFidgets`、走路、技能、受擊的路徑都涵蓋。閃避殘影另外用 `ghost:<id>` 釘住。重畫場景時不放開（重畫中途還在播的片段下一幀才換貼圖）。
2. **淘汰後延後銷毀**：ArtTextures 的 LRU 淘汰時只從快取拿掉，放進待銷毀清單，等下一次重畫場景的 `endFrame`（舊的小人都拆掉之後）才銷毀；很久沒重畫時累積到上限的一半就先銷毀（都是沒有小人在用的）。`endFrame` 清「這輪沒用到」的貼圖時也跳過被釘住的。

**驗證**：
- 測試（`textureLru.test.ts`）：
  - 20 個人各停在一個待機姿勢、別人一直要新姿勢（2000 次，上限 50，偶爾重畫）：畫面上每個人目前的貼圖都沒被銷毀、快取不超過上限；
  - 釘住跟著換貼圖移動、兩個人用同一張時一個放開仍釘著、`release`／`releaseAll`；
  - 延後銷毀：淘汰後還沒銷毀、flush 才銷毀。
- 實機（自己開的伺服器 8328，存檔在 scratchpad `g6n4/saves`，build 版；無頭 Chrome 用 CDP、獨立的使用者資料夾）：
  - **霧渡鎮**：待機開著 65 秒以上，主控台 0 個錯誤；另外在石記鐵鋪室內放 60 秒＋30 秒連拍，0 個錯誤；
  - **主城（樞島）**：從大世界圖傳送過去，待機開著 65 秒以上，0 個錯誤；
  - **對照**：暫時把兩層修法都關掉重新 build，霧渡鎮同樣流程 65 秒內出現 4 次 `[BattleRenderer] 戰場繪製失敗，重建繪製器`（`Cannot read properties of null (reading 'alphaMode')`），證實是同一個 bug；之後還原、重新 build。
- `#perf?lower=1&secs=20`：貼圖數停在 600（上限生效），60 FPS，主控台沒有錯誤。

## 7. 順手項：頭頂粒子照實際高度（6N-9 驗收第 4 點）

`particleTop(u) ＝ BODY_H ＋ (FEET − unitTopY(u)) / K − 標準人形頭頂`：照 6C-8b 的 `unitTopY` 和標準人形差多少就移多少。標準人形不變（＝34），大體型異形（例：大型魔像）往上，矮的（史萊姆）往下。只移頭頂的煙、泡泡、暈眩的星星與圈；火苗、藤、水滴、電弧不動。測試鎖住。
