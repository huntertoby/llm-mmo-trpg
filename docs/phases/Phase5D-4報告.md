## 4. 代決（最保守預設；規格 33.8）

| # | 事項 | 代決 |
|---|---|---|
| 5D4-1 | 完整畫面放哪 | 大世界左欄切換（同成長、任務），不另開彈出視窗；右側只留摘要 |
| 5D4-2 | 裝備比較 | 沿用一輪的預算分數比較與 `GearCardView`，不另算 DPS 等數字 |
| 5D4-3 | 配方表的「每件裝備」 | 世界不追蹤別人身上的裝備；用「碼的最後一次變動」近似：有裝備從這個碼改出新碼就不列、有人用這個碼打出新裝備就列。兩個人同時拿著同一個碼的裝備、其中一人重骰時，那個碼會先不列（另一人的裝備還是那個碼），直到再有人用它打造 |
| 5D4-4 | 帶電利用詞條 | 只加 1 條（傷害）；「雷電傷害」的元素篩選要引擎新的 change |
| 5D4-5 | 拿掉固定詞條的順序 | 點數高的先拿；同點數先拿後面的（第 1 條 build 詞條較有機會留下） |
| 5D4-6 | 分解掉的裝備的碼 | 照「最後一次變動」：分解不改配方表（那個碼仍列出） |
| 5D4-7 | 重骰事件句子裡原本那條的數值 | 事件沒記原本的數值，寫「+n」（不改事件格式） |

## 5. 待 PM 決定

1. **配方表的近似**（代決 5D4-3、5D4-6）：要精確「每件裝備最新一筆」需要世界知道每件裝備現在的碼（例如在世界快照記「碼 → 目前持有的裝備數」，分解、賣掉、重骰時增減）。目前的近似在多人同碼的情況會暫時漏列。
2. **帶電利用的精確效果**（8.21.4.1「對潮濕或帶電中的目標雷電傷害增加」）要引擎的元素篩選 change；目前是「利用帶電的技能傷害 +N」。
3. **降級後拿掉的固定詞條**多半是第 1 條的技能強化（8 點）：低等級招募者借高等級影子時，影子會失去 build 詞條。要不要改成「第 1 條保留、從後面的開始拿」。
4. **戰鬥中道具剩幾個**：引擎的單位檢視沒有一般技能的已用次數，按鈕只顯示「每場 N 次」，用完時停用（原因是通用的「目前沒有合法目標」）。要顯示「剩 n 個」需要 API 帶出 `skill_uses`（不改引擎規則，只加檢視欄位）。
5. **新詞條沒跑模擬**（守則：不跑大型模擬）；數值照現有同類詞條。
6. **戰鬥紀錄一行溢出 6px**（1600×900、`span.log-text`，`__layoutSmoke` 回報）：本段沒動戰鬥紀錄，應是既有問題，請排進下一個前端小修。
7. `tests/api/test_world_economy_api.py::test_fight_buy_and_pouch` 開發中在 `-n 4` 失敗一次、單獨重跑通過（同 5D-2b 待決 8 的既有不穩定：效用 AI 代打不保證贏）；沒有改測試。
8. 驗證時不小心在 `F:\tmp_unused` 建了一個 0 位元組的空檔（下錯了相對路徑）；安全檢查不讓我刪除專案外的檔案，請使用者手動刪掉。
