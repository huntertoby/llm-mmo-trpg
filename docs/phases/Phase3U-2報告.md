# Phase 3U-2 報告｜戰場人物比例放大

依 `docs/art/人物放大.md`（美術 PM 定案）與 `docs/phases/Phase3U計畫.md` 第 2 節。只動 `client/src/render`、戰場開發頁；沒碰 3U-1 的範圍。

## 做了什麼

| 項目 | 改動 |
|---|---|
| 人（紙娃娃）、人形召喚物 | `DOLL_SCALE` 0.74 → **0.92**（`paperdoll.ts`；舊值留作 `DOLL_SCALE_OLD` 供算增量） |
| 形態 | `formScale` ＝ `0.6 × (DOLL_SCALE／0.74) × min(size, 1.3)`：跟著放大，封頂 1.3 不變；光環半徑走同一個 `formScale`（52px 格熊的光環 16×1.3×0.6×1.243×1.3） |
| 野獸、物件召喚物 | 縮放 1 → **1.15**（新常數 `SUMMON_SCALE`） |
| 頭頂狀態列 | `ROW_Y` 再上移：人與人形召喚物 `52×(0.92−0.74)×(T/52)`（≈ 9.4px／52px 格），野獸與物件召喚物 `52×(1.15−1)×(T/52)`（≈ 7.8px）；高瘦（精靈）與形態的額外上移照舊疊加（本來就乘 `DOLL_SCALE`，隨之變大） |
| 腳下光環、HP 條、字母標記 | 不動 |
| 貼圖解析度 | 照實際顯示大小畫：`ArtTextures.setScreenScale(devicePixelRatio × 場景縮放)`（`BattleRenderer` 每次 resize／setScale 時設定），解析度 ＝ `ceil(2 × 顯示比例 × 螢幕縮放) / 2`，夾在 1.5～6；快取鍵含解析度（`f|<res>|…`、`s|…`、`g|…`、`a|…`）。縮放變動時舊解析度的貼圖在 `endFrame` 被清掉。沒設螢幕縮放（測試、無 DOM）用舊預設 3 |
| 測試 | 更新 `inkDoll.test.ts`（0.92、約 48px）、`inkForm.test.ts`（形態縮放與光環半徑含放大比）；新增 `artTextures.test.ts`（解析度級距、88px 比 52px 高且不低於顯示倍率、縮放常數） |
| 開發頁 | 新增 `client/scale-gallery.html`＋`src/dev/scaleGallery.ts`：`#cell52`／`#cell88` 同一場面；`#perf` 量滿場 20 隻。`ArtTextures` 加 `size` getter 供量測 |

## 前後對照圖（`docs/phases/img/`）

同一場面（headless Chrome，devicePixelRatio 2，由 `scale-gallery.html` 產生）：第 0 排空、第 1 排為上排敵人（3 位）、第 2 排是**高台**（高度 2；由左到右：戰士、**精靈**、**矮人**、**熊形態**、**龍形態**〔冰〕、**狼（野獸召喚物）**、**骷髏（人形召喚物）**，全部帶 3 個狀態圖示）、第 3 排是前排的精靈、矮人、狼、熊形態、戰士（蓋住高台排的腳）。

| | 52px 格 | 88px 格 |
|---|---|---|
| 前（0.74／1.0） | `3U-2-before-52.png` | `3U-2-before-88.png` |
| 後（0.92／1.15） | `3U-2-after-52.png` | `3U-2-after-88.png` |

「前」是把 `DOLL_SCALE`、`SUMMON_SCALE` 暫時改回舊值並把貼圖解析度改回固定 3 後截的（截完已還原，未留在 commit）。

**觀察（給美術 PM）**
1. 人頭頂超出上一格約 2～3 成（精靈最多）；形態的龍頭超出約 4 成，在 45% 內。
2. 頭頂狀態列確實跟著頭頂上移，沒有壓到頭。**代價**：列比以前更高，會蓋到「上一格單位」的下半身與 HP 條（88px 圖中高台排的狀態列壓在上排敵人的腳／光環上）。舊版狀態列本來就會壓到上一格的 HP 條附近，現在更明顯；規格沒有要求避開，沒另外處理。
3. 88px 格下用顯示解析度畫，邊線與髮絲、龍翼紋理沒有糊（dpr 2 截圖放大看過）。

## 效能（滿場 20 隻，88px 格；`scale-gallery.html#perf`，連跑 200 次 `renderer.draw` 取平均；headless Chrome、無 GPU，數字僅供前後相對比較）

| | 每幀 draw 平均 | 貼圖快取數量 |
|---|---|---|
| 前（解析度固定 3） dpr 1／dpr 2 | 0.657 ms／0.570 ms | 37／37 |
| 後（依顯示大小） dpr 1／dpr 2 | 0.530 ms／0.526 ms | 37／37 |

快取數量不變（解析度是鍵的一部分，同一縮放下仍是一種外觀一張）。每幀成本沒增加（差異在雜訊內）。貼圖像素：88px、dpr 1 時人 2.0 倍（原固定 3）、dpr 2 時 3.5 倍（原 3），野獸 2.0／4.0 倍；52px 格 dpr 1 為 1.5 倍——都不低於實際顯示倍率，也沒有過度浪費。縮放（視窗大小）改變時，換解析度會讓當幀有一次性重畫成本，之後穩定。

## 待 PM 決定

1. **狀態列蓋住上一格單位**：見觀察 2。若不想蓋，可改成「狀態列只上移到不超過上一格血條」或改小圖示；需美術 PM 看圖後決定。
2. 野獸、物件召喚物的狀態列上移量用 `52×(1.15−1)≈7.8px`（以 52px 高估算，因為舊畫布 64×64 腳底在 58）；實際各體型（小到大）頭頂高度不同，沒逐一量。
3. 形態的狀態列上移 `formRowRise` 沿用「形態比人高出的部分」，與人共用同一個基礎上移（9.4px），所以形態列的總上移＝人上移＋（形態高−人高）；龍／樹人看起來合理，未另行微調。
4. 貼圖解析度夾在 1.5～6 的上下限是我定的保守值（規格只說「照實際顯示大小」）。
5. `scale-gallery` 是開發用頁面（同其他 gallery，不進正式 build），若不想留可刪。
