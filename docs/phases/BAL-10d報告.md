# BAL-10d 報告：收束（#74）＋收回家族共用機制（#75）

依 `docs/phases/PhaseBAL計畫.md` 第 4 節實作。設計：`docs/design/06-技能.md` 6.34.4「收束」「收回家族」。沒有連真模型。

## 做了什麼
1. **共用機制「收回」**（新模組 `src/trpg/skillgen/flash_trade.py`）：
   - `Trade(remove, gain, core)`：`remove`「拿掉什麼」（同小變化改法的簽名，回傳結構草稿）、`gain`「換成什麼」（額外的重調字典與旋鈕，同 `tuning_extras`；收束用 `no_gain`＝只換效果本身的威力）、`core`（單發上限量什麼，預設 `target_power`：傷害／治療／護盾各自對單一目標的期望量）。BAL-10e 的精煉、合體、專注只要寫 `remove`＋`gain`（必要時 `core`）加進 `TRADES`。
   - `apply_trade`：收回前用預算器算總點數 → 目標點數＝收回前總點數＋一份 `budget_step_permille`（同階可用預算 ×（1＋代價折抵）× 40‰）→ 只用威力旋鈕重調到這個比例（`retune(..., target_ratio, power_only=True)`；推拉距離不動），強度下限照 6.34.3（`power_floor`）→ 單發上限檢查 → 超過時依 `complete.cost_cuts` 的順序累計減費用（只減不拿掉），每減一格照「上限對應的總點數 ÷ 新可用預算」重調，比例不低於減費前的強度下限比例、且不超過上限的第一個為結果；減不動就 `None`（不出選項）。
   - `MINOR_OPS`＝一般改法＋收回的 `remove`；`flash_derive`（`_minor_drafts`、`unimplemented_ops`、`apply_variation` 走 `apply_trade`）與 `flash_offer`（候選篩選）改用它。`evolution.retune`／`_tuned` 新增 `power_only` 參數（預設 False，其他呼叫者行為不變）。
2. **收束模板**（`content/flash_templates.yaml`，`category: area`、`prefix_zh: 收束`、`min_tier: 1`，排在範圍類最後）：
   - `converge_single` 收成單體：多格形狀（直線、錐形、十字、3×3、環形、連鎖、範圍光環）→ 單體；射程沿用原本的距離（有射程的照舊、武器射程照舊、直線／錐形取長度、以自己為中心的改 1）。範圍骨架不允許單體，所以新增模板欄位 `skeletons`（`FlashTemplate.skeletons`），收成單體依序改試 `strike`、`combo`（只取允許新形狀的骨架；原骨架允許就先用原骨架）。
   - `converge_step` 縮小一級：直線／錐形長度 −1（不低於形狀最小值）、3×3 → 十字（射程沿用）；已是最小一級不出。
   - 適用：主動技、非陷阱、有作用在目標（不是自己）的傷害／治療／護盾；表面、區域跟著技能形狀縮；複合技只改 `skill.shape`（第一段），接續段不動。
3. **單發上限**：`rules.single_hit_cap_permille: 3000`（`FlashRules` 新欄位）；基準＝同階、同 AP 單體技能預算（`tier_budget` × AP 係數）。
4. **相容**：蓄力、換形狀、重閃（`replaced` 下限照樣傳進 `apply_trade`）、轉型重套、目錄打亂、LLM 提議 schema 都走原路徑；`Variation`／存檔欄位沒變，`LOG_FORMAT`、存檔版本不用升。確定性：亂數全由 `variation_rng` 分流。
5. 腳本：`scripts/flash_converge_measure.py`（新）；`scripts/flash_category_audit.py` 改用 `MINOR_OPS`（否則收束被誤列「op 未實作」）；`scripts/flash_minor_coverage.py` 補收束的「結構不符」原因。
6. 測試：新增 `tests/skillgen/test_flash_converge_bal10d.py`（20 個：兩種形狀、直線射程＝長度、自身中心射程 1（環形傷害、光環治療）、推距不動、最小一級不出、單體不出、無威力不出、上限截斷改減費、減不動不出、初值上限不觸發、(a)/(b) 守恆、候選排在範圍類最後、前面模板套不上時會出現、確定性）；`test_flash_templates.py` 的登錄檢查改用 `MINOR_OPS`、`ENGINE_TEMPLATES` 加入兩個收束（引擎實戰＝卡片）。
7. **行為快照** `tests/skillgen/fixtures/refactor_3wr2.json` 重產，**2 筆變**（都是閃現出題）：
   - `skill_quake_wave@11@1`：第 2 次出題原本只有 3 個選項，補滿時多了 `converge_step`。
   - `skill_rune_ward@5@2`：第 2 次出題的範圍類前面模板都套不上，`converge_single` 進入混合選項 → 快照依種子選到的那一個變了，第 3 次出題跟著變。
   其他（完整技能強度、升階重配、其餘閃現出題）不變。

**(a)/(b) 練法比較**：16 列兩種都收成單體。
- 「同預算單發」（把一份同階單體預算剛好花完時的單發，拿掉最後重調抽到的比例、閃現加成、冷卻折抵）：**16／16 列 (b)≤(a)**（多數相等）——預算守恆成立：擴範圍時總點數不變、每個目標分到的變少，收束時再全部換回來。

## 待 PM 決定
1. **【解讀】單發上限的基準**：「同階單體技能預算」取 `tier_budget` × 這招的 AP 係數（不含代價折抵與閃現加成）。照這個基準初值 3 倍在內建技能完全不會觸發（最多到 58%）；若玩法 PM 的意思是「原招單發的 3 倍」或「不含 AP 係數的 tier_budget」，改 `cap_points` 一處即可（後者對 3 AP 技能會收緊）。
2. **【數值】AI 選中率 0%**：收束排在範圍類最後、沒有用法分數（保守：不搶既有模板順位）。若要讓它出現，可加用法分數（例如「平均目標數 < 1.5 → 收束 +2」，同換形狀的寫法）或調整資料順序；玩家指定範圍類時仍看得到（前面模板不夠 3 個時）。
3. **【規則】收不成單體的範圍技（7 招）**：帶表面、`split_heal`、`destroy_object`、`shockwave`、`leave_form` 的範圍技，打擊／連擊骨架不允許這些附帶效果。要不要讓收成單體也可改試控制骨架（但傷害占比上限 40%），或放寬骨架規則，請玩法 PM 決定；目前保守不出。
4. **【解讀】直線／錐形收成單體的射程取長度**（「原本的距離」）；環形、範圍光環、射程 0 的十字／3×3 改射程 1。
5. **【範圍】縮小一級只做規格列的**（直線／錐形長度 −1、3×3→十字）；環形半徑 2→1、光環半徑 −1、連鎖跳數 −1、十字→單體 都沒做。
6. **【解讀】「+40‰」與其他閃現的差異**：收束只在收束前總點數上加一份 40‰；其他小變化（蓄力等）重調時會在強度下限～100% 重抽比例，可以一次吃掉之前沒用到的加成。所以實際倍數受「最後一次是什麼閃現」影響（見 (a)/(b) 實際倍數 4 列 (b)>(a)）。若希望收束也「吃滿」，可把目標改成 max(收束前比例＋40‰, 隨機目標)。
7. **【解讀】減費用**：順序沿用 `complete.cost_cuts`（維持費、冷卻、法力、耐力、AP），累計減到某欄最少留 1 再換下一欄；減費後總點數可以低於收束前（強度下限改用「比例」：不低於減費前的下限比例），否則冷卻、法力減了也過不了原本的點數下限。
8. 陷阱、地面格的收束照設計表歸 BAL-10e，本段不出。
