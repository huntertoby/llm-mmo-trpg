## 交付項目

1. **畫布留邊**：戰場畫布上緣約半格、右緣約四分之一格。確認不影響格子座標換算、點擊命中、鏡頭與 HUD 對位（1600、1280、800 寬各看一次），戰鬥版面其他元素不位移到重疊。補測試（座標換算、點擊）。
2. **補拍 2 項**：① 鳥「移動接攻擊」連拍（要拍到鳥走至少兩格再攻擊，中間不落地、不再起飛）；② 一般外觀蜥蜴站最上排的 `atk:tailover` 333 ms 一張。另加大型／精英蜥蜴站最上排與最右欄的 333、500 ms 各一張，確認留邊後不被裁。
3. **實機巡檢**（自己啟動伺服器的真引擎與 AI，正常速度）：
   - 四款第二種片段（犬狼、山豹、野豬、蜥蜴；熊已看過）各至少看到一次，記錄每次重畫的格號，確認有沒有漏格（CB-3 報告的蜥蜴 667 那格）。
   - 山豹斑點在實戰各片段都在身體輪廓內；鳥移動接攻擊的連接。
   - CB-2e 的收霧斬（霧鎖真人第 3 階段）與震波（碎晶之主第 1 階段）各看到一次，記錄播的是哪個片段、對不對。
   - 到不了的寫明原因與用什麼替代（開發入口、暫存內容把對手換成指定敵人等；暫存內容不得進 repo）。
4. 報告列出巡檢中看到的所有問題（附截圖或格號紀錄）。

## 驗收條件

- `corepack pnpm -C client typecheck`、`corepack pnpm -C client test`（vitest 全部）通過；在 `client` 內 `npx vite build` 通過。快照有變時說明原因。
- 交付項目 2、3 每一項都要有截圖或連拍；實機到不了的寫「實機未看」。只靠 vitest 的不算通過。
- 預覽與伺服器用自己啟動的（不用 8000、8001、8092 埠），網址一律加 `?mute=1`；結束時只關自己啟動的程序。
