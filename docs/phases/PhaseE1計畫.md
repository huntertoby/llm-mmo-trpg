## 已定的規則

| 題目 | 結果 |
|---|---|
| 主動、反應、修正、被動技佔不佔欄 | 都不佔 |
| 反應的次數 | 和其他反應共用每輪 1 次，用反應設定選優先（同 08 拳套「反擊」的前例） |
| 同一個主動技從兩處拿到 | 變成兩招，冷卻分開算 |
| 同一個反應從兩處拿到 | 兩個都列出來，每輪還是只能反應 1 次 |
| 全身上限（例如全身傷害 +50%） | 照舊 |

## 範圍

1. **盤點現況**（寫進報告第 1 節）：
   - 裝備現在怎麼授予技能：`granted_actions`、`engine/grants.py` 的暫時授予、`gear_checks`，以及 `modifiers.py` docstring 寫的「裝備授予的常駐技能」。
   - 哪幾類技能（主動、反應、修正、被動）已經可以授予，哪幾類被擋下。
   - 引擎列舉「可以用的技能」都經過 `UnitState.all_skills` 嗎？有沒有繞過它的地方？
2. **四類技能都能由裝備授予，而且不佔欄**：
   - 欄位上限的檢查（主動欄、反應欄、被動欄）不算裝備授予的技能。
   - `empty_active_slots`（普攻精通）的空格數也不算它們。順便把 `modifiers.py` 空格計數的疑點查清楚、修好，報告寫明改前、改後。
   - 反應：照現有的反應規則，共用每輪 1 次，加進反應設定的優先排序。
3. **同一個技能從兩處拿到**：
   - 主動技變成兩招，冷卻、使用次數分開算。技能可能以 id 為鍵，這時要加「來源」或實例鍵，而且要能序列化、可重播。
   - 反應兩個都列出來，每輪仍只能 1 次。
   - 舊存檔、舊戰鬥紀錄照 `docs/phases/戰鬥紀錄格式變更.md` 判斷。新欄位要有預設值，舊紀錄的結算不能變。
4. **授予技能的預算檢查**：
   - 授予的技能用現有的技能預算檢查器檢查，一律照 1 階的預算窗。
   - 「1 階」做成設定欄位，放在 content 規則，開進數值工坊，寫中文名和調高、調低的影響。
   - 物品這邊扣 60% 詞條預算當名額，屬於 E6-a，這段不做。
5. **同一個被動或修正技重複（等使用者定）**：
   - 數字怎麼加：越疊越少，還是全部加滿？
   - 非數字效果是不是各自發動？
   - 使用者定了以後，開發 PM 補寫這一項。
6. **顯示**：
   - 技能列、反應欄標「來自〇〇裝備」。
   - API 帶來源欄位，要有預設值，並重產 OpenAPI 和前端型別。
   - 用字和版面先照現有的「暫時獲得」標記做法。新的視覺交美術 PM 驗收截圖。
7. **AI**：AI 會用裝備授予的主動技與反應，照現有技能的評分方式，不另加權重。

## 不做

- 招牌效果的 60% 定價、同時 3 個、改寫規則 1 個、傳說產生器（E6）。
- 招牌效果的內容本身，也就是 50 條（排在 E6 之後）。
- 不改既有的數值，不改 `docs/design/`、`config/` 既有的值。
