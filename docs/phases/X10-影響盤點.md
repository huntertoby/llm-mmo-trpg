# ×10 數值尺度：影響盤點（2026-11-20，開發 PM）

> 來源：`docs/design/05-*.md` 5.4.1（#169 題 10，含法力、耐力也 ×10 的修正）。
> 這是 finder 讀程式碼的推論，行號可能差幾行，改之前要讀原文確認。標「未核對」的要逐筆查。

## 關鍵做法（開發 PM 定）
- **骰子記法不變**：`2d8` 照樣寫 `2d8`。擲出的面值乘上 `content/rules/core.yaml` 新加的 `dice_value_scale: 10`，分布和爆骰都不變。
  - 這樣技能預算的骰子平均（`budget.py` `_dice_average`）、`MIN_DICE`、組合器的骰子階梯都不用改，預算點數照舊。
- **固定值（flat）×10，預算按 ÷10 計**，點數單位不變（5.4.1「屬性 +10 ＝ 3 點」）。
- 換算一律走一支腳本，照欄位清單改 `content/`，不手改。

## 1. 引擎
- 屬性修正 (屬性−base)//divisor：參數在 `core.yaml` `ability_mod_base`／`ability_mod_divisor`（10／2 → 100／20）。
  - 用到的地方：`engine/effects/surface_entry.py`、`engine/ice_slide.py`、`engine/summons/core.py`、`world/perception.py`、`world/situations.py`。
- 骰子：`shared/rng.py` 的 roll；d20 不變（`rules/combat.py`、`maneuvers.py`、`battle.py`）。
- 傷害公式 `rules/combat.py` 85-125：(骰＋固定)×1000＋屬性縮放，有最低傷害 `min_damage`。攻防值和命中只看比值。
- HP、法力、耐力上限：`content/rules.py` 649-723、149-165。
- 耐力回復 `turns.py` 用 `core.yaml` 的 `stamina_regen`。
- 寫死的「1 點」下限：`effects/handlers.py` 172、429、528；`practice.py` 74。
- 召喚成長：`summons/core.py` 113-132（`flat_per_level_permille` 實際是固定傷害）。
- 形態維持費：`forms.py` 300-347；背刺骰 `weapon_traits.py`。

## 5. 數值工坊
- 調過的值直接寫回 `content/`，並且 git commit（`api/tuning/writeback.py`）。沒有另外的覆寫檔。
- `tuning_fields.yaml` 的 `hint_min`／`hint_max` 要 ×10。
- ratios 快取以內容雜湊為 key，換算後會自動重算。
- 「換算紀錄要讓使用者認得出自己調過的數字」目前沒有機制。
