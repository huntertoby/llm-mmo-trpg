### C 墨線殘留掃描

- **程式**：人物畫法的唯一入口 `paperdoll.drawFigure` 看 `dollSkin()`，預設 `"q"`，`setDollSkin` 在正式程式裡沒有人呼叫（只有測試），所以 `inkDoll.drawInkFigure`（C 人物）正式畫面走不到。頭像 `portrait.ts` → `qPortrait`、形態 `inkForm.drawForm` → `drawQFormBody`、異形與頭目 `inkCreature.drawCreature`（QK-4 的 Q 部件＋外框）、事件插圖與醒來插圖都走 `drawFigure`／`drawCreature`。仍是 C 墨線的只有武器小圖示（`weaponIcon.ts` → `inkWeapons`），屬第 9 節「圖示不在 QK 範圍」。

### 6.3 開發入口用法（只在開發模式＋`TRPG_DEV_ROUTES=1`；前端要 `?dev=1`）

- **開場朝向**：`?dev=1&boss=north_slope&bossregion=cloud_ridge&bossface=east` → 頂列「頭目戰（開發）」。用既有的 `UnitSpawn.position` 排起始位置（主角在地圖中間、隊友在兩側隔一格、第一個敵人在那個方向：近戰相鄰、遠程隔一格），開場朝向照正式規則（面向敵方重心）；另用既有的 `first_team` 讓我方先動，主角不會先被打得轉身。API：`POST …/dev-boss?location=&region=&facing=north|east|south|west`。
- **開場召喚物／形態**：`&bossopen=summon|form`（API `opening=`）：AI 代打到輪到主角 → 照合法動作找第一個做得到的技能（落點離主角近的先試）→ 再代打到輪到主角。角色要有那種技能（例：圖騰杖＋召喚物、單手劍＋形態，種子 0 就有），沒有回 422。和 `bossai` 不能同時用。
- **傳送到某區城鎮**：`&tp=ashen_waste`（預設灰燼荒原）→ 頂列「傳送（開發）」；API `POST …/dev-teleport?region=`。**會直接改角色存檔、不寫世界日誌**（這個角色之後的世界日誌重播會對不上，只給開發角色用）；主線限制不管，正式的傳送照舊不行（測試有證）。
- 正式模式不可達：伺服器 `dev_router` 只在開發模式掛、另要環境變數（`tests/api/test_world_dev_boss.py` 證明關開發模式時路由不存在、沒環境變數 404）；前端按鈕包在 `devMode &&` 裡（`src/screens/qk9bDevEntry.test.ts`）。
- 都是「初始設定＋動作列表」，不改規則與數值；戰鬥不回寫世界（同 6F-3）。
