# 技能生成「挑選模式」提案（玩法 PM ＋ 開發 PM）

> 2026-11-14 起草。**提案，不是定案**：使用者看過、回答第 6 節的題目後，才由玩法 PM 寫進 `docs/design/`（06 6.7、6.34.7、07 7.6）。
> 使用者原話：「我有想過一個 把所有可能都先生成 下來 然後 再靠演算法算出適合的都丟給llm 讓她自己選 有沒有說法 然後他只要取名之類的就好」；「請玩法 PM 和開發先一起寫一份提案」。
> 背景：LB-1、LB-2、LB-2b 的 20 題，LLM 自己設計整招時約 15～40% 退回組合器；主因是規則多、模型讀不全（LB-2b：Gemma 剩下的錯誤 96 條裡 61 條是變奏，其次是漏關鍵字、超預算）。使用者已選 Gemma 26B-A4B、溫度 0.7。
> 分工：第 1～6 節玩法 PM 寫；第 7 節技術由開發 PM 補。

## 0. 一句話

**程式先做出一大批「保證合法」的候選，依這位玩家的關鍵字、手上技能和打法打分數，留下最合適的十來個；LLM 只負責從裡面挑、取名、寫描述。** 規則全由程式保證，LLM 不再需要讀懂預算、骨架、變奏這些規則，所以不會被退回。

這個做法在推薦系統裡叫「先召回、再排序、最後由模型重排」（generate-then-rank / retrieve-and-rerank）；在遊戲裡就像 Slay the Spire、Hades 的「從牌池抽、依規則加權、玩家挑」，只是多了一層 LLM 依故事挑選與命名。

## 1. 現在的流程和這個提案差在哪

| | 現在（自由設計） | 挑選模式 |
|---|---|---|
| 誰組技能 | LLM 從原語拼（06 6.7 第 1～2 步），驗證器檢查，失敗重試，最後退組合器 | 組合器（含閃現模板）一次出幾十個合法候選 |
| 誰保證規則 | 驗證器事後擋 | 候選本來就合法，驗證器只是保險 |
| LLM 輸出 | 整份技能 JSON（形狀、效果、變奏……） | 「選第幾號」＋名稱＋描述（＋一句為什麼適合這位玩家） |
| 失敗時 | 退組合器隨機給（玩家看不出差別，但沒有「為你挑的」） | LLM 回壞了 → 直接用分數最高的幾個，名稱用組合式（6.34.5「{前綴}・{原名}」） |
| 個人化靠什麼 | LLM 讀傾向與現有技能自己想 | 打分數（程式）＋ LLM 依故事挑（第 4 節） |

注意：**現行設計裡 LLM 自由設計的範圍本來就不大**（#69 之後）：
- 任務、創角的三選一白板早就由組合器出、不呼叫 LLM（07 7.6、06 6.34.1）。
- LLM 自由設計只剩：閃現與重閃的「變化」（結構小）、劇情技能（骨架固定，只改名稱元素描述）、機遇與許願池的完整技能、測試原型的白板（6.34.7「預先生成」那一列）。
所以挑選模式實際動到的是**閃現／重閃、完整技能（機遇、許願池、原型特殊時刻）、測試原型白板**這幾處。

## 2. 會影響哪些既有設計

| 既有設計 | 影響 | 要守住的東西 |
|---|---|---|
| **06 6.7 生成流程** | 第 1～3 步改成「組合器出候選 → 打分 → LLM 挑選命名」；第 6 步（LLM 寫名稱、描述）保留 | 守則 3「LLM 只能提議」反而更徹底：LLM 連數值都碰不到 |
| **升級三選一（原型）／任務三選一（6.27.4）** | 出題結構不變：加深、橋接、新方向各 1 格；「新方向」10% 從通用池（#55）、偏離平均 ≤ 1.1 張（#110）、至少 1 張非傷害（#142）**由程式保證，不交給 LLM**。LLM 在**每一格裡**從幾個候選挑 1 個並命名 | 三格的意義不能被 LLM 打亂（例：三張都挑加深）；所以是「每格各挑一」，不是「全部混在一起挑三」 |
| **閃現（6.34.3、6.34.4）** | 模板本來就把合法變化全列出來（現在是 LLM 失敗時的退路）；改成主路：程式依用法統計排好，LLM 從中挑 4 個（指定類別時挑 3 個）並取變化名 | 混合至少 2 類、指定類別只出該類、類別按鈕上的數量、**轉型保底（#70）固定佔一格不給 LLM 挑掉**、強度下限（6.34.3、#160）都在候選階段就篩完；「和現在一樣」的卡（平衡待查第 27 條）可以順手不進候選 |
| **大變化（第 3 次，6.34.5）** | 加深、橋接至少各 1 個照舊，由程式先佔格 | 同上 |
| **重閃** | 同閃現；#160 例外格的提醒、「比原本弱」小標照舊（候選本來就帶分數） | — |
| **完整技能（6.34.6：原型特殊時刻、機遇、劇情）** | 組合器整招出候選（預算上限 +120‰、含一個大變化等級的結構），LLM 挑選命名。劇情技能本來就骨架固定，等於已經是挑選模式 | 機遇「只給橫向技能」（07 7.6）照舊 |
| **許願池（07 7.6）** | **建議保留自由設計**（第 3 節）：玩家用文字許願，重點就是「我的點子」。失敗時不再退「隨機組合器」，改退挑選模式——**拿願望文字當打分訊號**，LLM 從候選裡挑最接近願望的 | 每週次數上限、`<player_input>` 規則照舊 |
| **#161 層數關鍵字（連擊、怒氣、專注、氣）**與所有關鍵字 | 候選帶哪個關鍵字由組合器保證，LB 裡「沒帶到題目關鍵字」這類錯誤消失。前提是組合器對每個關鍵字都有足夠配方（6.27.2 每池至少 3 招、6.27.4 供給補齊）；不夠的關鍵字候選會少 | 要盤點：每個關鍵字 × 種類（主動／被動／反應）× 階級，組合器出得出幾種（第 7 節由開發估） |
| **6.34.7 預先生成、10 秒退回** | LLM 的工作從「寫整招」變成「挑＋命名」，輸出短、幾乎不會失敗，超時退回的情況會少很多 | 日誌記最後給出的選項與來源（重播不呼叫 LLM）照舊 |
| **#126 命名風格（依界域）** | 不變，LLM 只剩這件事，可以寫得更好 | — |
| **核心初衷：每位玩家長出獨一無二、有主題、有協同的 build** | 見第 5 節「最大的取捨」 | — |

## 3. 哪些場合用挑選、哪些保留自由設計（玩法 PM 建議）

| 場合 | 建議 | 理由 |
|---|---|---|
| 測試原型的升級三選一白板 | **挑選** | 白板定義簡單（一個核心效果、一個關鍵字），組合器做得很好；LLM 自由設計白板沒有多出什麼 |
| 任務三選一（大世界） | **挑選**（現在是組合器、不呼叫 LLM；改成挑選只多一層「依故事挑＋取名」） | 讓任務給的招也有「為你挑的」感覺；不想多呼叫 LLM 也可以維持現狀 |
| 閃現、重閃 | **挑選** | 模板已經把合法變化列全，LLM 只要挑和取名；現在 LLM 提議的變化常被退回模板，這一步最划算 |
| 原型特殊時刻、機遇的完整技能 | **挑選** | 整招自由設計是 LB 退回率最高的地方 |
| 劇情技能 | 不變（本來就骨架固定、LLM 只改名稱元素描述） | — |
| **許願池** | **保留自由設計**，失敗退「以願望打分的挑選」 | 玩家寫了文字，就是想要「我想的那招」；這是 LLM 創意唯一保留的出口，也是第 5 節缺點的解藥 |
| 之後（學習敵人招式、營火融合） | 先挑選 | 照同一套 |

## 4. 打分數要看什麼

**原則**：候選全都合法、同階同預算（6.12），所以分數**不比強弱**，只比「適不適合這位玩家」。打分只用引擎已記錄、確定性的資料。

| 項目 | 看什麼 | 出處 |
|---|---|---|
| 關鍵字配合 | 這格要的是加深（帶最多的關鍵字）、橋接（帶兩個已有的）、新方向（還沒有的）；符合的才進這格 | 6.27.4 |
| 協同 | 候選「製造」的關鍵字，玩家手上有招「利用」，或反過來（例：已有施加燃燒 → 對燃燒目標加傷的候選加分）；越多條連線分越高 | 6.27、6.7 第 1 步原意 |
| 打法（傾向向量、行為紀錄） | 常站的位置（前線／後方／高處）、常用元素、常用動作（例：常跳上高台 → 高處候選加分）、互動過的物件 | 07 7.1、6.27.4「行為紀錄」 |
| 武器與屬性路線 | 縮放屬性跟主屬性、武器技配目前武器；照 #110 的四步找法 | 6.27.4 #110 |
| 用法統計（閃現） | 這招實際怎麼用（常打幾個人、常在什麼地形放）→ 對應的變化排前面 | 6.34.3「類別內的選項依用法統計排序」 |
| 種類比例 | 主動 70%、被動 20%、反應 10% | 6.34.1、07 7.6 |
| 多樣性（扣分） | 留下的候選彼此太像（同骨架、同形狀、同效果只差數字）就扣分，避免 LLM 拿到十個一樣的 | 6.8「打法差異檢查」的精神 |
| 非傷害保底 | 每次三選一至少 1 張非傷害 | #142 |
| 許願池專用 | 願望文字和候選的關鍵字、元素、效果類型有多接近（由 LLM 判斷或簡單比對，開發定） | 07 7.6 |

**權重放進數值工坊**，由使用者調（同 AI 估值表的做法）；玩法 PM 不定數字。

**LLM 在挑什麼（程式做不到的部分）**：故事與界域。例：玩家剛在雲嶺救了一位劍修、編年史裡常出現「守護」，LLM 從同分的幾個候選裡挑最對味的，並照雲嶺風格取名（#126）。原型沒有文字輸入時，這一層作用比較小，主要是取名。

## 5. 優缺點

**優點**
1. **不會被退回**：候選本來就合法，LB 的 15～40% 退回幾乎歸零；不會再出現「玩家拿到的其實是隨機組合器版」。
2. **快、穩**：LLM 輸出從整份技能縮成「編號＋名字＋描述」，prompt 也不用塞整套規則；10 秒退回很少發生。小模型（Gemma 26B）就夠。
3. **規則改了不用教 LLM**：以後加新原語、新關鍵字、改預算，只要組合器跟上，prompt 不用跟著改（現在每次改規則都要補 prompt、補回饋，見 LB-2b）。
4. **個人化更可控**：協同、打法、關鍵字分布是程式算的，可以測、可以在工坊調；不用賭 LLM 有沒有讀進傾向向量。
5. **名字與描述品質會更好**：LLM 只剩這件事。
6. **公平**：候選本來同階同預算，LLM 只挑不改，強弱不受模型好壞影響。

**缺點與風險**
1. **最大的取捨：驚喜變少**。LLM 自由設計偶爾會拼出組合器沒有的結構；挑選模式下，玩家能拿到的技能種類＝組合器配方的範圍。核心初衷「獨一無二」會變成「從很大的池裡，依你的路線挑出、並為你命名」——獨特性來自**路線**（每人的關鍵字、閃現選擇、用法統計不同），不是來自**沒人見過的結構**。
   - 解藥：許願池保留自由設計；組合器配方持續擴充（6.27.4 供給補齊已在做）；之後可以把許願池做出、玩家愛用的結構收進組合器配方（後期，另議）。
2. **組合器要撐得住**：某些關鍵字 × 種類 × 階級的配方少（例：LB 的 Q12 史詩被動＋高處），候選會很少甚至挑不出 3 個。要先盤點（第 7 節）。
3. **同一份配方，兩位玩家可能拿到同一招只是名字不同**。閃現會讓它們之後長開（6.34「同一招白板在兩位玩家手上會長成兩招」），所以白板層面可以接受；完整技能比較明顯。
4. **打分權重要調**：調不好會一直推同一類（例：永遠推加深，build 越來越窄）。07 7.2「新方向固定 1 張」、#110 偏離上限照舊保護。
5. **工作量**：要做打分、候選池快取、LLM 挑選的 schema 與 prompt（第 7 節估）。

## 6. 要使用者決定的題目（每題第一個是建議）

1. **哪些場合改用挑選？**
   - **A（建議）照第 3 節**：閃現／重閃、原型白板、完整技能（原型特殊時刻、機遇）、任務三選一改挑選；**許願池保留自由設計**，失敗退「以願望打分的挑選」。
   - B 全部挑選，連許願池也是（許願池用願望文字打分）：最穩，但玩家寫的願望只能從現有配方裡找最像的。
   - C 只把挑選當退路：照舊先讓 LLM 自由設計，失敗才挑選（取代現在的「退隨機組合器」）。改動最小，但退回、慢的問題還在。
2. **LLM 挑的範圍**
   - **A（建議）程式依格子出題，每格給 LLM 4～6 個候選、挑 1 個並命名**（三選一＝3 格；閃現不指定＝4 格的混合，類別與轉型保底由程式先佔）。出題規則（加深／橋接／新方向、非傷害保底、轉型保底）程式保證。
   - B 一次給 LLM 10～15 個，讓它自己挑 3 個：LLM 自由度大，但可能打亂格子規則，要事後再檢查。
   - C LLM 不挑，只命名（程式直接取分數最高的）：最快最穩，但「LLM 依故事挑」那層沒了。
3. **LLM 可不可以微調候選**（例：把火換成冰、改形狀）？
   - **A（建議）不行，只能挑和命名**：一微調就要重新驗證，又回到會被退回的老問題。想要不同元素，就讓程式出那個元素的候選。
   - B 可以換元素（只換元素，程式重算預算與驗證；不合法就用原候選）。
4. **挑選模式要不要開思考（reasoning）**？（開發 PM 在第 7 節補速度數字）
   - **A（建議）預設不開**：挑選和命名是短答案（LB-1 裡 qwen、swift 開著思考時整招設計全部退回，現在設定是 `reasoning_effort=none`），不開思考應該就夠，速度優先（10 秒退回）。等第 7 節的小測再說，如果開了思考挑得明顯更對味、又在時間內，再改。
   - B 開思考、放寬 max_tokens：挑得可能更貼近故事，但每次多幾秒，預先生成較常來不及。
   - C 只在許願池（自由設計）開思考，挑選不開。
5. **打分權重誰調**
   - **A（建議）放進數值工坊，由使用者調**（同 AI 估值表）；玩法 PM 只定「看哪些項目」（第 4 節）。
   - B 先寫死初值，之後再開工坊。

## 7. 技術（開發 PM 補）

> 待開發 PM 補：組合器能不能撐住候選量（每次幾十個、各關鍵字 × 種類 × 階級的配方盤點）、打分怎麼做（資料來源、確定性、快取）、prompt 與 schema 會小多少、速度（含開不開思考的小測）、工作量與分段、確定性與重播（候選池與 LLM 選擇怎麼記日誌）、測試。
