## 範圍

1. **招牌欄位**：詞條加上招牌類型欄位，五種照 8.27：新動作、新反應、地形規則、行為改寫、改寫規則。
   - 欄位是空值時不輸出，既有資料的序列化結果不能變。
2. **60% 定價**（8.30 第 11 點）：
   - 招牌的點數是詞條預算的 60%，用分數算，不捨去。
   - 剩下的預算照 8.30 第 2 點分：放得下幾條算幾條，放不下技能強化就不放。
   - 70% 下限只看招牌以外、放得下的那部分。
3. **條數**（8.30 第 1 點）：招牌算進條數。
   - 稀有＝招牌＋1～2 條。
   - 史詩＝招牌＋2 條，其中 1 條照 8.21.6。
4. **產生器**：
   - 稀有、史詩的主手、副手、身體、腳、項鍊，先依部位權重放 1 條招牌，再分剩下的預算。
   - 權重：部位偏向的類型 3、其他類型 1；項鍊全部 1。
   - 沒有候選的類型，權重當 0。
   - 材料傾向不影響招牌。
   - 開關做成設定欄位，**預設關**。關著的時候，產生器和預算檢查的結果要逐位元不變。
5. **改寫規則拿掉「限傳說」**（8.27）：`RuleAffix` 不再強制 `legendary_only`。超過上限時改標灰、由玩家選，這部分是 E6-b1 的事，這段不做。這段只拿掉「限傳說」這個限制，而且已經在用的路徑結果不能變。

## 不做

- 不做打造指定、重骰（E6-a2），不做同時 3 個與勾選（E6-b），不做傳說（E6-c）。
- 不改引擎，`LOG_FORMAT` 不升。
- 不改 `docs/design/`、`config/` 既有的值。新的設定欄位可以加，初值照 8.30。

## 驗收

- **結果不變**（開關關著）：下面都要 different=0。
  - 442 招逐招預算、78 場、census 小樣本。
  - 產生器種子比對：同一組種子產出的物品，開關關著時逐位元相同。用現有的種子測試，或新寫一個比對腳本。
- **測試**：
  - 開關打開時的情況：
    - 招牌一定在。
    - 招牌是 60% 預算。
    - 放不下時只出招牌，例如 1 級稀有靴子。
    - 條數。
    - 部位權重。
    - 沒有候選的類型不會被抽到。
    - 70% 下限只看招牌以外的部分。
  - 開關關著時不出招牌。
  - 改寫規則不再要求限傳說。
- **靜態檢查**，結束碼都要是 0：ruff、format、mypy、lint-imports、`trpg content check`、`classify.py --check`。新數字要歸類。
- **全量檢查**：全部 commit 之後跑 `uv run python scripts/check.py --all`，這次已預先授權，不用先問。接著跑 slow 的 parity 和 cli。
