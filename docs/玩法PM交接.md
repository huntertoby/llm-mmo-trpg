## 1. 你的角色與分工

| | 玩法 PM（你） | 開發 PM |
|---|---|---|
| 負責 | 和使用者討論玩法問題、比較選項、記錄決定 | 把決定排進階段規格、派實作 agent、驗收 |
| 可以改的檔案 | 本檔；`docs/design/`（設計細節，使用者說「好 寫入」後才寫） | `docs/phases/`、`docs/PM交接.md`、程式 |
| 不做的事 | 不寫程式、不寫階段規格、不派實作 agent | — |

- 使用者（GitHub：huntertoby）是 **最終決策者**，不是工程師。**所有回覆一律用繁體中文**；回覆要精簡、有結論，用表格整理選項。
- 使用者習慣：設計問題先討論、比較選項，再說「好 寫入」才寫進文件。重大設計變更先問，不要自己寫入。
- 開發 PM 可能同時在另一個對話工作。你 **只改本檔與 `docs/design/`**，改完 commit（訊息第一行英文，例如 `docs: gameplay decision on pulling objects`）並 push；push 前先 `git pull`。
- 決定寫好後，在第 3 節把狀態改成「已決定，待排入」，並請使用者轉告開發 PM（或使用者自己開開發 PM 的對話說「讀玩法PM交接 第 3 節」）。

## 2. 先了解的東西

1. 讀 `CLAUDE.md` 與 `docs/專案計畫.md`（總覽）；需要時讀 `docs/design/05-戰鬥.md`（戰鬥規則）、`06-技能.md`（技能）、`07-角色成長.md`（roguelite 循環）。
2. **自己試玩**：在專案資料夾執行 `uv run python scripts/play.py`，會建置前端、啟動伺服器並開瀏覽器（`http://127.0.0.1:8000/`）。也可以用 CLI：`uv run trpg battle --map <id> --seed <n>`、`uv run trpg map list`。
3. 目前的遊戲狀態（2026-10-19 更新：**網頁單場戰鬥已完整可玩**，Phase 3 剩 3-5 roguelite 一輪流程與存檔、3-6 收尾試玩）：
   - 網頁介面已有：開場與 AI 行動逐步播放（正常／快／略過）、HUD（AP、移動、反應、狀態、腳下表面）、技能列（選目標、滑過看命中率與傷害、可能的連鎖）、反應設定（每個反應可設自動／詢問／關閉）與詢問視窗、環境預告（下一輪火焰蔓延、爆炸、援軍會標在格子上）、隊友快捷指令（集火、守位、撤退、保護、利用環境）。
   - **還不能玩一整輪**：目前每次只打一場，沒有升級、選技能、存檔（3-5 在做）。
   - 玩家操控 1 名主角，2 名隊友與敵人由 AI 控制。
   - 主角的基本動作：移動、攻擊、防禦、推擊（相鄰敵人，力量對抗，推 1 格）、絆倒（相鄰敵人，敏捷對抗）、互動（**只能推** 相鄰的可推物件 1 格）、技能、結束回合。
   - 技能的位移原語有 `push`、`pull`（拉扯）、`teleport`、`knock_prone`，但 **只有技能能拉**，基本動作不能。
   - 10 張正式地圖、8 種地圖類型；12 個 build（`content/sim/builds.yaml`）。
   - 平衡尚未調整（勝率偏高或偏低都正常），平衡待辦在 `docs/PM交接.md` 3.3。

## 3. 玩法回饋與決定

每一項：使用者的原話（摘要）→ 目前規則 → 選項 → 決定。狀態：**待討論**／已決定，待排入／已排入（由開發 PM 填階段）。

### #1 不能把箱子往回拖（2026-10-19，待討論）

- **使用者回饋**：主角右邊是不能走的格子，上方有箱子。想把箱子往自己這邊（往左）拖開路，但只能推，不能拖。
- **目前規則**：`Interact` 只有 `mode: push`（沿「主角 → 物件」方向推 1 格）。程式已預留 `mode` 欄位，加「拉」不需要改動作格式。拉扯單位只能靠技能。
- **可以討論的方向**（給使用者比較）：
  - 基本動作加「拉物件」：主角後退 1 格、物件跟著移動 1 格（像推箱子遊戲的拉）。成本與推一樣，或更貴（例如需要力量檢定、耗 AP 較多）。
  - 也讓基本動作能「拉相鄰敵人」，或維持只靠技能，保留技能的價值。
  - 地圖設計面：是否有地圖因為只能推而卡住路線？
- **決定**：（待討論）

## 4. 試玩時可以問使用者的問題（Phase 3 的 🎮 戰鬥手感檢查）

1. 單場戰鬥好玩嗎？決策有意義嗎？
2. 換地圖時，build 有時強時弱，並促使你調整打法嗎？
3. 不同類型的 build（輸出、坦克、輔助……）打起來感覺明顯不同嗎？
4. 會想再玩一輪嗎？

問題出在戰鬥規則或地圖時，在第 3 節記一項；出在介面（看不懂、不好點）時，記一項並標「介面」，開發 PM 會排進 Phase 3 的 UI 修正。
