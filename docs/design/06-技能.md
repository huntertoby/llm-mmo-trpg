# 專案計畫：技能系統（第 6 節）

> 本檔為 `docs/專案計畫.md` 的一部分，總覽與守則見該檔。

## 6. 技能系統（模板組合）

### 6.1 技能組成

```
技能 = 目標形狀 + 效果原語 ×(1~4) + 條件 + 代價 + 標籤 + 敘事
```

### 6.2 模板三級分類

| 類別 | 內容 | 管理方式 |
|---|---|---|
| 數值型 | 傷害、治療、護盾、增減益百分比 | 可大量製作、自由組合，靠調數值控制 |
| 結構型 | 目標形狀、位移、延遲、表面狀態、召喚 | 組合性強，需互斥規則 |
| 改寫規則型 | 額外行動、重置冷卻、免死、複製技能、轉移傷害 | 數量少、出現機率低、每技能最多 1 個、有硬性上限 |
| 改造型（2026-10-19 新增，見 6.14） | 改變自己 **其他技能或基本動作** 的規則，例如「你的推擊撞牆時點燃目標」 | 以標籤或動作類型為目標；傳說的核心之一 |

模板之間要**正交**：每個原語只做一件事，不做「傷害＋燃燒＋推擊」的大包裝。

### 6.3 初版原語清單

**目標形狀**：`self`、`single(range)`、`line(n)`、`cone(n)`、`cross`、`square3`、`ring(self, r=1)`、`ground_tile(range)`、`chain(n_jumps)`、`allies_in_radius(r)`

**效果原語**

- 傷害：`damage(dice, element)`、`damage_over_time(element, per_turn, duration)`、`delayed_damage(turns)`、`execute_bonus(hp_threshold)`
- 防護：`heal`、`heal_over_time`、`shield`、`damage_reduction`、`cleanse`
- 位移：`push(1~2)`、`pull(1~2)`、`swap`、`teleport(range)`、`leap`、`knock_prone`
- 狀態：`burn`、`freeze`、`bleed`、`poison`、`blind`、`fear`、`stun`、`slow`、`root`、`mark`、`taunt`、`silence`、`weaken`、`vulnerable`
- 增益：`buff_attr`、`haste(+move)`、`grant_advantage_next`、`conceal`
- 地形：`create_surface(type)`、`destroy_object`、`create_obstacle`、`ignite_tile`、`raise_terrain(n)`、`lower_terrain(n)`
- 物件（2026-10-19 新增，見 6.15）：`collision`（撞擊，強制位移的通用規則）、`hurl_object`、`pierce`、`topple`
- 資源：`add_stack(name)`、`consume_stack(name)`、`restore_resource`、`steal_buff`
- 召喚：`summon(template, duration)`
- 自身位移與持續區域（2026-10-19 新增，見 6.16）：`dash`（衝鋒）、`leap`、`swap`（設計清單原有，未實作）、移動或跟隨的持續區域
- 改寫規則型：`grant_ap(n)`、`reset_cooldown`、`cheat_death`、`copy_skill`、`redirect_damage`、`extra_reaction`

**條件**：`target_has_status`、`self_hp_below`、`target_hp_below`、`height_advantage`、`target_on_surface`、`moved_this_turn`、`adjacent_ally`、`target_isolated`、`first_round`

**代價**：`mana`、`hp_percent`、`stacks`、`cooldown(turns)`、`uses_per_battle`、`self_status`、`ap_cost(1~3)`、`reaction`（改用反應而非 AP）

**觸發時機**（被動與詞條用）：`on_hit`、`on_crit`、`on_kill`、`on_damaged`、`on_turn_start`、`on_turn_end`、`on_move`、`on_natural_20`、`every_n_hits(n)`

#### 6.3.1 實作對照（Phase 2D–2E 後，2026-10-19）

上面是設計時的原語清單；實際的資料 ID 以 `content/` 為準（原語 `skill_primitives.yaml`、狀態 `statuses.yaml`、條件 `skill_conditions.yaml`、觸發時機 `skill_triggers.yaml`、層數 `stacks.yaml`）。差異如下：

| 設計名稱 | 實作方式 |
|---|---|
| `damage_over_time` | `apply_status`：`bleed`（流血）、`poison`（中毒）；燃燒 `burning` 主要由火元素與表面產生 |
| `heal_over_time` | `apply_status`：`regenerating`（再生） |
| `damage_reduction` | `apply_status`：`guarded`（護衛） |
| `buff_attr` | `apply_status`：`empowered`（激昂） |
| `haste` | `apply_status`：`hasted`（加速） |
| `taunt`、`fear`、`silence`、`blind`、`mark` | `apply_status`：`taunted`、`feared`、`silenced`、`blinded`、`marked` |
| `stun`、`slow`、`root`、`weaken`、`vulnerable` | `apply_status` 同名狀態 |
| `conceal` | `apply_status`：`concealed`（隱蔽；黑暗表面、草叢也會給） |
| `shield` | 原語 `shield`，帶狀態 `shielded`；重複施加取較大值 |
| `freeze` | `apply_status`：`frozen`（冰凍，硬控跳過回合，受火焰傷害解除；Boss 轉緩速）。冰元素觸及站在水上的單位也會冰凍 1 回合（Phase 2H-1） |
| 代價 `self_status` | `SkillCost.self_status`：只限 vulnerable、weaken、slow、root，持續 2–3（含施放當回合），依點數折抵；技能結算後施加（Phase 2H-1） |
| 姿態 | 狀態 `stance_*`（`stance_fury`、`stance_bulwark`），由 `kind: stance` 技能進入 |

Phase 2E 新增、設計清單原本沒有的原語：

- `intercept`：替相鄰隊友擋下攻擊（稀有，只能出現在 `event: ally_hit_adjacent` 的反應技）。和改寫規則型的 `redirect_damage`（任意轉移傷害，傳說）不同，後者仍延後。
- `place_trap`：在地面放置陷阱（陷阱骨架）。
- `add_stack`、`consume_stack`：層數累積與消耗（蓄力／終結骨架）。

**反應技的觸發事件**（`SKILL_REACTION_EVENTS`）：`hit_by_melee`、`hit_by_attack`、`ally_hit_adjacent`、`enemy_leaves_adjacent`。（6.16 E 決定新增 `hit_by_spell`、`ally_downed`、`enemy_enters_adjacent`，可再加 `ally_targeted`。）

**Phase 2E 的規則決定**（細節見 `docs/phases/Phase2E計畫.md` 0.2）：

- **層數**分兩種，由資料定義：`owner: self` 累積在施放者身上（蓄能，例如靜電），`owner: target` 疊在命中的目標身上（印記，例如破甲印，數輪沒再疊就清空）。施放者型的 `add_stack` 要命中才累積。
- **姿態**：花 1 AP 進入，持續到取消；同時只能有一個，進入新姿態會取代舊的；自己回合內取消免費；倒下或戰鬥結束時解除。
- **被動**只做「觸發型」（觸發時機 ＋ 效果）；觸發的效果自動命中，所以被動一律 `category: spell`、`weapon_req: any`。「修正型」被動（例如「燃燒中的敵人受到傷害 +10%」）還沒做。
- **陷阱**只有放置者陣營看得見；敵方 AI 不知道位置、不會迴避。傳送不觸發陷阱，步行與強制位移會。

### 6.5 預算公式（初始值，需以模擬調整）

```
raw         = Σ(效果原語基礎點數 × 強度係數)
shaped      = raw × 形狀倍率        （single 1.0、line3 1.4、chain 1.5、cone3 1.6、square3 2.0）
conditioned = shaped × 條件倍率     （無條件 1.0、常見條件 0.85、苛刻條件 0.6）
total       = conditioned × Π 協同係數（依標籤組合查表，例如 action_economy + burst = 1.5）

可用預算     = tier_budget[tier] × AP係數[ap_cost] + 代價折抵（每回合冷卻 +x、每場限一次 +y、自傷 +z）
              AP係數（初始值）：1 AP ＝ 0.5、2 AP ＝ 1.0、3 AP ＝ 1.6；反應技 ＝ 0.6；被動另表
驗證         = 0.7 × 可用預算 ≤ total ≤ 1.0 × 可用預算   （太弱也退回，避免廢技能）
```

### 6.6 硬性上限

- 觸發連鎖深度 ≤ 3。實作上分成兩個上限（`content/rules/core.yaml`）：`max_chain_depth`（效果佇列中環境互動的連鎖）與 `max_trigger_depth`（技能觸發：被動、反應、陷阱；動作本身為 0，觸發產生的觸發 +1，超過就不結算並發出 `TriggerLimitReached`）。
- 每個技能最多 1 個改寫規則型原語；此類技能必須「每場限一次」或冷卻 ≥ 4 回合。傳說技能改為花費源力時，此限制可放寬或取代（見 6.14.4，數值由模擬決定）。
- 每個技能效果原語 ≤ 4 個。
- 控制遞減：同一目標被同類控制後 2 回合內抗性 +50%；Boss 的硬控（stun、freeze）轉為 slow 或 weaken。
- 同一回合對同一目標的同類增益不疊加，取最高值。實作：重複施加同一狀態時，剩餘回合取較長者（Phase 2G-1）；護盾取較大值。
- 推擊、拉扯 ≤ 2 格（裝備技能強化詞條最多再 +1）。
- 技能只能要求武器大類（`melee`／`ranged`／`focus`／`any`），不可要求特定武器類型。
- 互斥規則表：例如 `no_cooldown` 不可搭配 `allies_in_radius` 或 `square3`。

### 6.7 生成流程

1. LLM 根據玩家經歷、傾向向量與 **現有技能組** 提出技能概念，優先考慮與現有技能的協同（例如已有「施加燃燒」，候選可為「對燃燒中的目標額外傷害」）。
2. LLM 從原語清單組合出效果（輸出受 schema 限制，只能使用存在的原語 ID）。
3. 預算驗證器計算點數；超出或過弱則退回重組（最多 N 次，失敗則改由隨機組合器生成）。
4. 硬性上限與互斥規則檢查。
5. 自動模擬（見 6.8）。
6. 通過後由 LLM 撰寫名稱、描述、施放敘事。

### 6.8 模擬測試

- 每個新技能與同級標準怪物、標準隊伍跑數百場自動戰鬥（固定 AI 策略）。
- 輸出：每回合平均傷害（DPR）、控制回合數、治療量、平均戰鬥長度、異常事件（無限迴圈、一回合擊殺 Boss）。
- 超出同級分佈閾值（例如 DPR > 第 95 百分位 × 1.2）自動退回。
- **build × 地圖類型矩陣**：以代表性 build（推擊流、火焰流、雷電流、坦克、遠程……）在每種地圖類型各跑數百場，產出表現矩陣。驗收：沒有任何 build 在所有地圖類型都排名前段；每個 build 至少在一種地圖類型排名前段。
- 協同是預期內的：允許 build 內技能互相加成，但以協同係數計入預算，並在矩陣中監測整體強度。
- **打法差異檢查**（2026-10-19 新增）：除了強度，也檢查新技能是否 **改變玩家的決策**（需要特定站位、地形、順序或與其他技能搭配），而不只是換名字、換元素的同一種用法。先由 PM 試玩時主觀打分，不必自動化；Phase 4 技能生成的驗收要包含這項（見 6.14.5）。

### 6.9 技能骨架

原語是最小積木；骨架規定一個技能的結構，避免拼出「傷害＋治療自己＋冰面＋推開」這類四不像。LLM 生成時 **先選骨架，再填原語**，預算依骨架分配（核心效果與附帶效果的占比）。骨架以資料定義於 `content/skeletons/`。

| 骨架 | 結構 | 範例 |
|---|---|---|
| 打擊 strike | 單體傷害 ＋ 0–1 個附帶效果 | 碎骨重擊：傷害＋擊倒 |
| 範圍 area | 形狀傷害 ＋ 表面或狀態 | 灰燼誓約：錐形火焰＋火表面 |
| 控場 control | 狀態為主，傷害為輔 | 寒鎖：定身 2 回合 |
| 位移 displace | 位移為核心，搭配環境 | 颶風踢：推 2 格，撞牆額外傷害 |
| 蓄力／終結 builder / finisher | 一個累積層數，一個消耗層數 | 靜電掌（＋層）／雷霆終結（消耗） |
| 連段 combo | 條件為「本回合或上回合做過某事」 | 追擊：對本回合被你擊倒的目標必定暴擊 |
| 陷阱／延遲 trap | 延遲觸發 ＋ 地面 | 灰燼地雷：2 回合後爆炸 |
| 光環／增益 aura | 範圍內友方加成 | 守誓者旗幟 |
| 召喚 summon | 召喚物 ＋ 持續時間 | 餘燼之靈 |
| 反應技 reaction | 反應觸發 | 反擊：被近戰命中時還擊 |
| 姿態 stance | 切換狀態，持續到取消 | 狂怒姿態：傷害上升、防禦下降 |
| 被動 passive | 觸發時機 ＋ 效果 | 燃燒中的敵人受到傷害 +10% |
| 改造 modifier（2026-10-19 新增，見 6.14.1） | 指定目標（標籤或動作類型）＋ 改變內容 | 焚牆：你的推擊撞牆時點燃目標 |

技能 **類型**（`kind`）：`active`（花 AP）、`reaction`、`passive`、`stance`。

### 6.10 與屬性的連動

- **縮放屬性**（`scaling_attr`，見 7.2）：傷害、治療、護盾量依此屬性值縮放。
- **控制命中**：施加狀態的抵抗判定，以縮放屬性值對目標抗性值套用比例公式（5.4）。
- **持續時間不隨屬性成長**：固定回合數，避免控制鎖死。
- **雙屬性縮放**（史詩以上）：例如力量 50％＋智力 50％，讓混搭 build（魔劍士）成立。實作：`secondary_scaling_attr`，所有讀取技能縮放屬性值的地方取兩個有效屬性的平均（含法術命中與控制抵抗）；武器技的武器傷害與命中照舊（Phase 2H-2）。
- **專精加成**：技能的縮放屬性 **是你最高的屬性** 時，獲得小加成（範圍 +1 或持續 +1 擇一，由技能定義）。相對條件，任何等級都適用，並讓配點有「專精或平均」的取捨。實作：`mastery: range`（施放距離 +1，不加範圍大小）或 `duration`（施加的狀態 +1）；以**基礎屬性**判斷，並列也算；雙屬性技能不可設定；不計預算（Phase 2H-2）。

### 6.11 與裝備的連動

| | 武器技（`category: weapon`） | 法術技（`category: spell`） |
|---|---|---|
| 傷害來源 | 武器傷害 × 技能倍率 | 技能本身的傷害骰 × 屬性縮放 |
| 命中使用 | 武器攻擊值 | 法器的法術攻擊值 |
| 隨裝備成長 | 更好的武器 | 更好的法杖、魔典 |
| 武器需求（`weapon_req`） | `melee` 或 `ranged` | `focus` 或 `any` |

- **元素灌注**：沒有元素的武器技繼承武器元素（火焰劍的旋風斬會變成火焰旋風斬，可點燃油桶）。
- **標籤**：技能標籤是裝備技能強化詞條（8.8）與共鳴（8.9）的目標，生成時必須正確標記。
- **技能卡片顯示連動**：例如「受灰燼之牙強化：傷害 +15%｜灰燼共鳴 2/4」。

### 6.12 技能的軸

| 軸 | 有無 | 說明 |
|---|---|---|
| 階級 `tier` | ✅ | 決定預算；隨角色等級解鎖（例如每 5 級開放新階級） |
| 技能等級 `rank` | ✅ | 1–5 級，每級小幅提升，滿級可進化；**成長方式待決定（#8）**，暫定靠使用成長並保留接口 |
| 稀有度 `rarity` | ✅ | 決定可用 **哪些種類** 的原語，**不增加強度**（同階級預算相同） |
| 品質 | ❌ | 技能不需要，避免軸太多 |

| 稀有度 | 可用內容 |
|---|---|
| 普通 | 數值型原語、簡單形狀 |
| 稀有 | 結構型原語（位移、表面、召喚）、條件 |
| 史詩 | 觸發、連段、雙屬性縮放 |
| 傳說 | **1 個核心（改寫規則、改造、改變規則，三擇一）＋ 花費源力**（2026-10-19 決定，見 6.14.4、6.16） |

> **目前實作（Phase 2 後）**：條件與連段骨架從 **稀有** 就能用（`Phase2B計畫.md` 4.6）；被動骨架最低 **史詩**；反應技、姿態、蓄力／終結、陷阱骨架最低 **稀有**（`Phase2E計畫.md` 0.2 決定 H）。雙屬性縮放已做（2H-2，史詩以上）；改寫規則型原語還沒做，所以**傳說與史詩完全相同**（見 `docs/PM交接.md` 3.1.1）。

同階級預算相同，普通技能不會被淘汰，只是較單純；避免「誰抽到傳說誰贏」。

### 6.13 技能欄位

- 「學會」的技能數量不限；戰鬥時只能 **裝備有限的技能**，暫定 **主動 6、被動 2、反應 1**（待決定 #9）。
- 戰前可依地圖類型、天氣與勝利條件更換技能組（例如「下一場是沼澤＋撤離，換上雷電與位移技能」），讓 build 的價值體現在選擇中。

### 6.14 build 的個性：改造、協同與源力（2026-10-19 決定，待實作）

> 來源：`docs/玩法PM交接.md` 第 3 節 #2。使用者要求在 Phase 3-5、3-6 之前實作（拆段與規格由開發 PM 決定）。

**問題**：骨架、原語、預算、模擬很擅長保證技能「不會太強」，但不保證「玩起來不一樣」。預算 0.7–1.0 的窗口與模擬退回，會讓技能往「傷害 ＋ 一個附帶效果」的平均值靠攏，結果名字與敘事獨特，用法卻相同。真正讓 build 有個性的東西（改寫規則、技能互相觸發、修正型被動）正是最少、最晚做的，而且改寫規則型還沒做，**所以目前傳說與史詩完全相同**。以下各項補上這一層，不推翻現有系統。

#### 6.14.1 改造型技能（新類別）

- 不是新的一招，而是 **改變你已有的技能或基本動作**。目標以 **標籤**（例如 `fire`、`displace`）或 **動作類型**（推擊、絆倒、普攻、互動）指定，內容為「附加效果」「改變數值」「獲得標籤或元素」之一。
- 例子：

| 名稱（示意） | 目標 | 改變 |
|---|---|---|
| 焚牆 | 推擊與 `displace` 技能 | 被推的單位撞牆或撞物件時，點燃目標 |
| 餘燼循環 | 所有技能 | 命中燃燒中的敵人時，該技能冷卻 −1 |
| 重踏 | `displace` 技能 | 推擊距離 +1，但 AP +1（受 6.6「推擊、拉扯 ≤ 2 格」上限，超過則改為撞擊傷害） |
| 雷之手 | 普攻 | 帶雷元素（可導電、可與水互動） |

- 預算：依「被改造的技能大約會被使用幾次」估點，以模擬校正；改造效果同樣計入協同係數。
- 改造型以被動欄位裝備（或另設欄位，由開發 PM 決定），稀有度最低 **史詩**；傳說可以帶更強的改造（見 6.14.4）。
- 之後「技能依用法進化」（文字輸入方向，`玩法PM交接.md` #3）會以改造型為基礎。

#### 6.14.2 協同的四條管道

| 管道 | 做法 | 例子 | 現況 |
|---|---|---|---|
| 1 狀態當燃料 | 技能 **消耗** 目標身上的狀態，換取效果（引爆） | 引爆燃燒：移除燃燒，立刻造成剩餘的燃燒傷害並濺射相鄰 | 已有條件判斷與標記引爆（`skill_mark_detonation`）；推廣成通用的「消耗狀態」原語 |
| 2 環境當中介 | 技能 A 造出表面或物件，技能 B 利用它 | 召水 → 雷電沿水擴散；造油 → 點火 | ✅ 已有，是本專案的強項 |
| 3 監聽自己的動作 | 新增觸發時機，讓被動與改造能在「你做了某件事」時觸發 | 「每當你施放火焰技能，下一個雷電技能範圍 +1」「你推動的敵人撞牆時，施加流血」 | 目前只有 6.3 的 9 種觸發時機 |
| 4 標籤改寫 | 改造型讓技能 **獲得** 標籤或元素，進而接上管道 2、3 | 「你的推擊類技能帶火元素」→ 推進油裡就著火 | 無（即 6.14.1） |

- 管道 3 建議新增的觸發時機（數量與名稱由開發 PM 決定）：`on_cast_tag(tag)`（施放帶某標籤的技能時）、`on_status_applied(status)`（你施加某狀態時）、`on_forced_move`／`on_collision`（你推動的單位被移動或撞擊時）、`on_enter_surface`（敵人進入你造的表面時）。
- 所有觸發仍受 `max_trigger_depth`（6.6）限制，不會無限連鎖。

#### 6.14.3 修正型被動

- 6.3.1 記載目前被動只做「觸發型」。補上 **修正型**：持續改變數值，不需要觸發，例如「燃燒中的敵人受到你的傷害 +10%」「你在高處時命中 +1」。
- 修正型被動是 build 協同的黏著劑，和 6.14.1、6.14.2 一起實作。

#### 6.14.4 傳說的定位與源力

- **傳說 ＝ 1 個核心 ＋ 花費 1–2 點源力。** 核心 **三擇一**：改寫規則型原語（6.3）、改造型（6.14.1）、改變規則（6.16 F）。（2026-10-19 使用者決定；3C-4a 原本規定傳說一定要有改寫規則，改為三擇一。） 源力可以取代或縮短 6.6 對改寫規則型的冷卻限制，讓傳說成為一場戰鬥的高潮，而不只是「冷卻比較長的強技能」。
- 改寫規則型原語（6.3：`grant_ap`、`reset_cooldown`、`cheat_death`、`copy_skill`、`redirect_damage`、`extra_reaction`）至少先做幾個，讓傳說成立；先做哪幾個由開發 PM 決定。
- **源力**（參考《神界：原罪2》的秘源點；名稱暫定）：

| 規則 | 決定 |
|---|---|
| 存放 | **一輪內保留，跨戰鬥帶著走**，讓「留給 Boss」有意義。roguelite 一輪的存檔要記錄源力（影響 Phase 3-5） |
| 上限與保底 | 上限 **3 點**；**每場戰鬥開始至少 1 點**，避免「捨不得用、整場存著」 |
| 取得：戰鬥之間 | 戰後獎勵、營火等 |
| 取得：戰鬥中 | 地圖上的 **源泉格**（部分地圖才有，增加搶位置的戰術）、擊殺精英、Boss 戰前保底 |
| 誰能用 | **先只給傳說技能**（必須花）。「任何技能花 1 點做源力強化」列為之後的選項 |
| 數值 | 取得量、源泉格數量、傳說花 1 或 2 點，由模擬或試玩調整 |

- 要避開《神界：原罪2》的兩個已知問題：點數太稀有時玩家整場存著不用；前期太少、後期太多。上限與保底就是為此設計。

#### 6.14.5 打法差異檢查

- 見 6.8。新技能除了通過強度檢查，也要回答：「拿到這招後，你的決策有沒有改變？」（站位、地形、順序、搭配）。
- 先由 PM 試玩時主觀打分，不必自動化；Phase 4 技能生成的驗收（🎯 好玩檢查點）要包含這項。

### 6.15 物件原語：場景物件當武器與工具（2026-10-19 決定，待實作）

> 來源：`docs/玩法PM交接.md` 第 3 節 #4。使用者要求四項都在 Phase 3-5 之前實作。戰場規則面見 `05-戰鬥.md` 5.1「物件當武器與工具」。

**問題**：物件目前只能被元素觸發、被打破、被推或撥開，以及提供掩護、阻擋視線，還不能當武器或工具。「多樣的戰場讓每個 build 發光」在物件上只剩「火焰流能燒它」。颶風踢的設計描述寫了「撞牆額外傷害」，但撞擊沒有實作（推擊超過上限的距離目前直接捨去）。

**四個原語**（以下為建議預設值，細節與數值由開發 PM 定，並以模擬調整）：

| 原語 | 類型 | 規則 |
|---|---|---|
| `collision` 撞擊 | 通用規則（所有強制位移都適用）＋ 可調強度的效果 | 被推、拉、擊退的單位因障礙提前停下時，每少走 1 格受一次撞擊傷害（物理）。撞到單位雙方都受傷；撞到 `breakable` 物件時物件也受傷。產生 `on_collision` 事件（接 6.14.2 管道 3）。技能可加強撞擊傷害；改造型可把「超過推擊上限而捨去的距離」轉成撞擊傷害 |
| `hurl_object` 投擲物件 | 效果原語 | 舉起射程內的 `pushable` 物件，丟到目標格。命中判定照技能；落點單位受傷，可附擊倒。物件落地後依標籤結算：`explosive` 爆炸、`breakable` 碎掉、其他留在落點附近的空格。物件的元素互動照常觸發（油桶落地爆炸、點燃） |
| `pierce` 穿透 | 技能屬性（或改造型的改變內容） | 遠程攻擊或直線形狀 **無視半掩護**，並能穿過 `penetrable` 物件，對物件與後方目標都造成傷害（後方目標可打折）。石柱、土牆仍擋。例：改造型「你的箭能穿透木製物件」 |
| `topple` 推倒 | 物件規則 ＋ 效果原語 | `topplable` 物件被推擊或技能推動時，往遠離方向倒下，壓住一條直線（建議 2–3 格）：格上單位受傷並擊倒，物件變成倒塌物件（`blocks_move`、`half_cover`）。技能可直接以推倒為效果 |

- **只有技能能投擲與穿透**，基本動作不行；撞擊與推倒對基本動作的推擊也適用。
- 稀有度：`hurl_object`、`topple` 屬結構型（稀有以上）；`pierce` 可作為稀有以上的技能屬性，或改造型的內容；撞擊強化屬數值型。預算點數由開發 PM 以模擬決定。
- 骨架：`hurl_object`、`topple` 適合 **位移 displace** 與 **範圍 area** 骨架；`pierce` 適合 **打擊 strike** 與直線形狀。

**新流派與發光的地圖**

| 流派 | 核心 | 發光的地圖 | 不利的地圖 |
|---|---|---|---|
| 念力流 | 投擲物件 ＋ 元素互動 | 箱子、油桶多的倉庫、油庫 | 空曠平原 |
| 撞擊流 | 推擊 ＋ 撞擊傷害 | 狹窄走廊、牆多的室內 | 開闊地形（和推下深淵的位移流區分） |
| 穿透射手 | 穿透 ＋ 遠程 | 敵人據守掩護的地圖 | 沒有掩護的地圖 |

**連帶工作**

- 補物件標籤 `penetrable`、`topplable`，並在部分地圖擺放對應物件。
- 敵人與隊友 AI 要會評估撞擊與投擲。
- 加示範技能（例：念力投擲、穿甲箭、震地推倒）與代表性 build（念力流、撞擊流），跑 `sim matrix` 確認新流派在對的地圖強，沒有全地圖最強。
- 網頁技能預覽要顯示投擲落點與物件、穿透路線、推倒的壓住範圍、預期的撞擊傷害。

### 6.16 技能能力的缺口補齊（2026-10-19 決定，待實作）

> 來源：`docs/玩法PM交接.md` 第 3 節 #5。玩法 PM 統整「技能能做什麼、不能做什麼」後列出 8 個缺口，使用者要求 **全部在 Phase 3-5 之前實作**。以下為建議預設值，細節、數值、拆段由開發 PM 決定，並以模擬調整。

| # | 缺口 | 做法 | 受益的流派 |
|---|---|---|---|
| A | **自身位移** | 新原語 `dash`（衝鋒：沿路徑移到目標相鄰格，再結算後續效果；路徑被擋則停下）、`leap`（跳到範圍內的格子，無視中間的單位與低矮障礙，可上下 1 層高度）、`swap`（與目標單位交換位置，敵我皆可，例如把敵人換到危險格） | 近戰、刺客、位移流 |
| B | **召喚** | 啟用 `summon` 骨架與原語：在指定格召喚 `content/units/` 的召喚物範本（例：元素之靈、骷髏、圖騰），持續 N 回合，由效用 AI 控制，緊接在召喚者之後行動。同時存在的數量有上限；倒下或到期就消失，不給經驗與源力。圖騰類不能移動，只提供光環或每回合效果 | 召喚師（新流派） |
| C | **連段條件** | 補齊 6.3 條件清單：`moved_this_turn`、`adjacent_ally`、`target_isolated`、`first_round`；可另加「本回合已施放過帶某標籤的技能」 | 所有流派，提升打法差異（6.14.5） |
| D | **修正能讓技能變形** | 修正規則（6.14.1）新增可改的內容：範圍大小 +1、形狀轉換（單體 → 直線或連鎖，限合法組合）、目標類型（例：治療技能也能對自己）。形狀改變依 6.5 的形狀倍率重算預算 | 改造型 |
| E | **反應時機** | 新增反應事件 `hit_by_spell`（被法術命中）、`ally_downed`（隊友倒下）、`enemy_enters_adjacent`（敵人進入相鄰格），可再加 `ally_targeted`（隊友被瞄準時） | 反應流、守護者 |
| F | **改變規則型傳說** | 傳說的第三種核心：直接改變一條戰鬥規則。例：「你的火焰對隊友治療而非傷害」「你可以推動任何物件，包括石柱與牆」「你移動經過敵人時，對他施加流血」「你倒下時留下持續 2 輪的分身」。要花源力（或做成以源力啟動的持續效果），每人最多裝 1 個 | 傳說 |
| G | **持續區域** | 新原語：會移動或跟隨的區域。例：火牆每輪沿方向前進 1 格；光環跟著施放者移動（持續 N 回合）。單位進入或回合開始時結算效果，並在環境預告（5.7）中顯示 | 控場、輔助 |
| H | **資源互動** | 新原語 `restore_resource`（回復法力，或讓冷卻 −1）、`steal_buff`（移除目標一個增益並施加到自己身上） | 法師、輔助、刺客 |

**傳說的核心改為三擇一**：改寫規則型原語、改造型、改變規則（F），再加上花費源力（6.14.4）。

**連帶工作**

- 每項至少 1 個示範技能，並裝進代表性 build。
- AI 要會合理使用召喚、衝鋒、交換、持續區域。
- 網頁技能預覽與環境預告要顯示衝鋒路徑、交換、召喚物、移動中的區域。
- 完成後跑 `sim matrix`，確認沒有 build 爆衝。
- **規模**：B 召喚、G 持續區域工作量最大（新單位、AI、回合順序、介面），可以拆成獨立的小階段，但仍排在 3-5 之前。
