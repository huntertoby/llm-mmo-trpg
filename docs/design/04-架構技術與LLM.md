## 4. 系統總架構

> 原型階段（Phase 0–4）只用到：規則引擎、內容資料、技能生成器、模擬器、LLM 層（技能生成與命名），以及在本機運行的 Web 客戶端。其餘為後期。

```
[Web 客戶端]  區域地圖、格子戰鬥、點選＋文字輸入、敘事串流
    │ WebSocket
[閘道]  驗證、速率限制、輸入長度與內容過濾
    │
[遊戲伺服器（權威）]
    ├─ 世界服務：區域分片、玩家位置、AoI、位面合成
    ├─ 戰鬥實例：每場戰鬥一個 actor，執行規則引擎
    ├─ 規則引擎（trpg.engine，純函式）
    └─ 事件日誌（event sourcing）＋ 狀態快照
    │ 事件匯流排
[世界模擬]  陣營、經濟、區域安全度、物資、生態（確定性 tick）
    │
[敘事導演層]
    ├─ 意圖解析器（小模型）
    ├─ 戰鬥敘事器（中模型，串流）
    ├─ NPC 代理（小模型）
    ├─ 任務生成器（需求 → 模板 → LLM 包裝 → 驗證 → 發布）
    ├─ 技能生成器（行為傾向 → 原語組合 → 預算 → 模擬 → 命名）
    ├─ 地圖組裝器（場景描述 → 格子模板 → 連通性與公平性檢查）
    ├─ 場景／副本 GM（中大模型）
    └─ 世界 GM（大模型，低頻非同步）
    │
[記憶與知識]  世界聖經、知識圖譜、向量庫、玩家個人史、位面旗標、摘要管線
[營運]  內容審核、GM 後台、日誌回放、成本監控
```

**兩個速度層**：
- 即時層：移動、AoI、聊天、戰鬥實例中的狀態同步（毫秒～秒級）。
- 敘事層：任務、NPC、世界事件、技能生成（秒～小時級），透過事件匯流排讀取即時層事件，透過受限工具寫回世界狀態。

## 10. LLM 整合

> 原型階段只用到技能生成與命名（升級時，非同步）；Phase 5 加入意圖解析與戰鬥敘事；其餘為後期。

| 任務 | 模型層級 | 延遲目標 | 頻率 |
|---|---|---|---|
| 意圖解析 | 小 | < 800ms | 每次文字行動 |
| 戰鬥敘事 | 中 | 首字 < 1s，串流 | 每回合 |
| NPC 對話 | 小 | 串流 | 高 |
| 場景／副本 GM | 中大 | 串流 | 中 |
| 任務包裝 | 中 | 非同步 | 低 |
| 技能生成 | 中大 | 非同步（升級時） | 低 |
| 地圖組裝 | 中 | 非同步／預生成 | 中 |
| 世界 GM | 大 | 非同步，每小時 | 很低 |

- 全部使用結構化輸出（tool use ＋ JSON schema），回傳後再以 pydantic 驗證。
- Prompt 存為版本化檔案（`src/trpg/llm/prompts/`），每次呼叫記錄 prompt 版本。
- 所有 LLM 輸出（解析結果、生成的技能與文字）都寫入事件日誌；重播時讀取紀錄，不重新呼叫 LLM，以維持確定性。
- 成本控制：模型路由、prompt caching、串流、離峰預生成、每玩家每小時 token 預算（超額降級到小模型或預製內容）。
- 評估集：為解析器、敘事器各建立一組固定輸入與預期輸出，作為回歸測試。
- **「自然」是主題名稱，不是元素**（2026-10-24 決定，見 `docs/archive/玩法決定紀錄_1-138.md` #48）：LLM 生成「自然」主題的技能時，用毒素、大地、風、治療、藤蔓召喚物、荊棘牆組合；主題詞放在 `content/llm/` 的世界觀或命名資料，Phase 4 處理。

## 11. 安全

- 玩家輸入包在 `<player_input>` 標籤中，系統提示明確說明其為資料。
- 物品、經驗值、資源只能由引擎產生。
- 輸出端內容審核；多人場景中的越界內容會影響其他玩家，需即時過濾。
- GM 後台：可介入場景、修正世界狀態、回放事件日誌。

## 12. 技術選型（預設，可調整）

| 項目 | 選擇 | 備註 |
|---|---|---|
| 後端語言 | Python 3.12＋ | 引擎、技能、模擬、LLM、伺服器 |
| 套件管理 | uv | 鎖定相依版本；前端另用 pnpm |
| 驗證 | pydantic v2 | 所有 LLM 輸出、內容資料檔與網路訊息 |
| 測試 | pytest、hypothesis（property-based） | |
| 程式品質 | ruff（lint ＋ 格式化）、mypy（strict）、import-linter | |
| 亂數 | 自行實作可種子化 PRNG（xoshiro128**） | 引擎禁用 `random` 模組全域函式 |
| 伺服器 | FastAPI（含 WebSocket）＋ uvicorn | Phase 3 起提供本機 API；多人連線於 Phase 6 |
| 資料庫 | PostgreSQL（事件表＋快照）＋ pgvector | 後期；原型以本機 JSON 存檔 |
| 快取／訊息 | Redis（session、pub/sub、Streams） | 後期；之後可換 NATS／Kafka |
| 資料分析 | pandas、matplotlib | 平衡報表、build × 地圖矩陣 |
| 前端 | React ＋ PixiJS（Vite 建置、TypeScript） | Phase 3 起；2D 俯視角格子，高度以色階、陰影與數字標示；Phase 3 前可再調整 |
| LLM | Anthropic Python SDK（tool use、prompt caching、streaming） | 經 LLMClient 抽象，模型 ID 寫在設定檔 |
| CI | GitHub Actions | 尚未建立 GitHub repo 時，先以本機 `scripts/check` 執行同樣的檢查 |

**取捨說明**：原本選 TypeScript 是為了讓引擎在伺服器與瀏覽器共用。改用 Python 後，技能預覽（`preview`）由後端 API 計算；單人原型在本機運行，延遲可忽略，多人時再加快取。

## 13. 專案結構

```
/
├─ CLAUDE.md          # 給 AI 實作者的守則（第 0 節精簡版）與文件索引
├─ pyproject.toml     # uv 專案設定、ruff、mypy、pytest、import-linter
├─ src/trpg/
│  ├─ shared/         # 共用型別、Rng、ID、錯誤
│  ├─ engine/         # 純確定性規則引擎：格子、單位、行動、判定、效果佇列、事件
│  ├─ content/        # 內容資料的 pydantic schema 與載入器（資料本身在頂層 content/）
│  ├─ skillgen/       # 技能組合器、預算計算、互斥與上限檢查、驗證器
│  ├─ sim/            # 批次自動戰鬥模擬與平衡報表
│  ├─ llm/            # LLMClient、MockLLMClient、prompts、schemas、評估集
│  ├─ narrative/      # 意圖解析、敘事、NPC 代理、任務生成、地圖組裝、世界 GM
│  ├─ roguelite/      # 原型循環：一輪流程、地圖與遭遇抽選、升級、本機存檔
│  ├─ api/            # FastAPI 應用（Phase 3 起）
│  └─ cli/            # 終端機工具：跑戰鬥、跑模擬、印出戰場
├─ content/           # 資料檔：原語、形狀、骨架、條件、代價、格子物件、互動表、地圖模板、印記、共鳴、詞條、掉落表、預算表
├─ tests/             # pytest，目錄結構對應 src/trpg/
├─ client/            # Web 前端（Phase 3 起）
├─ docs/
│  ├─ 專案計畫.md      # 總覽、守則與開發階段（設計細節在 design/）
│  ├─ design/         # 依主題拆分的設計細節（04-架構技術與LLM.md、05-戰鬥.md ……）
│  ├─ phases/         # 各階段的實作規格（Phase0計畫.md ……）與完成報告
│  └─ archive/        # 舊版計畫
└─ scripts/           # 開發與模擬腳本（check、sim 等）
```
