# 專案計畫：開放世界與敘事（第 9 節）

> 本檔為 `docs/專案計畫.md` 的一部分，總覽與守則見該檔。

## 9. 開放世界與敘事（後期規劃）

### 9.1 階層式說書人

| 層級 | 模型 | 頻率 | 職責 |
|---|---|---|---|
| 世界 GM | 大 | 每小時遊戲時間，非同步 | 讀取全服事件摘要與模擬狀態，產生世界事件與劇情鉤子 |
| 場景／副本 GM | 中大 | 即時 | 一個隊伍或場景的互動與敘事 |
| NPC 代理 | 小 | 高頻 | 日常對話，只帶人設、記憶與當下情境 |

場景之間的影響透過世界狀態與事件日誌傳遞，不讓 LLM 彼此直接對話。

### 9.2 狀態驅動任務（storylet）

- 世界由可量化狀態組成：陣營聲望、村莊安全度、物資、NPC 心情與目標。
- 世界模擬讓狀態自行變動（陣營擴張、商路、怪物遷徙）。
- 任務是「需求」的產物；同一需求有多種解法，選擇會再改變狀態。
- 任務結構與獎勵由系統模板決定，LLM 只負責包裝敘事與 NPC 動機。

```json
{
  "need_id": "village_food_shortage",
  "region": "ashford",
  "trigger": { "stat": "food", "lt": 30 },
  "solutions": ["escort_caravan", "clear_bandits", "find_alt_source"],
  "reward_template": "tier2_common",
  "expires_in_hours": 48
}
```

### 9.3 後果分層與位面

| 層級 | 內容 | 呈現 |
|---|---|---|
| 個人 | NPC 態度、私人劇情線 | 個人位面 |
| 隊伍／公會 | 共同完成的劇情 | 群體位面 |
| 伺服器 | 多人累積的大型行動（守城成敗） | 世界 GM 定期結算後改變共享世界 |

世界狀態支援「同一區域多個版本的覆蓋層」，玩家進入區域時依其旗標合成看到的世界。

### 9.4 體驗密度三層

1. **開放野外**：一般探索與戰鬥，LLM 在背景生成事件與 NPC 對話。成本低、量大。
2. **NPC 互動**：自由文字對話，可說服、威脅、交易，結果透過工具落到聲望與任務狀態。
3. **故事副本／GM 場景**：完整 TRPG 模式，場景 GM 全程主持。最貴，集中投放。

### 9.5 記憶與一致性

每次 LLM 呼叫依序組裝 context：
1. 固定系統提示（GM 風格、規則、可用工具）——放在前綴以利 prompt caching
2. 世界聖經中與此地相關的條目（檢索）
3. 當前場景狀態（從引擎讀取，不從聊天紀錄推斷）
4. 在場角色與 NPC 的相關記憶（知識圖譜 ＋ 向量檢索）
5. 最近幾輪對話 ＋ 本場景摘要

輸出後經 **canon 驗證器**（規則 ＋ 小模型）檢查是否提及已死 NPC、地理錯誤、違反設定；違反則重新生成。場景結束時由摘要管線壓縮為長期記憶。

### 9.6 賽季大世界：精簡的魔獸世界式運作（2026-10-22 決定，見 `docs/玩法決定紀錄.md` #29）

> 目標情境見 `docs/專案計畫.md` 1.2（5～10 位朋友、共享世界、賽季制、每季大 Boss、現金獎勵）。使用者原話：「一輪5場只是測試 實際上應該會像魔獸世界那個方式來運作」。roguelite 一輪（7.1）只是戰鬥與技能的測試原型。題材不綁定（世界觀待決定）。

#### 9.6.1 主城與小鎮

| 地方 | 功能 |
|---|---|
| **主城**（1 座） | 排行榜與 Boss 擊殺紀錄（以確定性重播驗證）、Boss 進度與封印、公告板（世界事件、懸賞）、整備（換技能組、配點、休息）、看朋友的 build 與編年史、許願池、技能工坊（只開放靶場試玩與改造自己已有的技能） |
| **區域小鎮**（每區 1 座） | 任務起點、傳送點、區域商人、區域懸賞；由 NPC 撐場面 |

- 交易第一季不做（避免朋友之間輸送資源影響獎金公平）；鐵匠與裝備見 08（Phase 5）。

#### 9.6.2 移動：地點圖

- 每個區域是一張 **地點圖**：15～25 個地點，點哪裡就走過去，路上可能遇敵；部分地點 **要探索才會出現**（隱藏地點）。城鎮之間用傳送點。
- 這是 `docs/專案計畫.md` 3.2 #2「區域內自由移動，遇敵展開格子」的 **先行版**，不推翻原決定；之後可以升級成完整的自由移動。
- 遇敵展開的戰鬥格子取自該地點的地圖模板（沿用 05 的地圖類型、勝利條件與環境）。

**地點種類**（內容由玩法 PM 設計，資料定義）

| 種類 | 內容 |
|---|---|
| 營地 | 敵人據點；戰鬥，勝利條件輪替（全滅、撤離＝護送或突圍、守點＝防守） |
| 遺跡 | 情境判定（9.6.4）＋可能通往隱藏地點 |
| 祭壇、異象 | 機遇（7.6）的觸發點；有條件（天氣、時間、帶某關鍵字的技能、某印記） |
| 商隊、村落 | 任務與懸賞的 NPC |
| 秘境（隱藏） | 探索判定或隱藏任務才會出現；精英、稀有獎勵、劇情線索 |
| 精英巢穴 | 懸賞目標，先打倒的人拿大獎 |

#### 9.6.3 任務結構

| 類型 | 內容 | 互動 |
|---|---|---|
| 賽季主線 | 劇情章節，導向本季 Boss；章節獎勵含劇情技能（7.6） | 各自推進 |
| 區域任務鏈 | 每區一條，3～6 步；結尾給該區主題的技能三選一 | 各自推進 |
| 隱藏任務 | 由情境判定成功、探索秘境或行為條件（例：在某地點用火擊殺 5 名敵人）觸發 | 先發現的人可在地點留下線索 |
| 懸賞板 | 每日刷新；精英或稀有敵人先打倒的人拿大獎，其他人拿小獎 | 競爭 |
| 世界事件 | 全服合作目標（例：3 天內清掉 30 場侵蝕戰鬥）；成功開放新區域或削弱 Boss，失敗則世界惡化 | 合作 |
| Boss 封印 | 全服累積封印鑰匙才解鎖 Boss；解鎖時間事先公告，全員同時開打 | 先合作、後競賽 |

**人少時世界不空**：共享世界狀態（朋友清掉的營地、打通的道路大家都看得到）；地點上的足跡與留言（「某某在這裡打倒了精英」）；**朋友的影子**——可以招募朋友的 build 當 AI 隊友，或在世界事件中遇到它（沿用隊友 AI）。

**第一季範圍建議**：主城＋2 個區域＋主線＋懸賞板＋Boss；其餘逐季加入。整體是 Phase 5 以後的多段工程。

#### 9.6.4 情境判定（2026-10-22 決定，見 `docs/玩法決定紀錄.md` #31）

> 使用者原話：「llm 給你一個情境 然後你回答你怎麼解決 然後 按屬性判定 給你相對的獎勵或懲罰」

像 TRPG 的技能檢定。和許願池（7.6）、文字輸入差異化（`玩法PM交接.md` #3）共用同一條安全流程，是文字輸入最早落地的地方。

1. **情境**：來自 **情境模板**（content 資料）：基準難度、**允許的屬性**（2～3 種，例：力量破門、敏捷攀爬、感知找機關）、獎勵表與懲罰表。LLM 只依模板與世界狀態寫情境敘述。
2. **玩家回答**：用文字描述怎麼解決，放在 `<player_input>` 內。**第一次送出即定案**，不能重打來換判定。
3. **LLM 提議**（pydantic 驗證）：從允許的屬性中選一個、方法分類（力取、智取、潛行、說服……），難度只能在基準 **±2** 內調整；回答明顯行不通時可以提議「劣勢」。
4. **引擎判定**：檢查提議合法，擲 d20＋屬性修正（亂數由種子、玩家、情境衍生，可重播），結果分 **成功／部分成功／失敗** 三段。
5. **獎懲**：從模板的表中照結果挑選，**有預算上限**。LLM 不能產生表外的獎勵。
6. **敘述**：LLM 只負責敘述結果。

**公平原則**（現金獎勵）：
- **文筆不換強度**：文字只決定「用哪個允許的屬性、什麼方法」，**沒有創意加值**。
- **獎勵不給永久戰力**：只給任務幣、經驗、補給、線索、通往隱藏地點或機遇的入口、短期 buff；新技能只透過機遇（橫向、同預算）。
- 所有判定寫入事件日誌（第一季不設每日次數上限，見 9.7）。

**規則**（2026-10-22 使用者決定：「照建議」）

| 項目 | 決定 |
|---|---|
| 創意加值 | **沒有**；好回答的價值在於選到自己擅長的屬性與方法 |
| 結果分段 | **成功／部分成功／失敗** 三段 |
| 失敗懲罰 | **依情境危險度分級**，最重到「受傷或敵人增援」；輕的是失去補給、下一場戰鬥帶 debuff |
| 每日次數 | ~~5 次~~ → **第一季不設上限**（2026-10-22 使用者：「不防爆肝」，見 #32） |
| 朋友的影子代替判定 | **先不行**，之後再考慮 |

#### 9.6.5 世界觀：碎界五區（2026-10-23 決定，見 `docs/玩法決定紀錄.md` #42）

> 使用者原話：「戰場配對 2 題和碎界 4 題都採用 A」

- **碎界**：源晶核心崩裂，世界碎成漂浮的界域；各界域保留不同的文明風格，技能的力量來自源晶的頻率（LLM 用語見 `content/llm/world_shattered.yaml`）。名稱與描述日後仍可由 LLM 重新生成。
- **五區**：

| 區 | 風格 | 視覺 | 槍的造型 |
|---|---|---|---|
| 晶冠城邦 | 奇幻 | 米白石材＋藍紫晶光、金飾 | 少見、不禁止 |
| 雲嶺 | 東方 | 青石、墨灰、竹青、點朱紅、薄霧 | 少見、不禁止 |
| 魔導樞市 | 魔導科技（黃銅＋晶能＋符文，不走霓虹賽博） | 鐵板、黃銅、晶能青、符文橘 | 黃銅晶能 |
| 灰燼荒原 | 災變 | 焦土、炭黑、熔岩橘 | 舊鐵 |
| 霜潮海境 | 海境 | 沙色、淺海藍、浮冰白、珊瑚 | 木托火槍 |

- 槍各區都可以有，造型跟著區域（武器規則不分區，見 08 8.11）。
- 每區的戰場地圖池見 05 5.1「區域地圖池」；每區一個敵人家族、一條區域任務鏈（9.6.3）。
- 美術：區與區只換配色與造型，技能圖示、狀態、元素色共用（`docs/art/碎界五區比較.md`、`docs/art/區域外觀換法.md`）；**第一個做的區域是雲嶺**。
- 第一季範圍仍是「主城＋2 個區域」（9.6.3 末），哪兩區在大世界開發前決定。

### 9.7 賽季制：第一季（測試季）（2026-10-22 決定，見 `docs/玩法決定紀錄.md` #32）

> 使用者原話：「最多先兩個禮拜吧剛上線可能會很多bug 主要讓他們測試 甚至打不過boss就讓他們對打決勝負」；「不防爆肝 人家花那麼多時間玩應得的 第一次 也需要大量的測試」；「好先這樣」。

**節奏（14 天）**

| 時段 | 內容 |
|---|---|
| 第 1～3 天 | 主線第 1～2 章、區域 A；世界事件 #1（成功則開放區域 B） |
| 第 4～7 天 | 區域 B、懸賞；世界事件 #2（收集 Boss 封印鑰匙） |
| 第 8～10 天 | 封印鑰匙集滿即解鎖 Boss（最早第 8 天）；未集滿則 **第 10 天強制解鎖**；解鎖前 24 小時公告 |
| 解鎖～第 13 天 | Boss 競賽（首殺者得現金獎勵） |
| 第 14 天 | 無人首殺時舉行季末對打賽 |

- 世界事件每 3～4 天 1 個（共 3 個）；懸賞 **先搶先贏**，不設每日數量。

**上限（不防爆肝，只防靠重試刷運氣）**

| 項目 | 第一季 |
|---|---|
| 一般戰鬥、懸賞、情境判定 | **不設每日上限** |
| Boss 挑戰 | **每日 3 次**，每次的種子由伺服器給 |
| 許願池 | **每週 2 次** |
| 賽季等級上限 | **10**。沒有體力上限時，等級上限是主要的平衡器：花時間多的人較早到頂，但 Boss 依滿等設計，到頂後比的是 build 與打法 |

**季末保底：影子循環賽**

- 每人提交 build＋AI 行為設定，引擎自動讓每兩人對戰（3 張事先公布的地圖 × 交換先後手 × 多個種子），勝場數最高者勝。
- 全員拉到等級上限、屬性點重新分配；技能照常受預算上限約束，比的是 build。
- 每場存「初始狀態＋種子＋動作列表」，任何人都能在網頁上重播驗證。
- **有人首殺 Boss**：獎金歸首殺者，對打賽改為不給獎金的娛樂賽。**無人首殺**：獎金歸對打賽冠軍。
- 對應 `docs/專案計畫.md` 3.2 #4（PvP）：季末保底採非同步影子對決；即時 PvP 仍暫不做（專案 PM 修改）。

**測試季的 bug 處理**

- 回報管道：Discord「#bug回報」頻道＋遊戲內「回報」按鈕（自動附上該場重播 ID）。
- 事先公告：利用已知 bug 取得的成果無效；主動回報 bug 給任務幣獎勵。
- 影響公平的嚴重 bug：修正後重播受影響的戰鬥，作廢不當獲利；牽涉 Boss 首殺時由使用者裁定。一般 bug：全員補償任務幣。
- 每場戰鬥記錄引擎版本，修正前的重播仍可重現；熱修正避開 Boss 開放期間或事先公告。

**季末重置**

- 清空：等級、技能、任務幣、世界狀態。
- 保留：帳號、首殺與冠軍的榮譽稱號、編年史與印記收藏（紀念用，不影響數值）、bug 回報者紀念稱號。
- 正式季的重置範圍之後再議。
