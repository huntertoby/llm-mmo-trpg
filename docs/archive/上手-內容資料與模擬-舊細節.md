## 二、量新手任務一路打過去的做法（原檔第二節）

**量新手任務一路打過去的做法（`scripts/ob6_newbie_sim.py`，OB-6b）**

1. **直接呼叫純函式 `world_step`，不用 `WorldStore`**：`WorldStore.create` 的角色 ID 與世界種子用 `secrets`，每次不同（CB-2d 同一份內容量到 32% 與 52% 就是這個原因）。腳本自己組 `WorldState(season_seed=…)`、`new_character(…, pending_hero(library), region="cloud_ridge")` 加 `opening=new_opening(seed)`，種子＝`SEED_BASE + 格 × 1000 + i`。
2. 流程：`opening_class` → 接 `starter_ferry` → BFS 一次走一格（盡量避開目標以外的視野，碰到就打）→ 第 1、2 步 → 沿出口走回霧渡鎮 → `opening_confirm` → 延後的三選一一律選第 1 張 → 第 3 步一路走到 `terrace_clash`，路上每一場都打。輸了就停。時間固定（`NOW`），清空的隊伍不重生。
3. 打一場：`prepare_battle` → `begin_battle` → `advance`（`CommandedAI(UtilityAI)`），`on_step` 收步驟並看主角的 `SkillUsed`、`UnitDowned`；再把步驟送 `FightAction`。比 `auto_steps` 再 `_run` 少算一次。
4. **配對**：第 1、2 步與正式選定只跑一次，第 3 步對每個候選內容各跑一次（候選在記憶體裡換：`dataclasses.replace(library, units=…, world_encounters=…)`；內容庫的快取欄位是 `init=False`，replace 後是新的）。對照表列每格的淨變動與「倒下與否」翻轉的人數。
5. `--per-cell` 是「走到第 3 步的人數」：第 1、2 步輸掉的人另列，腳本依序補第 80、81… 個人直到每格分母夠（驗收要求分母 ≥ 80）。
6. 4 格 × 80 人（實際 325 人）`--jobs 4` 約 2 分鐘（OB-6b 實測 126 秒）；冒煙用 `--per-cell 2`，同參數跑兩次 JSON 逐字相同（除了耗時）。
7. **和 CB-2d 的 42% 不能直接比**：舊量測從竹林直接走去梯田（帶著第 2 場剩的 HP、三選一全跳過）；新流程第 3 步前回霧渡鎮正式選定（HP 回滿、屬性重配、兩組三選一選第 1 張），所以第 3 步倒下率掉到 ≤ 8%（`docs/phases/PhaseOB-6b報告.md`）。第 1→2 步之間仍不休息，竹林是帶著渡口剩的 HP 打。

## 四、常踩的坑（原檔第四節，已結案段的實作細節）

28. **「只能來自某關鍵字」的規則用專屬關鍵字判斷**（BS-1）：`trpg.content.silent_strike.silent_strike_problems` 用 `derive_from_facts(..., exclusive_only=True)`，要求帶無聲的技能專屬關鍵字恰好只有 `concealed`（`silent_strike` 與「給無聲步」本身在 `skill_keywords.yaml` 推導成隱蔽）。內容載入（`skill_checks._check_keywords` 之後）、`validate_skill`（規則碼 `silent_strike.source`，LLM 提議與工坊共用）、詞條「授予動作」（`gear_checks._action_problems`）三處擋。`content.skills.problems` 不能匯入 `keyword_derive`（循環），所以放在獨立模組。
29. **`grant_skill` 可以給修正技能的唯一例外**（BS-1）：`is_silent_grant`（修正技能、不需啟動、每條規則都是 `silent_strike`）；預算改成每回合 `skill_budget.yaml` 的 `silent_strike_round_milli`（`budget.py::_grant_skill_points`）。能給的技能清單有三份要一起改：`content.skills.problems.granted_skill_problems`（驗證）、`skillgen/proposal/params.py::grantable_skills`（LLM schema 列舉）、`skillgen/option_params.py` 的 `skill` 選單（工坊；`test_workshop_options.py::test_every_shipped_skill_fits_the_options` 會抓）。
30. **只給手寫技能的條件**（DD-3 `all_strikes_hit`）：`ConditionDef.handwritten_only: true` → LLM schema 不列（`proposal/builder.py::_condition_union`）、選項標 `unavailable_zh`（`option_params.condition_choice`）、`validate_skill` 擋「不是內建、不是開局包、沒有 `parents`」的技能（`condition.handwritten_only`；從內建技能進化或閃現改寫的照原招）。位置限制（只能寫在效果上、不在 `any_of`）在 `skills/problems.py::_all_strikes_problems`。比值腳本把它和 `wielding_weapon` 一樣當「自然擲出來」不另做情境（`sim/skill_ratio.py::_NATURAL_CONDITIONS`）。
33. **BS-3 放寬第 28 點的無聲來源規則**：改成「技能要帶隱蔽，可以同時帶別的關鍵字」。因為無聲本身（`silent_strike`、給無聲步的 `grant_skill`）就會推導成隱蔽，`silent_strike_problems` 先用 `_without_silence` 把這兩種事實拿掉，再推導其餘部分的專屬關鍵字：沒有任何專屬關鍵字（無聲步、影纏）→ 通過；有而且含 `concealed`（毒＋暗影傷害、火＋上隱蔽）→ 通過；有但不含（只有毒、只有火）→ 擋。內容載入與 `validate_skill` 共用這個函式，所以改一處兩邊都生效；詞條仍用 `carries_silent` 一律擋。注意：修正規則的 `add_element: shadow` **不會**推導成隱蔽（隱蔽只認 `damage element: shadow`、上隱蔽狀態、煙霧與黑暗地形等），寫「火＋隱蔽」的修正技測試時別拿它當隱蔽來源。
34. **「接下來 N 回合」的顯示與資料差 1**（BS-3 影纏）：`grant_skill` 在持有者回合結束時倒數，給自己的時候施放那回合就先扣 1，所以「2 個完整回合」的資料是 `duration: 3`。卡片文字（`narrative/skills.py::_grant_skill`）與預覽（`preview._grant_infos`）用 `content.skills.silent_rounds_shown` 顯示 N＝資料 − 1；只適用「給自己的無聲」（`affects: self`、`is_silent_grant`），飛行等其他給技能照資料顯示。預算（`_grant_skill_points`）、戰鬥紀錄文字、HUD 的「剩 N 輪」仍照資料值（3）。
35. **閃現蓄力、輕巧的規則在 `skillgen/flash_cost.py`**（FL-1a，06 6.34「費用方向」第 1～4 點）：`flash_derive.apply_variation` 遇到 `op` 在 `COST_OPS`（`charge`、`light`）就交給 `_apply_cost`——先走原本的預算重調（同一組子亂數，所以本來就合格的結果逐字不變），結果要過 `accept_for`（蓄力：`strength_moves` 至少一項變強；輕巧：沒有一項變強、至少一項變弱）；不過再走確定性退路 `charge_adjusted`／`light_adjusted`（傷害 → 治療護盾與狀態強度 → 狀態回合，一次只動一項）。輕巧在 AP 1 時不走重調（強度下限只換算 AP，重調只會打平或變強）。蓄力的回合累計上限要「原招」：`apply_variation(..., origin=)`，`derive_chain` 傳 `at_role_tier(base)`。每一級的幅度在 `skill_budget.yaml` 的 `flash_cost`（`BudgetRules.flash_cost`，工坊白名單 `kind: budget`）。**模擬改前行為**：`flash_derive.COST_OPS = frozenset()` 就回到改前的通用路徑（FL-1a 用它逐條預測 parity 夾具，126 條改前雜湊全部等於夾具）；掃描腳本與預測寫法見 `docs/phases/PhaseFL-1a報告.md`。
36. **卡片上的法力是實付值**（`core.mana_cost`，×0.8 四捨五入）：資料 3 → 2 實付都是 2。比對「前 → 後」（`api/flash_changes.py`，`FlashOptionOut.changes`）照卡片數字，所以這種改動不列；規則層（`flash_cost.strength_moves`）只比效果強度欄位，不看代價。
37. **輕巧的「少付」看卡片實付值**（FL-1c，06 6.34「費用方向」第 5 點）：`flash_ops._light_cost_drafts(skill, fields, library)` 用 `_paid`（法力照 `core.mana_cost`）比減 1 前後，實付沒變就 **停**（不出這項、也不改試後面的項目；前面已排進來的照舊）。所以 AP 1、只剩法力可減、法力 3（×0.8 → 2）的招不出輕巧（飛行、咒印飛彈、霜寒之觸、收割靈魂、靜電掌、燼咒、雷咒）。
38. **增益的回合也算「狀態回合」**（FL-1c 第 6 點）：`flash_cost._has_rounds` ＝ `apply_status`（增減益都算）＋ `grant_skill`（展翼、賜予羽翼）＋ `affects: allies` 的 `zone`（戰歌）；對敵或全體的 zone（火牆）不算。這些原語的回合卡片數字（`card_stats` 的 `amount`）沒有，`api/flash_changes.py` 另用 `_BUFF_ROUNDS_ZH`（「獲得技能回合」「區域回合」）列差異。區域裡的巢狀狀態（戰歌的激昂）不在退路裡（激昂沒有 `scales_with_magnitude`，調不了「加值」）。**模擬改前行為**：`flash_ops._paid = lambda _l, _f, v: v`、`flash_cost._has_rounds` 換成只認 `apply_status`（`docs/phases/PhaseFL-1c報告.md` 的預測腳本）。
39. **「有沒有閃現選項」事先算**（FL-1c 第 7 點）：`skillgen.flash_offer.has_options(library, request)`＝不指定類別出題會不會至少 1 個選項（同一套 `_builder`、`UsageSource`，類別＝這次可出的 ∪ 補位用的小變化類別，大變化另看轉型保底；不看 LLM 提議），結果快取在 `ContentLibrary.flash_option_cache`（鍵＝請求內容 SHA-256，512 筆清空）。`roguelite.flashes.flash_available` 包一層；`run_presenter._flash_out` 只在 `problem_of` 為 `None` 時算，沒有選項 → `can_flash=False`、`flash_problem_zh=NO_OPTIONS_ZH`、`flash_available=False`（大世界的 `hero_panel` 共用）。1 階主動 277 招第一次呼叫中位 1.6ms、最慢約 80ms；和 `make_offer` 逐招比對（含第 2、3 次）809 筆一致。
40. **FL-1d 補定的增益範圍**：`flash_cost._BUFF_DURATION_TYPES` 再加護盾（沒寫回合＝2，`strength_table` 也補 2）、`cheat_death`、`redirect_damage`（沒寫回合時不調）；只對友方的區域裡巢狀的 `apply_status` 經 `_walk` 走進強度表、退路與原招回合表（`_Step.sub`，鍵 `effects[i].effects[j]:…`），算法同直接施加的狀態。給 AP、額外反應的數量不算。差異清單的列名在 `api/flash_changes.py` 的 `_BUFF_ROUNDS_ZH` 與 `_nested_rows`。不死、轉移傷害的回合預算器不計價，輕巧降它們不會降比例（魂結輕巧＝轉移傷害 3 → 1；FL-1e 後 3 → 2）。
41. **輕巧的回合：只有沒計價的每次最多 −1**（FL-1e，06 6.34「費用方向」第 6 點，玩法 PM e0e22fd9f；原版「所有回合每次最多 −1」已撤回）：`flash_cost._duration_step` 往下時，預算器沒計價的回合（`_UNPRICED_DURATION_TYPES`＝不死 `cheat_death`、轉移傷害 `redirect_damage`）只給 `now − 1` 一格（`LIGHT_UNPRICED_STEP`），其他回合照 FL-1d 一路降到合格（最少 1，點燃斬燃燒 5 → 2）。`light_adjusted` 沒變：第一個有合格結果的項目就用，所以降 1 量不出有沒有扣回也照樣出輕巧（魂結 3 → 2）。第一版全部限 −1 時 74 筆輕巧消失（AP 2 → 1 少付太多，降 1 比例仍約 143%）、展翼沒選項，所以撤回。**預測快照的寫法**：包一層 `flash_derive.light_adjusted`，同時算新舊兩版、回傳舊版，記下有分歧的測試或夾具條目（pytest 外掛 `-p`，見 `docs/phases/PhaseFL-1e報告.md`）。
