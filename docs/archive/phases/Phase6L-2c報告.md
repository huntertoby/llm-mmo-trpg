# Phase 6L-2c 報告：閃現預先生成的鍵不含用法統計

依據：6L-2b 報告「待 PM 決定」第 3 點，玩法 PM 已決定（鍵不放用法統計、同一招最多 1 個請求、
第一次閃現照 #132 在渡口戰後就開始、上限不變）。

## 1. 做了什麼

- **暫存區的閃現鍵不含用法統計**：新增 `trpg.world.generated.flash_pregen_key`，輸入與
  `flash_key` 相同但拿掉 `usage`（前綴 `flash-pregen/`）。`WorldPregen` 的暫存區改用這把鍵
  （`_slot`；劇情技能與機遇照舊用請求的鍵）。
- **統計只讀一次**：排進佇列的請求就是開始生成那一刻的請求（含那時的統計），之後統計變了，鍵不變，
  不重開；已經在生成或做好的都不重開。同一招同一次出題（同一欄、同一類別、同樣的階級、武器、
  其他技能）在暫存區只會有一筆。
- **按下時**：供應者用不含統計的鍵找到那一筆，給出去前把 `FlashGen.key` 改成按下那一刻的
  `flash_key`（引擎比對鍵；`record.tag` 保留生成時的鍵，看得出用的是哪一份）。引擎照樣用
  `make_offer` 逐一驗證變化、套不上的用模板補；日誌記下的就是這一份，重播照 6L-2 只讀日誌。
- 時機與上限沒改：閃現仍在戰後、那招可以閃了就開始（不看地點）；每角色 3 招、全服 12 筆。

## 2. 鍵的新組成

| 鍵 | 用途 | 內容 |
|---|---|---|
| `flash_key`（沒改，值逐字相同） | 引擎的請求鍵、日誌紀錄的鍵、重播查找 | 前綴 `flash/{技能}/{第幾次}/{重閃次數}/{類別}`；角色、原技能、閃現狀態、**用法統計**、種子、欄位、類別、其他技能的關鍵字分布、階級、目前定義、區域、武器 |
| `flash_pregen_key`（新） | 預先生成暫存區 | 前綴 `flash-pregen/…`；同上但**不含用法統計** |

`flash_key` 只是把輸入抽成 `_flash_data` 再加上 `usage`，JSON 排序後雜湊，值與以前相同
（相關重播測試全過）。

## 3. 重播與版號

- `WORLD_RULES_VERSION` **不升（12）**：世界引擎（`trpg.world.growth`）沒改；`flash_key` 值不變；
  日誌記的是最後給出的版本（鍵是按下那一刻的鍵），重播用 `recorded` 依鍵查，舊日誌與新日誌都照讀。
- 唯一的行為差別在 API 層：給出去的 LLM 變化可能是用較舊的統計做的。這只影響「當下給什麼」，
  不影響重播（重播讀日誌那一份）。

## 6. 待 PM 決定

1. **用舊統計做的變化**：按下時給的是開始生成那一刻的統計做的變化。統計會影響 LLM 提議的方向
   （例如常打多目標就偏向範圍），連打很多場後，提議可能比較貼近較早的打法。引擎驗證照舊，所以不會
   不合法，只是不一定反映最新打法。我採照玩法 PM 決定、不做「統計差太多就重做」。
2. **鍵其他欄位變了仍會重做**：升級換階級、換武器、換其他裝備中的技能（關鍵字分布變了）時，暫存鍵會換，
   舊的丟掉、重新生成（這些會改變合法的選項，不能沿用）。做到一半的舊請求中斷不了（6L-2 待決 2），
   但單一佇列下不會同時進行。
3. **指定類別或重閃**：玩家按下時指定類別、或重閃某一欄，是另一次出題（鍵不同），沒預測到就當場排進
   佇列；這和「同一招最多 1 個」不衝突（預測端每招只排 1 個），但當場的那個會和預測的那個並存到
   預測被丟掉為止。
4. 測試的「連打 5 場」是直接改角色的用法統計模擬，沒有真的打 5 場戰鬥（真的打仗太慢）。真的打仗時
   若升級換階級，照第 2 點會重做一次。
