## 2. 對照規格

1. **格子大小**：照戰鬥繪製器的預設縮放 `BattleRenderer.scale = 1`（每格 `TILE_SIZE` 48 CSS 像素），`FIELD_SCALE = 1`。霧渡鎮（24×18）畫布 1152×892，在 1040×624 視窗的舞台（1008×556）放不下，所以跟著走。
2. **跟隨／夾邊界／置中**：`followCamera(view, grid, focus)`：每個方向各自判斷，地圖比畫面大就以主角為中心、夾在 `[0, 地圖−畫面]`；比畫面小就置中。走路時每一格都把鏡頭目標設成那一格，CSS `transition: transform 120ms linear`（同 `STEP_MS`），和小人的逐格補間同步。換地圖時不播平移（直接跳）。
3. **框矩形接口（給 6C-2）**：`WorldField` 的 `hud.frame?: TileRect | null`；有值時改用 `frameCamera(view, grid, rect)`：縮放取「範圍＋四周半格放得進畫面」，上限 1（不放大）、下限 0.5，以範圍中心為準並夾在地圖內；切換時平移 300ms。純函式也可以單獨用。
4. **小地圖**：`visibleTiles()` 算出鏡頭看得到的格子範圍，小地圖上畫白框；說明卡加上「白框＝畫面看得到的範圍」。
5. **點擊換算**：畫布用 CSS `translate` 平移，`BattleCanvas` 原本就用畫布的 `getBoundingClientRect()` 換算格子，所以鏡頭位移自動算進去（沒改 `BattleCanvas`）。`viewToTile()` 是同一個換算的純函式版，測試確認兩者結果一樣。
6. **出口半透明**：`exitViewRects(field, cam, stage)`：以畫面上的出口位置判斷，**只算畫面上看得到的出口格**（見待決 2）。
7. **視窗大小變化**：舞台大小沿用 6B-5 的 `useHudStage`（ResizeObserver＋resize），鏡頭隨大小重算；實測從 1040×624 改成 800×600 時鏡頭立即重算。
8. 非 HUD 版面（節點圖地點旁的舊左欄）沒動，照舊整張放進去。

## 4. 待 PM 決定（都已照最保守的做法做完）

1. **「戰鬥的預設尺寸」**：取繪製器的預設 scale＝1（每格 48 像素）。戰鬥畫面實際上是自動填滿（`fitScale`，0.5～2 倍，看視窗大小），所以戰鬥時的格子大小會隨視窗變。如果想要和某個視窗大小下的戰鬥格子一樣大，要改 `FIELD_SCALE`。
2. **畫面外的出口不讓 HUD 變半透明**：出口剛好在畫面外（只差 6B-5 的半格緩衝）時，原本的規則也會讓任務追蹤變半透明；改成只算畫面上看得到的出口格。
3. **`floatCardRule.test.ts` 失敗（6B-5 留下的）**：6B-5 的 HUD 面板用 `role="dialog"`，白名單沒有加 `world/WorldHud.tsx`；6B-5 報告待決 8 已說明它是點了才開的對話框。要加白名單或改元件，需另外決定（這段不在範圍）。
4. **框矩形的邊距與縮放**：`frameCamera` 預設四周各留半格、最多 1 倍（不放大）、最少 0.5 倍；6C-2 接上時可以依實際戰場調整。框住期間鏡頭不跟主角。
5. **地圖邊緣**：照規格到邊停住，所以靠邊時主角不在中央、可能靠近 HUD 塊（例如渡口石階 800×600 時主角在左下，離左下提示很近）；沒有另外加安全邊距。
6. **鏡頭焦點不算抬高**：跟隨用格子中心（不加該格的高度抬高），高台上主角會比中央略高幾個像素。
