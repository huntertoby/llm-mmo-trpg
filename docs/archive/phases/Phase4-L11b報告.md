# Phase 4-L11b 報告：一致性檢查詞表與規則調整

依玩法 PM 決定調整詞表與檢查規則，並用 4-L11 樣本做離線檢查（不連模型、不動 prompt 版本號）。

## 改了什麼

1. **補詞**（`content/llm/effect_words.yaml`）
   - 新增 `burning` 組：words 點燃、引燃、著火；matches 狀態 burning、表面 fire。
   - `fire` 組 `ignore` 加入點燃、引燃、著火（這些詞含「燃」「火」，不移出就會被 fire 組吃掉，只有火傷害也能過關）。
   - 新增 `vulnerable` 組：words 易傷、破綻；matches 狀態 vulnerable。「氣力」不收。
2. **比喻**
   - 規則寫成資料：詞表頂層 `simile_markers`（如、像、宛如、彷彿、猶如、好似）與 `simile_end`（結束標點集合）；`EffectWords` 新增兩個欄位，`consistency.strip_similes` 依資料把「引導詞起到下一個標點之間」的片段整段跳過（`mentioned_groups` 先過這一步；`check_added` 不套用）。
   - 詞移出：纏繞（root 組留纏縛）、氣流（wind 組）、癒合（heal 組留治療、治癒）。
   - 原句例外：earth 組 `ignore` 加「獻予大地」「大地深層」（4-L11 被擋原句 #10、#15）。
3. **missing_added 放寬**（`check_added`）：只要求「只屬於一組」的新增項目；同時對應多組的（clear_surface、blow_surface、元素精靈、燃燒狀態、火表面、隱蔽狀態等）不拿來要求。
4. 離線檢查腳本：`scripts/consistency_offline_check.py`（用卡片文字近似效果鍵，詞組在卡片找不到對應關鍵字就算被擋；新舊詞表比較）。
5. 測試（`tests/llm/test_consistency.py`，MockLLMClient／純函式）：burning 組、易傷組、比喻跳過（含標點邊界）、移出的詞與仍保留的詞、missing_added 多組不要求；原本用燃燒狀態的兩個測試改用暈眩（燃燒現在屬於多組，不再被要求）。

## 待 PM 決定

1. **burning 的 missing_added 不再被要求**：燃燒狀態同時屬於 fire 組（matches）與 burning 組，依「只屬於一組」規則被排除，所以「加深點燃」這類閃現變化不再強制名稱寫點燃。要保留的話，選項是把 burning 狀態從 fire 組 matches 拿掉（代價：只靠火元素描述「燃燒」的文字會被擋），或讓 burning 組單獨有一個「必須提到」的標記。同樣情形的還有隱蔽狀態（stealth／shadow 兩組）。
2. 比喻句的寫法沒有寫進 prompt（照指示不動 prompt 版本號）；模型不知道比喻不被檢查，但也不會因此被擋，影響不大。若想讓它放心用比喻，可在下次改 prompt 時補一句。
3. 比喻跳過是「引導詞起到下一個標點」：「如」會出現在不是比喻的詞裡（例如「如果」「不如」），目前沒有發現誤傷，若出現再加例外詞。
4. 樣本 #11「借隱蔽之姿…」仍被擋，因為不知道當時技能是否有隱蔽；若是條件（潛行偷襲）才算，需看技能資料再決定是否為 `skill_facts` 漏收條件中的狀態。
