## 1. 高度標記被單位擋住

**做法：把標記畫在單位圖層之上。**（`render/rowLayers.ts`）
- 每一排的圖層順序原本是「地形 → 裝飾 → 物件 → 高度徽章 → 陷阱 → 單位 → 上層霧」，改成「… → 陷阱 → 單位 → **高度徽章** → 上層霧」。
- 標記仍然在**南邊一排之下**，南邊一排的人照常蓋過來。標記還在格子左上角，大小沿用 6F-9 的最小尺寸。

**為什麼不改到右上角**
- 人形的身體寬度大約是格子中心 ±12 世界 px，頭頂會伸到上一排。標記本身約 19 px 寬，800 寬時會放大到 1.54 倍（約 29 px）。所以不管放左上角還是右上角，都會和身體重疊。
- 6F-9 的 1600 截圖裡，(4,4) 的右上角也有朝向箭頭和手臂。只換角落的話，被擋的情況還是會發生，只有畫在單位之上才保證看得到。

**截圖**
- 1600×900：`6f10_1_battle_1600`（全畫面）、`6f10_1_height_occupied_1600_zoom`（(4,4) 有人站）、`6f10_1_height_empty_1600_zoom`（(5,5) 沒人站）。
- 800×600：`6f10_1_battle_800`、`6f10_1_height_occupied_800_zoom`、`6f10_1_height_empty_800_zoom`。

**副作用**：有人站時，標記會蓋住那個人的頭左側一部分。800 寬時標記放大，蓋到的範圍比較大（見待決 1）。

## 2. 飄字被戰場邊緣切掉

做法（`render/floatStack.ts` 新增 `clampFloatCenter`；`BattleRenderer.makeEffect` 新增 `placeFloat`、`floatBounds`）：
- **每一幀**都用當下的大小把整個字夾在戰場裡：彈一下的放大、暴擊的放大和黑邊都算進去。邊緣留 2px（`FLOAT_EDGE_PAD`）。
- 四個邊都處理：
  - 左右：地圖兩側邊緣。
  - 上：畫布上緣，含頭頂預留區（和 6F-6 的上限一致）。
  - 下：地圖下緣。
  - 計算時扣掉鏡頭偏移。
- 字比戰場還寬或還高時，放在正中間。
- 傷害字和狀態字（「＋狀態」）都走同一條路。原本只用停住時的寬度夾左右（`clampFloatX`），彈一下時字會比停住時大，所以靠邊時會被切到。
- 狀態字的光環照舊用 `clampFloatX`，只夾左右，沒有改。

**截圖**（開場輪到敵人，主角在左緣 (0,3) 被推去撞地圖邊緣，出現兩個「撞擊！」）
- `6f10_2_edge_1600`、`6f10_2_edge_1600_zoom`（左緣，3 倍）
- `6f10_2_edge_800`、`6f10_2_edge_800_zoom`
- 字和黑邊都在畫布內，離左緣約 2px。

## 3. 量詞統一

新增 `battle/pickCount.ts`：
- `tileCount` 輸出「N 格」。
- `unitCount` 輸出「N 個」。
- `pickCountText` 依可選的東西決定：只有格子寫「N 格」，只有單位或物件寫「N 個」，兩種都有寫「N 個目標、M 格」。

**改了的地方**
| 位置 | 之前 | 之後 |
|---|---|---|
| 選取面板（`ActionPanel.modeHint`），格子技能 | 紅框 19 個 | 紅框 19 格（和技能列一致） |
| 選取面板／技能列，攀跳的紫色格子 | 共 N 個／（N 個） | 共 N 格／（N 格） |
| 兩段選取的第 2 段（`hurlPromptText`）：投擲、傳送、影步的落點 | 紅框 N 個 | 紅框 N 格 |
| 兩段選取的第 2 段：互換的第二個人 | 紅框 N 個 | 照舊「個」 |
| 複合技能第 1 段（`compositePrompt` 和技能列） | 紅框 N 個 | 落點算「格」，目標算「個」 |
| 第二段選目標、複製技能的對話框 | 目標或格子（共 N 個可選） | 共 N 個選項（數的是選項，不是格子） |

- 單位、物件的數量照舊用「個」：斬擊的「2 個」、守護的隊友、投擲第 1 段的物件或人、傳送的人。
- 掃過 `client/src` 全部給玩家看的字串，「一個格子」這類「個＋格子」的說法沒有改。
- 測試加了一條原始碼掃描：說到「格子／落點／紫色」時，緊接的括號裡不能寫「${…} 個」（「個選項」除外）。
- 實機：`6f10_4_summon_1600` 拍到選取喚起骷髏時，左側面板寫「紅框 13 格」，技能列寫「（13 格）」。

## 4. 召喚物的狀態列與回合數徽章

做法（`render/unitSprite.ts` 新增 `summonRowLayout`；`render/minMark.ts` 的 `registerMark` 多一個 `relayout`）：
- 回合數徽章改成「圓心在節點原點」，節點放到徽章位置，可以整個移動。
- 每次地圖縮放改變、狀態列的倍率 k 跟著改變時，都重新排一次：
  1. 徽章不動，狀態列夾在格子左緣和「徽章左緣 − 2px」之間。放得下就照原間距；放不下先縮小圖示間距，最小 6。
  2. 縮到最小還放不下時（800 寬有「+N」、地圖縮得很小，或炸彈把徽章往左推），徽章搬到狀態列**上方**：x 不變，下緣離狀態列上緣 2px。這時狀態列改成夾在格子左緣和右緣之間。
- 「+N」小圓連白邊算進寬度，比圖示多 3px。
- 狀態列一律不超出格子左右，各留 1px。
- 非召喚物的狀態列排法沒有改。

**截圖**（固定狀態：實機放「喚起骷髏」召出骷髏戰士；攔下戰鬥 API 的回應，在召喚物身上補 3 個狀態：守護、強化、虛弱，畫面顯示 2 個圖示＋「+1」。畫面是正式戰鬥畫面真的畫出來的）
- 1600×900：`6f10_4_summon_1600`、`6f10_4_summon_1600_zoom`。徽章在原位，狀態列往左讓開。
- 800×600：`6f10_4_summon_800`、`6f10_4_summon_800_zoom`。放不下，徽章移到狀態列右上方。

## 待 PM 決定

以下都照最保守的做法先做完了：

1. **高度標記畫在單位之上，會蓋住站在上面的人的頭左側**。800 寬時標記放大成 1.54 倍，蓋到的範圍比較大（`6f10_1_height_occupied_800_zoom`）。如果覺得太擋，可以選：
   - 有人站時把標記的底色調淡；
   - 有人站時把標記縮回原本的大小；
   - 移到格子左下角，但會和 HP 條、字母標記搶位置。
2. **「戰場範圍」的上緣用畫布上緣**，含頭頂預留區，不是地圖上緣。理由：第一排的人頭頂上方本來就是預留給浮動字的（6F-6 起），改用地圖上緣的話，第一排的字會被壓到身體上。
3. **字比戰場還寬時放正中間**，不縮小字。目前沒有實際會發生的例子。
4. **召喚物徽章放不下時移到狀態列上方**，800 寬時會蓋到骷髏的右肩一點。另一個做法是讓狀態列在召喚物身上不放大，但這樣違反 6F-9 定的 10px 下限，所以沒有採用。
5. **「共 N 個可選」改成「共 N 個選項」**（第二段選目標、複製技能的對話框）。這兩處數的是選項，選項可能是格子、單位或方向，所以不改成「格」。灌注關鍵字的「共 6 個可選」數的是關鍵字，沒有改。
6. **左右靠邊推進來的浮動字，可能和同一格或隔壁格往上堆的字靠得比較近**。`6f10_2_edge_1600_zoom` 裡，「撞擊！」和主角的「−3」有部分重疊。這是 6F-6 的堆疊規則（只照同一格往上堆，不管左右），這次沒有改。
7. **召喚物操控面板的「1 骷髏戰士1HP 46/46」**，名字和 HP 之間沒有空隙（`6f10_4_summon_800` 右側）。這不在這次的範圍內，沒有改，只記下來。
