# Phase 3-30 報告｜第 32.1 項 浮動卡互動規則一致化

> 範圍：只動前端（`client/`）。其餘 32.x 項（累積清單）本報告不涵蓋。

## 1. 雷紋刻印與念力傾倒定位不同的原因

舊的技能卡浮動層（`SkillBar` 的 `.skill-card-float`）是**以整條技能列定位**，不是以按鈕定位：`left: 50%` 置中、`bottom: calc(100% + 6px)` 貼在技能列上方，寬 380px。結果：

- 技能列上方還有一行提示文字，卡片與按鈕之間有「提示行＋6px」的空隙；滑鼠從按鈕往上滑，中間經過的是空白，離開按鈕後只有 180ms 就關閉。
- 卡片水平位置與按鈕無關。按鈕在技能列**最左邊**（雷紋刻印是第一招）時，卡片偏右上，正上方根本沒有卡片，往上滑滑不進去；念力傾倒在中間、剛好落在卡片水平範圍內，所以「往上滑」碰巧進得去。
- 另外右側的被動／反應小圖示用另一套 `enter/leave` 與 `pinned` 狀態，行為與主按鈕不同。

## 2. 規則實作

新增共用層，所有浮動卡走同一套：

- `client/src/ui/floatCard.ts`：純邏輯，無 React／DOM。`FloatController`（滑過 150ms 開、離開 250ms 寬限、卡片／橋接區進出、釘住、焦點、`hold`、同時只開一張的登記）與 `floatPlacement`（貼齊、翻轉、往內推）。
- `client/src/ui/useFloatCard.tsx`：`useFloatCard` hook（觸發元素事件、Esc、點外面、Tab 進卡片）與 `FloatCard` 元件（portal 到 body、`position: fixed`、量測後貼齊觸發元素、透明橋接區）。
- 使用者：`SkillBar`（主動技能 `SkillSlot`、被動／反應／姿態小圖示 `MiniSlot`）與 `PartTip`（部件說明框）。舊的 `tipState.ts`（與其測試）移除，由 `floatCard.ts` 取代。
- CSS：`.float-card`（外框，朝向觸發元素的一側有 6px 透明橋接 padding）＋`.float-card-body`；`.part-tip-box` 改為外框樣式。

逐條規則：

1. 滑過 150ms 顯示、離開 250ms 寬限，期間滑進卡片（含橋接區）保持開著；卡片內的部件說明框開著時以 `hold` 保持外層卡片不關。
2. 貼齊觸發元素上方、無空隙（橋接區在外框內）；放不下翻到下方；兩邊都放不下選空間大的一邊再推；左右夾進視窗（技能卡左緣對齊按鈕，部件說明框置中）。
3. 點卡片釘住；Esc、點外面關閉；同時只開一張（模組內登記，新的取代舊的，巢狀部件說明框 `nested` 例外）。
4. 按鈕以鍵盤取得焦點（`:focus-visible`）時顯示；卡片開著時 Tab 直接進入卡片，Shift+Tab 回到按鈕；觸控（`pointerType === "touch"`）不走滑過，點擊開關。

## 4. 待 PM 決定

1. **單位資訊卡（`HoverFloat`）與反應設定、裝備沒有納入共用元件**。單位資訊卡是滑過戰場格子觸發（沒有觸發元素、不可互動，`pointer-events: none`），已有自己的邊界夾住邏輯；反應設定與裝備目前只有原生 `title`，並沒有浮動卡。規格第一行把它們列為範圍，我保守地只收斂「真正有觸發元素的浮動卡」（技能列、`PartTip`）。是否要把反應列、裝備格的 `title` 也改成浮動卡，或讓單位資訊卡可釘住，請決定。
2. **技能按鈕的滑鼠點擊不釘住卡片**（點按鈕是選取／施放；若同時釘住卡片，會蓋住戰場下緣）。釘住方式是：點卡片本身、觸控點按鈕、以及灰掉無法施放的按鈕與被動／反應小圖示（點一下就釘住）。規格寫「點一下觸發元素或卡片即釘住」，若要滑鼠點技能按鈕也釘住，改 `SkillBar.tsx` 的 `pinOn` 即可。
3. `PartTip` 的說明框原本不攔截滑鼠（`pointer-events: none`），現在可以被滑進去（為了「卡片→部件」與橋接區的一致規則），在工坊選項按鈕上方的說明框因此會擋住下方一小塊區域。
4. 截圖為 `.jpg`（環境沒有 PNG 轉檔工具）。
5. 觸控裝置與鍵盤 Tab 行為僅有單元測試與程式邏輯，未在實機觸控環境驗證。
