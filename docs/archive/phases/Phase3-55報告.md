# Phase 3-55 報告：卡片寫出具體屬性

規格：`docs/phases/Phase3計畫.md` 第 65 節。

## 做了什麼

| 規格 | 實作 |
|---|---|
| 1 武器技算法句寫具體屬性 | `SkillDef._formula_names_zh`（`content/skills.py`）：有持有者武器時寫實際屬性（`WeaponDef.skill_scaling_names_zh`：單屬性「力量」、同類雙屬性「敏捷／力量（取較高）」、物理＋心智「力量／智力（取平均）」、3I-3 技能心智第二屬性「…與智力（取平均）」），附「目前 +N」。沒有持有者寫「武器屬性」，並多一行「武器屬性看手上的武器：斧、雙手劍等＝力量；魔導劍＝力量／智力（取平均）；…」（`weapon_attr_examples_zh`，由武器資料產生；依武器大類過濾、不含召喚物專用、同屬性合組、最多 5 組） |
| 1 親和效果那一行 | `effect_summary` 對武器技的 `wielding_weapon` 效果補「，這把武器吃力量／智力（取平均）」（`_affinity_attr_text`；副手條件、非武器技不補）。符文斬：「武器傷害 ×0.9（雷電）（敵方），若手持魔導劍時，這把武器吃力量／智力（取平均）」 |
| 1 效果句裡的縮放與對抗屬性 | 有持有者時，效果句的 `scaling_label`／`contest_label`（擊倒、推、傳送的對抗）也寫那把武器實際的屬性（`ContextVar` 在 `skill_card` 期間帶持有者武器）；沒有持有者維持舊寫法 |
| 1 工坊有 `weapon` 參數 | 新增 `WorkshopCheckRequest`（`weapon` 選填），`POST /api/workshop/check` 帶武器時卡片以那把武器為持有者（大類和技能的武器需求不符就不用）；前端 `workshopCheck(draft, heroWeapon)`。目前 App 沒有傳 `heroWeapon` 的來源（沿用 3-48b 的狀態），所以畫面上仍是「列例子」；接上主角手上武器後自動變實際屬性（沒有屬性值，所以只寫屬性名、不寫「目前 +N」） |
| 2 「條件：手持武器」 | 查明：**不是技能條件**（符文斬 `condition: null`）。是卡片組裝圖示的條件小圓（`條件：{條件名稱}`），名稱取自 `content/skill_conditions.yaml` 的 `wielding_weapon.name_zh`＝「手持武器」，也出現在「最低稀有度」的原因列。它是效果層級的親和條件（有意義：這招有一個「拿特定武器才多的加成」），但「手持武器」讀起來像「需要拿武器才能用」。改成「手持指定武器」（yaml、工坊選項說明、glossary 夾具）。另外 `condition_text` 沒帶武器 ID 的 `wielding_weapon` 以前會露出英文代號，改為「手持指定的武器時」 |
| 3 法術技 | 確認：法術卡的算法句一向寫具體屬性（單屬性「智力」、雙屬性「智力／感知（取平均）」），組合主題（智力或感知）是工坊的選項範圍，選定後卡片寫選定的屬性；新增測試每 5 招抽 1 招法術技驗證 |
| 5 行為一致測試 | `tests/narrative/test_card_attributes_55.py`：卡片「目前 +N」＝實戰 `DamageDealt.scaled_permille`（單手劍、匕首取較高、魔導劍＋意志、鞭取平均四組）；另有範例產生、無持有者、有持有者、親和行、對抗行、法術技測試（共 24 項）。既有 `test_weapon_skill_scaling`、`test_arcane_blade_3i3`、`test_rule_texts_41c` 的一致測試不變 |
