### 3.2 底線第 1～8 條

1. **交出前並排比對**：和已定案的同類美術並排，品質不可以低於已定案版本（浮島對 `art/shots/misc/world-painted.png`；人物、頭像對 `qDoll.js`、`art/shots/misc/key-poses.png`、`art/shots/misc/parts-4dir.png`；圖示對 `art/shots/misc/story-icons.png`、3T-4 武器圖示、`skillIcons.js`；框與按鈕對 HUD A、`art/shots/region/region-themes.png`）。
2. **已有素材一定要用**：直接呼叫 `QDoll.stamp`、`WorldPaintedArt.drawBackdrop`、`Portraits.portrait`、`GearArt.draw`、`SkillIcon.draw`、`ItemIcons.draw`，不另畫簡化版。
3. **不能用幾何占位冒充樣張**；真的要占位就在樣張上寫「占位」，交件時說明之後用什麼換。
4. **逐元素檢查**：背景、角落小圖、清單項目、按鈕、空狀態、提示文字都要看，每個元素都說得出用的是哪套已定案畫法。
5. **寫「之後再補」要追蹤**：記進 0.1 的表，不可以變成永久占位。
6. **人物樣張必檢：四方向＋武器朝向**：正面、背面、朝東、朝西四格逐格看披風、盾、副手、武器的位置與前後；武器「握把在手、作用端朝 −y」再依方向轉；樣張頁首跑自測（`style-compare-3.html` 151 項）；盾與披風同色時靠位置與邊框分開。
7. **只靠自測過關，不算完成**：每張放大 3 倍親眼看，逐張寫「我看到：手在…、武器在…、配件在…」，對照真人常識。畫法原則：武器掛在手上（位置與角度由主手決定，副手再去握第二個握點）；姿勢不靠 IK 自動解，每類、每方向先手調關鍵姿勢；只在正面的配件（腰帶扣、紋章、領口、扣子、前襟）側面轉到前緣、背面不畫。
8. **一次整理交件，交件後由獨立審查 agent 看特寫**（11-04 晚使用者：「感覺要先把 美術pm停掉 因為我們任務 分很多次給他 一次告訴她要修哪些」；審查流程：「好」）。專案 PM 整理總清單，美術 PM 全部做完一次交件，中途不分批；交件要附所有樣張路徑、3 倍特寫清單、每張的「我看到」；四面分別畫（對照表 `art/部件四方向清單.md`）。

### 3.3 驗收開發交件的固定步驟

1. 看報告的檢查清單。
2. 每張截圖逐元素看；幾何形狀或純色塊代替圖示的不通過；有素材卻沒用的不通過。
3. 至少一張實機截圖；只有開發頁或假資料時在紀錄裡寫「實機未看」並開一條追蹤。
4. 地圖、城鎮類要看完整張圖；配角設施逐一確認有自己的外觀。
5. 和已定案的同類並排看一次。
6. 紀錄 `docs/art/<段>檢查.md` 寫明看了哪些、沒看哪些。commit 後回開發 PM，給專案 PM 一行結論。段落結案後，檢查紀錄搬到 `docs/archive/art/`，截圖刪掉。
